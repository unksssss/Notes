#### 1. `Assets/Scripts/Base/RoleBase.cs`（15:44）—— 开火链路从 `Player` 下沉到基类

改之前：`Fire_ARs` / `Fire_Launchers` / `PlayFireAudioClip` 全写在 `Player` 里，`EnemyAI` 想开火只能复制一遍。改之后 `RoleBase` 提供固定流程，子类只覆盖一个钩子：

```cs
protected void Attack()
{
    if (currWeaponItem == null) return;
    switch (currWeaponItem.WeaponType)
    {
        case 1: Fire_ARs();      break;   // 自动步枪
        case 2: Fire_Launchers(); break;  // 火箭筒
    }
}

// 唯一的差异化钩子：这颗子弹朝哪飞
protected virtual void SetBulletType(Bullet bullet) { }

protected virtual void Fire_ARs()
{
    if (currWeaponItem.currNum == 0) return;   // 空弹夹直接返回
    currWeaponItem.Shoot();                    // 扣一发
    animatorManager.Fire();                    // 开火动画
    PlayFireAudioClip();                       // 开火音效（按 WeaponType 选 clip）

    var bulletGo = ResourcesMgr.Instance.GetInPool(ResourcesPath.Bullets, currWeaponItem.BulletName);
    bulletGo.transform.position = muzzle.position;
    bulletGo.transform.rotation = muzzle.rotation;

    var bullet = bulletGo.GetOrAddComponent<Bullet>();   // 池化对象复用组件，不重复 Add
    bullet.StartMove(currWeaponItem.BulletName, currWeaponItem.AttackValue,
        currWeaponItem.Speed, currWeaponItem.Range,
        AudioClipMgr.Instance.bulletImpact_1, ResourcesPath.Effect_Imp_Metal);
    SetBulletType(bullet);                     // 交给子类定朝向

    var effectGameObject = ResourcesMgr.Instance.GetInPool(ResourcesPath.Effects, "MuzzleFlash");
    var muzzleEffect = effectGameObject.GetOrAddComponent<MuzzleEffect>();
    muzzleEffect.OnStart("MuzzleFlash", muzzle);
}
```

**为什么这么写** —— 这是标准的**模板方法模式**：基类把「开火」这个动作固定成「判弹夹 → 扣弹 → 动画 → 音效 → 取子弹 → 定朝向 → 枪口特效」七步，子类不许改顺序，只能填「定朝向」这一步。收益有三：

- 玩家和敌人不会出现「一边有音效一边没有」「一边扣弹一边不扣」的漂移；
- 加第三种角色（比如友军 NPC）零成本，只要实现 `SetBulletType`；
- 弹药 / 音效 / 特效的资源配置集中在一处，改一次全生效。

子类这边只剩表现层：

```cs
// Player.cs（15:44）
protected override void SetBulletType(Bullet bullet) => bullet.MainPlayerShoot();

public static event Action OnFire;

protected override void Fire_ARs()
{
    base.Fire_ARs();                       // 玩法逻辑全在基类
    OnFire?.Invoke();                      // 通知 UI/后坐力等外部系统
    UIFightingView.Instance.SetCurrTextNum(currWeaponItem.currNum, currWeaponItem.BulletNum);
}
```

职责边界很清楚：**基类管玩法，子类管表现**。`EnemyAI` 连 override 都不用写，只实现 `SetBulletType`：

```cs
// EnemyAI.cs（15:43）
protected override void SetBulletType(Bullet bullet)
{
    bullet.EnemyAIShoot(muzzle.position, pursueTarget.position);
}
```

顺带把敌人的武器装配也搬进了 `EnemyAI.Start()`：按 `WeaponID` 查 `WeaponConfig` → 载入对应 `RuntimeAnimatorController` 换枪械动画层（`animatorManager.EquipeGun`）→ 载入武器 prefab 挂到 `WeaponPoint` → `SetCurrentNum(BulletNum)` 装满弹夹。

#### 2. `Assets/Scripts/Fightings/Bullet.cs`（15:37）—— 六参 `StartMove` + 两个射击入口

签名从四参扩到六参，把「击中音效 + 击中特效名」也变成数据：

```cs
public void StartMove(string _bulletName, int _attackValue, float _speed, int _range,
                      AudioClip _audioClip, string _imp_EffectName)
{
    bulletName = _bulletName;  attackValue = _attackValue;
    speed = _speed;            range = _range;
    impact_AudioClip = _audioClip;
    imp_effectFileName = _imp_EffectName;
    beginPosition = transform.position;   // 记起点，用于射程判定
    isMove = true;
}
```

好处是 `Bullet` 里不再硬编码任何资源路径 —— AR 传 `bulletImpact_1` + `Effect_Imp_Metal`，RPG 传 `rocketImpact` + `Effect_Explosive_Barrel`，同一个子弹类通吃。

两个射击入口，差别只在「起点和方向怎么来」：

```cs
// 玩家：屏幕中心 + 随机偏移 → 世界射线
public void MainPlayerShoot()
{
    float offSetX = Random.Range(-1, 1) * accuracy;    // ⚠️ int 重载，见 Part D
    float offSetY = Random.Range(-1, 1) * accuracy;
    Vector2 center = new Vector2(Screen.width / 2f + offSetX, Screen.height / 2f + offSetY);
    ray = Camera.main.ScreenPointToRay(center);
    this.transform.position = ray.origin;              // ⚠️ 覆盖了枪口位置
    transform.rotation = Quaternion.LookRotation(ray.direction);
}

// 敌人：枪口 → 目标（带三轴散布，瞄身体不瞄脚）
public void EnemyAIShoot(Vector3 muzzle, Vector3 target)
{
    float offSetX = Random.Range(-1f, 1f) * enemyShootAccuracy;   // 这里是对的 float 重载
    float offSetY = Random.Range(-1f, 1f) * enemyShootAccuracy;
    float offSetZ = Random.Range(-1f, 1f) * enemyShootAccuracy;
    target = new Vector3(target.x + offSetX, target.y + offSetY + 1f, target.z + offSetZ);
    Vector3 dir = (target - muzzle).normalized;
    ray = new Ray(muzzle, dir);
}
```

`target.y + 1f` 是刻意的：目标点通常取敌人/玩家的 `transform.position`（脚下），加 1 米才打到胸口高度，否则子弹全打地。

击中判定用 `Physics.Raycast(ray, out hit, distance, layer)`，`layer` 取 `~（1 << NameToLayer("Projectile")）` 排除自身层，避免子弹打自己。已确认 `ProjectSettings/TagManager.asset` 第 35 行确有 `Projectile` 层，`NameToLayer` 不会返回 -1。

#### 3. `Assets/Scripts/Role/EnemyAI.cs`（15:43）—— `SetSpeed` 用 `MoveTowards` 修掉「负速度倒着跑」

这是昨天留下的最重一个坑，今天换掉了实现：

```diff
- private void AddSpeed(float _runSpeed)
- {
-     if (runSpeed >= _runSpeed) { runSpeed = _runSpeed; return; }
-     runSpeed += Time.deltaTime * 3f;
- }
- private void MinusSpeed(float _speed)
- {
-     if (runSpeed >= _speed) { runSpeed = _speed; return; }
-     runSpeed -= Time.deltaTime * 3f;      // ← 没有下限
- }
+ private void SetSpeed(float _targetSpeed)
+ {
+     runSpeed = Mathf.MoveTowards(runSpeed, _targetSpeed, 3f * Time.deltaTime);
+ }
```

**为什么这么写**：`Mathf.MoveTowards` 的语义是「朝目标走、最多走这么远」，目标值天然就是上下限 —— 既不会冲过目标，也不会越过 0 掉进负数。原实现是「快过目标就钳位、否则继续减」，看着像平滑，实际漏了「当前值在目标另一侧」这一半情况，具体复现链见下面 Part B 第 7 条。

同时 `SelfPos` 从临时变量提升成属性，避免每处手写拍平：

```cs
private Vector3 SelfPos => new(transform.position.x, 0, transform.position.z);
```

攻击节奏加了节流（`lastShootTime` + `Time.time - lastShootTime > 1f`），否则 `Update` 每帧都会走一次 `Attack()` 把弹夹打空。

### 其他技术产出（Part D）

#### 1. `Bullet.Move` 超距分支缺 `return` → 同一发子弹二次回池

```cs
// Assets/Scripts/Fightings/Bullet.cs:54-78
private void Move()
{
    transform.Translate(ray.direction * (Time.deltaTime * speed), Space.World);
    float distance = Vector3.Distance(beginPosition, transform.position);
    if (distance > range)
    {
        isMove = false;
        ResourcesMgr.Instance.ReturnPool(bulletName, this.gameObject);   // ← 没有 return
    }
    // 下面这段同一帧还会继续执行
    if (Physics.Raycast(ray, out var hit, distance, layer))
    {
        ...
        ResourcesMgr.Instance.ReturnPool(bulletName, this.gameObject);   // ← 第二次回池
    }
}
```

**根因链**：`ReturnPool` 是无条件 `Add`：

```cs
public void ReturnPool(string fileName, GameObject bullet)
{
    bullet.SetActive(false);
    if (gameObjectPool.ContainsKey(fileName))
        gameObjectPool[fileName].Add(bullet);      // 不判重
    else
        gameObjectPool.Add(fileName, new() { bullet });
}
```

所以超距那一帧如果射线恰好命中（射程边界撞墙很常见），同一个 GameObject 会在池 list 里出现两次 → 之后两次 `GetInPool` 返回**同一个对象** → 两颗子弹共用 transform、互相拽着走、伤害算两次。

**修法**（两处都建议）：

```cs
if (distance > range)
{
    isMove = false;
    ResourcesMgr.Instance.ReturnPool(bulletName, gameObject);
    return;                       // ① 本帧到此为止
}
```

```cs
// ② 池本身兜底判重，防止任何调用方重复归还
public void ReturnPool(string fileName, GameObject bullet)
{
    bullet.SetActive(false);
    if (!gameObjectPool.TryGetValue(fileName, out var list))
    {
        list = new List<GameObject>();
        gameObjectPool.Add(fileName, list);
    }
    if (list.Contains(bullet)) return;
    list.Add(bullet);
}
```

**这是第 4 天**（11-10 首提、11-12 / 11-16 复述未改）。池的「归还」必须是幂等操作 —— 这是对象池的基本契约，不该依赖调用方小心翼翼。

#### 4. `MainPlayerShoot` 覆盖 `transform.position` → 起点与射程判定脱节（第 7 天）

- 子弹从**相机**飞出，相机在角色脑后时子弹从脑后冒出来，且射线起点先命中角色自己；
- `beginPosition` 仍是枪口 → 射程按「枪口到当前位置」算，比实际飞行距离短一截。

修法：`MainPlayerShoot` 只算方向，不要动位置；或改成把起点作为参数传进去。

## Ideas

- 今天的重构是**模板方法模式**的一个干净样本：「玩家和敌人只差一个朝向来源」这个观察，比「复制一遍 Player 的开火代码」值钱得多。下一步可以把**伤害结算**也做成钩子（`OnHit(RaycastHit hit)`）—— 现在 `Bullet` 里硬编码了 `ImpactEffect`，敌人打中玩家和玩家打中墙走的是同一套表现。
- `Bullet.Move` 每帧用 `Physics.Raycast(ray, distance)` 从**原点**重测整条路径，是 O(n²) 的累计浪费。正确做法是每帧只测本帧步长：`ray.origin` 更新为上一帧位置、`distance = speed * Time.deltaTime`。子弹一多就是实打实的开销。
- `Debug.Log` 是「临时诊断」的典型残留。值得养成习惯：排查用的日志一律包 `#if UNITY_EDITOR` 或 `[Conditional]`，修完即删 —— 否则它会以「几毫秒」的形式留在真机上。
- 速度平滑今天出现了三种写法：`Lerp`（永不达目标）、`MoveTowards`（恒速逼近、天然带界）、自定义加减（要自己管边界，一漏就出负数）。值得单独整理一篇「数值平滑三选一」，把 `Lerp` 的 `t` 是「比例」而不是「速度」这件事讲透。
- 「池的归还必须幂等」这条契约，比「记得写 return」更本质。任何 `Return`/`Release`/`Unsubscribe` 接口都该自带判重 —— 调用方永远会犯错。
- 敌人 AI 现在把「感知 / 决策 / 移动 / 动画」四件事塞在一个类里，`OnPatrol` 同时干「找目标」和「改状态」。今天的 `SetSpeed` 修好后，「移动」这一层算是稳定了，可以开始拆 —— 📎 [[有限状态机FSM — 手写实现与状态切换边界]] / 📎 [[行为树工程实现 — 黑板、RUNNING 中断与节点生命周期]]
