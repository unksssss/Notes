### 其他技术产出 — Empty 伤害系统落地

今天下午是 `Empty` 项目**第一次把「伤害」做成系统**，而不是在 `Bullet` 里 `if (CompareTag("Enemy"))` 硬判。三层切分：

```
投递层 Bullet          →  只认 IDamageable，不知道对面是谁
协议层 IDamageable     →  OnDamage(DamageInfo) 定义「受伤」长什么样
受体层 Health + EnemyAI →  数值归 Health，表现归角色
```

#### 1. 协议层：`readonly struct` 当消息

`Assets/Scripts/Base/IDamageable.cs`（15:25 新建）

```csharp
public readonly struct DamageInfo
{
    public readonly int attackDamage;
    public readonly Vector3 hitPoint;    // 击中点（飘字位置 / 特效朝向）
    public readonly Vector3 hitNormal;   // 击中点法线（弹孔贴合法线方向）
    public readonly GameObject source;   // 谁打的（仇恨 / 击杀归属）
    public readonly int teamID;          // 阵营

    public DamageInfo(int attackDamage, Vector3 hitPoint, Vector3 hitNormal,
                      GameObject source, int teamID) { /* 逐字段赋值 */ }
}

public interface IDamageable
{
    void OnDamage(DamageInfo damage);
}
```

**为什么是 `readonly struct` 而不是 `class`**：全自动步枪 10 发/秒 × 100 敌人 = 每秒 1000 次「命中事件」，用 class 就是每秒 1000 个待回收对象，GC 压力直接顶上来；struct 按值传、零堆分配。`readonly` 双重收益：字段物理不可改（下游无法篡改），且**传参不产生防御性拷贝**。

**为什么打包成对象而不是 `OnDamage(int, Vector3, Vector3, ...)`**：今天加「暴击倍率」、明天加「元素类型」，参数列表每加一个都要改接口 + 所有实现 + 所有调用点；struct 只动协议层。这就是「参数对象」重构手法。

#### 2. 受体层：数值与表现分家

`Assets/Scripts/Role/Health.cs`（15:29 新建）

```csharp
public class Health : MonoBehaviour, IDamageable
{
    private int currentHealth;
    private bool isDead = false;
    private int TeamID = -1;
    public Action<DamageInfo> OnDamaged;
    public Action<DamageInfo> OnDied;

    public void Init(int maxHealth) { currentHealth = maxHealth; }

    public void OnDamage(DamageInfo damage)
    {
        if (isDead) return;
        if (TeamID == damage.teamID) return;
        currentHealth = Mathf.Max(0, currentHealth - damage.attackDamage);
        Debug.LogError($"currentHealth: {currentHealth}, damage: {damage.attackDamage}");
        OnDamaged?.Invoke(damage);
        if (currentHealth == 0) OnDied?.Invoke(damage);
    }
}
```

`Health` 里**一行表现代码都没有**，受击僵直放在 `EnemyAI`：

```csharp
// EnemyAI.Start()
health.OnDamaged += OnDamaged;
health.OnDied    += OnDied;

private void OnDamaged(DamageInfo info)
{
    isTakingDamage = true;          // Move() 首行 if (isTakingDamage) return;
    StartCoroutine(WaitTakingDamage());
}
private IEnumerator WaitTakingDamage()
{
    yield return new WaitForSeconds(0.3f);
    isTakingDamage = false;
}

// EnemyAI.OnDisable() —— 退订做对了
health.OnDamaged -= OnDamaged;
health.OnDied    -= OnDied;
```

同一个 `Health` 能挂玩家 / 敌人 / 可破坏木箱，表现各写各的；代价是订阅必须退订，否则 `Health` 销毁后仍被委托持有 → 无法回收。

#### 六个漏洞（按致命度）

**① `TeamID` 私有且从未赋值 → 友伤判定恒不成立**

```csharp
private int TeamID = -1;              // 全项目没有一处赋值
if (TeamID == damage.teamID) return;  // -1 == 0 → 永远 false
```

判定写对了，**输入是死的** → 敌人打敌人照样扣血。特征：代码看着完全正确、跑起来毫无效果，因为判据一侧是常量。

```csharp
// 修复方向：阵营跟血量一起初始化
public void Init(int maxHealth, int teamID)
{
    currentHealth = maxHealth;
    TeamID = teamID;
}
```

**② `Bullet` 硬编码 `teamID = 0` → 所有子弹同一阵营**

即使 ① 修好，敌人和玩家射出的子弹**仍然都算 0 号阵营**。阵营必须从**发射者**继承：`StartMove` 时把 shooter 的 teamID 一起带进来。

**③ `isDead` 从不置 `true` → `OnDied` 重复触发**

血量到 0 后，**每一发后续子弹**都让 `Mathf.Max(0, 0 - dmg) == 0` 成立 → `OnDied` 再发一次。今天 `OnDied` 是空实现所以没炸；一旦填上「播死亡动画 + 入池 + 从敌人列表移除」，就会**重复入池** → 同一个 GO 在池里存两份 → 下次 `GetInPool` 两次拿到同一个对象，两把枪共用一个子弹。

```csharp
if (currentHealth == 0)
{
    isDead = true;          // ← 缺这一行
    OnDied?.Invoke(damage);
}
```

**死亡幂等**是这类系统的必答项：`OnDied` 必须**至多执行一次**。

**④ `currentHealth` 默认 0，且 `Player` 从未 `Init`**

`Health.Init` 只在 `RoleBase.SetRoleInfo` 里调用，而 `SetRoleInfo` 只有 `EnemyAI` 走得到（`FightingManager.OnSceneCreateEnemy` 显式调用）。`Player` 是场景里摆好的预制体，**没人调 `SetRoleInfo`** → 玩家根本没有 `Health` 组件 → 敌人射玩家时 `damageable?.OnDamage` 静默跳过。就算挂上 `Health`，`currentHealth` 默认 0 → **一枪就死**。

**⑤ `GetComponent<IDamageable>()` 不查父链**

碰撞体挂在子物体上（模型子物体带 `BoxCollider`、`Health` 在根上）会返回 null。今天「恰好能用」是因为 `CharacterController` 就在根物体上 —— **依赖实现细节的正确**。

```csharp
IDamageable damageable = hit.collider.GetComponentInParent<IDamageable>();
```

**⑥ `Debug.LogError` 当伤害日志用**

`LogError` 进错误统计、CI/打包配置里常被当失败、且每次调用抓堆栈（比 `Log` 贵一个数量级）。调试期用 `Debug.Log`，正式版条件编译或删。

```csharp
private Vector3 GetAimPoint(float range)
{
    Vector2 screenCenter = new Vector2(Screen.width / 2f, Screen.height / 2f);
    Ray camRay = Camera.main.ScreenPointToRay(screenCenter);

    int layerMask = ~LayerMask.GetMask("Player", "Projectile");

        ? hit.point
        : camRay.origin + camRay.direction * range;
}

protected override void SetBulletType(Bullet bullet)
{

}
```

#### 三道模板题的失败模式对照

| 题目 | 通过率 | 逻辑 | 真正错在哪 | 症状特征 |
| --- | --- | --- | --- | --- |
| 整数优先队列 | 0%（示例三行全错） | push / top / pop 一个没错 | **方向**：默认大根堆，极值取反 | 输出**有内容**但数值全不对，每行都错 |
| 字符串哈希 | 0%（stdout 0 字节） | 计数去重完全正确 | **通道**：结果写进 `return` | 输出**完全为空**，退出码恰好等于答案 |
| 大整数哈希 | 0%（小样例 40 vs 80） | 哈希表本身没错 | **漏读**：题面「先读后写」，只写了没读 | 输出有内容、量级也接近，但**语义是另一道题** |

三条补上「非 0 非 100 怎么自查」的判据表（承接 11-20 那四道模板题）：

1. **stdout 一个字节都没有** → 先查有没有 `cout`，再看是不是写进了 `return` / 抛异常 / 死循环。**空输出永远是通道问题，不是算法问题。**
2. **输出有内容、每行都错、且错得很「整齐」** → 查方向：比较器、正负号、升降序、极值取错端。
3. **输出量级对但数值系统性偏离** → 查**题意有没有漏步骤**（今天的「只写不读」），拿 3~4 步手推一遍对比。
4. **从第 k 行开始全错** → 输入流错位（漏读 / 多读一个变量 / `long long` 溢出导致 failbit）。
5. **小数据过、大数据挂** → 复杂度或常数（`endl` / 无 IO 加速 / 无 `reserve`）。
6. **偶发错、重跑结果不同** → 未初始化 / 哈希碰撞 / 迭代器失效。

> 一句话：**先确认「结果有没有出去」，再确认「出去的是不是对的」，最后才怀疑算法。**
