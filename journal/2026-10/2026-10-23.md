#### 二、今日新代码的 5 个硬伤

##### ① `MonsterBT.SetUpTree()` 缺 `return` —— 整个项目编译失败

**文件**：`Assets/Scripts/BT/MonsterBT.cs`

```cs
// 原始
protected override Node SetUpTree()
{
    Node root = new Selector(new List<Node>(

        ));
}
```

**问题**：方法声明返回 `Node`，实际没有 `return` → **CS0161「并非所有代码路径都返回值」**。这是**编译错误不是警告**，意味着今天写的 `TaskGoToTarget` / `TaskAttack` 一个都跑不起来，Unity 控制台会直接把整个 `Assembly-CSharp` 标红。

**根因**：树还没组装完（`List<Node>` 是空的），先搭了壳。另外文件头注释里 `path` 写的是 `MonsterTree.csMonsterTree.cs`——模板复制过来没改。

```cs
// ✅ 修复：顺序即优先级，能打就打、打不到就追、都没有才巡逻
protected override Node SetUpTree()
{
    var attack = new Sequence(
        new CheckPlayerInAttackRange(transform, 3f),
        new TaskAttack(transform));

    var chase = new Sequence(
        new CheckPlayerInFOVRange(transform, 10f, playerLayer),
        new TaskGoToTarget(transform));

    var patrol = new TaskPatrol(agent, waypoints);

    return new Selector(attack, chase, patrol);   // ★ 别忘了 return
}
```

##### ② 黑板 key 大小写不一致：写 `"player"`，读 `"Target"`

**文件**：`Assets/Scripts/BT/TaskAttack.cs` / `TaskGoToTarget.cs`

```cs
// 写端（CheckPlayerInFOVRange.cs:26，10-22 的代码）
parent.parent.SetData("player", colliders[0].transform);

// 读端（今日新代码）
Transform target = (Transform)GetData("Target");   // ★ 大写 T，且 key 名也不同
```

**问题**：`GetData` 沿父链找不到 `"Target"` → 返回 `null` → `(Transform)null` 强转成 `null` → 下一行 `target.position` 直接 **NRE**。两个动作节点都是第一帧就崩。

**根因**：黑板是 `Dictionary<string, object>`，**key 是纯字符串，编译器完全不管**。这类错在 C# 里零成本、零提示，只有运行时才炸——昨天笔记里写的「`Dictionary<string,object>` 三态问题」（值为 null / key 不存在 / 类型不对）今天以最朴素的形式复发了：**key 拼错**。

```cs
// ✅ 修法一（最小改动）：常量类收口，写错就编译不过
public static class BBKeys
{
    public const string Player = "player";
}
parent.parent.SetData(BBKeys.Player, colliders[0].transform);
var target = GetData(BBKeys.Player) as Transform;

// ✅ 修法二（根治）：泛型黑板，用类型当 key
public void Set<T>(T v) => map[typeof(T)] = v;
public bool TryGet<T>(out T v) { ... }
```

##### ③ 动作节点恒 `RUNNING` → `Selector` 左边的分支把兄弟饿死

**文件**：`Assets/Scripts/BT/TaskGoToTarget.cs`

```cs
public override NodeState Evaluate()
{
    Transform target = (Transform)GetData("Target");
    if (Vector3.Distance(tranform.position, target.position) > 0.01f)
    {
        tranform.position = Vector3.MoveTowards(tranform.position, target.position, 3f * Time.deltaTime);
        tranform.LookAt(target);
    }

    state = NodeState.RUNNING;   // ★ 无条件 RUNNING，永远不 SUCCESS / FAILURE
    return state;
}
```

**问题**：如果按「追击 → 攻击」顺序挂进 `Selector(TaskGoToTarget, TaskAttack)`，`TaskGoToTarget` 第一帧返回 `RUNNING`，`Selector` 遇 `RUNNING` 立刻短路 → **`TaskAttack` 永远不会被 tick**。怪物会贴到玩家身上一直推，但一刀不砍。

**根因**：和昨天 `TaskPatrol` 恒 `RUNNING` 饿死追击分支是**同一个坑**，只是换了个动作节点又犯一次。行为树里「持续型动作」必须自带**让位条件**，否则它一旦被执行就永久占住这条路径。

```cs
// ✅ 修复：到达（进攻击距离）就返回 SUCCESS，把控制权交回 Selector
public override NodeState Evaluate()
{
    if (GetData(BBKeys.Player) is not Transform target)
    {
        state = NodeState.FAILURE;
        return state;
    }

    if (agent.remainingDistance <= agent.stoppingDistance + 0.05f)
    {
        state = NodeState.SUCCESS;      // ★ 追到了，让位给攻击分支
        return state;
    }

    agent.SetDestination(target.position);
    state = NodeState.RUNNING;
    return state;
}
```

##### ④ 直写 `transform.position` + `LookAt`，与 `NavMeshAgent` 双写

**文件**：`Assets/Scripts/BT/TaskGoToTarget.cs`（`TaskPatrol` 同病）

**问题**：`MonsterController.Start()` 里有 `agent = GetComponent<NavMeshAgent>();`——**同一个 GameObject 上挂着 NavMeshAgent**。`agent.updatePosition` / `updateRotation` 默认都是 `true`，agent 每帧会把自己的内部位置与朝向**写回** `transform`。于是：

| 冲突 | 表现 |
| --- | --- |
| `transform.position = MoveTowards(...)` vs `agent.updatePosition` | 每帧互相覆盖 → 原地抽搐、位移被抹掉、走不进拐角 |
| `transform.LookAt(target)` vs `agent.updateRotation` | 每帧两次写 rotation → 朝向抖动 |
| 绕过寻路 | 直接穿墙、脱离 NavMesh、`agent.remainingDistance` 与实际位置完全不一致 |

**根因**：NavMeshAgent 是「位置的唯一所有者」，任何直接写 `transform.position` 的代码都是在和它抢所有权。细节已单独成篇 → 📎 [[NavMeshAgent 移动控制 — SetDestination 与 transform 直写的冲突]]

**额外风险**：`MonsterController.Update()` 里跑的是 FSM（`fsm.Update()`），`Tree.Update()` 里跑的是行为树。**若 `MonsterBT` 和 `MonsterController` 挂在同一个 prefab 上，两套 AI 会同时驱动同一个 agent** —— 状态机让它走、行为树让它停，表现是「一顿一顿」。要么二选一，要么把 FSM 那侧的 `Update` 关掉。

##### ⑤ `TaskAttack`：依赖具体类型、每次 `GetComponent`、计时器无重置

**文件**：`Assets/Scripts/BT/TaskAttack.cs`

```cs
// 原始
private PlayerHealth  playerHealth;          // ★ 声明了但从未使用（CS0169 警告）
private float attackTime = 1f;
private float attackCount = 0f;

public override NodeState Evaluate()
{
    attackCount += Time.deltaTime;
    if (attackCount >= attackTime)
    {
        attackCount = 0;
        Transform target = (Transform)GetData("Target");
        var playerHealth = target.GetComponent<PlayerHealth>();   // ★ 局部变量遮蔽字段，每秒查一次
        playerHealth.TakeDamage(10);                              // ★ 伤害硬编码
    }

    state = NodeState.RUNNING;
    return state;
}
```

| 问题 | 根因 | 后果 |
| --- | --- | --- |
| 依赖 `PlayerHealth` 具体类 | 昨天文档里刚定的「伤害契约」是 `IDamageable` + `DamageInfo`（`MonsterController.TakeDamage(in DamageInfo)` 已实现），这里却绕回去绑具体类型 | 只能打玩家，打不了其他可破坏物；与项目自身架构相悖 |
| 每次攻击 `GetComponent` | 没缓存 | 每秒一次组件查找（虽不致命，但属无谓开销） |
| `attackCount` 无重置入口 | `Node` 没有 `OnEnter` / `OnExit` 钩子 | 节点被 `Selector` 切走再切回来，计时器保留半截 → 第一次攻击可能瞬发 |
| 恒 `RUNNING` 且不判距离 | 动作叶没有让位条件 | 玩家跑出 3 米后，攻击节点仍占着分支（同 ③） |
| `attackTime` / `10` 硬编码 | 没接 `MonsterConfig` | 不同怪物无法差异化 |

```cs
// ✅ 修复
public class TaskAttack : Node
{
    private readonly IDamageable owner;
    private readonly int damage;
    private readonly float interval;
    private float timer;

    public TaskAttack(IDamageable owner, int damage = 10, float interval = 1f)
    {
        this.owner = owner; this.damage = damage; this.interval = interval;
    }

    public override void OnExit() => timer = 0f;    // ★ 被打断就重置，避免残留

    public override NodeState Evaluate()
    {
        if (GetData(BBKeys.Player) is not Transform target)
        {
            state = NodeState.FAILURE;
            return state;
        }

        timer += Time.deltaTime;
        if (timer < interval) { state = NodeState.RUNNING; return state; }

        timer = 0f;
        if (target.TryGetComponent(out IDamageable dmg))
            dmg.TakeDamage(new DamageInfo { damage = damage });

        state = NodeState.RUNNING;
        return state;
    }
}
```

> ⚠️ `OnExit` 是**需要自己给 `Node` 加的钩子**（基类目前只有 `Evaluate`）。没有 Enter/Exit，任何带内部状态的节点都无法正确处理「动作中途被抢占」。

## Ideas

- **组装期才是行为树的 bug 高发段**：单个节点看都没问题，一挂到 `Selector` 上就互相饿死（`TaskPatrol` 饿死追击、`TaskGoToTarget` 饿死攻击）。给 `Tree` 加一个 `[SerializeField] bool logTick`，每次 tick 打一行 `(节点名, 返回值)`，组装期靠日志而不是靠猜——比再写 5 个节点类型有用
- 黑板 key 用字符串的坑今天换了个姿势复发（`"player"` 写 / `"Target"` 读）。**修法不是「记住用同一个字符串」，是让编译器管**：常量类起步，泛型黑板根治
- `TaskAttack` 的 `attackCount` 暴露了 `Node` 缺 `OnEnter`/`OnExit`：**带内部状态的动作节点，没有 Exit 钩子就永远做不干净「动作被打断」**。这个钩子必须补进基类，否则每加一个计时器节点就要再想一遍「被抢占怎么办」
- 今天 4 个新文件、0 个修复，是典型的「加法优先」。但 #1/#7/#11 三个硬伤让新代码**根本没被执行过**——**加法做得越多，验证来得越晚，最后一次性面对 16 个 bug**
- `MonsterBT` 与 `MonsterController` 若同挂一个 prefab，FSM 与 BT 会同时驱动同一个 `NavMeshAgent`。这其实是个不错的对照实验素材：同一只怪，一套 FSM 一套 BT，比对着看谁更好调试
- 作品说明砍到 85 行的过程本身很有价值：**从 380 行删到 85 行的每一次删减，删掉的都是「其实没做完」的部分**
