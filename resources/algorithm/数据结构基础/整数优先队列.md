# 整数优先队列（堆）

## 一、题目

维护一个允许重复的多重集合，三种操作（`n ≤ 10⁶`）：

| op | 含义 |
|---|---|
| `1 x` | 插入 `x`（`1 ≤ x < 2³¹`） |
| `2` | 输出集合中的**最小**元素 |
| `3` | 删除一个最小元素 |

官方示例：

```
输入          输出
7             3
1 5           3
1 3           5
2
1 10
2
3
2
```

## 二、核心认知

`std::priority_queue` **默认是大根堆**。题目要的是**最小**元素 —— 所以这题的第一步不是写逻辑，是**把堆的方向掰过来**。

## 三、❌ 灯皇的错：用了默认的大根堆

```cpp
priority_queue<int> que;      // ❌ 大根堆，top() 是最大值
```

实测官方示例：

```
你的输出:  5        正确:  3
          10               3
           5               5
```

逻辑（push / top / pop）一点没错，**方向反了**。

## 四、正解：显式指定小根堆

```cpp
#include <iostream>
#include <queue>
#include <vector>
#include <functional>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int q;
    priority_queue<int, vector<int>, greater<int>> que;   // ★ 小根堆
    if (!(cin >> q)) return 0;

    while (q--) {
        int op;
        cin >> op;
        switch (op) {
            case 1: { int x; cin >> x; que.push(x); break; }
            case 2: { cout << que.top() << '\n'; break; }
            case 3: { if (!que.empty()) que.pop(); break; }
        }
    }
    return 0;
}
```

### 三个模板参数是什么意思

```cpp
priority_queue< T , 底层容器 , 比较器 >
priority_queue< int, vector<int>, greater<int> >
```

- `T`：元素类型
- 底层容器：默认 `vector<T>`（堆就是"用数组存的完全二叉树"，所以 vector 正好）
- 比较器：默认 `less<T>`

**为什么 `greater` 才是小根堆？**（这是最反直觉的地方）

优先队列的定义是：**`top()` 返回"按比较器意义下最大"的那个元素**。

- `less<int>`：`a < b` 表示 a 更小 → 大的赢 → **大根堆**
- `greater<int>`：`a > b` 表示 a 更大 → 小的赢 → **小根堆**

一句话记：**比较器写的是"什么算小"，堆顶是"最不小"的那个。**

> 同一个 `greater<int>` 用在 `sort` 里是**降序**，用在 `priority_queue` 里却得到**小根堆** —— 因为 sort 要"排在前面的更小"，而 priority_queue 要"堆顶的最大"。方向感不同，别记混。

## 五、其他两个问题

### ① `endl` 在 5×10⁵ 次输出下很贵

`n ≤ 10⁶`，其中可能一半是查询。`endl` 每次都 `flush`。

实测（本机 `-O2`，5×10⁵ 插入 + 5×10⁵ 查询）：

| 版本 | 耗时 |
|---|---|
| 你的（`endl`，无 IO 加速） | **2.75 s** |
| 修正（`'\n'` + `sync_with_stdio(false)`） | **0.52 s** |

差 5 倍。很多题限时 1s，这一条就够挂了。

### ② 空堆上 `top()` / `pop()` 是 UB

```cpp
case 2: { cout << que.top(); }   // 空堆 → 未定义行为（可能崩、可能读到垃圾）
case 3: { que.pop(); }           // 同上
```

- `std::priority_queue::top()` 返回**引用**，堆空时读的是越界内存
- `pop()` 对空堆会做一次 downward/heapify，同样越界

`empty()` 判断是 `O(1)`，加上没坏处。题目一般保证不空，但加上更稳。

## 六、复杂度

| 操作 | 复杂度 |
|---|---|
| `push` | `O(log n)` |
| `top` | `O(1)` |
| `pop` | `O(log n)` |
| 总 | `O(n log n)` |

底层是 `vector` 上的二叉堆：`push` 上浮（sift-up），`pop` 是"把末尾搬到根再下沉"（sift-down），所以 `pop` 是 `O(log n)` 而不是 `O(1)`。

## 七、优先队列的边界（面试常问）

1. **没有迭代器** —— 不能遍历、不能用 `find`、不能删任意元素，只能操作堆顶。要删任意元素得用 `multiset`，或者"懒删除"（另开一个删除标记表，`top()` 时把已删的弹掉）
2. **不能修改堆内元素** —— 想"改某个元素再重新堆化"做不到，只能"删掉 + 重新 push"（懒删除）
3. **重复元素随便放** —— 允许重复，`top()` 只保证是极值之一
4. **自定义结构体**：要么重载 `operator<`，要么写仿函数 `struct Cmp { bool operator()(const Node& a, const Node& b) const { return a.d > b.d; } };`（同样反直觉：写 `>` 得到小根堆）

## 八、延伸

- **求中位数（数据流）**：一个大根堆放左半边、一个小根堆放右半边，保持大小差 ≤ 1
- **Dijkstra**：`priority_queue<pair<int,int>, vector<...>, greater<>>`（`pair` 默认按 first 再 second 比较，正好按距离排序）
- **合并 K 个有序链表**：小根堆存每个链表的当前头节点
- **手动版**：`make_heap` / `push_heap` / `pop_heap` 三个算法可以自己控制底层数组，需要"堆 + 额外信息"时用
- **`multiset` 替代方案**：题目要是还要"删任意值"，`multiset.begin()` 是 `O(1)`、`erase(it)` 是 `O(1)` 摊还，同样能当小根堆用，代价是常数更大
