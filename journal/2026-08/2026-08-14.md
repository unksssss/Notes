### FireSim_URP_VR — EquipmentInputBridge 按键→装备使用桥接器

目标：`Assets/Scripts/Author/LJW/Equipment/Runtime/EquipmentInputBridge.cs`（命名空间 `FireSimVR.Equipment`）

把 `XRInputModule.ButtonInfoReceived` 事件按"手 + 按键 + 手势"翻译成 EquipmentManager 的使用请求：

- `[DisallowMultipleComponent]` 防同物体重复挂载导致事件重复订阅
- `Configure()` 支持运行时动态配置（装备管理器/输入模块/左右手），立即 `TryBindInputModule()`
- `Update()` 里 `_subscribedInputModule == null` 时自动重绑（场景切换/单例重建兜底）
- `OnDisable` 先 `GetManager()?.EndUse(_hand, this)` 通知管理器结束使用，再解绑事件
- **按 `buttonUseMode` 三模式分发**：`PressAndHold`（Down→BeginUse / Up→EndUse）、`SingleClick`（UseOnce）、`Toggle`（ToggleUse）
- `ResolveTarget()` 按 **FarRay → Near → Poke → UI** 优先级取悬停物体作为使用上下文目标

```csharp
case EquipmentButtonUseMode.PressAndHold:
    if (info.Gesture == XRButtonGesture.Down)  manager.BeginUse(_hand, context);
    else if (info.Gesture == XRButtonGesture.Up) manager.EndUse(_hand, this);
    break;
```

> 知识点：订阅外部单例事件必须成对出现（Subscribe/Unsubscribe），`OnDisable` 是兜底清理点，否则对象销毁后回调仍触发 = 经典泄漏。📎 [[XR Interaction Toolkit 配置指南]]

### FireSim_URP_VR — HighPressureNozzleEquipment 高压水枪（扳机模拟量驱动）

目标：`Assets/Scripts/Author/LJW/Equipment/Runtime/Equipments/HighPressureNozzleEquipment.cs`

水枪不套用 BeginUse/UpdateUse 按键流，而是 **Update 里直接读扳机模拟量**：

- `_triggerDeadZone = 0.02`：低于死区直接归零，防手柄漂移误喷
- `Mathf.MoveTowards(pressure, target, 8f * dt)` 水压平滑过渡，不跳变
- **喷水迟滞（Hysteresis）**：达到 0.12 才开始喷、跌到 0.08 才停——避免在临界值反复开关抖动
- 把手旋转：`Quaternion.Slerp(released, pressed, CurrentPressure)`，按压角度 `-30°` 绕可配本地轴
- 水声联动：`volume = pressure`、`pitch = Lerp(0.8, 1.2, pressure)`，spraying 时才 Play/Stop
- `OnValidate` 强制 `_sprayStopThreshold <= _sprayStartThreshold` 防反配置
- `EndUse` 故意不归零水压（注释：避免数字按键松开阈值影响扳机模拟量完整读取）

```csharp
float targetPressure = triggerValue <= _triggerDeadZone ? 0f : triggerValue;
float pressure = Mathf.MoveTowards(CurrentPressure, targetPressure, _pressureChangeSpeed * Time.deltaTime);
```

> 知识点：物理连续量输入（扳机/摇杆）用"死区 + 平滑 + 迟滞"三段处理，是所有拟真手感装备的通用套路。

### C++ 学习 — 手搓链地址法 HashMap 完成 ✅

目标：`D:\CppTest\hello\HashMap\HashMap.cpp`（教学会话逐步 review 完成）

- **功能**：`hash`（std::hash + 取模）/ `put`（找桶→沿链找→改值/头插）/ `get`（返回 `V*`，nullptr 表示不存在）/ `remove`（prev+cur 双指针，链头/中间分支）/ 析构（遍历桶逐链 delete，先备份 next）/ **自动扩容 rehash**（负载因子 0.75，质数翻倍，搬节点不复制，std::move 换数组）
- **7 个教学踩坑**：
  1. `vector` 没有 `count` 只有 `size()`
  2. put 必须只查 `hash` 定位的桶（遍历所有桶在空桶会空指针崩溃）
  3. `while(current->next)` 漏链尾 → `while(current != nullptr)`
  4. `buckets[index]=Node(...)` 类型错+覆盖链 → `new Node` 头插
  5. 死循环：遍历链忘记步进 `current = current->next`
  6. 返回值设计：`V*` 而非值（-1 魔法值陷阱）
  7. **rehash 隐蔽 bug**：`hash()` 内部 `% 旧桶数` 再 `% newCount` ≠ 原始 `% newCount` → 改 `hash(key, capacity)` 带参版
- **环境**：控制台中文乱码终极方案 = 源码 UTF-8（`-finput-charset=UTF-8`）+ `main` 开头 `SetConsoleOutputCP(CP_UTF8)`；tasks.json 已更新

> 知识点：链地址法与开放地址法是哈希表两大冲突解法，扩容 rehash 时哈希函数必须用**新容量**取模——这是最常见的隐蔽 bug。📎 [[哈希表冲突解决与Dictionary底层]]
