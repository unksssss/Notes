# 位运算

## 一、六个运算符

| 运算符 | 名字 | 作用 |
|---|---|---|
| `&` | 按位与 | 都是 1 才 1（**取位 / 清位**用） |
| `\|` | 按位或 | 有一个 1 就 1（**置位**用） |
| `^` | 按位异或 | 不同才 1（**翻转位、无进位加法**） |
| `~` | 按位取反 | 0↔1（配合与用来清位） |
| `<<` | 左移 | 整体左挪，低位补 0 = **×2ⁿ** |
| `>>` | 右移 | 整体右挪 = **÷2ⁿ**（向下取整） |

---

## 二、地基：补码

这是理解所有位运算的前提。**整数在内存里存的是补码**，正数补码 = 原码，负数是「取反加一」。

实测（32 位 int，每 4 位空一格）：

```
          5 -> 0000 0000 0000 0000 0000 0000 0000 0101
         -5 -> 1111 1111 1111 1111 1111 1111 1111 1011
         -1 -> 1111 1111 1111 1111 1111 1111 1111 1111
         -2 -> 1111 1111 1111 1111 1111 1111 1111 1110
 2147483647 -> 0111 1111 1111 1111 1111 1111 1111 1111
-2147483648 -> 1000 0000 0000 0000 0000 0000 0000 0000
```

三个推论直接就能用：

1. **`-1` 是全 1**（32 个 1）。因为 `-1 + 1 = 0`，而全 1 加 1 恰好全部进位溢出成 0。
2. **`~x = -x - 1`** —— 因为 `x + ~x = 全 1 = -1`。
3. **最高位（bit31）是符号位**：0 正、1 负。`INT_MAX` 是「0 + 31 个 1」，`INT_MIN` 是「1 + 31 个 0」。

> 这也是为什么 `LONG_MAX` 在 Windows 上只有 32 位 —— 之前踩过的那个坑，根子在这里。

---

## 三、取位与改位六件套（★ 背这张表）

以 `x = 180`（二进制 `1011 0100`）、`k = 2` 为例：

| 目标 | 写法 | 说明 |
|---|---|---|
| **取第 k 位** | `(x >> k) & 1` | 右移把那一位挪到最低，再与 1 |
| **置 1** | `x = x \| (1 << k)` | 该位变 1，其他位不变 |
| **清 0** | `x = x & ~(1 << k)` | `~(1<<k)` 只有该位是 0，与完就清掉了 |
| **翻转** | `x = x ^ (1 << k)` | 异或 1 取反、异或 0 不变 |
| **最低位的 1**（lowbit） | `x & (-x)` | 见第四节 |
| **消掉最低位的 1** | `x & (x - 1)` | 每消一次少一个 1，可用来数 1 的个数 |

实测（x = 180）：

```
x            = 180  0000 0000 0000 0000 0000 0000 1011 0100
x & 1        = 0    (奇偶：1 奇 0 偶)
(x>>3)&1     = 0    (取第 3 位)
x | (1<<2)   = 180  ← 第 2 位本来就是 1，所以看不出变化
x & ~(1<<2)  = 176  0000 0000 0000 0000 0000 0000 1011 0000  (清 0)
x ^ (1<<2)   = 176  (翻转，1 变 0)
x & -x       = 4    (lowbit)
x & (x-1)    = 176  (消掉最低位的 1)
```

> 注意第三行：**位运算只动指定的那一位，其他位原样保留**。所以「置 1」看不出变化是正常的 —— 拿「清 0」和「翻转」验证更直观。

### 三个组合判断

```cpp
x & 1                     // 判奇偶（比 x % 2 快，且对负数也正确）
x > 0 && !(x & (x - 1))   // 判是不是 2 的幂（只允许一个 1）
(x >> k) & 1              // 判第 k 位是不是 1
```

`x & (x-1)` 能判 2 的幂，是因为**只有单个 1 的数减 1 后，会把它变成 0、低位全变 1**，两者相与必然是 0。

## 四、lowbit：`x & (-x)` 为什么成立

`x = 12 = 0000 1100`，最低位的 1 在 bit2（权值 4）。

```
x     = 0000 1100
-x    = 1111 0100      ← 取反加一
x & -x= 0000 0100  = 4
```

**推理过程**：

1. 设 x 最低位的 1 在第 k 位，那它下面的 k 位全是 0。
2. `~x` 把这些低位 0 全变成 1；`+1` 之后这一串 1 全部进位回 0，并把第 k 位重新变回 1。
3. 所以 **`-x` 在第 k 位及以下与 `x` 完全一致**（低位都是 0，第 k 位都是 1）。
4. 而 **k 位以上，`-x` 与 `x` 恰好互补** → 相与全是 0。

结果就只剩第 k 位那一个 1。

**用途**：

| 场景 | 用法 |
|---|---|
| 树状数组 | `i += i & (-i)` 向上跳；`i -= i & (-i)` 向下跳 |
| 求最大 2 的幂因子 | `x & -x` 直接就是「x 能被 2 的几次方整除」的结果 |
| 拆解二进制 | 循环取 lowbit 再减掉，可逐个拿到所有 1 |

## 五、异或的四条性质（刷题神器）

```
a ^ a = 0          自反：任何数异或自己归零
a ^ b ^ a = b      交换 + 结合：成对出现的都消掉
a ^ 0 = a          0 是单位元
a ^ b              = 「无进位加法」
```

**应用一：找唯一出现一次的数**（其他都出现两次）

```cpp
int singleNumber(vector<int>& a) {
    int r = 0;
    for (int v : a) r ^= v;     // 成对的互相抵消，剩下的就是答案
    return r;
}
```

实测 `{3, 7, 3, 4, 7, 4, 9}` → `9`。

**应用二：不用临时变量交换**

```cpp
a ^= b;  b ^= a;  a ^= b;
```

⚠️ 但**不推荐在工程里用**：可读性差、`a` 和 `b` 是同一个变量时会把自己清零。刷题炫技可以，写业务别用。

**应用三：找两个只出现一次的数**

先全部异或得到 `a^b`（非 0），取它的 lowbit 作为「分界线」，把数组分成两组分别异或 —— 两个答案就被分到不同组里了。

## 六、移位的三个坑

| 坑 | 说明 |
|---|---|
| **有符号右移是算术右移** | `-8 >> 1` 实测得 `-4`（补符号位），不是逻辑右移。C++ 标准里这是**实现定义**，只是所有主流编译器都做算术右移 |
| **`1 << 31` 是 UB** | 对有符号 int 左移溢出是未定义行为。实测 g++ 得到 `-2147483648`，但换编译器可能不同。**正确写法 `1u << 31`** |
| **移位数 ≥ 位宽是 UB** | `x << 32` 在 int 上未定义，不会自动变成 0，可能得到任何值 |

实测：

```
-8      >> 1 = -4              （算术右移）
0xFFFFFFF8 >> 1 = 2147483644   （逻辑右移，因为是无符号）
1 << 31  = -2147483648         （UB，只是 gcc 这么实现）
1u << 31 = 2147483648          （正确写法）
-1 >> 1  = -1                  （实现定义）
```

**规矩**：位运算尽量在**无符号类型**上做；需要 `2^31` 这类值时用 `1u`、`1LL`。

## 七、★ 优先级：最容易出错的地方

**位运算符的优先级低于比较运算符**，这是 C 语言历史遗留的设计失误。

```cpp
if (x & 1 == 1)      // ❌ 实际是 x & (1 == 1)，即 x & 1
if (x & 2 == 2)      // ❌ 实际是 x & (2 == 2)，即 x & 1 —— 完全错了！
if ((x & 1) == 1)    // ✅
if ((x & 3) == 3)    // ✅
```

优先级从高到低大致是：

```
~  →  算术 * / %  →  + -  →  移位 << >>  →  比较 < > <= >=  →  相等 == !=
   →  按位与 &  →  按位异或 ^  →  按位或 |  →  逻辑与 &&  →  逻辑或 ||  →  赋值
```

**结论：只要不是单独一句，位运算一律加括号。** 这不是风格问题，`x & 2 == 2` 这种写法会静默给出错误答案。

## 八、实战五个

### 1. 子集枚举（状压 DP 的基础）

```cpp
int n = 3;
for (int mask = 0; mask < (1 << n); ++mask) {
    for (int i = 0; i < n; ++i)
        if (mask >> i & 1) { /* 第 i 个元素被选中 */ }
}
```

`mask` 的每一位代表一个元素选没选，`2^n` 个子集一次枚举完。

### 2. 快速幂

```cpp
long long qpow(long long base, long long exp, long long mod) {
    long long res = 1;
    while (exp) {
        if (exp & 1) res = res * base % mod;   // 这一位要乘
        base = base * base % mod;
        exp >>= 1;
    }
    return res;
}
```

实测 `3^13 = 1594323`。原理：把指数按二进制拆开，`3^13 = 3^(1101b) = 3^8 · 3^4 · 3^1`。

### 3. 不用加减乘除做加法

```cpp
int add(int a, int b) {
    while (b) {
        int carry = (unsigned)(a & b) << 1;   // 进位：都是 1 的位
        a ^= b;                                // 无进位加法
        b = carry;
    }
    return a;
}
```

实测 `15 + 27 = 42`。这就是「异或 = 无进位加法」的直接应用。

### 4. 数 1 的个数（popcount）

```cpp
int popcount(unsigned x) {
    int cnt = 0;
    for (; x; x &= x - 1) ++cnt;   // 每次消掉最低位的 1
    return cnt;
}
```

C++20 有 `std::popcount`，GCC 有 `__builtin_popcount`。

### 5. 无分支取绝对值

```cpp
int myAbs(int x) {
    int mask = x >> 31;            // 负数得 -1（全 1），正数得 0
    return (x ^ mask) - mask;      // 负数：(~x)+1 = -x
}
```

## 九、易错点速查

| 坑 | 表现 |
|---|---|
| `x & 1 == 1` 不加括号 | 优先级问题，静默出错 |
| `1 << 31` | UB，应用 `1u << 31` |
| 有符号数做位运算 | 右移、溢出都不可控，尽量转 `unsigned` |
| `a ^= b ^= a ^= b` | 自交换会清零，且旧标准下是 UB |
| 把 `~` 当成「逻辑取反」 | `~` 是逐位取反，`!` 才是逻辑取反 |
| `x & (x-1)` 判 2 的幂忘了 `x > 0` | `0 & -1 == 0`，会把 0 判成 2 的幂 |
| `1 << k` 里 k 是 long long | 移位结果类型是 int，可能溢出，写 `1LL << k` |

## 十、面试延伸

- **为什么计算机用补码而不是原码**：原码有 ±0 两个零，减法还要单独处理符号；补码让「减法 = 加负数」，同一套加法器通吃。
- **`x & (x-1)` 和 `x & -x` 的区别**：前者消掉最低位的 1（用于数 1），后者取出最低位的 1（用于树状数组）。
- **BitSet 的底层**：`std::bitset<N>` 内部就是 `unsigned long` 数组，一个 64 位字装 64 个布尔值 —— 空间省 64 倍。
- **掩码（mask）在工程里**：Unity 的 `LayerMask`、文件权限位、状态标志位，都是「一个 int 存多个布尔」。
