#### 今日唯一源码改动：`Assets/Scripts/MonsterCTRL.cs`

> ⚠️ 该项目**未纳入 git**（`git status` 报 `not a git repository`），拿不到逐行 diff，以下按文件**现态**复盘。

**文件定位**：怪物宿主的「数据 + 能力提供方」。它不写任何状态逻辑，只负责读配置、持有组件、暴露访问点，让 `FSM/` 下的状态对象通过 `owner.XXX` 反向调用。

**今日收口的形态**——状态机构建从 `Start()` 里抽成独立方法：

```cs
private void Start()
{
    player = GameRoot.Instance.Player;
    playerHealth = GameRoot.Instance.PlayerHealth;
    Target = player;

    agent    = GetComponent<NavMeshAgent>();
    animator = GetComponent<Animator>();

    BuildStateMachine();   // ← 抽出来了，Start 只留组装顺序
}

private void BuildStateMachine()
{
    fsm = new MonsterStateMachine();
    fsm.RegisterState(State.Attack, new MonsterAttackState(this));
    fsm.RegisterState(State.Walk,   new MonsterWalkState(this));
    fsm.RegisterState(State.Idle,   new MonsterIdelState(this));
    fsm.ChangeState(State.Idle);   // 初始状态在注册完后主动切入
}
```

以及把状态需要的访问点全部提成属性（状态类只读不写，方向单一）：

```cs
public MonsterStateMachine FSM => fsm;
public NavMeshAgent Agent => agent;
public Animator Animator => animator;
public Transform Target { get; private set; }
public int ChaseDistance => chaseDistance;
public int AttacDistance => attackDistance;   // 拼写笔误，先记一笔
public bool CanAttack => canAttack;
public float DistanceToTarget() => Vector3.Distance(Target.position, transform.position);
```

**为什么这么写**：状态对象是纯 C# 类（不是 `MonoBehaviour`），拿不到 `transform` / `GetComponent`，所以宿主必须把「我能提供什么」显式摆出来。属性用 `=>` 表达式体 + 只读，等于给状态层一个**窄接口**：能读距离和组件，改不了配置。

**这层设计留下的三个隐患**（已写进笔记，不在这里展开修法）：

1. `Start()` 里 `GameRoot.Instance.Player` 依赖 `GameRoot.Awake` 先执行 —— `Awake` 阶段没有跨脚本顺序保证，`Start` 才有（同帧内所有 `Awake` 先于所有 `Start`），这条目前是安全的，但一旦有人把取 `Instance` 挪到 `Awake` 就会偶发 NRE。
2. `Awake()` 里 `monsterConfig.HP` 等六连读**没有空判** —— Inspector 忘挂 SO 就是一片 `NullReferenceException`，且报错行在 `Awake`，堆栈里看不出是配置缺失。
3. `Start()` 尾部还留着调试残留 `Debug.Log(Vector2.Dot(a.normalized, b.normalized))` —— 每只怪出生打一行日志，怪一多就是 GC 噪音。

#### 今日实战复盘：手写 FSM 的三层骨架

昨天夜间写完的 `Assets/Scripts/FSM/` 六个文件，今天配合宿主收口后才算跑通闭环。骨架是三层：

```cs
public interface IState
{
    void OnEnterState();   // 一次性：开动画、开导航
    void OnUpdate();       // 每帧：判条件、算转移
    void OnExitState();    // 一次性：关动画、复位标志
}

public abstract class MonsterStateBase : IState
{
    protected MonsterCTRL owner;
    protected MonsterStateBase(MonsterCTRL _owner) => owner = _owner;
    public abstract void OnEnterState();
    public abstract void OnUpdate();
    public abstract void OnExitState();
}
```

状态机的核心只有 20 行，但**切换顺序**是全部讲究所在：

```cs
public void ChangeState(State newStateID)
{
    if (currentStateId == newStateID) return;                 // 幂等早退，防自切
    if (!states.TryGetValue(newStateID, out var newState))    // 缺状态不崩
    { Debug.LogError("State not found"); return; }

    currentState?.OnExitState();     // ① 退出看旧 ID
    currentStateId = newStateID;     // ② 换 ID
    currentState = newState;         // ③ 换引用
    currentState.OnEnterState();     // ④ 进入看新 ID
}
```

> **Exit 看旧值、Enter 看新值，所以换 ID 必须卡在两者中间。** 顺序颠倒就会出现「退出时清理了新状态的东西」。

三个状态的行为分工也值得记：`Idle` 只做「玩家进视野就切 Walk」一件事，`Walk` 每帧 `SetDestination` + 距离判攻击/放弃，`Attack` 进入置 `isAttacking=true`、靠动画事件 `EndAttack()` 切回 Idle。**逻辑切状态，动画只负责播**——这条边界立住了，后面加 `Enraged` / `Dead` 才不会打架。

📎 [[有限状态机FSM — 手写实现与状态切换边界]]（新建，`resources/unity/architecture/`）—— 完整骨架 + 状态切换边界五要素 + FSM/行为树/GOAP 选型表 + 今日代码暴露的 6 个工程坑（每帧 `SetDestination` 的重复寻路、`attackCoolDown` 只读不写导致贴脸连击、纯 C# 状态机开不了协程所以冷却只能走时间戳、球形判定不判朝向、`int` 存距离、`GameRoot` 单例伪 null）。这是 `architecture` 区此前**完全没有**的方向。
