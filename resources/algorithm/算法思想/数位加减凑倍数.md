# 数位加减凑倍数

> 牛客原题名：**《小红的数位操作》**（京东 23 届春招笔经收录）。
> ⚠️ 原题条件与本文二~十节讲的**不完全一样**，先看下面这节再往下读。

## 一、题目

### 1.1 牛客原题（以这个为准）

给定正整数 `n`、`p`。每次操作选一个数位，使其 `+1` 或 `-1`。两条限制：

1. **每个数位最多只能操作一次**（可以不操作）；
2. **选 9 不能 `+1`，选 0 不能 `-1`**。

希望最终 `n` 成为 `p` 的倍数，输出操作后的整数。**若结果含前导零，要一并输出**；无解输出 `-1`；多解输出任意一个。

```
输入 72  7          → 63     （7−1=6、2+1=3）
输入 101 123456789  → 000    （1−1=0、中间 0 不动、1−1=0；0 是任何数的倍数）
输入 40  9          → -1
```

**这三个条件会彻底改变模型**：

| 条件 | 后果 |
|---|---|
| 「**最多**操作一次」 | 每位 3 种选择（不动 / +1 / −1）→ 搜索空间 `3^k`，不是 `2^k` |
| 9 不能加、0 不能减 | 每位可选值被截断，不会出现进位 / 借位 |
| **前导零要输出** | 答案必须**按字符串拼**，不能只留数值（`000` 和 `0` 不一样） |

正解见「十一、牛客原题正解」—— **本文二~十节那套 `2^k` 的解法在原题上会错**，比如 `101 123456789` 会输出 `-1` 而正解是 `000`。

### 1.2 简化版（二~十节讲的是这个）

把条件收紧成「**每位必须**操作一次、不限 9/0」，得到一个干净得多的模型：

```
输入 12 3   →   3        （4 个候选 23 / 21 / 3 / 1，3 和 21 都是 3 的倍数，取最小得 3）
输入 4  5   →   5        （个位 +1）
输入 9  5   →  10        （9 + 1，自然进位）
输入 999 2  → 888        （每位 -1：999 - 111）
输入 10 9   →  -1
```

这个版本的价值在于：它能逼出「**第 i 位 ±1 ≡ 整体 ±10ⁱ**」这个核心认知，而且**进位/借位全部自动处理**。理解了它，再回头做原题就只剩「多一个不操作分支」和「按字符串输出」两件事。

## 二、★ 核心认知：第 i 位 ±1 ≡ 整体 ±10^i

这是本题唯一需要想通的事，想通了代码只剩十行。

设 `n` 的十进制展开为 `n = Σ dᵢ · 10ⁱ`（i 从右往左，个位是 i=0）。

对第 i 位做 `+1`：

```
操作后的数 = Σ(dⱼ + [j==i]) · 10ʲ = Σ dⱼ·10ʲ + 10ⁱ = n + 10ⁱ
```

对第 i 位做 `-1`，同理是 `n - 10ⁱ`。

所以：

> **「第 i 位 +1」就是在整个数上加 `10ⁱ`；「第 i 位 -1」就是减 `10ⁱ`。**

于是所有可能的结果，恰好是

```
{ n + Σ δᵢ · 10ⁱ  |  δᵢ ∈ {+1, -1}，i = 0..k-1 }
```

共 `2^k` 个（k 为位数）。**每位都必选，所以是 2^k 而不是 3^k。**

### 这个转化为什么重要

它一次性消掉了两个"看起来必须特判"的异常：

| 表面异常 | 实际情况 | 数值等价 |
|---|---|---|
| 个位 `9 + 1 = 10`，两位了？ | **进位** | `n + 1`，比如 19 → 20 |
| 某位 `0 - 1 = -1`，出现负数字？ | **借位** | `n - 10ⁱ`，比如 105 的十位 -1 → 95 |

如果按"把每位数字改完再拼成字符串"的思路写，这两处就必须单独处理，而且极容易写错（拼出来的 `"1"+"10"` 到底算 110 还是 20？）。

**用数值加权之后，进位和借位是自动发生的，一行特判都不用写。**

### 一个意外的巧合

`vectorToNum` 那种 `sum = sum*10 + d` 的线性写法，恰好也实现了这个等价关系 —— 因为它是线性的：`Σ(dᵢ+δᵢ)·10ⁱ`。所以「先拼位再转数」和「直接加 10ⁱ」在数学上完全一致，只要别在中途做判断。

## 三、正解代码

```cpp
#include <iostream>
#include <string>
#include <climits>
using namespace std;

int main() {
    long long n, p;
    while (cin >> n >> p) {
        string s = to_string(n);
        int k = (int)s.size();

        long long best = LLONG_MAX;
        for (int mask = 0; mask < (1 << k); ++mask) {
            long long val = n;
            long long w = 1;                       // w = 10^i
            for (int i = 0; i < k; ++i) {
                val += ((mask >> i) & 1) ? w : -w; // δᵢ = +1 / -1
                w *= 10;
            }
            if (val > 0 && val % p == 0)
                best = min(best, val);
        }
        cout << (best == LLONG_MAX ? -1 : best) << '\n';
    }
    return 0;
}
```

要点：

1. **`mask` 的 bit i 对应 `10ⁱ`**，所以 `w` 从 1 开始每轮 `*= 10`（从右往左走），不要和字符串下标的从左往右搞混。
2. **`val` 从 `n` 起步**，不是从 0 累加 —— 因为每位都必须改，`n` 本身不是候选答案（`n=12,p=3` 的候选是 23 / 21 / 3 / 1，没有一个等于 12）。
3. **`val > 0` 这个条件不能省**：可能出现负数或 0，而题目要的是正倍数。
4. **取 `min` 是为了输出最小的那个**。如果题面只要求"输出任意一个"，找到就 `break` 更快。
5. **首位减 1 可能变成 0，位数会变少**：`12` 的十位 −1 得 `03`，即数值 `3`（`12−10=3`），这是合法的。若题目额外要求"位数保持不变"，就得额外排除首位为 0 的结果 —— 这会让 `12` 的答案从 `3` 变回 `21`。

### 复杂度

| 项 | 值 |
|---|---|
| 时间 | `O(k · 2^k)`，k ≤ 19 时约 1000 万次内层操作 |
| 空间 | `O(1)`（不算 `to_string`） |

`n` 在 `long long` 范围内（19 位）时 `2^19 ≈ 52 万`，每个组合扫 k 位，完全够用。

## 四、初版代码的四个硬伤

### ❌ 硬伤 1：最后一位永远不参与运算

```cpp
bool isNP(vector<int>& nums, int left, bool isAdd, int p) {
    if (left == nums.size() - 1) return false;   // ← 递归到个位就直接投降
    ...
}
```

递归走到**个位**（下标 `k-1`）时无条件 `return false`，**个位的 ±1 从来没有被执行过**。

后果比"漏一位"严重得多：整个递归树的所有叶子都返回 `false`，`||` 全是 `false`，所以 `isNP` **恒返回 false** → `solve` 恒 false → main 永远打印 `-1`。

### ❌ 硬伤 2：不回溯，两个分支互相污染

```cpp
nums[left] = leftValue;                     // 原地改了数组
...
return isNP(nums, left + 1, true,  p)       // 分支 A：继续改后面的位
    || isNP(nums, left + 1, false, p);      // 分支 B：拿到的已经是 A 改过的数组
```

`nums` 是引用，分支 A 深递归时把 `nums[left+1..]` 全改掉了，返回后分支 B 从**被污染的状态**继续。

**实测证据**（`n=12, p=3`）：

```
初始 nums = [1, 2]

分支 A（十位 +1）:
  nums[0] = 1+1 = 2        → [2,2] → 22，22 % 3 = 1，不输出
  递归 left=1 → 命中硬伤1，直接 false

分支 B（十位 -1）:
  nums[0] = 2 - 1 = 1     ← 注意！此时 nums[0] 已经是 2，不是原始的 1
  → [1,2] → 12，12 % 3 == 0 → 输出 12   ← 一个「每位都没改」的数被当成答案
```

所以程序输出 `12-1`：**先多打了一个非法答案 `12`，又因为 `solve` 返回 false 再打 `-1`**，而候选答案 `21` 一次都没被枚举到。

> 正确做法有两种：① 递归前 `int old = nums[left];` 递归后还原；② 干脆不改数组，把 `val` 当参数往下传（正解就是这么做的，天然无副作用）。

### ❌ 硬伤 3：`if (n < p) return false;` 砍掉一半答案

操作可以让数**变大**，所以 `n < p` 完全可能凑出 `p` 的倍数：

| 输入 | 正确 | 你的 |
|---|---|---|
| `4 5` | `5`（4+1） | `-1` |
| `1 2` | `2`（1+1） | `-1` |

这个提前返回没有任何依据。

### ❌ 硬伤 4：检查放在"中途"而不是"叶子"

```cpp
nums[left] = leftValue;
int result = vectorToNum(nums);     // 此时后面几位还没操作
if (result % p == 0) cout << result;  // 把半成品当成答案输出
```

枚举类问题的判据必须作用在**完整解**上（走完全部位）。放中途会让"只改了前几位的中间值"混进答案，这是 `12` 被打印出来的第二个原因。

## 五、最小改动版（保留你的骨架）

不想重写成位运算的话，原骨架只改 8 处就能跑通。核心两件事：**把「递归到个位就 return」改成「走完全部再判断」**，以及**补上回溯**。

```cpp
vector<int> NumToVector(int n)                 // ① 去掉 new，直接值返回
{
    vector<int> nums;
    while (n > 0) {
        nums.insert(nums.begin(), n % 10);
        n /= 10;
    }
    return nums;
}

long long vectorToNum(const vector<int>& nums) // ② int -> long long
{
    long long sum = 0;
    for (int i : nums) sum = sum * 10 + i;
    return sum;
}

void dfs(vector<int>& nums, int left, int p, long long& best)
{
    if (left == (int)nums.size()) {            // ③ 走完全部位才判断
        long long r = vectorToNum(nums);
        if (r > 0 && r % p == 0 && r < best) best = r;
        return;
    }

    int old = nums[left];                      // ④ 记住原值

    nums[left] = old + 1;
    dfs(nums, left + 1, p, best);

    nums[left] = old - 1;
    dfs(nums, left + 1, p, best);

    nums[left] = old;                          // ⑤ 回溯
}

long long solve(int n, int p)
{
    vector<int> nums = NumToVector(n);         // ⑥ 删掉 if (n < p) return false
    long long best = LLONG_MAX;
    dfs(nums, 0, p, best);
    return best == LLONG_MAX ? -1 : best;
}

int main() {
    int n, p;
    while (cin >> n >> p) cout << solve(n, p) << '\n';   // ⑦⑧ 换行 + 不再写 if(!solve)
    return 0;
}
```

八处改动一览：

| # | 原来是 | 改成 | 为什么 |
|---|---|---|---|
| ① | `new vector<int>()` 再返回 `*p` | 直接值返回 | 不再泄漏 |
| ② | `int vectorToNum` | `long long` | 候选值可能超 `int` |
| ③ | `if (left == size-1) return false;` | `if (left == size)` 时判断并 return | 个位必须参与，且只有叶子才判断 |
| ④⑤ | 直接改 `nums[left]` 后递归两路 | 记 `old`，两路分别赋值，最后还原 | **回溯**，否则分支互相污染 |
| ⑥ | `if (n < p) return false;` | 删掉 | 操作能让数变大 |
| ⑦ | `if (!solve(...)) cout << -1;` | 直接 `cout << solve(...)` | 让 `solve` 自己返回 `-1` |
| ⑧ | `cout << -1` 没换行 | 补 `'\n'` | 多组用例必须逐行输出 |

`isAdd` 这个参数可以整个删掉 —— 它的作用只是「这一层选 +1 还是 -1」，而递归里本来就调两次，直接写在 `dfs` 内部更清楚。

> 这个版本**并不会更快**，仍是 `O(k·2^k)`，而且每个叶子还多一次 `O(k)` 的 `vectorToNum`。但它是不推翻骨架、能立刻做对的最短路径。第三节的位运算版只是把「拆位 / 拼数」两步省掉了，数学上完全等价。

实测：8 个用例全过，与位运算版**随机对拍 20000 组差异 0**。

## 六、四个次要问题

| # | 问题 | 后果 |
|---|---|---|
| 5 | `vector<int>& NumToVector(int n)` 里 `new vector<int>()` 再返回 `*p` | **内存泄漏**，每组用例漏一个 vector，且调用方拿不到指针无法释放。直接按值返回即可（NRVO，零拷贝） |
| 6 | `cout << -1;` 没有换行 | 多组用例的输出全糊在一行，判题按行比对必挂 |
| 7 | `if (result % p == 0) cout << ...;` 后不 `return true` | 找到答案还继续递归，会输出多个结果 |
| 8 | `else if (result == 0)` | **死代码**：`0 % p == 0` 恒成立，永远进不了这个分支；而且那时 `result` 是 0，也不是"全 0 串" |
| 9 | 没 `#include <string>`；`left == nums.size()-1` 有符号/无符号比较 | 前者部分编译器报错，后者只是 `-Wsign-compare` 警告 |

## 七、实测对照

用正解与"暴力模拟（真的把每位数字 ±1 后拼成新数）"双跑，9 个用例结果完全一致：

| n | p | 正解 | 说明 |
|---|---|---|---|
| 4 | 5 | **5** | 个位 +1，`n < p` 也要算 |
| 1 | 2 | **2** | 单数字 |
| 12 | 3 | **3** | 4 个候选 23 / 21 / 3 / 1，最小倍数 3（首位 1−1=0，掉位） |
| 9 | 5 | **10** | `9 + 1`，进位 |
| 10 | 9 | **-1** | 十位必须动，4 种组合都不是 9 的倍数 |
| 105 | 95 | **-1** | 三位都动，8 种组合都凑不出 95 |
| 19 | 3 | **30** | `19 + 10 + 1` |
| 23 | 7 | **14** | `23 - 10 + 1` |
| 999 | 2 | **888** | 每位 -1 |

> `10 9` 这个用例特别值得记住：它说明「每位**必须**操作一次」和「**最多**操作一次」是两个不同的题。如果允许不操作，`10 - 1 = 9` 就是答案；但个位改、十位不改，就不符合"每位只能操作一次"的强制读法。

## 八、必须记住的点

1. **第 i 位 ±1 = 整体 ±10ⁱ** —— 想通这句，题目从"字符串变形"降级成"2^k 枚举"。
2. **进位/借位不需要特判** —— 加权求和自动处理。9+1 就是 +1，0-1 就是 -10ⁱ。
3. **枚举的判据必须放在叶子** —— 中途的值不是解。
4. **改共享状态必须回溯**，或者干脆不用可变状态（把 `val` 当参数传）。
5. **不要用 `n < p` 之类的"看起来合理"的条件提前剪枝** —— 先验证它是不是真的必要条件。

## 九、易错点速查

| 坑 | 表现 |
|---|---|
| 递归边界写成 `left == size-1` 就 return | 最后一位永不处理，函数恒 false |
| 改数组不回溯 | 分支互相污染，输出"没操作过的数"（`12` 那次） |
| 判据放在递归中途 | 半成品混入答案 |
| `n < p` 直接返回 | 漏掉 `4→5`、`1→2` 这类答案 |
| 忘记排除 `val <= 0` | 负数或 0 被当作倍数输出 |
| 多组输出没换行 | 所有答案糊成一行 |
| `1 << k` 用 `int` | k ≥ 31 时溢出（本题 k ≤ 19，但换成大数输入就要注意） |

## 十、面试延伸

**① 如果 n 是 100 位的大数字符串？**

`2^100` 枚举不可能。改用 **meet in the middle**：把位分成前后两半，各自枚举 `2^50`... 仍然太大。真正的做法是 **按模 DP**：

```
dp[i][r] = 处理完前 i 位、当前余数为 r 是否可达（或最小数值）
转移：dp[i+1][(r ± 10ⁱ) % p] |= dp[i][r]
```

状态数 `k × p`。当 `p` 较小（比如 ≤ 10^5）时可行；`p` 很大时就只能回到 `2^k` 枚举。

**② 如果 n 最多 40 位、p 任意？**

`2^40` 也太大。此时用 **meet in the middle**：前半 20 位枚举 `2^20` 个和，后半同理，两边排序后找配对使 `(a + b) ≡ -n (mod p)` —— 复杂度降到 `2^(k/2) · log`。

**③ 如果要求"操作次数最少"而不是"每位必改"？**

就变成 `3^k`（每位 +1/-1/不改），或按 BFS 逐层扩展（每层多改一位）。题意一变，模型要重做 —— 这也是为什么读题时"必须"和"最多"要抠清楚。

**④ 为什么这题的检查不能用"贪心"？**

因为 `p` 的倍数在数轴上分布没有单调性：`n+10ⁱ` 和 `n-10ⁱ` 哪个更接近目标倍数，完全取决于具体数值，不构成可以逐位贪心的结构。这类"模约束 + 组合选择"的题，基本只能枚举或 DP。

## 十一、牛客原题正解（3^k + 字符串拼装）

回到 1.1 的三个条件，只需在简化模型上改两处：

- **每位三种选择**：`d`（不动）、`d+1`（仅当 `d < 9`）、`d-1`（仅当 `d > 0`）
- **按字符串累积**：用 `cur` 保存已选数字的字符，叶子命中时直接作为答案 —— 这样 `000` 能原样输出

```cpp
#include <iostream>
#include <string>
using namespace std;

string s, cur, ans;
long long P;
bool found = false;

void dfs(int i, long long val)
{
    if (i == (int)s.size()) {
        if (val % P == 0) { ans = cur; found = true; }   // 0 % P == 0，所以 000 也算命中
        return;
    }
    int d = s[i] - '0';

    cur.push_back(s[i]);                                 // ① 不操作
    dfs(i + 1, val * 10 + d);
    cur.pop_back();
    if (found) return;                                   // 找到即停（多解输出任意一个）

    if (d < 9) {                                         // ② +1，9 不行
        cur.push_back(char('0' + d + 1));
        dfs(i + 1, val * 10 + d + 1);
        cur.pop_back();
        if (found) return;
    }

    if (d > 0) {                                         // ③ -1，0 不行
        cur.push_back(char('0' + d - 1));
        dfs(i + 1, val * 10 + d - 1);
        cur.pop_back();
    }
}

int main() {
    long long n;
    while (cin >> n >> P) {
        s = to_string(n);
        cur.clear(); ans.clear(); found = false;
        dfs(0, 0);
        cout << (found ? ans : "-1") << '\n';
    }
    return 0;
}
```

### 三个要点

1. **`val` 从 0 开始累加**（`val * 10 + d`），不是从 `n` 起步 —— 因为「不动」也是合法选择，而且我们要逐位拼装。这里 `d` 永远落在 `0..9`，**不会出现进位 / 借位**，所以 `val * 10 + d` 就是真实的十进制拼接。
2. **`cur` 是答案的唯一来源**。只看 `val` 会丢掉前导零：`000` 和 `0` 数值相等，但题面要求原样输出。
3. **`found` 之后立刻 `return`**：题面说「多解输出任意一个」，找到就停。

### 复杂度

`O(3^k)`，`k` 为位数。原题 `n ≤ 10^13` → `k ≤ 14`，`3^14 ≈ 478 万`，加上「找到即停」实际远小于此。

> 若某个题解版本要求「**输出值最大的解**」，就去掉 `found` 短路、改成比较 `stoll(cur)` 取最大 —— 但那样必须遍历完整的 `3^k` 棵树。

### 实测（原题三个样例）

| n | p | 期望 | 本文 2^k 简化解 | 原题 3^k 正解 |
|---|---|---|---|---|
| 72 | 7 | `63` | `63` | **`63`** |
| 101 | 123456789 | `000` | **`-1`** ❌ | **`000`** |
| 40 | 9 | `-1` | `-1` | **`-1`** |

中间那行就是「题面少一个条件、解法直接废掉」的实证：`101` 的中间位是 `0`，**原题允许不动它**，于是 `1−1, 0, 1−1` 得到 `000`；而「每位必须操作」的模型里这一位只能变 `1`，永远凑不出 `0`。
