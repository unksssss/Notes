# A\* 寻路算法

> 来源：牛客《25届游戏客户端开发求职总结》零跑汽车 U3D 一面真题"讲一下 a\*算法"（Day 37 面经，首学）

## 核心公式

> **f(n) = g(n) + h(n)**

| 分量 | 含义 | 类比 |
|---|---|---|
| g(n) | 起点 → 当前节点的**实际已走代价** | 已经花掉的钱（确定值） |
| h(n) | 当前节点 → 终点的**启发式估计代价**（曼哈顿/欧氏距离） | 预计还要花的钱（估算） |
| f(n) | **优先队列排序键**，每次取 f 最小的节点扩展 | 总预算，越小越优先 |

## 与 BFS / Dijkstra 对比

| 算法 | 排序依据 | 特点 |
|---|---|---|
| BFS | 无（层序扩散） | 无权图最短路径（步数），但盲目均匀扩散，不看终点方向 |
| Dijkstra | 仅 g(n)（起点实际代价） | 有权图最优，但"只算旧账不看地图"，可能先往反方向绕 |
| **A\*** | **g(n) + h(n)** | Dijkstra + "开天眼"：每步用估算距离盯着终点，又准又快 |

- **灵魂类比** 🧭：BFS = 无脑水波；Dijkstra = 闷头走路不看目的地；A\* = 带方向的 Dijkstra
- Unity NavMesh 底层内嵌 A\* 思想

## 两个极端退化（面试加分）

- **h(n) = 0** → A\* 退化成 Dijkstra（最稳但最慢）
- **只按 h(n) 走** → 贪心最佳优先（最快但**不保证最优**）

## 可采纳性（admissible）——保证最优的关键

- **h(n) 必须永远 ≤ 真实代价**（乐观估计、不虚报）→ A\* 保证找到最优路径
- **高估的后果**：最优路径上节点的 f 被算得虚高 → 在队列中排后、被推迟扩展甚至错过 → 最终结果**可能不是最短路径**
- 低估仍能保证最优，只是扩展更多节点、更慢

## 网格启发函数选择

- 四方向移动（上下左右）：曼哈顿距离 `|dx| + |dy|`（可采纳）
- 八方向移动：对角距离（可采纳且更紧）
- 欧氏距离对四方向也可采纳但偏松（扩展更多节点）

## 面试表达框架

1. 先讲痛点：网格寻路要"最短 + 高效"
2. BFS 无权最优但盲目 → Dijkstra 有权最优但低效（不看终点）
3. A\* = Dijkstra + 启发式：f = g + h，优先队列取 f 最小扩展
4. 保证最优：h 可采纳（≤ 真实代价）；高估会错过最优解
5. 应用：游戏寻路、NavMesh 底层、塔防怪物寻路
