### FireSim_URP_VR — FireCar_Interaction 四卷帘门工具交互扩展

目标：`Assets/Scripts/Author/LJJ/Interactions/FireCar_Interaction.cs`

消防车交互从"单卷帘门开启"升级为**四工具仓卷帘门**：高压水枪/破拆工具/其他/灭火器 各一个卷帘门，选中收起卷帘门 → 激活对应工具物体。

- 每个卷帘门 `Init()` 统一注册：自动挂 `XRIEventReceiver`（射线事件）+ `HighlightEffect`（绿色 Profile，hover 亮 / 离开灭）
- `OnSelectEntered` → `RollerDoorX.DOScaleZ(0, 1f)` 卷帘门沿 z 缩到 0 收起 → `OnComplete` 激活对应 Tool

```csharp
xrier1.OnSelectEntered.AddListener((info) =>
{
    RollerDoor1.DOScaleZ(0, 1f).SetEase(Ease.Linear).OnComplete(() =>
    {
        Tool1.gameObject.SetActive(true);   // 卷帘门收起后工具才出现
    });
});
```

- 保留原有登车链路：`SetPlayerToCopilot`（`XROrigin.MoveCameraToWorldLocation` + `MatchOriginUpCameraForward` 传送到副驾驶）→ 卷帘门 `DOLocalMoveZ(7.83f, 3)` 开启 → `CarTF.DOPath(路径, 20s, Linear, Full3D).SetLookAt(0.01f)` 沿电影院路径行驶 → 到达终点 `SetParent(null)` 解除父子 + 传送终点
- ⚠️ 注意：4 个卷帘门注册逻辑是 `#region` 复制 4 份，字段手动拖拽（RollerDoor1-4 / Tool1-4），可考虑数组 + 循环重构

> 知识点：卷帘门"选中 → 缩放到 0 隐藏"比"移开"更省事（不占视觉空间，DOTween 本地缩放即可）；工具物体先 `SetActive(false)`，由卷帘门动画 OnComplete 激活，实现"先开仓后见物"的时序感。XROrigin 传送 = `MoveCameraToWorldLocation` 定位置 + `MatchOriginUpCameraForward` 定向。📎 [[XR射线交互与World Space Canvas]]、[[XR Interaction Toolkit 配置指南]]、[[dotween详解]]

### FireSim_URP_VR — InteractionController 交互控制器三查校验

目标：`Assets/Scripts/Author/LJJ/Interactions/InteractionController.cs`

交互物体的统一入口控制器，`Start()` 三连初始化，配置错误直接 `LogError` 点名，防止场景里漏配组件导致静默失效：

1. `InitInteractionObjectBaseList()`：**自动收集**控制器下的所有子物体，逐个要求挂 `InteractionObjectBase` 子类，没有就报错
2. `InitComponent()`：批量补 `HighlightEffect`（缺失自动 AddComponent）+ 统一赋绿色 Profile + 预置 highlighted 后失活（等射线触发）
3. `CheckCollider()`：三查校验——① `InteractionObject` 是否赋值 ② 交互物体有没有 `Collider`（没有则射线点不到）③ 有没有 `HighlightEffect`

```csharp
if (!obj.InteractionObject.TryGetComponent<Collider>(out Collider c))
{
    Debug.LogError($"{obj.InteractionObject.name} 上没有挂载 [Collider] 碰撞体组件");
    return;
}
```

> 知识点：交互系统配置项越多越容易漏配，启动时集中校验 + 报错点名是低成本高收益的做法（一次遍历，日志直接定位物体名）。`TryGetComponent<T>` 比 `GetComponent<T>() != null` 少一次空引用检查。📎 [[XR Interaction Toolkit 配置指南]]、[[UnityEngine.Object 判空与销毁机制]]

### FireSim_URP_VR — InteractionObjectBase 基类事件生命周期（防重复点击 + 防泄漏）

目标：`Assets/Scripts/Author/LJJ/Interactions/InteractionObjectBase.cs`

交互物体抽象基类，`OnEnable` 自动挂 `XRIEventReceiver` 并订阅三个射线事件；`OnDisable` 清空监听：

- **防重复点击**：`SelectEntered` 回调里先把 `InteractionObject` 的 `Collider.enabled = false`，交互完成即失效，防止连点重复触发（如卷帘门收一半又被点）
- **防泄漏**：`OnDisable` 里 `RemoveAllListeners()` 三连，面板/物体 SetActive 切换时不会累积重复回调
- 事件回调转发到虚方法 `HoverEntered/HoverExited/SelectEntered`，子类（FireCar_Interaction 等）override 即可扩展

```csharp
xrier.OnSelectEntered.AddListener((args) =>
{
    Collider c = InteractionObject.GetComponent<Collider>();
    c.enabled = false;          // 一次交互后禁用碰撞，防重复触发
    SelectEntered();
});
```

> 知识点：**一次性交互（点击即消失/传送）必须禁用 Collider**——XRI 的 Select 事件在按住期间会持续触发，只靠状态位容易漏；关碰撞体是最物理的"失效"方式。订阅/退订必须成对写在 OnEnable/OnDisable。📎 [[MonoBehaviour生命周期与SetActive的坑]]、[[XR射线交互与World Space Canvas]]
