# 排序算法：快排 / 归并 / 堆排

## 对比总览（必背）

| 算法 | 平均时间 | 最坏时间 | 额外空间 | 稳定 | 特点 |
|------|---------|---------|---------|------|------|
| 快排 | O(n log n) | **O(n²)** | O(log n) | ❌ | 平均最快，怕有序数组 |
| 归并 | O(n log n) | O(n log n) | **O(n)** | ✅ | 稳定，适合外部排序 |
| 堆排 | O(n log n) | O(n log n) | **O(1)** | ❌ | 省内存，常数大实际慢 |

> **记忆口诀**：快排快但怕有序、归并稳但费内存、堆排省内存但慢常数。

## 1. 快速排序（平均之王）

**一句话**：选个基准值，把数组劈成「小 / 大」两半，基准归位，再对两半递归。

### 1.1 Hoare 划分（★ 推荐背这一个）

```cpp
void quickSort(vector<int>& a, int l, int r)
{
    if (l >= r) return;                      // 0 或 1 个元素，天然有序
    int i = l - 1, j = r + 1;
    int p = a[(l + r) >> 1];                 // ★ pivot 取【中间位置】的值
    while (true) {
        do ++i; while (a[i] < p);            // 从左边找第一个 >= p 的
        do --j; while (a[j] > p);            // 从右边找第一个 <= p 的
        if (i >= j) break;                   // 交叉了，划分结束
        swap(a[i], a[j]);
    }
    quickSort(a, l, j);                      // ★ 左半是 [l, j]
    quickSort(a, j + 1, r);                  // ★ 右半是 [j+1, r]
}
```

四个必须理解的点：

**① 为什么 `i` 从 `l-1`、`j` 从 `r+1` 开始？**
配合 `do ++i` 的语义（先加再用），第一次比较的就是 `a[l]` 和 `a[r]`。而 `p` 取自区间**内部**，所以 `a[i] < p` 这个条件在两端一定会停住 —— **天然哨兵，不会越界**，不用额外写 `i <= r`。

**② 为什么是 `a[i] < p` 而不是 `<=`？**
必须严格小于。写成 `<=` 时，全相同数组里 `i` 会一路冲到底，越界崩溃。

**③ 为什么递归边界是 `j` 和 `j+1`，不是 `i`？**
交叉后 `j` 是「左半段最后一个下标」、`i` 是「右半段第一个下标」。用 `j` 才能保证 `[l,j]` 与 `[j+1,r]` **两段都非空**，不会无限递归。**这是最容易写成死循环的地方。**

**④ 为什么 pivot 取 `a[(l+r)>>1]`（中间位置）？**
这是**免费的抗退化**：有序数组里中间位置的值恰好是中位数，划分最均衡。实测 1e6 已升序数组，Hoare 版 8ms，和随机数据一样快 —— **根本不需要额外随机化**。

### 1.2 Lomuto 划分（最好懂，但会退化）

```cpp
void quickSort2(vector<int>& a, int l, int r)
{
    if (l >= r) return;
    int p = a[r], i = l;                     // 以最右为 pivot
    for (int j = l; j < r; ++j)
        if (a[j] < p) swap(a[i++], a[j]);
    swap(a[i], a[r]);                        // pivot 归位到 i
    quickSort2(a, l, i - 1);
    quickSort2(a, i + 1, r);
}
```

代码短、只有一个指针往前扫，**讲解时用这个最清楚**。但 pivot 固定取最右，在**已排序数组**和**全相同数组**上都会退化成 `O(n²)`。

实测（本机 g++ -O2）：

| n | Lomuto 有序 | Hoare 有序 | Lomuto 全相同 |
|---|---|---|---|
| 2000 | 2.05 ms | ~0 ms | ~0 ms |
| 4000 | 5.39 ms | ~0 ms | 2.65 ms |
| 8000 | 19.85 ms | ~0 ms | 11.44 ms |
| 16000 | **77.46 ms** | **1.01 ms** | **45.44 ms** |

n 每翻倍耗时 ×4 —— 这就是 `O(n²)` 的样子。`n = 1e5` 时会到十几秒。

### 1.3 三路划分（重复元素多时接近 O(n)）

```cpp
void quickSort3Way(vector<int>& a, int l, int r)
{
    if (l >= r) return;
    int p = a[l + rand() % (r - l + 1)];
    int lt = l, i = l, gt = r;               // [l,lt) < p | [lt,i) == p | (gt,r] > p
    while (i <= gt) {
        if      (a[i] < p) swap(a[lt++], a[i++]);
        else if (a[i] > p) swap(a[i], a[gt--]);
        else               ++i;              // == p 就留在中间
    }
    quickSort3Way(a, l, lt - 1);             // 中间那段 == p 的【完全不再参与递归】
    quickSort3Way(a, gt + 1, r);
}
```

**关键收益**：中间整段等于 pivot 的元素被永久排除。

实测 1e6 **全相同**：Hoare 8ms，三路 **0ms**。

⚠️ Lomuto 在三路里也能写（`[l,i) < p`、`[i,k) == p`），但上面的双指针版更省交换。

### 1.4 迭代版（显式栈，绝不爆栈）

```cpp
void quickSortIter(vector<int>& a, int l, int r)
{
    vector<pair<int,int>> st;
    st.push_back({l, r});
    while (!st.empty()) {
        auto [lo, hi] = st.back(); st.pop_back();
        while (lo < hi) {
            int i = lo - 1, j = hi + 1, p = a[(lo + hi) >> 1];
            while (true) {
                do ++i; while (a[i] < p);
                do --j; while (a[j] > p);
                if (i >= j) break;
                swap(a[i], a[j]);
            }
            // 大的那半压栈，小的那半继续循环 -> 栈深度恒为 O(log n)
            if (j - lo < hi - j - 1) { st.push_back({j + 1, hi}); hi = j; }
            else                     { st.push_back({lo, j});     lo = j + 1; }
        }
    }
}
```

**先处理短的那半、长的用循环接着做**（尾递归消除），递归/栈深度永远是 `O(log n)`，极端数据也不爆栈。

### 性能实测（1e6 元素，g++ -O2）

| 场景 | Hoare | 随机 pivot + 尾递归 | 三路 | 迭代 |
|---|---|---|---|---|
| 随机 | 66 ms | 75 ms | 77 ms | 66 ms |
| 全相同 | 8 ms | — | **0 ms** | — |
| 已升序 | 8 ms | 33 ms | — | — |
| 已降序 | 8 ms | — | — | 10 ms |

⚠️ **随机化不是免费的**：随机数据下 Hoare（中间 pivot）最快，加了随机数开销反而慢 15%。所以优先用「中间位置 pivot」，**不要无脑随机化**。

### 复杂度与性质

| 项 | 值 |
|---|---|
| 平均 / 最好 | `O(n log n)` |
| 最坏 | `O(n²)`（pivot 每次都极偏） |
| 空间 | `O(log n)` 递归栈；最坏 `O(n)`，靠尾递归消除可恒为 `O(log n)` |
| **稳定性** | **不稳定** ❌ —— 交换会打乱相等元素的相对顺序 |

不稳定举例：`[3a, 3b, 1]` 划分后可能变成 `[1, 3b, 3a]`。

### 五个坑速查

| 坑 | 表现 |
|---|---|
| 递归边界用 `i` 而不是 `j` | 死循环 / 栈溢出 |
| `while (a[i] < p)` 写成 `<=` | 全相同数组越界崩溃 |
| pivot 固定取 `a[l]` 或 `a[r]` | 有序输入退化 `O(n²)` |
| 漏掉 `if (l >= r) return` | 空区间无限递归 |
| 递归先处理长的那半 | 深度 `O(n)`，1e5 以上易爆栈 |

## 2. 归并排序（稳定暖男）

**思想**：分治（和快排相反顺序）
1. 数组对半拆，拆到单元素（天然有序）
2. 两两合并：双指针从小到大归并成有序区间

**复杂度**：
- 时间稳定 O(n log n)，任何输入都不退化
- 空间 O(n)：合并需要辅助数组
- **稳定**：合并时相等元素先取左半边

**适用**：外部排序（数据大到内存装不下）、链表排序（顺序访问，天然适配归并）。

**为什么归并适合链表/外部排序，快排不行（Day 23 加深）**：
- **链表**：归并的合并只需顺序遍历两个有序序列，链表天然只支持顺序访问；快排的 partition 要随机访问 + 双向扫描交换，链表上定位第 i 个元素是 O(n)，直接退化
- **外部排序（超大文件）**：切块 → 每块读入内存排成有序段（run）→ **多路归并**逐段合并写回磁盘，内存永远只装得下几块；快排需要**全量数据在内存**随机访问，物理上做不到
- **稳定性**：归并稳定（相等元素保持原序），多关键字排序（先按 A 再按 B）时第一轮顺序不丢；快排交换会打乱
- **复杂度保证**：归并任何输入都是 O(n log n)；快排最坏 O(n²)（有序数组 + 固定基准），随机化/三数取中也只是概率缓解

## 3. 堆排序（省内存硬汉）

**思想**：数组表示完全二叉树（大顶堆：父 ≥ 子）
1. **建堆**：乱序数组调整成大顶堆，堆顶 = 最大值
2. **排序**：堆顶与末尾交换 → 堆大小减 1 → 堆顶下沉（sift down）恢复堆性质
3. 重复直到堆空

**复杂度**：
- 最坏也 O(n log n)，输入好坏都稳定
- 空间 O(1)：原地排序
- **不稳定**：交换堆顶/末尾时相等元素相对顺序可能变

**缺点**：常数大、cache 不友好（跳跃访问），工程上通常比快排慢。

**⚡ 数组 ↔ 完全二叉树索引映射（必背）**：
```
索引 i 的节点：
  左孩子 = 2*i + 1
  右孩子 = 2*i + 2
  父节点 = (i-1) / 2
```

**下沉（sift down）**：堆的核心操作——把某节点与较大的孩子交换，直到父 ≥ 子。单次 O(log n)。

**⚡ 建堆是 O(n) 不是 O(n log n)（面试最爱挖的坑！Day 18/19 连续复习）**：
从最后一个非叶节点（`n/2 - 1`）倒着逐个下沉，越靠近底层的节点下沉次数越少，总操作数求和是**线性**的。多数人误以为是 O(n log n)。

**核心直觉**：堆 ≠ 有序数组，只保证"父 ≥ 子"（大顶堆），所以**只有堆顶是全局最大值，兄弟之间无序**。排序 = 反复"堆顶与末尾交换 → 堆大小减 1 → 堆顶下沉"，共 n-1 次 × O(log n) = O(n log n)。

**⚡ 升序还是降序？（Day 33 灯皇答反过，必背口诀）**：
- **大顶堆 → 升序**：堆顶是最大，与末尾交换 → 大数依次归位到**数组尾部**，从后往前填，前段自然剩最小
- **小顶堆 → 降序**：堆顶是最小，先被扔到末尾
- 口诀：**"大顶堆，尾巴先放大，排出来升序；要降序就换小顶堆"**

**排序阶段逐轮演算（Day 33 教学，例 [12,9,8,5,6,4,3] 大顶堆）**：
```
第1轮: 12↔3 堆缩[0..5] 3下沉2层 → [9,6,8,5,3,4 | 12]
第2轮: 9↔4  堆缩[0..4] 4下沉2层 → [8,6,5,4,3 | 9,12]
第3轮: 8↔3  堆缩[0..3] 3下沉2层 → [6,4,5,3 | 8,9,12]
第4轮: 6↔3  堆缩[0..2] 3下沉1层 → [5,4,3 | 6,8,9,12]
第5轮: 5↔3  堆缩[0..1] 3下沉1层 → [4,3 | 5,6,8,9,12]
第6轮: 4↔3  → [3 | 4,5,6,8,9,12]  完成：升序 ✅
```
每轮三件事：**交换堆顶↔堆尾 → heapSize-- → 新堆顶下沉**；已排序区永远在数组尾部（竖线右侧），不再参与堆操作。

## 面试高频题

1. **快排为什么最坏是 O(n²)？** → 每次基准都是最值，分区退化成每次只去掉一个元素，递归深度 n
2. **哪个排序稳定？** → 归并 ✅；快排/堆排 ❌
3. **排序大文件用哪个？** → 归并（外部排序，分段读入内存归并）
4. **要求 O(1) 空间 + 保证最坏 O(n log n)？** → 堆排
