# 多重集合操作

## 一、题目

维护一个多重集合（**允许重复**），六种操作：

| op | 含义 | 注意 |
|---|---|---|
| 1 x | 插入 `x` | |
| 2 x | 删除**一个** `x`；不存在则忽略 | 「一个」是关键 |
| 3 x | 输出 `x` 的出现次数 | |
| 4 x | 输出元素**总个数**（含重复） | ★ 这一行也有 `x` |
| 5 x | 前驱：小于 `x` 的最大元素，无则 `-1` | |
| 6 x | 后继：大于 `x` 的最小元素，无则 `-1` | |

**输入格式**：`n`，然后 `n` 行，**每行两个整数 `opt` 和 `x`**（`0 ≤ |x| ≤ 10⁶`）。

官方示例 2：

```
输入          输出
6             2
1 2           1
1 2           1
3 2
2 2
3 2
4 0
```

## 二、核心认知

`multiset` = 允许重复的 `set`，底层同样是红黑树。**所有接口一模一样**，只有语义随"重复"而变：

| 接口 | `set` | `multiset` |
|---|---|---|
| `insert(x)` | 已存在则忽略 | 再存一份 |
| `erase(x)` | 删掉那个（唯一的） | **删掉所有等于 x 的** ❗ |
| `count(x)` | 0 或 1 | 出现次数 |
| `lower_bound / upper_bound` | 同 | 同（跨过所有等于 x 的） |

所以这题的坑**只在「删除」和「输入」**，前驱后继的写法一个字都不用改。

## 三、❌ 灯皇的两个错

### ① `op == 4` 分支没读 `x` → 之后全部错位

```cpp
if(op==4){ cout<<sizeOfSet()<<endl; }   // ❌ 这一行的 x 还留在缓冲区
```

题目说得很明确：「每行输入两个整数 `opt` 和 `x`」，示例 2 最后一行就是 `4 0`。

漏读一个 token，后面就像多米诺骨牌：下一次 `cin >> op` 会把那个残留的 `x` 当成操作类型，再下一次把真正的 `op` 当成参数……实测：

```
输入              你的输出     正确输出
5
4 3               0            0
1 5               0            1
3 5               -1           1
4 0               -1           1
4 0
```

**一行没读干净，后面全乱。** 这是 ACM 模式最典型的坑之一（和「`cin >> n` 后直接 `getline` 读到空串」同源）。

**最稳的写法：不管哪个分支需要，先统一读两个整数**

```cpp
int op, x;
cin >> op >> x;      // 每行都是两个，统一读，谁不用谁闲着
```

### ② `erase(x)` 删掉了所有 `x`，题目只要删一个

```cpp
Mset.erase(x);                        // ❌ 等于 x 的全部消失
auto it = Mset.find(x);               // ✅ 只删一个
if (it != Mset.end()) Mset.erase(it);
```

`multiset::erase` 有两个重载，语义完全不同：

| 写法 | 行为 | 复杂度 |
|---|---|---|
| `erase(key)` | 删除**所有** `key` | `O(log n + k)` |
| `erase(iterator)` | 删除**这一个** | `O(1)`（摊还） |
| `erase(first, last)` | 删除区间 | `O(k)` |

用错重载，示例 2 直接挂：

```
输入        你的输出     正确输出
6           2            2
1 2         0            1      ← 两次插入后删一次，应剩 1 个
1 2         0            1
3 2
2 2
3 2
4 0
```

**删除不存在的元素**：`erase(key)` 返回删除个数（0 表示没删到，安全）；`erase(iterator)` 传 `end()` 是 **UB**，所以必须先 `find` 再判 `!= end()`。

## 四、正解

```cpp
#include <iostream>
#include <set>
using namespace std;

multiset<int> ms;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int q;
    cin >> q;
    while (q--) {
        int op, x;
        cin >> op >> x;                    // ★ 统一读两个
        switch (op) {
            case 1: ms.insert(x); break;
            case 2: {                      // ★ 只删一个
                auto it = ms.find(x);
                if (it != ms.end()) ms.erase(it);
                break;
            }
            case 3: cout << ms.count(x) << '\n'; break;
            case 4: cout << ms.size()    << '\n'; break;
            case 5: {
                auto it = ms.lower_bound(x);
                if (it == ms.begin()) cout << -1 << '\n';
                else { --it; cout << *it << '\n'; }
                break;
            }
            case 6: {
                auto it = ms.upper_bound(x);
                if (it == ms.end()) cout << -1 << '\n';
                else cout << *it << '\n';
                break;
            }
        }
    }
    return 0;
}
```

两组官方示例实测：`1`、`2 / 1 / 1`，全对。

## 五、前驱后继为什么不用改

`multiset` 里 `lower_bound(x)` 仍然返回**第一个 `>= x`** —— 它会跨过前面所有等于 `x` 的元素。所以：

- 前驱 `< x` = `lower_bound(x)` 再 `--`（此时落在最后一个 `< x` 上，哪怕中间有一堆 `x`）
- 后继 `> x` = `upper_bound(x)`（跳过所有等于 `x` 的）

原理详见 [[集合操作与前驱后继]]，重复元素不影响这两个函数的定义。

## 六、其他小细节

- **`count(x)` 的复杂度是 `O(log n + k)`**，`k` 是出现次数。极端情况（10⁵ 个相同元素、反复 `count`）会退化 —— 那时要用 `map<int,int>` 维护计数
- **`size()` 返回 `size_t`**，含重复计数
- **`erase(key)` 的返回值**是删除的元素个数，想统计"删了几个"可以直接用
- `#include <bits/stdc++.h>` 在牛客没问题

## 七、复杂度

| 操作 | 复杂度 |
|---|---|
| 1 / 2 / 5 / 6 | `O(log n)` |
| 3 | `O(log n + k)` |
| 4 | `O(1)` |
| 总 | `O(q log n)` |

## 八、面试延伸

- **`set` vs `multiset` vs `map` vs `unordered_*`**：要不要重复、要不要有序，两个维度四个选择
- **「只删一个」在 `map` 里怎么写**：`map[key]` 是计数，删一个就是 `if (--mp[key] == 0) mp.erase(key);`（这种做法还能顺手统计次数，比 `multiset` 更省）
- **「按值删区间」**：`ms.erase(ms.lower_bound(l), ms.upper_bound(r))` 一次删掉 `[l, r]` 内所有元素
- **工程里**：`multimap` 常用于"一键多值"的场景（同一个 key 挂多条记录）
