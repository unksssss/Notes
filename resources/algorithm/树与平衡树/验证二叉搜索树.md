# 验证二叉搜索树

对应 **剑指 Offer 98 / LeetCode 98**。

> 题面：给定一棵二叉树，判断它是否是**有效**的二叉搜索树。
> 有效 BST 的定义：
> 1. 节点的**左子树**只包含**严格小于**当前节点值的数；
> 2. 节点的**右子树**只包含**严格大于**当前节点值的数；
> 3. 所有左子树和右子树自身也必须是二叉搜索树。

## 一、核心认知：约束是「整棵子树」级，不是「父子」级

BST 的定义里写的是「**左子树所有节点** < 根 < **右子树所有节点**」—— 注意是**整棵子树**，不是「左孩子」和「右孩子」。

这带来一个关键推论：**每个节点能取什么值，由它所有祖先共同决定**。该节点必须落在祖先们逐步收窄出来的一个**开区间**里。

### ❌ 经典反例：父子全合法，但不是 BST

```
       10
      /  \
     5    15
         /  \
        6    20
```

- `10 > 5` ✓　`10 < 15` ✓　`15 > 6` ✓　`15 < 20` ✓
- **每条父子边都合法**
- 但 `6` 落在 `10` 的**右子树**里，必须 `> 10` —— 而 `6 < 10`

所以「只比较父子」这种判据**必然误判**。这类反例在面试里几乎是标准考点，一定要能当场画出来。

## 二、❌ 初版代码的三层问题

```cpp
bool isValidBST(TreeNode* root) {
    if(root) return true;                                    // ①
    return isValidBST(root->left)&&isValidBST(root->right);   // ②
    if(root->val>root->left->val&&root->val<root->right->val) return true;  // ③
    else return false;                                       // ③
}
```

| 层 | 问题 | 后果 |
| --- | --- | --- |
| **控制流** | ① `if(root) return true;` **少写了 `!`** | 非空 → 恒返回 `true`，任何树都判通过；空 → 走 ② 对 `nullptr` 解引用**崩溃** |
| **控制流** | ② 递归调用只在 `root == nullptr` 时执行 | 必然空指针解引用，且 `&&` 两侧都没机会跑 |
| **不可达** | ③ 在 `return` 之后 | **永远执行不到**，是死代码 |
| **算法思想** | 只比父子（`root->val > root->left->val`） | 跨层约束丢失，见第一节反例 |
| **算法思想** | ③ 判完直接 `return`，不再递归子树 | 即使父子都对，也没检查孩子们的子树 |
| **健壮性** | ③ 访问 `root->left->val` 没判空 | 叶子节点直接崩 |

**结论：这版代码没有一个分支是对的。** ① 让函数恒真，② 让它崩，③ 根本到不了。

## 三、解法一：上下界区间递归（首选）

核心机制：**每个节点带一个允许的开区间 `(low, high)` 往下走**。

```cpp
class Solution {
public:
    bool isValidBST(TreeNode* root) {
        return check(root, LLONG_MIN, LLONG_MAX);     // 根节点：(-∞, +∞)
    }

private:
    bool check(TreeNode* node, long long low, long long high) {
        if (!node) return true;                              // 空节点不违反任何约束
        if (node->val <= low || node->val >= high) return false;  // 出界 → 不是 BST
        return check(node->left,  low, node->val)             // 左子树：上界收紧为 node->val
            && check(node->right, node->val, high);           // 右子树：下界收紧为 node->val
    }
};
```

### 为什么能抓住 `6` 那个反例

```
10 ∈ (-∞, +∞)  ✓
├─ 5  ∈ (-∞, 10)  ✓
└─ 15 ∈ (10, +∞)  ✓
   └─ 6 ∈ (10, 15)  ✗  6 < 10
```

区间从根一路传下来，`10` 这个下界一直"跟着"了右子树的孙子 —— 这正是「父子比较」看不到的东西。

### ⚠️ 边界必须用 `LLONG_MIN / LLONG_MAX`

很多题解写 `LONG_MIN / LONG_MAX`，在 LeetCode（Linux，LP64）能过，但**在 Windows / VS 上会挂**：

- Windows 是 **LLP64**，`long` 只有 **32 位**，`LONG_MIN == INT_MIN`
- 于是节点值恰好是 `INT_MIN` 时，`node->val <= low` → `INT_MIN <= INT_MIN` → **误判为 false**

安全写法（三选一）：

```cpp
check(root, LLONG_MIN, LLONG_MAX);                                  // <climits>
check(root, numeric_limits<long long>::min(), numeric_limits<long long>::max());  // <limits>
// 或者干脆不用数值边界，改用「前驱指针」—— 见解法二
```

## 四、解法二：中序遍历（BST 中序 = 严格升序）

BST 的**定义等价于**「中序遍历结果严格递增」。所以只要中序走一遍，检查是否一直递增即可。

```cpp
class Solution {
public:
    bool isValidBST(TreeNode* root) {
        TreeNode* prev = nullptr;
        return inOrder(root, prev);
    }

private:
    bool inOrder(TreeNode* node, TreeNode*& prev) {          // ★ 引用！同《二叉搜索树转双向链表》
        if (!node) return true;
        if (!inOrder(node->left, prev)) return false;        // 左子树不合法 → 立即剪枝
        if (prev && prev->val >= node->val) return false;    // 必须【严格】递增
        prev = node;                                         // 更新前驱
        return inOrder(node->right, prev);
    }
};
```

### 这题和《二叉搜索树转双向链表》是同一个坑

`prev` 必须写成 `TreeNode*&` —— 与 [[二叉搜索树转双向链表]] 里 `prev` 的用法**完全一致**：

- `prev` 每层都要被更新，且**外层要用到内层更新后的值** → 必须引用传参
- 值传递的话，每层各持一份副本，返回时副本销毁，外层 `prev` 永远是 `nullptr` → **校验完全失效，函数恒返回 true**

这就是「**谁需要把改动带出去，谁就加 `&`**」这条铁律的第二次登场。

## 五、解法三：迭代中序（显式栈）

```cpp
bool isValidBST(TreeNode* root) {
    stack<TreeNode*> st;
    TreeNode* cur  = root;
    TreeNode* prev = nullptr;
    while (cur || !st.empty()) {
        while (cur) { st.push(cur); cur = cur->left; }       // 向左压到底
        cur = st.top(); st.pop();                            // 弹出 = 访问
        if (prev && prev->val >= cur->val) return false;     // 校验递增
        prev = cur;
        cur = cur->right;
    }
    return true;
}
```

优点：不依赖引用、不怕深递归爆栈。**面试被追问"不用递归"时直接上这个**。

## 六、三解法对比

| | 上下界递归 | 中序递归 | 中序迭代 |
| --- | --- | --- | --- |
| 核心思想 | 区间约束 | 升序校验 | 升序校验 |
| 时间 | O(n) | O(n) | O(n) |
| 空间 | O(h) | O(h) | O(h) |
| 需要 `TreeNode*&` | 否 | **是** | 否 |
| 边界陷阱 | **有**（LLONG_MIN） | 无 | 无 |
| 推荐度 | ★★★ 首选 | ★★ 体现"中序=升序"的理解 | ★★ 防爆栈 |

## 七、必须记住的点

**① BST 约束是「子树级」的**

`10` 的右子树里**每一个**节点都要 `> 10`，不只是右孩子。这是本题唯一的核心认知，也是所有错误判据的根源。

**② 必须「严格」**

`node->val <= low || node->val >= high` —— 等号也要拒绝。BST 通常不允许重复值（LeetCode 98 明确要求严格）。

中序版对应 `prev->val >= node->val` 才 `return false`，写成 `>` 就把相等的放过去了。

**③ 上下界要「单向收紧」**

- 往**左**：上界收紧成 `node->val`，下界**保持**（不要写成 `low` 与 `node->val` 取 max 之类的多余操作）
- 往**右**：下界收紧成 `node->val`，上界**保持**

写成「两侧都收紧」就会把合法子树误判为非法。

## 八、易错点

1. `if(root) return true;` **少写 `!`** → 恒真，或空树时崩溃
2. **只比较父子** → 跨层约束丢失（反例 `10/5,15/6,20`）
3. 判完父子**直接 return**，不递归子树
4. 访问 `root->left->val` 前**不判空** → 叶子崩溃
5. 边界用 `INT_MIN/INT_MAX` 或 `LONG_MIN/LONG_MAX` → 节点值等于边界时误判（**Windows 下 `long` 是 32 位**）
6. 中序版 `prev` **忘记引用** → 校验完全失效
7. 用 `>` 而非 `>=` 判违规 → 放过重复值

## 九、复杂度

| 维度 | 值 |
| --- | --- |
| 时间 | **O(n)**，最坏每个节点访问一次；发现违规可提前 `return false` 剪枝 |
| 空间 | 递归 **O(h)**；迭代栈 O(h)；最坏（退化成链）O(n) |
| 额外空间 | 上下界版 O(1)（只用两个数值）；中序版 O(1)（一个前驱指针） |

## 十、面试延伸

- **「BST 中序有序」是万能钥匙**：验证 BST、第 k 小元素、恢复 BST（两节点被误交换）、BST 转有序链表，全部靠它
- **「恢复二叉搜索树」** → LeetCode 99：中序遍历找**两处逆序对**，交换对应节点的值
- **「BST 中第 k 小的元素」** → 中序走到第 k 个
- **「为什么不能只比较父子」** → 就是本题的核心考点，一定要能当场画反例
- **「BST 里能不能有重复值」** → 看业务定义；LeetCode 98 要求严格递增，但红黑树实现的 `multiset` 是允许重复的
- **「AVL / 红黑树还需不需要验证 BST」** → 不需要，它们在插入时就维持了，见 [[二叉平衡树AVL]]、[[红黑树]]
