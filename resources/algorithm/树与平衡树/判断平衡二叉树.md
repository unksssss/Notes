# 判断平衡二叉树

对应 **剑指 Offer 55-2 / LeetCode 110**。

> 题面：输入一棵二叉树，判断它是否是平衡二叉树。
> **只需要考虑平衡性，不需要考虑它是不是排序二叉树。**
> 平衡的定义：对树中**每一个节点**，其左右子树的高度差的绝对值不超过 1。

## 一、核心认知

定义里的两个关键词，恰好对应初学者最常犯的两个错：

| 关键词 | 含义 | 对应错误 |
| --- | --- | --- |
| **每一个节点** | 必须递归到所有节点，不能只看根 | 只判 `pRoot` 的左右高度 |
| **不超过 1** | `|hl − hr| ≤ 1`，**差 1 也合法** | 写成 `hl == hr` |

### ❌ 两个反例（错误方向正好相反）

**反例 A：根平衡，但子树不平衡 → 会「漏判为 true」**

```
        1
       / \
      2   3
     /     \
    4       5
   /         \
  6           7
```

- 根：`height(左) = 3`、`height(右) = 3` → **相等**
- 但节点 `2`：`height(左) = 2`、`height(右) = 0` → **差 2**，不平衡

只看根 → 返回 `true` ❌

**反例 B：高度差 1，本来就合法 → 会「误判为 false」**

```
    1
   / \
  2   3
     /
    4
```

- 根：`height(左) = 1`、`height(右) = 2` → **差 1 ≤ 1**，合法
- 但 `==` 判据要求相等 → 返回 `false` ❌

## 二、❌ 初版代码的问题

```cpp
bool IsBalanced_Solution(TreeNode* pRoot) {
    if(!pRoot) return true;
    return height(pRoot->left) == height(pRoot->right);   // ① ②
}
int height(TreeNode* root) {
    if(!root) return 0;
    return max(height(root->left),height(root->right))+1;
}
```

| # | 问题 | 后果 |
| --- | --- | --- |
| ① | **只判根节点，没递归左右子树** | 子树不平衡时会漏判为 `true`（反例 A） |
| ② | **`==` 而不是 `abs(...) <= 1`** | 高度差为 1 的合法树被判 `false`（反例 B） |
| ③ | `height` 被反复调用 | 复杂度退化到 `O(n log n)`，链状树 **`O(n²)`** |

## 三、解法一：自顶向下（直观，但慢）

最小修正版 —— 在初版基础上只改两处：

```cpp
bool IsBalanced_Solution(TreeNode* pRoot) {
    if (!pRoot) return true;
    return abs(height(pRoot->left) - height(pRoot->right)) <= 1
        && IsBalanced_Solution(pRoot->left)      // ★ 补上：递归左子树
        && IsBalanced_Solution(pRoot->right);    // ★ 补上：递归右子树
}

int height(TreeNode* root) {
    if (!root) return 0;
    return max(height(root->left), height(root->right)) + 1;
}
```

### ⚠️ 复杂度陷阱

`height()` 在**每一层**都要重新遍历整棵子树：

- 完全平衡树：`T(n) = 2·T(n/2) + O(n)` → **`O(n log n)`**
- 退化成链：每层 `height` 走 `O(n)`，共 `n` 层 → **`O(n²)`**

**面试官几乎一定会追问「能不能 O(n)」** —— 所以这版只能用来口头描述思路，别当最终答案。

## 四、解法二：后序 + `-1` 哨兵（首选，O(n)）

核心想法：**让 `height()` 顺便把「是否平衡」也报上来。**

```cpp
class Solution {
public:
    bool IsBalanced_Solution(TreeNode* pRoot) {
        return getHeight(pRoot) != -1;               // -1 表示「子树失衡」
    }

private:
    // 返回子树高度；若该子树已不平衡，返回 -1
    int getHeight(TreeNode* node) {
        if (!node) return 0;
        int lh = getHeight(node->left);
        if (lh == -1) return -1;                     // ★ 左子树已废，立即短路
        int rh = getHeight(node->right);
        if (rh == -1) return -1;                     // ★ 右子树已废，立即短路
        if (abs(lh - rh) > 1) return -1;             // ★ 当前节点失衡
        return max(lh, rh) + 1;                      // 平衡 → 正常返回高度
    }
};
```

### 三个关键点

**① 判断必须在「后序位置」**

先拿到 `lh`、`rh` 才能算差。放到前序位置就变成「还不知道子树高度就下结论」。

**② `-1` 是「双职责哨兵」**

一个返回值同时承载两个信息：`≥ 0` 表示高度，`-1` 表示「这棵子树已经判定失衡」。这样就不需要额外的 `bool` 参数或成员变量。

**③ 两处 `-1` 短路不能省**

```cpp
if (lh == -1) return -1;   // ★ 少了这句
if (rh == -1) return -1;   // ★ 少了这句
```

少了它们，即使左子树已经失衡，代码还是会白跑完右子树 —— **复杂度退化回 `O(n²)`**，等于没用上剪枝。

**有了短路：每个节点只访问一次 → `O(n)`。**

## 五、解法三：返回 `pair<是否平衡, 高度>`

不想用 `-1` 哨兵（怕和「高度 −1」混淆）的话，显式返回两个值：

```cpp
pair<bool, int> dfs(TreeNode* node) {                // {是否平衡, 高度}
    if (!node) return {true, 0};

    auto [lok, lh] = dfs(node->left);
    if (!lok) return {false, 0};                     // 左不平衡 → 短路
    auto [rok, rh] = dfs(node->right);
    if (!rok) return {false, 0};                     // 右不平衡 → 短路
    if (abs(lh - rh) > 1) return {false, 0};         // 当前节点失衡
    return {true, max(lh, rh) + 1};
}

bool IsBalanced_Solution(TreeNode* pRoot) {
    return dfs(pRoot).first;
}
```

语义更清晰（`bool` 不会被误当成高度），代价是要多写几行。

## 六、必须记住的点

**① 是「每个节点」，不是「根节点」**

平衡是**全树性质**。任何「只看根」的判断都会漏掉深层违规。

**② 是「差 ≤ 1」，不是「相等」**

`abs(hl - hr) > 1` 才判非法。写成 `hl != hr` 就是要求「完美平衡」，比 AVL 还严格。

**③ 别忘了 `abs()`**

写成 `hl - hr > 1` 只挡住了「左边过高」，右边过高（`hl - hr` 为负）就溜过去了。

**④ 后序 + 短路才能 O(n)**

只加哨兵不加短路，复杂度还是 `O(n²)`。

## 七、易错点

1. **只判根，不递归子树** → 漏判（反例 A）
2. **`==` 代替 `abs(...) <= 1`** → 误判（反例 B）
3. **漏 `abs()`** → 只拦一边
4. **只加 `-1` 哨兵、不加短路** → 复杂度退化回 `O(n²)`
5. **在后序位置之前判断** → 还没拿到子树高度就下结论
6. **`height` 的基准定义不统一**（空节点 0 / 叶子 0）→ 判据阈值要对齐；本笔记统一用「空节点 0、叶子 1」

## 八、复杂度

| 解法 | 时间 | 空间 |
| --- | --- | --- |
| 自顶向下（`height` 重复调用） | `O(n log n)`，链状树 **`O(n²)`** | `O(h)` |
| **后序 + `-1` 哨兵 + 短路** | **`O(n)`** | `O(h)` |
| `pair` 版 | `O(n)` | `O(h)` |

## 九、与《验证二叉搜索树》的对照

两道题有一个**共同陷阱**：

| | [[验证二叉搜索树]] | **判断平衡二叉树** |
| --- | --- | --- |
| 约束 | 每个节点的子树值域合规 | 每个节点的左右高度差 ≤ 1 |
| **性质类型** | **全树性质**（每个节点都要满足） | **全树性质** |
| 只看根/只看父子会怎样 | 漏掉深层违规（`10/5,15/6,20`） | 漏掉子树不平衡（反例 A） |
| 共同解药 | **递归到每个节点** | **递归到每个节点** |
| 优秀解法共性 | 后序 + 剪枝（上下界递归 / 中序校验） | 后序 + 剪枝（`-1` 哨兵） |

> **自查口诀**：遇到「每个节点都要满足」的题，写完先问一句 —— **子树我判了吗？**

## 十、面试延伸

- **「AVL 和平衡二叉树什么关系」** → AVL 是「严格平衡」的实现（`|bf| ≤ 1`），本题判的就是 AVL 的合法性前提；见 [[平衡二叉树]]、[[二叉平衡树AVL]]
- **「红黑树是平衡二叉树吗」** → 是，但属于**弱平衡**（树高 `≤ 2log₂(n+1)`），并不满足本题 `|bf| ≤ 1` 的严格标准
- **「这题能不能不用递归」** → 可以，用显式栈做后序遍历 + 记录每个节点高度（用 `unordered_map`），代码复杂度明显上升，面试一般不必
- **「如果要求每层都平衡（完全平衡）呢」** → 再加一个「节点数 = 2^h − 1」的约束，即判断满二叉树
