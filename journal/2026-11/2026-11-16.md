#### 1. `Assets/Scripts/Base/RoleBase.cs`（新建，20:35，44 行）—— 玩家与敌人的公共装配抽到基类

`Player` 和 `EnemyAI` 都要「拿 CharacterController、拿 Animator、找挂枪点、包一层 AnimatorManager」，今天把这五件事提到基类：

```cs
public class RoleBase : MonoBehaviour
{
    protected CharacterController characterController;
    protected Animator animator;
    internal AnimatorManager animatorManager;
    protected AudioSource audioSource;
    protected Transform WeaponPoint;
    internal WeaponItem currWeaponItem;

    protected virtual void Start()
    {
        characterController = GetComponent<CharacterController>();
        animator = GetComponentInChildren<Animator>();
        audioSource = GetComponent<AudioSource>();
        animatorManager = new AnimatorManager(animator);
        FindWeaponPoint(transform);
    }
}
```

三个值得记的点：

- **`protected virtual Start()` 而不是 `abstract`**：Unity 不会调用父类里被隐藏（`new`）的同名 `Start`，子类必须 `protected override void Start()` + `base.Start()` 才能拿到基类装配。写成 `abstract` 就丢掉了 Unity 的消息派发（MonoBehaviour 只认签名匹配，不认 `abstract`），所以只能是 `virtual` + 约定「子类首行 `base.Start()`」。
- **`GetComponentInChildren<Animator>()` 包含自身**：所以 `FightingManager` 在根节点 `AddComponent<Animator>()` 后，这里拿到的是**根上那个空 Animator**，不是角色模型自带的。查过 `TP_CH_*_Cubic.prefab` 三个都没有 `m_AnimatorController` 段（本来就没挂 Animator），所以当前行为正确 —— 但一旦换成带 Animator 的 Low Poly 角色模型，就会变成「根上状态机设参数、子物体状态机播动画」，参数全打空。
- **`WeaponPoint` 找不到时是 `null`，后面 `weapon.transform.parent = WeaponPoint` 会静默把枪设成世界根**（`parent = null` 不抛异常）。这是今天真正炸到的点，见下方缺陷表 ②。

#### 3. `Assets/Scripts/Fightings/FightingManager.cs`（16:30，162 行）—— 按环形布局批量刷敌人

```cs
private void OnSceneCreateEnemy()
{
    Vector3 center = player.transform.position;
    var roleInfos = RoleInfoManager.Instance.GetAllConfig();
    int count = roleInfos.Count * 2;                 // 每种角色刷 2 个 → 5×2 = 10
    for (int i = 0; i < count; i++)
    {
        var roleInfo = roleInfos[i % roleInfos.Count];   // 轮流取，保证每种都有

        GameObject enemy = new GameObject("EnemyAI");
        var enemyAI = enemy.AddComponent<EnemyAI>();
        enemyAI.Init(roleInfo);
        enemy.AddComponent<AudioSource>();

        var cc = enemy.AddComponent<CharacterController>();
        cc.center = new Vector3(0, 1, 0);
        cc.radius = 0.3f;
        cc.height = 1.9f;
        enemyAI.AddComponent<Animator>();            // Component.AddComponent = 加到同一个 GO

        var role = ResourcesMgr.Instance.LoadAndCreateRole(roleInfo.PrefabName);
        role.transform.SetParent(enemy.transform, false);

        float R = Random.Range(30, 80);              // int 重载 → 整数距离 [30,80)
        Quaternion q = Quaternion.AngleAxis(i * 30f, Vector3.up);
        Vector3 position = center + (q * Vector3.forward).normalized * R + Vector3.up * 5f;
        enemy.transform.position = position;         // 天上 5m，靠 CharacterController 落下来
    }
}
```

- **环形撒点**：`AngleAxis(i * 30f, up)` → 每 30° 一个，配合 `Random.Range(30, 80)` 的半径抖动，10 个敌人刚好铺满一圈。⚠️ 但 `i * 30f` 在 `i >= 12` 时会绕回起点，配表超过 6 条（`count > 12`）就会出现同点重叠 —— 现在 5 条安全，扩表必踩。改成 `i * (360f / count)` 就和条数解耦。
- **`enemyAI.AddComponent<Animator>()` 是 `Component.AddComponent`**，等价 `enemy.AddComponent<Animator>()`，挂在同一个 GameObject 上。写法能跑但极易误读成「给 EnemyAI 组件加子组件」。
- **`CharacterController` 参数**：`center=(0,1,0)` + `height=1.9` → 胶囊底部在 `y = 0.05`，抬 5m 落下后脚刚好贴地。📎 [[CharacterController移动 — Move vs SimpleMove]]

**算法两题根因提炼**（详细解析已在笔记里，此处只记结论）：

1. **回文字符串**：`i == j` 只覆盖奇数长度；偶数长度退出时是 `i = j + 1`。穷举 {a,b} 长度 0~6 共 127 串，**偶数回文 14/14 全判错，奇数 0 错**，非回文因为中途就退出而侥幸全对 —— 这种「一半对一半错」的 bug 手工测最容易漏。
2. **最小覆盖子串**：三处独立错误（少 1 / 无解返回整串 / start 与 length 不同步）叠加，6552 组**全错**；改完第一版又引入两处新错，8736 组实测 728 组段错误。**「改一处、对拍一次」比「改三处、跑一遍」快得多**。

**参数/配置**：`RoleInfo.json` 与 `WeaponGun.json` 都在 `Assets/StreamingAssets/Json/`，但 `RoleInfoManager.JsonPath` 写的是绝对路径 `E:\unityproject\...`（11-12 已记为老债，Android 上 `jar:file://` 下同步 `string JsonPath` 这条路本身就不成立）。

## Ideas

- 双武器槽本质是「固定长度环形缓冲 + 当前指针」，`List` 的 `Capacity` 完全不该出现在这里 —— 抽一个 `WeaponSlot` 结构（`WeaponItem[2]` + `index`）能把 ①②⑤ 三类 bug 一次性消灭。
- `RoleBase` 现在只有「装配」，下一步该往「受击 / 死亡 / 血量」长；`RoleInfo.Health` 已经在表里了但代码完全没用 —— 血量是敌人 AI 的第一个真实需求。
- 敌人目前只会自由落体，`EnemyAI.Update` 里只有重力。要动起来得接 FSM 或行为树，📎 [[有限状态机FSM — 手写实现与状态切换边界]] / 📎 [[行为树工程实现 — 黑板、RUNNING 中断与节点生命周期]]
- `OnEnterWeaponArea` 每帧对**所有**武器算一次 `Vector3.Distance`，7 把枪无所谓，上百把就该上空间划分（📎 [[A星寻路算法]] 里的网格思想或八叉树）。
- 环形撒点的 `i * 30f` 应该换成 `360f / count`，让「刷几个」和「怎么排」解耦。
