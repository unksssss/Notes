```csharp
// BeCreatedGo.cs —— 三个生命周期各打一条日志，顺带打 activeSelf
private void Awake()    { Debug.Log("Awake"); }
private void Start()    { Debug.Log("Start"); }
private void OnEnable() { Debug.Log("OnEnable: " + gameObject.activeSelf); }
```

```csharp
// CreateGo.cs
public BeCreatedGo prefab;

void Start() {
    var go = Instantiate(prefab);
    //awake 在实例化时就会调用一次
    go.enabled = false;
}
```

**为什么这么写**：这是为了用**日志顺序**实证三件事 —— ① `Instantiate` 是不是同步执行 `Awake`；② 实例化后立刻 `enabled = false` 还能不能拦住 `OnEnable` / `Start`；③ `activeSelf` 与 `enabled` 到底谁管谁。

**实测结论**：`Instantiate` **同步执行 Awake**（`Instantiate` 返回前 Awake 已跑完），紧接着的 `enabled = false` **拦不住已经发生的 Awake 与 OnEnable**，只能把 `Start` 延后到组件重新启用那一刻。完整的分阶段执行顺序与两个开关的分界见 📎 [[MonoBehaviour生命周期与SetActive的坑]]。

##### 坑一：`BundledCopyOption` 默认 `None` → 内置包缺三件套

**现象**

```
file:///.../Assets/StreamingAssets/yoo/DefaultPackage/DefaultPackage_2026-10-13-962.hash → 404
→ InitializePackageOperation 失败 → FsmInitializePackage.cs:99 只报 warning，流程静默中断
```

**根因（挖到源码）**

| 层 | 事实 | 源码位置 |
| --- | --- | --- |
| ① | `BuiltinFileSystem` 初始化**必须**读到 `<Package>_<Version>.hash`；`File.Exists` 不满足就发 `file://` 请求，404 直接 `SetError` | `RequestBuiltinPackageHashOperation.cs:44-63` |
| ② | HostPlayMode 下 `CopyBuiltinPackageManifest = true`，会**无条件**拷贝内置 version / manifest / hash；注释写明「只负责拷贝文件，不负责校验」 | `FsmInitializePackage.cs:68` / `CopyBuiltinPackageManifestOperation.cs:79-105` |
| ③ | 打包窗口的 `BundledCopyOption` **默认值就是 `None`** → 不拷 version/manifest/hash，也不生成 `BuiltinCatalog` | `BuildParameters.cs:95`、`TaskCopyBundledFiles_SBP.cs:19`、`TaskCreateCatalog_SBP.cs:18` |

StreamingAssets 里当时已有的 version + bytes 是**手动拷的**，正好漏了 hash —— 这是「手动补文件」的必然结局。

**关键：补 hash 只是第一层。** `BuiltinFileSystem.OnCreate`（`BuiltinFileSystem.cs:348-356`）会创建 `BuiltinBundleCache`，其 `BBCInitializeOperation` → `LoadBuiltinCatalogOperation` **强依赖 `BuiltinCatalog.bytes`**。只补 hash 能过初始化，**加载资源时照样挂**。

**修复**：AssetBundle Builder 的「内置资源拷贝选项」改为 **`ClearAndCopyAll`** 重新构建 → 自动拷全 `version + <ver>.bytes + <ver>.hash + 43 个 bundle + BuiltinCatalog.json/bytes`。

#### 算法详记：验证二叉搜索树（剑指 98 / LeetCode 98）

**题面**：判断二叉树是否为有效 BST —— 左子树**所有**节点严格小于根、右子树**所有**节点严格大于根，且左右子树自身也是 BST。

**❌ 初版代码：三层问题，没有一个分支是对的**

```cpp
bool isValidBST(TreeNode* root) {
    if(root) return true;                                    // ① 少写 `!`
    return isValidBST(root->left)&&isValidBST(root->right);   // ② 只在 nullptr 时执行
    if(root->val>root->left->val&&root->val<root->right->val) return true;  // ③ 死代码
    else return false;
}
```

| 层 | 问题 | 后果 |
| --- | --- | --- |
| 控制流 | ① `if(root)` **少写 `!`** | 非空 → 恒 `true`，任何树都判通过；空 → 走 ② 对 `nullptr` 解引用崩溃 |
| 控制流 | ② 递归只在 `root == nullptr` 时执行 | 必然空指针解引用，`&&` 两侧都跑不到 |
| 不可达 | ③ 写在 `return` 之后 | 永远执行不到，纯死代码 |
| 算法思想 | 只比父子 | **跨层约束丢失** |
| 算法思想 | 判完直接 `return`，不递归子树 | 即使父子都对，孩子自己的子树也没校验 |
| 健壮性 | 访问 `root->left->val` 前不判空 | 叶子节点直接崩 |

**根因（唯一核心认知）**：BST 的约束是**整棵子树级**。定义写的是「左子树**所有**节点 < 根」，所以每个节点能取什么值由**所有祖先共同决定** —— 必须落在祖先逐步收窄出来的开区间里。

**经典反例**：

```
       10
      /  \
     5    15
         /  \
        6    20
```

每条父子边都合法（`10>5` `10<15` `15>6` `15<20`），但 `6` 在 `10` 的右子树里却 `6 < 10` → 不是 BST。只比父子的判据**必然误判**。

**✅ 解法一：上下界区间递归（首选）**

```cpp
bool check(TreeNode* node, long long low, long long high) {
    if (!node) return true;
    if (node->val <= low || node->val >= high) return false;   // ★ 等号也要拒绝
    return check(node->left,  low, node->val)                  // 往左只收紧上界
        && check(node->right, node->val, high);                // 往右只收紧下界
}
```

**⚠️ Windows 专属边界坑**：题解常写 `LONG_MIN / LONG_MAX`，LeetCode（Linux LP64）能过，**Windows 会挂** —— LLP64 下 `long` 只有 32 位，`LONG_MIN == INT_MIN`；节点值恰为 `INT_MIN` 时 `INT_MIN <= INT_MIN` 成立 → **合法 BST 被误判 false**。用 `LLONG_MIN / LLONG_MAX` 或 `numeric_limits<long long>`。

**✅ 解法二：中序递归（BST 中序 = 严格升序）**

```cpp
bool inOrder(TreeNode* node, TreeNode*& prev) {      // ★ 引用传参
    if (!node) return true;
    if (!inOrder(node->left, prev)) return false;
    if (prev && prev->val >= node->val) return false; // 必须严格递增
    prev = node;
    return inOrder(node->right, prev);
}
```

`prev` 必须是 `TreeNode*&` —— 和 📎 [[二叉搜索树转双向链表]] **完全同一个坑**：值传递时每层各持一份副本、返回即销毁，外层 `prev` 永远 `nullptr` → 校验失效、函数恒 true。「**谁需要把改动带出去，谁就加 `&`**」第二次登场。

**✅ 解法三：迭代中序（防深递归爆栈）**

```cpp
while (cur || !st.empty()) {
    while (cur) { st.push(cur); cur = cur->left; }   // 向左压到底
    cur = st.top(); st.pop();
    if (prev && prev->val >= cur->val) return false;
    prev = cur;
    cur = cur->right;
}
```

**三解法对比**

| | 上下界递归 | 中序递归 | 中序迭代 |
| --- | --- | --- | --- |
| 时间 / 空间 | O(n) / O(h) | O(n) / O(h) | O(n) / O(h) |
| 需要 `TreeNode*&` | 否 | **是** | 否 |
| 边界陷阱 | **有**（`LLONG_MIN`） | 无 | 无 |
| 推荐度 | ★★★ 首选 | ★★ | ★★ 防爆栈 |

**必须记住的三条**
1. **BST 约束是子树级**，不是父子级 —— 所有错误判据的根源
2. **必须严格**：`<= low || >= high` 两侧等号都拒绝；中序写 `>=` 而非 `>`
3. **上下界单向收紧**：往左只收上界、往右只收下界；两侧都收会把合法子树误判非法
