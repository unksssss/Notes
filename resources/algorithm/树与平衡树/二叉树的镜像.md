# 二叉树的镜像

对应 **剑指 Offer 27 / LeetCode 226**。

> 题面：操作给定的二叉树，将其变换为源二叉树的镜像。
> 即：把每个节点的**左右子树互换**，返回（通常就是原根节点）。

## 一、核心认知：镜像改的是「结构」，不是「值」

镜像的本质只有一句话：

> **对每个节点做一次 `swap(left, right)`。**

这是**结构变换** —— 交换的是左右孩子的**指针**，树的**形状**随之翻转。

**❌ 交换 `a->val` 和 `b->val` 是错的**：那只是给两个格子换了标签，树的形状一点没动。

而且「交换值」这个思路有个致命盲区 —— 单链树：

```
   1            镜像后            1
  /              ────►             \
 2                                 2
```

只有一个节点、**根本没有第二个值可换**，但**结构仍然需要翻转**（`left` 变成 `right`）。所以「交换值」连问题都没描述对。

## 二、核心认知二：单参骨架，不是双参

本题和 [[对称的二叉树]] 最容易串味，务必分清：

| | 判对称 LC101 | **求镜像 LC226** |
| --- | --- | --- |
| 递归签名 | `bool isMirror(TreeNode* a, TreeNode* b)` | `TreeNode* Mirror(TreeNode* root)` |
| 参数个数 | **双参** | **单参** |
| 处理单位 | **成对**处理 `(a, b)` | **每个节点自己**操作 |
| 动作 | 比较 + 交叉配对 | `swap(left, right)` |
| 读写 | 只读 | 写（改指针） |

**为什么镜像不需要配对**：因为它是「每个节点各自交换左右孩子」，是**逐节点的局部操作**，不需要另一个节点做参照。

记忆点：**判对称要有两个东西才能「照镜子」，求镜像只要自己「翻个面」。**

## 三、❌ 初版思路的问题（用判对称骨架 + 交换值）

初版思路：仿照判对称，把 `root->left` / `root->right` 成对入队，每次弹出一对 `a`、`b` 做处理。

| # | 问题 | 后果 |
| --- | --- | --- |
| 1 | **交换 `a->val` / `b->val` 而非指针** | 根本性错误：树形完全没变，只换了标签；单链树无从下手 |
| 2 | **`aLast` / `bLast` 初值 `nullptr` 就解引用** | 单链树第一次进入循环 `aLast` 仍为 `nullptr`，`aLast->right = a` **立即崩溃**；任何左右不齐的树必崩 |
| 3 | **`bLast->left = b;` / `aLast->right = a;` 意图不明** | 把节点挂到「上一个节点」身上，会**覆盖它原有的子树** —— 结构性摧毁原树 |
| 4 | **`if(!a&&!b) continue;` 是死代码** | 上一行 `if(!a||!b)` 已涵盖（`!a\|\|!b` ⊇ `!a&&!b`），永远走不到 |
| 5 | **`queue<TreeNode*> queue;`** | 变量名遮蔽 `std::queue` 模板名，`using namespace std` 下危险 |
| 6 | **单参问题用了双参骨架** | 骨架错位，这是代码跑偏的根源 |

## 四、解法一：递归（首选）

```cpp
class Solution {
public:
    TreeNode* Mirror(TreeNode* pRoot) {
        if (!pRoot) return nullptr;              // 空节点直接返回
        swap(pRoot->left, pRoot->right);         // ★ 交换左右孩子【指针】
        Mirror(pRoot->left);                     // 递归翻转两棵子树内部
        Mirror(pRoot->right);
        return pRoot;
    }
};
```

### 必须记住的点

**① 交换的是指针，不是值**

`swap(pRoot->left, pRoot->right)` —— 参数是**两个指针字段**。写成交换 `val` 就完全跑偏了。

**② `swap` 放递归前还是后都行**

因为左右两棵子树**都要翻**，先后顺序不影响最终结果。区别只在于递归时访问的是「交换后的 left/right」（即原来的 right/left），但两棵都会被翻到。

**③ 不需要配对，不需要 `aLast` / `bLast`**

引入「上一个节点」这类状态，说明骨架用错了。

## 五、解法二：迭代（队列 / 栈）

```cpp
// BFS 版
TreeNode* Mirror(TreeNode* pRoot) {
    if (!pRoot) return nullptr;
    queue<TreeNode*> q;
    q.push(pRoot);
    while (!q.empty()) {
        TreeNode* node = q.front(); q.pop();
        swap(node->left, node->right);
        if (node->left)  q.push(node->left);     // 判空后再入队
        if (node->right) q.push(node->right);
    }
    return pRoot;
}
```

把 `queue` 换成 `stack` 就是 DFS 版，逻辑完全一致 —— 因为「每个节点 swap 一次」这个操作**与遍历顺序无关**。这正是本题适合迭代的原因：**不需要回溯状态**。

**入队前必须判空**，否则 `nullptr` 被推进队列，后面 `node->left` 虽然还能跑（swap 空指针字段的地址是安全的，因为 `node` 本身非空），但会白白膨胀队列；不如入队前就挡掉。

## 六、易错点

1. **交换 `val` 而不是交换指针** —— 最根本的错，且在某些简单例子上「看起来是对的」
2. **用「判对称」的双参成对骨架** —— 串味，且会引入 `aLast` / `bLast` 这种不该有的状态
3. **`aLast` / `bLast` 初值 `nullptr` 未判空就解引用** → 崩溃
4. **把节点挂回「上一个节点」的 left/right** → 覆盖原子树，结构性摧毁
5. **写 `if(!a&&!b)` 这类死分支** → 说明上一行的条件没想清楚
6. **变量名遮蔽标准库模板名**（`queue` / `stack` 作变量名）

## 七、复杂度

| 维度 | 值 |
| --- | --- |
| 时间 | **O(n)**，每个节点恰好 `swap` 一次 |
| 空间 | 递归 **O(h)**；队列 / 栈最坏 **O(n)** |
| 原地性 | ✅ 只改指针，`O(1)` 额外节点 |

## 八、面试延伸

- **对合性（自反）**：镜像操作是**对合运算** —— 对镜像后的树再做一次 `Mirror` 就回到原树。这是「交换」类操作的特征
- **中序序列反序**：镜像后树的中序遍历结果，正好是原中序遍历的**逆序**。反过来，如果一棵树**对称**，它的中序遍历就是**回文**（对应 [[对称的二叉树]] 里「回文是必要条件」那条）
- **「用镜像实现判对称」**：先 `Mirror` 一棵树再判两棵树是否相同（LC100）—— 思路直观但要 O(n) 额外空间且破坏输入，**面试不推荐**
- **「判断一棵树能不能通过若干次左右交换变成另一棵树」** → 递归判「子树集合相同」，本质是判断两棵树是否**同构**
- **「N 叉树的镜像」** → 反转孩子数组：`reverse(children.begin(), children.end())`
