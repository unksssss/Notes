# 事件总线实现 — 订阅令牌与发布期快照

## 一、需求

```csharp
SubscriptionToken Subscribe<T>(Action<T> callback);   // 订阅，返回 token
bool Unsubscribe(SubscriptionToken token);            // 取消，返回是否成功
void Publish<T>(T data);                              // 依次广播给所有订阅者
```

约束：

1. 发布前**确定订阅数量**（本次只发给这些人）
2. 发布过程中**新增的订阅，下次发布才执行**
3. 异常处理——不能因为一个订阅者炸了影响其他人

---

## 二、四个关键决策

| 决策 | 选择 | 理由 |
| --- | --- | --- |
| 新订阅如何不参与本次发布 | 发布前锁定 `count`，只遍历 `[0, count)` | 新订阅追加到末尾，天然落在边界外。比 `ToArray()` 快照省掉每次的数组分配 |
| 发布中取消怎么处理 | 只标记 `IsActive = false`，**不 RemoveAt** | `RemoveAt` 会让后面元素前移，正在遍历的索引直接错位 |
| 墓碑何时清理 | 只在**非发布中**压缩（`_publishDepth == 0`） | 压缩会移动元素，遍历中做必炸 |
| 订阅者抛异常 | 捕获后继续，并抛给 `OnSubscriberException` | 广播不能因一个模块的 bug 全线瘫痪，但也不能静默吞掉 |

## 三、完整实现

```csharp
using System;
using System.Collections.Generic;

public readonly struct SubscriptionToken : IEquatable<SubscriptionToken>
{
    internal readonly Type EventType;
    internal readonly int Id;

    internal SubscriptionToken(Type eventType, int id)
    {
        EventType = eventType;
        Id = id;
    }

    public bool IsValid => EventType != null;

    public bool Equals(SubscriptionToken other) => EventType == other.EventType && Id == other.Id;
    public override bool Equals(object obj) => obj is SubscriptionToken o && Equals(o);
    public override int GetHashCode() => EventType == null ? 0 : EventType.GetHashCode() * 397 ^ Id;
    public override string ToString() => EventType == null ? "Token(invalid)" : $"{EventType.Name}#{Id}";
}

public sealed class EventBus
{
    private abstract class Entry
    {
        public int Id;
        public bool IsActive = true;
        public abstract void Clear();      // 断开委托引用，避免阻止 GC
    }

    private sealed class Entry<T> : Entry
    {
        public Action<T> Callback;
        public override void Clear() => Callback = null;
    }

    private sealed class Bucket
    {
        public readonly List<Entry> Entries = new List<Entry>();
        public int Dead;
    }

    private const int CompactThreshold = 8;

    private readonly Dictionary<Type, Bucket> _buckets = new Dictionary<Type, Bucket>();
    private int _nextId;
    private int _publishDepth;

    /// <summary>订阅者抛异常时回调，用于日志 / 上报。</summary>
    public Action<Exception> OnSubscriberException;

    public SubscriptionToken Subscribe<T>(Action<T> callback)
    {
        if (callback == null) throw new ArgumentNullException(nameof(callback));

        var type = typeof(T);
        if (!_buckets.TryGetValue(type, out var bucket))
        {
            bucket = new Bucket();
            _buckets.Add(type, bucket);
        }

        var entry = new Entry<T> { Id = ++_nextId, Callback = callback };
        bucket.Entries.Add(entry);          // 追加到末尾
        return new SubscriptionToken(type, entry.Id);
    }

    public bool Unsubscribe(SubscriptionToken token)
    {
        if (!token.IsValid) return false;
        if (!_buckets.TryGetValue(token.EventType, out var bucket)) return false;

        var entries = bucket.Entries;
        for (int i = 0; i < entries.Count; i++)
        {
            var entry = entries[i];
            if (entry.Id != token.Id) continue;

            if (!entry.IsActive) return false;      // 重复取消 → false

            entry.IsActive = false;                 // 只标记，不移动
            entry.Clear();
            bucket.Dead++;

            if (_publishDepth == 0 && bucket.Dead >= CompactThreshold)
                Compact(bucket);

            return true;
        }
        return false;                               // token 不存在 → false
    }

    public void Publish<T>(T data)
    {
        if (!_buckets.TryGetValue(typeof(T), out var bucket)) return;

        var entries = bucket.Entries;
        int count = entries.Count;      // ★ 发布前锁定订阅数量

        _publishDepth++;
        try
        {
            for (int i = 0; i < count; i++)
            {
                var entry = entries[i];
                if (!entry.IsActive) continue;           // 发布中被取消 → 跳过

                try
                {
                    ((Entry<T>)entry).Callback?.Invoke(data);
                }
                catch (Exception ex)
                {
                    try { OnSubscriberException?.Invoke(ex); }
                    catch { /* 处理异常时又抛，忽略，避免中断广播 */ }
                }
            }
        }
        finally
        {
            _publishDepth--;
        }

        if (_publishDepth == 0 && bucket.Dead >= CompactThreshold)
            Compact(bucket);
    }

    private void Compact(Bucket bucket)
    {
        var entries = bucket.Entries;
        for (int i = entries.Count - 1; i >= 0; i--)     // 倒序删，避免索引前移
        {
            if (!entries[i].IsActive) entries.RemoveAt(i);
        }
        bucket.Dead = 0;
    }
}
```

## 四、验证用例

```csharp
var bus = new EventBus();
bus.OnSubscriberException = e => Console.WriteLine($"异常: {e.Message}");

bus.Subscribe<int>(x => Console.WriteLine($"A: {x}"));

bool added = false;
bus.Subscribe<int>(x =>
{
    Console.WriteLine($"B: {x}");
    if (!added) { added = true; bus.Subscribe<int>(y => Console.WriteLine($"D(新增): {y}")); }
});

SubscriptionToken cToken = default;
cToken = bus.Subscribe<int>(x =>
{
    Console.WriteLine($"C: {x}");
    bus.Unsubscribe(cToken);            // 发布中取消自己
});

var badToken = bus.Subscribe<int>(x => throw new InvalidOperationException("boom"));

Console.WriteLine("=== 第 1 次 ===");
bus.Publish(1);
Console.WriteLine("=== 第 2 次 ===");
bus.Publish(2);
Console.WriteLine($"重复取消: {bus.Unsubscribe(badToken)} {bus.Unsubscribe(badToken)}");
```

预期输出：

```
=== 第 1 次 ===
A: 1
B: 1
C: 1
异常: boom
=== 第 2 次 ===
A: 2
B: 2
D(新增): 2
重复取消: True False
```

第 1 次 D 没有输出（在 `count` 边界外）；第 2 次 C 消失、D 出现。

## 五、三个易被追问的实现细节

**① `count` 必须在进入循环前取**

若写成 `i < entries.Count`，新增订阅当次就会被执行，直接违反需求。

**② 用 `Entry<T>` 而不是直接存 `Delegate`**

按 `typeof(T)` 分桶后，桶内元素必然是 `Entry<T>`，强转安全。泛型 `Action<T>` 存储不需要装箱，调用也是强类型委托。

**③ 嵌套发布（回调里再 Publish 同一 topic）**

`_publishDepth` 变 2，内层各自取新的 `count`，互不影响。内层结束时回到 1 **不压缩**——压缩只由最外层触发，所以不会打乱外层索引。

## 六、可能被追问的六个问题

| 问 | 答 |
| --- | --- |
| 为什么不用 C# 的 `event` 关键字 | `event` 编译期绑定、一个类只能声明固定几个；外部无法触发，也不能按 token 精确取消 |
| 发布中取消的订阅本次还执行吗 | 本实现是**不执行**（检查 `IsActive`）。「本次执行完、下次不执行」也合理，**关键是定义清楚** |
| token 为什么用 struct | 每次订阅不产生堆分配。必须实现 `IEquatable`，否则默认 `Equals` 会装箱 |
| `Unsubscribe` 为什么 O(n) | 只在同一 topic 的订阅里线性查找，n 通常很小。要 O(1) 就再维护 `Dictionary<(Type,int), Entry>` |
| 多线程发布怎么办 | 当前是主线程专用。多线程要么整体 `lock`，要么每次发布前 `ToArray()` 真快照（代价是分配） |
| 订阅不取消会怎样 | 委托持有目标对象引用 → **对象无法被 GC**，典型泄漏。token 要存下来，在 `OnDestroy` 里退订 |

---

## 七、可延伸的设计

- **优先级**：`Subscribe` 加一个 `priority` 参数，插入时按序放到合适位置（或发布时排序）
- **订阅者超时/降频**：高频事件（每帧）可以合并——同一帧内多次 `Publish` 只处理最后一条
- **弱引用订阅**：避免忘记退订导致泄漏，代价是每次发布要检查 `WeakReference.IsAlive`
- **按字符串 topic**：更灵活但拼写错误无编译检查；按类型分桶是更安全的默认
