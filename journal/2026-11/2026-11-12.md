配套的基类（`JsonManager.cs`，11-02 写的，今天才第一次有子类）：

```cs
public abstract class JsonManager<T, U>
    where T : class, IJsonData, new()
    where U : JsonManager<T, U>, new()
{
    private static JsonManager<T, U> instance;

    public static JsonManager<T, U> Instance
    {
        get
        {
            if (instance == null)
            {
                instance = new U();          // 自引用泛型 → 用 U 造自己
                instance.LoadConfig();
            }
            return instance;
        }
        set => instance = value;             // 对外可写，单例可被覆盖
    }

    protected abstract string JsonPath { get; }   // 每张表覆盖这一个属性
}
```

- **为什么用 `JsonManager<T,U>` 两个泛型参数**：C# 的静态字段属于**闭合泛型类型**，`JsonManager<WeaponConfig>` 和 `JsonManager<SkillConfig>` 各有一份 `instance`。但如果只写一个参数 `JsonManager<T>`，`new()` 造出来的就是基类自己，没法调子类的 `JsonPath`。把 `U`（`this` 类型）也当泛型参数传进来（CRTP / 自引用泛型约束），才能做到「每个表一个单例 + 单例是子类实例 + 路径由子类覆盖」。
- **加一张新表 = 一个 5 行子类**，读表、建字典、`GetConfig` / `GetAllConfig` 全部复用。
- ⚠️ **值仍然是绝对路径**：`E:\unityproject\Empty\...` 只有本机 Editor 能跑，打包后这个盘符根本不存在（详见 Part D ⑨）。**抽象属性把路径「抽出来」了，但没让路径「变对」** —— 配置化的收益是「改一处」，不是「自动正确」。

```cs
private void Start()
{
    player = FindAnyObjectByType<Player>();

private void OnSceneCreateGun()
{
    var configList = WeaponConfigManager.Instance.GetAllConfig();
    for (int i = 0; i < WeaponPoints.childCount; i++)          // 7 个 Weapoint_0~6
    {
        int index = Random.Range(0, configList.Count);          // int 重载，上界独占，这里是对的
        var go = ResourcesMgr.Instance.LoadAndCreate(ResourcesPath.Weapons, configList[index].PrefabName);
        go.transform.position = WeaponPoints.GetChild(i).position;
        go.transform.rotation = Quaternion.Euler(0, 0, 90f);    // 让枪「躺」在地上

        var rb = go.AddComponent<Rigidbody>();
        rb.useGravity = true;
        rb.collisionDetectionMode = CollisionDetectionMode.ContinuousDynamic;

        var boxCollider = go.GetComponent<BoxCollider>() ?? go.AddComponent<BoxCollider>();

        var weaponItem = go.AddComponent<WeaponItem>();
        weaponItem?.Init(configList[index]);
        AllWeaponItems.Add(weaponItem);
    }
}

private void Update() => OnEnterWeaponArea();   // 每帧全表两遍遍历
```

- **`CollisionDetectionMode.ContinuousDynamic`**：地面上的枪被玩家 `CharacterController` 推挤时，离散检测（`Discrete`）会在快速相对运动下直接穿过去，连续动态检测按扫掠体积算，代价是更高 CPU。7 把枪的量级完全付得起。
- **`Quaternion.Euler(0,0,90)`** 是把枪的 Z 轴转到水平 —— 美术资源默认朝向是「枪口朝前」，平放要绕 Z 转 90°。
- `OnEnterWeaponArea()` 用 `Vector3.Distance` 对 `AllWeaponItems` 全表 + `AreaWeaponItems` 全表各扫一遍（2m 阈值），通过 `out bool` 把「增/删是否发生」回传给外层，再决定要不要 `OnAreaWeaponChanged?.Invoke(...)`。7 把枪没问题，量级一上去就是今天面经里那道「大地图大量可拾取物怎么快速查询」的原型。

- **`SetCurrentNum(BulletNum)` 是今天新加的关键一行**：`WeaponItem` 是 MonoBehaviour 实例，`currNum` 是运行时状态。切走再切回来如果不重置，UI 上写的是 `BulletNum/BulletNum`（满弹），实际 `currNum` 还是上一轮打剩的 —— 显示与数据两张皮。
- **`Find("RL_01_Projectile")?.gameObject`** 加了空条件运算符（14:38 那轮指出的 NRE 已修）：步枪 prefab 没这个节点时 `Find` 返回 null，`?.` 让它安静跳过。
- **`Find("Muzzle")` 仍然没判空** —— 枪口是开火的唯一依赖，缺了必炸，这里反而该 `Debug.Assert` 而不是静默。
- **三级路径（关旧 → 查缓存 → 读表新建）** 是「武器实例复用」的最小实现：同一把枪第二次切回来不再 `Instantiate`，动画控制器只换 `runtimeAnimatorController` 引用。

#### 4. `UI/UIFightingView.cs` — 订阅开火事件、刷武器格

```cs
private void Start()
{
    Player.OnFire += OnFire;      // 静态事件，订阅

private void OnDestroy()
{

private void OnFind()
{
    weapon01 = transform.Find("Bottom/Weapon01").GetComponent<Image>();

    Btn_Crouch = transform.Find("Btn_Crouch").GetComponent<Button>();
    Btn_Fire   = transform.Find("Btn_Fire").GetComponent<Button>();
    txt_ResidueNum = transform.Find("Top/Txt_ResidueNum").GetComponent<Text>();
    txt_KillNum    = transform.Find("Top/Txt_KillNum").GetComponent<Text>();
    crosshair = transform.Find("Crosshair").GetComponent<Animator>();
    // 4 个按钮 onClick.AddListener(...)
}

public void SetWeapon01(Sprite _sprite, int num)
{
    weapon01.sprite = _sprite;
    Text text = weapon01.gameObject.GetComponentInChildren<Text>();
    text.text = $"{num}/{num}";
    currText = text;                       // 记住「当前显示的是哪一格」
}

public void SetWeapon02(Sprite _sprite, int num)
{
    weapon01.sprite = _sprite;             // ← 复制粘贴，应该是 weapon02
    Text text = weapon02.gameObject.GetComponentInChildren<Text>();
    text.text = $"{num}/{num}";
    currText = text;
}
```

- **`OnFire` 是 `static event`**，UI 在 `Start` 订阅、`OnDestroy` 退订，是正确姿势。但静态事件的持有者是**类型**而不是场景对象 —— 只要退订漏一次，`UIFightingView` 实例连同整棵 Canvas 就被委托链钉住（今天 Day 65 的 S9 就是这题）。
- **`currText` 的设计**：开火时只改「当前那一格」的文本，所以 `SetWeapon01/02` 各自把自己那格的 `Text` 记进 `currText`，`SetCurrText` 直接写。省一次查找，代价是「当前格」与「当前武器」两个状态分开维护、可能不同步。
- **`OnFind` 全是 `transform.Find("硬路径")`**：任一节点改名/换层级就是运行期 NRE，且报错指在 `UIFightingView` 上，看不出是预制体结构变了。这种写法在 `[SerializeField]` 能直接拖引用的 UGUI 场景里没有收益。

#### ⑨ 配表路径写死 `E:\` 绝对路径（今日最重）

**目标文件**：`Assets/Scripts/File/WeaponConfigManager.cs`（16:10 新建）

```cs

    => @"E:\unityproject\Empty\Assets\StreamingAssets\WeaponGun.json";
```

#### ⑮ `OnSceneCreateGun` 的两处隐式假设

```cs
var rb = go.AddComponent<Rigidbody>();          // 假设 prefab 没有 Rigidbody
```

#### ⑯ `JsonManager.Instance` 的懒加载会把异常吞成空表

```cs
if (instance == null)
{
    instance = new U();          // ← 先赋值
    instance.LoadConfig();       // ← 后加载，这里抛异常
}
```

`LoadConfig()` 抛异常（文件不存在 / JSON 格式错 / 字段类型不符）时，`instance` **已经不为 null**。下一次访问 `Instance` 时 `if` 不成立，直接返回这个**字典是空的**实例，`GetConfig` 全部返回 null，且**不会再报第二次错**。表现：第一次报一条异常，之后一路 NRE，日志上看不出根因。

**修复方向**：先 `var tmp = new U(); tmp.LoadConfig(); instance = tmp;`，或把 `LoadConfig` 包 try/catch 并置 `instance = null` 让下次重试。
