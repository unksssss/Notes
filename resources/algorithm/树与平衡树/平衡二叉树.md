# 平衡二叉树

## 一、核心认知

**「平衡二叉树」不是一个具体的树，而是一个家族概念。** 它的本质是在 BST 之上**附加一条「高度约束」**：

> 让树高始终保持在 `O(log n)`，从而避免 BST 退化成链。

三个概念的关系：

```
二叉搜索树（值序规则）  +  自平衡机制（高度约束）  =  平衡二叉搜索树
```

**判据换算**：平衡二叉树一定是 BST（极少数特例除外），但 BST 不一定是平衡的。

> ⚠️ **术语歧义**：国内教材（严蔚敏《数据结构》）直接把「平衡二叉树」定义为 **AVL 树**（`|bf| ≤ 1`）。所以**面试里说「平衡二叉树」大概率指 AVL**，但工程/学术语境下它是家族统称。答题时最好先界定：「严格意义的平衡二叉树指 AVL，泛指则包括红黑树等」。

## 二、为什么需要平衡

BST 的麻烦不在「不够有序」，而在 **「可能退化」**。

同一组数据 `1..7`，插入顺序决定树形：

```
顺序插入 → 高度 7（退化成链）        平衡后 → 高度 3
        1                                4
         \                              / \
          2                           2   6
           \                          / \ / \
            3                       1  3 5  7
             \
              4 ...
```

| | 退化链 | 平衡树 |
| --- | --- | --- |
| 树高 | `n` | `log n` |
| 查找/插入/删除 | **O(n)** | **O(log n)** |

**平衡树要做的，就是在「保持 BST 有序性」的前提下，「动态地把形状拉平」。**

## 三、衡量指标：平衡因子

```
bf(node) = height(node->left) - height(node->right)
```

- **AVL 的严格平衡**：每个节点 `|bf| ≤ 1`（只能取 −1、0、1）
- **红黑树的弱平衡**：不直接约束 `bf`，而是约束「黑高相等」+「禁红红」，间接得到 `树高 ≤ 2log₂(n+1)`

⚠️ **是高度之差，不是节点数之差** —— 这是面试常考的细节。

## 四、平衡强度是一条谱系

「平衡」没有唯一标准，从严格到宽松分四档：

| 类型 | 定义 | 代表 | 树高上界 |
| --- | --- | --- | --- |
| **严格平衡** | 每节点 `\|bf\| ≤ 1` | **AVL** | `1.44·log₂n` |
| **弱平衡 / 近似平衡** | 只保证 `树高 ≤ c·log₂n` | **红黑树** | `2·log₂(n+1)` |
| **随机化平衡** | 靠随机优先级达到期望平衡 | **Treap** | 期望 `O(log n)` |
| **均摊平衡** | 单次可能 `O(n)`，均摊 `O(log n)` | **Splay** | 均摊 `O(log n)` |

**取舍逻辑**：

- 越严格 → 树越平 → **查询越快**，但**写入时要转的次数越多**
- 越宽松 → 越「懒」 → **写入越快**，但查询路径略长

所以：**读多写少选 AVL，读写均衡选红黑树**。工程上红黑树用得最多（C++ `map/set`、Java `TreeMap`、Linux 内核 `rbtree`）。

## 五、靠什么维持平衡：旋转

所有自平衡 BST 的核心手段都是**旋转**：

> **旋转只改变局部结构，中序遍历顺序完全不变 → BST 性质自动保持。**

右旋示例：

```
      y                x
     / \              / \
    x   C    ──►     A   y
   / \                  / \
  A   B                B   C
```

中序遍历都是 `A x B y C`，一个节点都没动位置（相对次序），但高度变了。

这就是「**在不破坏有序性的前提下改形状**」—— 平衡树的全部魔法都在这里。

- AVL 的四型旋转（LL / RR / LR / RL）与「最小失衡子树」见 [[二叉平衡树AVL]]
- 红黑树用「颜色 + 旋转」把修复次数压到常数级，见 [[红黑树]]

## 六、与「完全二叉树」「BST」的区别：三个正交维度

今天连着接触的三个概念，正好是**三个互相独立的维度**：

| 概念 | 约束维度 | 一句话 | 目的 |
| --- | --- | --- | --- |
| [[完全二叉树]] | **形状** | 层序靠左连续、中间无空洞 | 能数组连续存储 |
| [[二叉搜索树BST]] | **值序** | 左子树全 < 根 < 右子树全 | 能二分查找 |
| **平衡二叉树** | **高度** | 树高控制在 `O(log n)` | 不退化 |

**三者可以两两组合**：

| 组合 | 实例 | 说明 |
| --- | --- | --- |
| 完全 + 平衡 | **堆** | 树高 `⌊log₂n⌋+1`，天然最优平衡，但**不是 BST** |
| BST + 平衡 | **AVL / 红黑树** | 这才是通常说的「平衡二叉搜索树」 |
| 完全 + BST + 平衡 | 理论最优 | 动态维持「完全」代价太高（插入删除可能整层平移），实际不做 |

⚠️ 特别注意：**完全二叉树可以极不平衡**（比如所有节点都挂在左斜方向但层序连续），**平衡二叉树也可以完全不是完全二叉树**（AVL 的最后一层节点不要求靠左）。两者毫无推导关系。

## 七、常见误区

1. **以为「平衡二叉树」是某种具体树** → 是家族概念；但国内教材常把 AVL 直接叫「平衡二叉树」，面试要按语境说清
2. **以为平衡 = 左右节点数相等** → 是**高度差**，不是节点数差
3. **和完全二叉树混淆** → 完全二叉树管形状、平衡二叉树管高度，**正交**
4. **以为 AVL 全面优于红黑树** → 查询 AVL 略胜；但**删除时 AVL 最坏要转 `O(log n)` 次，红黑树只要 ≤3 次**，写多场景红黑树更优
5. **以为平衡树永不退化** → Splay 单次可达 `O(n)`，只是**均摊** `O(log n)`；替罪羊树重建时也是 `O(n)`
6. **以为「平衡因子」可以按节点数算** → 必须是高度

## 八、一句话记住

> **平衡二叉树 = 给 BST 加一条「高度不能太大」的约束。**
> 严格的是 AVL（`|bf| ≤ 1`），宽松的是红黑树（`≤ 2log₂n`），
> 维持手段统一是**旋转** —— 改结构，不改中序。
