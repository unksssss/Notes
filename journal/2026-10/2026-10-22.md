#### 二、`Node.GetData` —— 一个 `!` 写反，整个黑板废掉

`Node.cs:42`

```diff
  public object GetData(string key)
  {
      object value = null;
-     if (!dataContext.TryGetValue(key, out value)) return value;
+     if (dataContext.TryGetValue(key, out value)) return value;
      //沿父级向上查找
      Node node = parent;
      while (node != null)
      {
-         value = node.GetData(key);          // 循环里又递归，O(depth²)
+         if (node.dataContext.TryGetValue(key, out value)) return value;
          node = node.parent;
      }
      return null;
  }
```

**根因**：`TryGetValue` 返回 `false`（自己身上没有）时**直接 return null**，后面 8 行父链查找永远是死代码。条件少写一个 `!`，黑板就只剩「自己存自己读」。

**为什么这么写会毁掉整棵树**：`player` 是写在 root 上的，`CheckPlayerInAttackRange` 是叶子——它自己字典里永远没有 `player`，于是 `GetData` 恒 `null` → **攻击分支永不触发**。

**关键 API 语义**：`Dictionary.TryGetValue(key, out value)` 命中返回 `true`，未命中返回 `false` 且把 `value` 置 `default`。**判断依据必须是 bool 返回值，不能看 `value == null`**——因为存进去的值本身可能是 `null`（三态问题，见新笔记 §2.4）。

#### 三、`Node.SetData` 用 `Add` —— 同 key 二次写入必抛

`Node.cs:35`

```diff
- public void SetData(string key, object value) { dataContext.Add(key, value); }
+ public void SetData(string key, object value) { dataContext[key] = value; }   // 索引器：存在则覆盖
```

`Dictionary.Add` 在 key 已存在时抛 `ArgumentException: An item with the same key has already been added`；索引器 `dict[key] = value` 才是「设置」语义（存在即覆盖、不存在即新增）。

**这条和第 2 条是连体婴**：因为 `GetData` 恒返回 `null`，`CheckPlayerInFOVRange` 每帧都重新 `OverlapSphere`、每帧都调 `SetData` → 第二次就抛异常。

#### 四、`Sequence` 遇 `RUNNING` 只 `break` —— 后面的兄弟照样被 tick

`Sequence.cs:18`

```diff
  case NodeState.RUNNING:
-     isAnyChildRunning = true;
-     break;                        // 只跳出 switch，foreach 继续
+     state = NodeState.RUNNING;
+     return state;                 // 立刻中断
```

**根因**：`break` 跳出的是 `switch`，不是 `foreach`。对比 `Selector` 里遇 `RUNNING` 直接 `return` 是**正确**的——两个组合节点对 `RUNNING` 的处理**不对称**。

**后果**：`Sequence[CheckPlayerInAttackRange, TaskAttack]` 里，条件节点返回 `RUNNING`（多帧转向）的那一帧，`TaskAttack` 还是被 tick 了一次 → 攻击动画重复触发、冷却被重复扣。

**为什么这么写**：`isAnyChildRunning` 这个变量名说明作者意识到了「有子节点在跑」，但把「有子节点在跑」当成了「继续跑其它兄弟」的理由。正确语义是「**到此为止**」。

另外 `Selector.cs:22` 在 `return state;` 后面还留了个 `break;` → CS0162 不可达代码。不致命，但**它会误导下一次重构把 `return` 改成 `break`**，也就是本条 bug 的来源。

#### 六、`static LayerMask` 从未赋值 = 0 —— 感知恒空

`CheckPlayerInFOVRange.cs:11` / `CheckPlayerInAttackRange.cs:11`

```cs
private static LayerMask playerLayerMask;   // 从未赋值
...
Physics.OverlapSphere(transform.position, 10, playerLayerMask);   // mask = 0
```

**根因**：`LayerMask` 是 struct，默认 `0` = 一个层都不检测 → `OverlapSphere` 恒返回空数组。而且 `private static` **不会被 Unity 序列化**（只序列化 `public` 或 `[SerializeField]` 的**实例**字段），`Node` 又不是 MonoBehaviour，**连 Inspector 都没有**。

**这条最阴**：它让上面第 2、3 条的 bug **完全不暴露**——`OverlapSphere` 返回空 → `SetData` 从没被调用 → 不抛异常 → 没人去查 `GetData`。**三个 bug 互相掩盖，只能一次性通读整条链路，不能靠报错驱动。**

#### 八、`Attach` 私有 + 组合节点只有无参构造 —— 树在 API 层面建不起来

`Node.cs:22`

#### 九、`Tree` 基类的 `Start` / `Update` 会被子类静默隐藏

`Tree.cs:15,20`

```diff
- protected void Start()  { root = SetUpTree(); }
- private   void Update() { if (root != null) root.Evaluate(); }
+ protected virtual void Start()  { root = SetUpTree(); }
+ protected virtual void Update() { root?.Evaluate(); }
```

Unity 的消息派发**不看访问修饰符**（`protected Start` 照样调得到），但**子类重新声明同名方法会隐藏基类版本**（CS0108 警告，很容易被无视）→ base 的 `SetUpTree()` 不执行 → `root` 恒 `null` → **树完全不动且不报错**。

#### 十、`TaskPatrol` 三连：NRE / 原地打转 / 绕过 NavMeshAgent

## Ideas

- 行为树真正的痛点不是节点类型，是**调试**：一棵 30 节点的树 tick 一次只能靠 30 行 `Debug.Log`。写个 `EditorWindow` 高亮当前执行路径 + 打印黑板快照，比再补 10 个节点类型有用得多
- 黑板用 `Dictionary<string, object>` 本质是「字符串 key 的弱类型容器」，把 key 换成 `Type`（`Dictionary<Type, object>` + 泛型 `Set<T>/TryGet<T>`）就能在编译期挡住「存 Transform 取 Rigidbody」，也不用再拼字符串
- 今天三个 bug 互相掩盖（`GetData` 写反 → 每帧 `SetData` → 撞 `Add` 异常，但 mask=0 让 `SetData` 根本没被调用）—— **这种连环雷只有通读整条链路能破**，以后 review 行为树代码先画「数据从哪来、到哪去」的一条线，再看每个节点
- `TaskPatrol` 恒 `RUNNING` 揭示一个设计缺口：**行为树里「持续型动作」需要一个「让位条件」**。可以让叶子自己查黑板（本项目做法），也可以在 `Selector` 上加「优先级重判」开关
- 感知节点（`OverlapSphere`）跑 10Hz 就够，没必要跟渲染同频。加一个 `float interval` + `lastCheckTime` 的节流器，顺手把 `NonAlloc` 也换上
- `UnityGroupWorking` 到现在还没 `git init`（10-21 就提过）。今天这 11 个 bug 想复盘「改前长什么样」又没 baseline——**这是第二次被同一件事绊住**
