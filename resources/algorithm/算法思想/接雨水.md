# 接雨水

## 一、题目

给定 `n` 个非负整数表示宽度为 1 的柱子高度，求下雨后能接多少单位的水。

```
[0,1,0,2,1,0,1,3,2,1,2,1]  → 6
[3,0,2,0,4]                → 7
[4,2,0,3,2,5]              → 9
[5,4,3,2,1]                → 0（一路下坡，存不住）
```

## 二、核心认知

**第 `i` 根柱子上方能积的水 = `min(左边最高, 右边最高) - h[i]`。**

为什么不是"左右紧邻的较高者"？因为水是被**两侧最矮的那道墙**卡住的 —— 而且那道墙可以是隔很远的山：

```
        水水水
  █     水水水     █
  █  水 水水水  水 █
  █  █  水水水  █  █
  3  0   1   0  3   ← 中间的 1 上方能存 min(3,3)-1 = 2
```

要挡住 `i` 处的水，`i` 左右两侧都**必须**有比自己高的柱子；水位高度由两侧**最高**里**较矮**的决定。

所以先把"每个位置左边的最高"和"右边的最高"预处理出来，再一次遍历求和 —— 这就是灯皇的思路，方向完全对。

## 三、❌ 灯皇的错：收尾统计时三个下标全写成了 `n`

```cpp
for (int m = 0; m < n; m++) {
    r += min(leftMax[n], rightMax[n]) - arr[n];   // ❌ 三个都该是 m
}
```

循环变量明明是 `m`，里面却全用了 `n`。而 `n` 是**长度**，合法下标是 `0..n-1` —— `leftMax[n]`、`rightMax[n]`、`arr[n]` **全部越界一个元素**。

`vector::operator[]` 不做边界检查，所以不崩、不报错，读到的是一段无关内存。实测（3000 组随机对拍）：

| 版本 | 错组数 |
|---|---|
| 原版 | **2881 / 3000**（剩下 119 组只是正确答案本来就 0） |
| 三个 `n` 改成 `m` | **0** |

同一份代码，我先后两次运行同一组 `[4,2,0,3,2,5]`：

```
第一次：你的 = 0
第二次：你的 = -201325074      ← 加了几个函数，内存布局变了，垃圾值就变了
```

**这就是越界读的铁证 —— 结果不稳定**。返回值还是 `-201325074`，一个"负数水量"。

### 为什么这种错特别容易犯

写循环时脑子里过的是"遍历整个数组"，手就写了 `n`。**判据：凡是在 `for (int m = 0; m < n; m++)` 里面，下标位置就应该是 `m`，出现 `n` 一定是写错了**（除非本来就故意取"末尾后一位"，比如哨兵）。

## 四、解法一：前后缀最大值（你的思路，改三个字母就对）

```cpp
long long maxWater(vector<int>& arr) {
    int n = (int)arr.size();
    if (n == 0) return 0;

    vector<int> L(n), R(n);
    L[0] = arr[0];
    for (int i = 1; i < n; ++i)   L[i] = max(L[i - 1], arr[i]);   // 含自己
    R[n - 1] = arr[n - 1];
    for (int i = n - 2; i >= 0; --i) R[i] = max(R[i + 1], arr[i]);

    long long res = 0;                     // ★ 累加也要 long long
    for (int i = 0; i < n; ++i) res += min(L[i], R[i]) - arr[i];
    return res;
}
```

你原来那个**双向循环**（`i` 从头、`j` 从尾，一趟同时填两侧）写得挺巧，逻辑也对 —— `leftMax[i]` 依赖 `leftMax[i-1]`（`i` 递增，已就绪），`rightMax[j]` 依赖 `rightMax[j+1]`（`j` 递减，已就绪），两边同时走完。**这段不用改**。

顺便清掉两个小东西：

- `vector<int> result(n, 0);` 定义了没用，删掉
- `int r = 0;` → `long long r = 0;`（函数返回 `long long`，内部却用 `int` 累加，长数组会溢出；而且上面那个 `-201325074` 就是溢出的结果）

## 五、解法二：双指针 O(1) 空间

```cpp
long long maxWater(vector<int>& arr) {
    int n = (int)arr.size();
    int l = 0, r = n - 1, lmax = 0, rmax = 0;
    long long res = 0;
    while (l < r) {
        lmax = max(lmax, arr[l]);
        rmax = max(rmax, arr[r]);
        if (lmax < rmax) { res += lmax - arr[l]; ++l; }   // 左边矮 → 结算左
        else             { res += rmax - arr[r]; --r; }   // 右边矮 → 结算右
    }
    return res;
}
```

### 为什么敢「只用一个侧的最大值」就结算

当 `lmax < rmax` 时，`l` 位置右边的最高值**至少**是 `rmax`，而 `rmax > lmax` —— 也就是说右边一定有一道比 `lmax` 更高的墙。那么 `l` 处的水位**只由 `lmax` 决定**（`min(lmax, 右边某个 ≥ rmax 的值) = lmax`），可以立刻结算。

**核心：两边都在往中间收，收的那一侧由"已知的较矮墙"决定，不依赖还没见过的柱子。**

## 六、解法三：单调栈（按层算）

```cpp
long long res = 0;
stack<int> st;                    // 存下标，对应高度单调递减
for (int i = 0; i < n; ++i) {
    while (!st.empty() && arr[st.top()] < arr[i]) {
        int mid = st.top(); st.pop();
        if (st.empty()) break;
        int h = min(arr[st.top()], arr[i]) - arr[mid];   // 这一层的高度
        int w = i - st.top() - 1;                        // 这一层的宽度
        res += (long long)h * w;
    }
    st.push(i);
}
```

思路完全不同：**按"水平层"算**，每弹出一个栈顶就结算它上方那一层。适合和"柱状图最大矩形（LC 84）"对照记。

## 七、必须记住的点

1. **水位 = `min(左全局最高, 右全局最高)`** —— 是"全局"，不是"紧邻"。别被"左边高右边高就积水"的直觉带偏。
2. **`for (int m = ...)` 里面用 `m` 不用 `n`** —— 这次的三个 `n` 全是越界。
3. **`vector::operator[]` 越界不检查** —— 不崩、不报警，读垃圾；**同一份代码换内存布局结果就变**（0 和 −201325074 就是两次不同布局）。
4. **返回 `long long` 就跑不掉了** —— 累加变量也得是 `long long`，否则中间态溢出。

## 八、易错点

1. **下标写成 `n`** —— 越界一格，结果随机。
2. **`int` 累加溢出** —— 数据量大时结果为负数。
3. **前后缀数组"含不含自己"** —— 用 `min(L[i], R[i]) - arr[i]` 时，`L`/`R` 必须**含自己**（否则两端柱子会算出负数）。如果你的 `L` 定义为"不含自己的左max"，就要改成 `min(L[i], R[i]) - arr[i]` 里额外处理边界。
4. **单调栈结算时的宽度** —— `i - st.top() - 1`，`-1` 是扣掉中间柱子的宽度。

## 九、复杂度

| 解法 | 时间 | 空间 |
|---|---|---|
| 前后缀最大值 | `O(n)` | `O(n)` |
| **双指针** | `O(n)` | **`O(1)`** |
| 单调栈 | `O(n)` | `O(n)` |

## 十、面试延伸

- **LC 11 盛最多水的容器**：只算"两端围成的矩形"，双指针每次移动较矮的一端
- **LC 84 柱状图中最大的矩形**：单调**递增**栈，和接雨水是镜像题（一个算"上方空间"，一个算"左右扩展"）
- **LC 407 接雨水 II（二维）**：从边界入队，用**最小堆**按高度从低到高灌水，`visited` 标记
- **LC 42 的"按层"直觉**：每一层就是一个"被水淹没的区间"，单调栈正是按层结算
- **工程里**：高度图/地形积水的简易模拟也是这个"两侧较矮墙"模型
