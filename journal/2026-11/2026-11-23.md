#### 一、第三人称相机：双节点分工 + 世界空间相乘的坑

**文件**：`Assets/Scripts/Role/Player.cs`（17:10）

```csharp
// Start
playerCamera   = GameObject.Find("PlayerCamera").transform;
cameraTransform = playerCamera.Find("Main Camera");

// LateUpdate
playerCamera.position = transform.position;
playerCamera.rotation = transform.rotation;

// OnMouseMove
transform.rotation       *= Quaternion.Euler(0, mouseX * EulerSpeed, 0);
cameraTransform.rotation *= Quaternion.Euler(-mouseY * EulerSpeed, 0, 0);
```

**分工是对的**（父节点承担 yaw、子节点承担 pitch），但 `cameraTransform.rotation *=` 乘的是**世界 X 轴**：

- 玩家 yaw = 0 时世界 X 恰好等于相机右方向，看不出问题；
- 玩家转身 90° 后，世界 X 变成相机的前后轴 → 鼠标上下移动变成**画面翻滚（roll）**，且已积累的 pitch 被甩到其他轴上。

**根因**：`Transform.rotation` 是世界空间四元数，`*=` 是「在世界上再转一次」，不是「绕自己转」。

**修复**：改用局部空间相乘（父节点只有 yaw，子局部 X 恒为相机右方向），并把 pitch 收敛成一个标量直接赋值 —— 顺带解决「无 clamp、累计到 ±90° 画面倒转」：

```csharp
private float pitch;

private void OnMouseMove(InputAction.CallbackContext ctx)
{
    Vector2 d = ctx.ReadValue<Vector2>();
    transform.rotation *= Quaternion.Euler(0, d.x * EulerSpeed, 0);
    pitch = Mathf.Clamp(pitch - d.y * EulerSpeed, -80f, 80f);
    cameraTransform.localRotation = Quaternion.Euler(pitch, 0, 0);
}

private void LateUpdate()
{
    Vector3 target = transform.position + transform.rotation * new Vector3(0, 1.6f, 0);
    playerCamera.position = Vector3.SmoothDamp(playerCamera.position, target, ref camVel, 0.05f);
    playerCamera.rotation = Quaternion.Euler(0, transform.eulerAngles.y, 0);   // 只跟 yaw
}
```

顺带修掉的两处：`playerCamera.position = transform.position` 把枢轴放在**脚底**（视线贴地、人挡镜头）；硬赋值无阻尼，`CharacterController` 贴地修正会一比一传导成画面抖动。

📎 完整推导见 [[第三人称相机控制 — LateUpdate 跟随与世界空间旋转相乘]]

#### 二、双输入源：键盘 + 摇杆，量纲对不上

**文件**：`Assets/Scripts/Role/Player.cs`

```csharp
// 摇杆分支
animatorManager.SetHorizontal(moveDirection.x * 4);
animatorManager.SetVertical(moveDirection.y * 6);

// 键盘分支
animatorManager.SetHorizontal(x * speed);   // speed = 6 或 2
animatorManager.SetVertical(y * speed);
```

**问题**：同一组 Animator 参数喂了两套量纲 —— 摇杆是 `±4 / ±6`，键盘是 `±6 / ±2`（蹲下时 `speed = 2`）。BlendTree 的阈值通常是 `-1~1`，喂 6 会**永远饱和**，慢走/快走的中间态根本出不来。

**根因**：把「速度值」当成了「输入值」。Animator 参数该是**归一化输入**，速度由 BlendTree 的阈值曲线或 `animator.speed` 表达。

**修复**：

```csharp
// 统一在 0~1 之间，摇杆/键盘都只喂归一化输入
animatorManager.SetHorizontal(moveDirection.x);
animatorManager.SetVertical(moveDirection.y);
```

另外 `isJoyStickControl` 的复位逻辑也有洞：只在「键盘有输入」时置 `false`，摇杆松手后键盘再按一下才夺回控制权 —— 期间摇杆残值一直在驱动移动。用「最后输入源时间戳」判断更稳。

#### 三、敌人武装装配：`Start` 里补齐武器链路

**文件**：`Assets/Scripts/Role/EnemyAI.cs`（17:12）

```csharp
protected override void Start()
{
    base.Start();
    WeaponConfig weaponConfig = WeaponConfigManager.Instance.GetConfig(WeaponID);
    animatorManager.EquipeGun(ResourcesMgr.Instance.LoadAnimatorController(weaponConfig.AnimatorType));
    animatorManager.SetHorizontal(0f);
    animatorManager.SetVertical(0f);
    animatorManager.Aim(true);

    GameObject weapon = ResourcesMgr.Instance.LoadAndCreate(ResourcesPath.Weapons, weaponConfig.PrefabName);
    WeaponItem weaponItem = weapon.AddComponent<WeaponItem>();
    weaponItem.Init(weaponConfig);
    currWeaponItem = weaponItem;
    currWeaponItem.SetCurrentNum(currWeaponItem.BulletNum);

    muzzle = currWeaponItem.transform.Find("Muzzle");
    weapon.transform.parent = WeaponPoint;
    weapon.transform.localPosition = Vector3.zero;
    weapon.transform.localRotation = Quaternion.identity;

    player   = FightingManager.Instance.player;
    enemyAIs = FightingManager.Instance.GetEnemies();
}
```

**为什么这么写**：敌人现在和玩家走**同一条武器链路**（`WeaponConfig` → `WeaponItem` → `muzzle` → `SetBulletType` → `Bullet.StartMove`），开火逻辑完全复用 `RoleBase`，子类只覆盖 `SetBulletType` 决定弹道方向 —— 这是模板方法的价值。

**三处隐患**：

1. `muzzle = Find("Muzzle")` 找不到就是 `null`，`Fire_ARs` 里 `muzzle.position` 直接 NRE（`RL_01_Projectile` 那类子物体名一样硬编码）。
2. `enemyAIs = GetEnemies()` 是 **Start 时的快照**（`ToArray()` 拷贝）：死掉的敌人仍在数组里，每帧对已禁用对象算距离；之后新生成的敌人永远不会被感知。
3. `SetBulletType` 里 `bullet.EnemyAIShoot(muzzle.position, pursueTarget.position)` —— `pursueTarget` 可能为 `null`（只在 `OnPatrol` 命中时赋值），且瞄的是**根节点 pivot（脚下）**，靠 `EnemyAIShoot` 里 `offSetY + Random.Range(1f, 1.5f)` 这个魔法数去「补身高」。

```csharp
protected override void SetBulletType(Bullet bullet)
{
    if (pursueTarget == null || muzzle == null) return;
    Vector3 aim = pursueTarget.position + Vector3.up * 1.2f;   // 瞄胸口，别靠偏移量兜
    bullet.EnemyAIShoot(muzzle.position, aim);
}
```

## Ideas

- 相机与角色是**两个自由度系统**，今天用「父 yaw / 子 pitch」解决；下一步若要加「肩射偏移」，第三层（相机本地偏移）就该独立出来，别再往 `playerCamera.position` 上叠。
- `Health` 的两个实例问题说明**「兜底创建」和「显式创建」不能共存**。工程里凡是 `GetOrAddComponent<T>()` 出现在生命周期方法里，外部就应禁止 `AddComponent<T>()` —— 可以写个 Editor 校验脚本扫一遍。
- `EnemyAI` 的感知、追击、躲避、攻击现在是**一堆 bool 叠在一起**（`isPursuing` / `isBeingPursuing` / `isPatrolling` / `isTakingDamage`），已经有 4 个状态互斥却靠 `if` 优先级维持 —— 该换 FSM 了，正好接上 📎 [[有限状态机FSM — 手写实现与状态切换边界]]。
- `enemyAIs` 快照的问题本质是「用数组缓存了会变的对象集合」。改成 `FightingManager` 提供 `IReadOnlyList<EnemyAI>` 实时视图，或让敌人注册/注销到空间分区。
- 元素方碑那题的教训可以外推：**凡是「操作只影响同奇偶位置」的题，先想不变量分组**，再想总量。
- `HybirdCLR` 已静默 42 天，Part A 连续多日「零改动」。若不打算续做，应把它降级为归档项目，把扫描目标正式换到 `Empty`。
