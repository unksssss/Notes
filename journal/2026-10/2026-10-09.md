### Notes 库 — Obsidian 表格自动格式化造成的「伪改动」（13 + 1 个文件）

**现象**：`git status --short` 显示 13 个 `resources/**/*.md` 与 `journal/2026-10/2026-10-08.md` 为 modified，看着像有大批内容被改。

**排查**：

```bash
git diff --stat          # 只报 1 个文件：journal/2026-10/2026-10-08.md | 6 ++++++ 6 ------
git diff <file>          # 差异全是 markdown 表格的列宽对齐 + 行尾 CRLF
```

- `resources/` 那 13 个文件：`git diff --stat` **内容差异为空**，仅报 `LF will be replaced by CRLF` → 是 Obsidian 打开笔记时做了行尾归一化，**无真实内容改动**；
- `journal/2026-10/2026-10-08.md`：差异是把表格重排为**列对齐的等宽格式**（`| 新笔记 |` → `| 新笔记      |`），属 Obsidian 编辑器的表格自动格式化（Tab 键或保存时的对齐），**语义零变化**。

**处置**：两者均**不纳入本次提交**，保持提交内容聚焦今日日记。⚠️ 经验：`git status` 的 modified 数不等于内容改动数，**必须用 `git diff --stat` 二次确认**，否则会把编辑器格式化的噪音混进 commit。

### 工具链 — `git push` 静默挂起 >4 分钟：加 HTTP 超时保护后 3 秒推完

**现象**：日记 commit 成功（`6f43f13`）后推送，报错并挂起：

```bash
$ git -c http.sslBackend=openssl push origin main
fatal: unable to access 'https://github.com/unksssss/Notes.git/':
       OpenSSL SSL_read: SSL_ERROR_SYSCALL, errno 0
# 随后重试：无任何输出，持续挂起 4 分 29 秒（最后手动 kill）
```

**排查**：

```bash
curl -sS -o /dev/null -w "%{http_code} %{time_total}s" --max-time 15 https://github.com
# → HTTP 200 in 7.78s   —— 网络通，但握手明显偏慢
git config --global --get http.proxy   # 空 —— 没配代理，排除代理干扰
```

**根因分析**：不是证书问题（10-08 的 `CRYPT_E_REVOCATION_OFFLINE` 才是，已用 `http.sslBackend=openssl` 绕过），这次是 **openssl 后端在慢链路上没有传输超时保护**——TCP 卡在半开状态时 git 会**无限等待**，既不报错也不退出，表现就是「静默挂起」。

**修复**：显式加 HTTP 低速率超时 + 回退 HTTP/1.1（HTTP/2 多路复用在弱网下更容易卡）：

```bash
git -c http.sslBackend=openssl \
    -c http.lowSpeedLimit=1000 \
    -c http.lowSpeedTime=30 \
    -c http.version=HTTP/1.1 \
    push origin main
# → 3 秒完成：d9b1cf8..6f43f13  main -> main
```

| 参数 | 作用 |
| --- | --- |
| `http.sslBackend=openssl` | 绕过 Windows schannel 的证书吊销在线检查（10-08 已踩） |
| `http.lowSpeedLimit=1000` + `lowSpeedTime=30` | 传输低于 1KB/s 持续 30s 即**主动中断**，把「无限挂起」变成「快速失败可重试」 |
| `http.version=HTTP/1.1` | 弱网下避开 HTTP/2 多路复用卡死 |

**结论**：`D:\Notes` 的推送建议统一用上面这条完整命令（可与 10-08 的经验合并成一条 alias），既解决证书吊销离线，也解决弱网静默挂起。
