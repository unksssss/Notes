题目：给 4 个数，用 `+ - * /` 和括号、每数恰好一次，判断能否得 24（牛客 BM64 / LC 679）。

#### 2. 根因一：`int` 存中间结果 = 凭空造出一种假运算

```cpp
// ❌ 灯皇原版
if (num[i] != 0) { temp.push_back(num[j] / num[i]); ... }   // int / int → 向零截断
```

`int / int` 不是数学除法：`12/8 = 1`（真 1.5）、`1/5 = 0`（真 0.2）。后果是**双向**的 —— 既漏判（`1 5 5 5` 的 `5*(5-1/5)` 需要 0.2）又误判。

实测 `1..13` 随机四数 **20000 组**（与分数精确解对比）：

| 类别 | 组数 | 占比 |
| --- | --- | --- |
| 误判（应 false 却 true） | **2868** | 14.3% |
| 漏判（应 true 却 false） | 38 | 0.19% |
| 合计 | 2906 | **14.5%** |

而 12 个手选用例**只错 1 个**（`1 5 5 5`）→ 手挑选例几乎测不出精度 bug。

完整假路径（实测追出，输入 `8 12 13 1`，真实无解）：

```text
int  版：12/8 = 1      → 13-1 = 12    → 12+12 = 24    → true  ❌
double：12/8 = 1.5     → 13-1.5 = 11.5 → 11.5+12 = 23.5 → false ✅
```

**修复**：换 `double`，比较与判零都用 eps。

```diff
- bool dfs(vector<int>& num) { ... if (num[i] != 0) cand = num[j] / num[i]; ... }
+ bool dfs(vector<double>& a) {
+     if (a.size() == 1) return fabs(a[0] - 24.0) < 1e-6;      // ★ 不能用 ==
+     ...
+     if (fabs(y) > 1e-9) cand[m++] = x / y;                    // ★ 判零用 eps
+     if (fabs(x) > 1e-9) cand[m++] = y / x;
+ }
```

实测 `double` 版与分数精确版在 2 万组上 **0 差异**。要绝对精确则上分数类（`long long p/q` 约分）。

#### 3. 根因二：`num.size() - 1` 无符号下溢 → 死循环

```cpp
for (int i = 0; i < num.size() - 1; i++)   // size() 返回 size_t
```

`size() == 0` 时 `0-1` 下溢成 `18446744073709551615`，`int i` 被提升为 `size_t` 后比较恒真 → **实测 2 秒不返回**。修法三选：`i + 1 < num.size()` / `(int)num.size()` 强转 / 开头 `if (num.size() < 2) return ...` 提前挡。

> 这是「无符号减法下溢」的通病，凡是 `xxx.size() - k` 出现在循环条件里都该警惕。

#### 4. 方法论沉淀：随机对拍（本次已补强进笔记）

今天真正的收获不是这道题，而是**「怎么证明自己写对了」**。手选用例 12 个只错 1 个，随机 2 万组错 14.5% —— 说明精度类 bug 的验证只有一条路：

1. **三件套**：精确基准（分数版）+ 待测实现 + 随机生成器（值域覆盖题目真实范围 1~13）；
2. **固定种子**并打印，出差异能原地复现；
3. **第一个反例就 break**，一次修一个；
4. **差异用例手动缩到最小**（本题缩到 `12 8 13 1` 才看清丢的是 0.5）；
5. **别只比 bool**，把两版中间结果一起打出来，才知道错在哪一步。

#### 6. 三角形最大相邻连通块归档（`d77ac7c`，18:35）

`resources/algorithm/算法思想/三角形的最大相邻连通块.md` 新建 201 行，同步 `resources/_index.md`、`resources/algorithm/_index.md`、`_tags.md`、`_graph.md`（5 files）。

题目：若干三角形（各用 3 个顶点编号表示），两个共享一条边（共享 2 个顶点）算「相邻」，求最大的相邻组大小。样例 `{{0,1,2},{0,2,3},{4,5,6},{2,3,4}}` → 3。

##### 灯皇的思路与它的三处独立错误

```cpp
vector<int> temp = indexArray[0];
for (int i = 2; i <= n; i++) {
    if (isConnected(temp, indexArray[i-1])) {   // temp 与当前三角形"相邻"
        dp[i] = dp[i-1] + 1;
        temp = AddItem(temp, indexArray[i-1]);   // 顶点合并进 temp
    } else {
        dp[i] = dp[i-1];
    }
}
```

**错误 ① `sameV == 2` 应为 `>= 2`（造成偏小，主力）**

`temp` 是多三角形**并集**，新三角形可能与它共享 3 个甚至更多顶点：

```
temp = {0,1,2,3}   ← T0{0,1,2} 与 T1{0,1,3} 合并
T    = {0,2,3}
共享 = {0,2,3} 共 3 个 → == 2 为 false → 判"不相邻" ❌
（但 T 与 T0 共享边 0-2、与 T1 共享边 0-3，完全连通）
```

最小复现：`{{0,1,2},{0,1,3},{0,2,3}}` 正解 3，代码给 2。

**错误 ② 用聚合顶点集判连通（造成偏大）**

顶点并集丢掉了「这个顶点来自哪个三角形」，于是两个本不相邻的三角形可以各贡献一个顶点「拼」出 2 个共享：

```
已选 T0={0,1,2}, T1={2,5,9}（相邻，合并）→ temp={0,1,2,5,9}
新来 T ={0,9,7} → temp∩T = {0,9} 大小 2 → 判"相邻" ❌
实际：T 与 T0 只共享 {0}，与 T1 只共享 {9}，跟这组毫无关系
```

> **核心认知**：连通性不能用「集合交集大小」代理。每条边是两个三角形之间的独立关系，必须**两两判**。

**错误 ③ 贪心只维护一个聚合体 → 结果依赖输入顺序**

```text
集合 {{1,5,6}, {1,4,6}, {1,3,6}, {0,1,2}}   正解 3
排列 A：原顺序                            → 3 ✅
排列 B：{{0,1,2}, {1,5,6}, {1,4,6}, {1,3,6}} → 1 ❌
```

B 里第一个 `{0,1,2}` 和后三个都不相邻（只共享顶点 1），`temp` 就永远卡在 `{0,1,2}`，后三个彼此共享 `1,6` 构成的连通块全被漏掉。

##### 实测：68% 不一致，且两个方向都错

顶点 0~7、每组 3~8 个三角形，随机 20000 组对拍并查集正解：

| 类别 | 例数 | 占比 |
| --- | --- | --- |
| 偏小（少算） | 12423 | 62.1% |
| 偏大（多算） | 1185 | 5.9% |
| **合计不一致** | **13608** | **68.0%** |

两个方向同时存在，正说明错误①（偏严）与错误②（偏松）在互相抵消 —— 这也是它「能过一部分用例、卡在 60%」的原因。

##### 正解：建图 + 并查集

```cpp
struct DSU {
    vector<int> p;
    DSU(int n) : p(n) { for (int i = 0; i < n; ++i) p[i] = i; }
    int find(int x) { return p[x] == x ? x : p[x] = find(p[x]); }
    void unite(int a, int b) { a = find(a); b = find(b); if (a != b) p[a] = b; }
};

int sharedVerts(const vector<int>& a, const vector<int>& b) {   // ★ const&，别按值
    int c = 0;
    for (int x : a) for (int y : b) if (x == y) ++c;
    return c;
}

int maxConnectedTriangles(vector<vector<int>>& tri, int n) {
    if (n <= 0) return 0;
    DSU d(n);
    for (int i = 0; i < n; ++i)
        for (int j = i + 1; j < n; ++j)
            if (sharedVerts(tri[i], tri[j]) >= 2) d.unite(i, j);   // ★ 两两判断

    map<int, int> cnt;
    int best = 0;
    for (int i = 0; i < n; ++i)
        best = max(best, ++cnt[d.find(i)]);
    return best;
}
```

复杂度 `O(n²)`（每次比 9 对顶点）、空间 `O(n)`。实测与独立写的 BFS 版逐例一致（2 万组 0 差异）。

##### 题目歧义：三种「最大」三种解法

| 题意 | 模型 | 解法 |
| --- | --- | --- |
| 最大连通组 | 无向图连通分量 | 并查集 / DFS，`O(n²)` |
| 最长相邻链（只接前一个） | 有向图最长路径 | 建图 + DFS 记忆化；**有环即无解**，要判环 |
| 最大团（两两相邻） | 最大团 | **NP-hard**，n 小才能回溯，别写贪心 |

灯皇的 `dp` 命名像第三种、`temp` 累积像第一种、`sameV==2` 像第二种 —— **模型没定，代码就成了混合体**，这才是错的深层原因。面试遇到「最大 XX」先钉三件事：组内关系是连通还是两两？要一段还是任意多？有无顺序要求？

##### 其它易错点

1. `isConnected(vector<int> a, vector<int> b)` 按值传 → 每对比较拷两次 vector，应 `const&`
2. 另传的 `n` 与 `tri.size()` 不一致会越界，建议直接用 `tri.size()`
3. 两个完全相同的三角形也共享边 → 必须 `>= 2`
