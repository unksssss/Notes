| --- | --- | --- |
| `BuildPipeline` | `ScriptableBuildPipeline` | 走 SBP（不是旧 `BuildPipeline.BuildAssetBundles`）—— 支持增量、可缓存、可拿到构建耗时 trace |

| `SupportExtensionless` | true | 地址可省略扩展名 |
| `UniqueBundleName` | false | 包名不加包前缀 —— **多包同名资源会冲突**，多包工程需改 true |
| `EnableSharePackRule` | true | **共享资源自动抽成独立包**（被 ≥2 处引用的资源） |
| `SingleReferencedPackAlone` | true | **仅被单个资源引用的资源单独成包** —— 与上一条配合，把「独立资源」和「共享资源」分开打包 |

| `WriteLinkXML` | true | 输出 `link.xml` 裁剪保护清单 |
| `ClearBuildCacheFiles` / `UseAssetDependencyDB` | false / false | 未清缓存、未启用依赖数据库 |
| `EncryptionServicesClassName` | `EncryptionNone` | 未加密 |

#### 三、两条打包警告（值得记的"正常但有用"日志）

#### 五、补丁流程 FSM 八节点（`PatchLogic/PatchManager.cs` + `FsmNode/`）

```
FsmInitializePackage → FsmRequestPackageVersion → FsmUpdatePackageManifest
→ FsmCreateDownloader → FsmDownloadPackageFiles → FsmDownloadPackageOver
→ FsmClearCacheBundle → FsmStartGame
```

`PatchManager` 是个**静态状态机 + 事件驱动**的组合：`Create(packageName, playMode)` 建节点、`Start()` 从首节点跑、`Update()` 由 `Boot.Update()` 每帧驱动；中途靠 `UserTryXxxEvent` 事件（`OnHandleEventMessage`）做 `ChangeState` —— **下载确认、重试这类"等用户/等结果"的环节用事件切回状态机**，而不是死等。

各节点关键 API：

| 节点 | 关键 API / 参数 | 要点 |
| --- | --- | --- |
| `FsmInitializePackage` | `YooAssets.TryGetPackage` / `CreatePackage` → `package.InitializePackageAsync(options)` | 按 `EPlayMode` 分四套 Options（见下） |
| `FsmRequestPackageVersion` | `package.RequestPackageVersionAsync()` → `operation.PackageVersion` | 版本号写回黑板，供下一步用 |
| `FsmUpdatePackageManifest` | `new LoadPackageManifestOptions(version, 60)` + `LoadPackageManifestAsync` | 第二参数 = 超时秒数 |
| `FsmCreateDownloader` | `new ResourceDownloaderOptions(10, 3)` + `CreateResourceDownloader` | `TotalDownloadCount == 0` → **直接跳 `FsmStartGame`**（无差异就不下载） |
| `FsmDownloadPackageFiles` | 下载器进度/完成事件 | 由 `UserBeginDownloadWebFilesEvent` 进入 |
| `FsmDownloadPackageOver` | — | 下载完成收尾 |
| `FsmClearCacheBundle` | `new ClearCacheOptions(ClearCacheMethods.ClearUnusedBundleFiles)` + `ClearCacheAsync` | **清"未使用"缓存**，不是清全部 |
| `FsmStartGame` | `GameManager.SetGamePackage(YooAssets.GetPackage("DefaultPackage"))` → 切场景 | 资源系统准备完毕才开始业务 |

**四种 `EPlayMode` 的初始化参数差异**（同一节点内四套分支，是选型题的标准答案素材）：

| PlayMode | Options | 文件系统 |
| --- | --- | --- |
| `EditorSimulateMode` | `EditorSimulateModeOptions` | `EditorSimulateBuildInvoker.Build(packageName, (int)EBundleType.VirtualAssetBundle)` 产出虚拟包根目录 + `CreateDefaultEditorFileSystemParameters`，并注入 `VirtualDownloadMode / VirtualDownloadSpeed(1024*1000) / AsyncSimulateMinFrame(5) / AsyncSimulateMaxFrame(10)` **模拟异步与假下载速度** |
| `OfflinePlayMode` | `OfflinePlayModeOptions` | `CreateDefaultBuiltinFileSystemParameters()`（只读 StreamingAssets） |
| `HostPlayMode` | `HostPlayModeOptions` | Builtin（+`CopyBuiltinPackageManifest=true`）+ `CreateDefaultSandboxFileSystemParameters(remoteService)`（+`DownloadMaxConcurrency=5` / `DownloadMaxRequestPerFrame=1` / `DownloadWatchdogTimeout=10`） |
| `WebPlayMode` | `WebPlayModeOptions` | WebGL 走 `CreateDefaultWebServerFileSystemParameters`；微信小游戏走 `WechatFileSystemCreater` + `WX.env.USER_DATA_PATH` 缓存目录（`#if UNITY_WEBGL && WEIXINMINIGAME`） |

> 💡 `Boot.cs` 默认 `EPlayMode.EditorSimulateMode`，`Awake` 里只做 `targetFrameRate = 60 / runInBackground = true / DontDestroyOnLoad`；`Start` 里 `YooAssets.Initialize()` → `PatchManager.Create("DefaultPackage", PlayMode)` → `Start()`。**`YooAssets.Initialize()` 全局只调一次**这条在示例里得到印证。

#### 2. 「包版本号命名」与「远端 URL 版本目录」是两套东西（辨析）

- 10-11 `HotUpdateDlls` 包版本 = `v1.1.5`（手工/配置式命名）；
- 10-13 `DefaultPackage` 包版本 = `2026-10-13-962`（**日期 + 自增序号**，YooAsset 默认按打包日期生成）；
- 而 `FsmInitializePackage.GetHostServerURL()` 里拼的是 `http://127.0.0.1/CDN/PC/v1.0`，那个 `v1.0` 是**代码里硬编码的 URL 一级目录**，与包版本无关。

→ 上传 CDN 时必须让 **URL 目录组织** 与 **`RemoteService` 拼出的路径** 对齐，否则 `RequestPackageVersionAsync` 取不到 `.version` 文件。这是热更"首跑失败"的高频原因。
