### 学习线 — IL 中间语言讲解（承接 Day 36 S1 AOT/JIT 追问）📎[[C# IL 中间语言与编译执行模型]]

Day 36 简答 S1【面经】HybridCLR 热更后追问"AOT 是什么"→ 引出 JIT vs AOT 对比，今日灯皇再问"介绍一下 IL"，展开完整讲解并已归档新笔记（commit bc19197，resources/csharp/）：

1. **IL/CIL 定义与两段论**：C# 源码经 csc 一次编译为 IL 中间语言（托管程序集，非机器码）；运行时再由 JIT（运行时逐方法翻译）或 AOT（发布前整体翻译）二次编译为机器码——"写一次，两段编译"是 .NET 跨平台/跨运行时的根基
2. **栈机模型**：IL 是**基于操作数栈**的虚拟机指令集，演示 `x + y` 三指令：
```il
ldarg.0    // 压入参数 x
ldarg.1    // 压入参数 y
add        // 弹出两值求和，结果压回栈
ret        // 弹出返回值
```
   对比 x86 的寄存器模型（eax/ebx…），栈机指令天然紧凑、与寄存器数量解耦，是 JIT 各平台移植容易的原因
3. **元数据与反射**：程序集除 IL 外还内嵌完整元数据表（类型/方法/字段签名），反射就是查元数据表——这也是 IL2CPP 下反射性能差的根源（见 [[IL2CPP 编译原理与陷阱]]）
4. **常见指令 ↔ 已学知识点对照**：
   - `box` 指令 = 装箱的本质（值类型转 object 分配托管堆）📎[[struct 装箱陷阱与值类型原理]]
   - `brfalse` 跳转 = 协程状态机 MoveNext 的分支骨架 📎[[协程原理与unitask]]
   - **编译器生成的隐藏类** = C# 闭包捕获变量的搬运工（Day 36 S5 刚考过）📎[[C# 闭包与委托 — 隐藏类与 GC 陷阱]]
5. **Unity 四条消费路线**（同 IL 起点、不同终点）：
   - Mono：JIT，开发期热迭代快，iOS 禁 JIT 受限
   - IL2CPP：IL → C++ → 机器码，AOT 全平台，反射/泛型受限需 link.xml
   - **CoreCLR**：Unity 6.6（08-31 发布）正在迁移的官方运行时，四阶段渐进（Day 36 Q1 官方动态已考）
   - **HybridCLR**：AOT 基底 + 补充元数据热更（Day 36 S1 面经已考）

### 学习线 — C 语言答疑：没有 class 还要不要管内存回收 📎[[内存管理方案对比]]

灯皇问"C 语言里没有 class，那还需要考虑内存回收吗"→ 澄清关键误区：**回收与否看有没有 GC（垃圾回收器），与有没有 class 无关**：

- C：**全手动** `malloc/free`——漏 free = 永久泄漏；过早/重复 free = 悬垂指针/UAF（use-after-free）
- C++：RAII + 智能指针半自动（scope 结束自动释放，呼应 [[Boehm GC 保守式垃圾回收原理]] 的确定性对比）
- C#：GC 自动回收托管对象，但 **native 资源仍须手动 Dispose/Destroy**（呼应 AssetBundle.Unload/Destroy 配对、[[AssetBundle 生命周期与卸载语义]] 泄漏教训）📎[[UnityEngine.Object 判空与销毁机制]]

结构化对比（GC 是语言运行时特性，不是 class 的附属品）：

| 语言 | 回收方式 | 典型事故 |
|---|---|---|
| C | malloc/free 全手动 | 泄漏 / 悬垂指针 UAF |
| C++ | RAII/智能指针半自动 | 裸指针误用、循环引用（shared_ptr） |
| C# | GC 自动 + native 手动 | 事件泄漏、AB 不卸载、纹理不释放 |

### 学习线 — C 语言答疑：没有 class 是否就没有栈堆之分 📎[[struct 装箱陷阱与值类型原理]]

灯皇问"C 没有 class 是不是就没有栈内存和堆内存的区别"→ 澄清第二个误区：**栈/堆是进程内存布局区域，与语言有无 class 无关**（连汇编都有）：

- C 内存四区：**栈**（自动压栈/弹栈、向下生长、局部变量）、**堆**（malloc/free 手动、向上生长）、**静态区**（static/全局）、**代码段**（只读）
- 直接证据：C 的 `struct` 局部变量就分配在栈上——栈堆划分早于"对象"概念

同时破除 C# 教学简化"struct 栈 / class 堆"：准确说法是**引用变量在栈、对象本体在堆**；struct 一旦装箱或作为字段嵌入 class，本体就进堆。C 视角反过来帮灯皇看清：栈/堆是内存管理机制，对象/值只是"谁来回收"的归属问题。

### 学习线 — C 语言答疑：声明结构体变量为何要加 struct 前缀

灯皇问"C 声明临时变量为什么前面要加 struct"→ 讲解 C 的**标签命名空间**设计：

- C 里 `struct Point` 声明的 `Point` 只是**标签（tag）**，活在独立的"标签命名空间"，完整类型名是 `struct Point` 整串；标签可与变量/函数同名不冲突（如 `int stat` vs `struct stat`）
- 解法：`typedef struct { ... } Point;`（可匿名结构体）；**自引用陷阱**——typedef 别名在声明结束才生效，链表 next 必须写 `struct Node *next`，不能写 `Node *next`
- C++ 将 struct/class 名并入普通命名空间故免前缀；C# 无此概念
