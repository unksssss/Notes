### FireSim_URP_VR — TipsPopup Alyx 风格死区跟随提示弹窗（新增）

目标：`Assets/Scripts/Author/Wt/UI/TipsPopup/TipsPopup.cs`

VR 世界空间提示弹窗，采用《半衰期：Alyx》风格的**死区跟随**：头部小动不跟、大动才重新锚定，避免提示框在眼前抖成筛子。

- `Show(text, duration)`：设文本 + 激活 + 重启隐藏协程（先 `StopCoroutine` 旧的再开新的，防连发缩短/延长显示）
- `LateUpdate` 死区判断：相机相对锚点位移 > `moveThreshold`(0.15m) **或** 旋转角 > `angleThreshold`(15°) 才更新 `lockedCamPos/lockedCamRot`
- **目标位置 = 锚定时的相机前方**（不是实时前方）→ 微小晃动提示框纹丝不动
- 位置用 `Vector3.Lerp(pos, target, dt * smoothTime)` 平滑跟随，**朝向仍实时 `LookAt(cam)`**，转头时提示框不歪

```csharp
if (!anchorValid ||
    Vector3.Distance(cam.position, lockedCamPos) > moveThreshold ||
    Quaternion.Angle(cam.rotation, lockedCamRot) > angleThreshold)
{
    lockedCamPos = cam.position;   // 只有大动才重新锚定
    lockedCamRot = cam.rotation;
    anchorValid = true;
}
Vector3 targetPos = lockedCamPos + lockedCamRot * Vector3.forward * distance;
transform.position = Vector3.Lerp(transform.position, targetPos, Time.deltaTime * smoothTime);
transform.LookAt(cam.position + cam.forward * 10f);   // 朝向实时跟随
```

> 知识点：VR 世界空间 UI"跟随"与"钉死"之间必须做**死区/阈值权衡**——完全钉死在头上=视角晃动全吃、完全实时跟随=画面抖动。锚定位置 + 实时朝向的组合是 Alyx 通用做法。📎 [[XR射线交互与World Space Canvas]]、[[XR Interaction Toolkit 配置指南]]

### FireSim_URP_VR — FireAxeBreakableDoor 消防斧破门 + Rayfire 物理破碎（补全）

目标：`Assets/Scripts/Author/LJW/Equipment/Runtime/Equipments/Interactable Object/FireAxeBreakableDoor.cs`

破门系统今日补上 **Rayfire 物理破碎**链路：耐久度打空 → 破碎动画 + 物理碎裂 + 碎片延迟清理。

- 耐久度：`ApplyDamage(damage)` 累计扣减，`m_CurrentDurability == 0` 才 `BreakDoor()`；已破门直接 return 防重复
- `BreakDoor()`：禁用 `m_BlockingColliders`（门体碰撞让路）→ Animator `SetTrigger("Break")` → 播放破碎音效 → `m_OnBroken` 事件
- **Rayfire 破碎时序（关键坑）**：`Initialize()` 后**必须 `WaitUntil(initialized)`** 等碎片初始化完成，再 `Demolish()`；否则碎片未生成直接 Demolish 无效
- 碎片清理：`Demolish` 后再 `WaitForSeconds(delay)`，遍历 `rayfireRigid.fragments` 逐个 `Destroy(frag.gameObject, delay)`——**带延迟的 Destroy 双保险**，碎片有下落/碰撞演出时间

```csharp
rayfireRigid.Initialize();
yield return new WaitUntil(() => rayfireRigid.initialized);   // 等碎片就绪
rayfireRigid.Demolish();
yield return new WaitForSeconds(delay);
foreach (var frag in rayfireRigid.fragments)
{
    if (frag != null) Destroy(frag.gameObject, m_DestroyDelay);
}
```

> 知识点：Rayfire 的 `Initialize→WaitUntil(initialized)→Demolish` 三步时序是硬性约定；破碎后的碎片是独立 Rigidbody，必须主动延迟销毁否则堆积成性能炸弹。协程等待用 `WaitUntil` 轮询条件比固定 `WaitForSeconds` 更稳。📎 [[协程原理与unitask]]、[[UnityEngine.Object 判空与销毁机制]]、[[Animator参数与性能优化]]

### FireSim_URP_VR — TaskTipsSystem 任务状态事件总线（新增骨架）

目标：`Assets/Scripts/Author/Wt/Task/TaskTipsSystem.cs`

按 `TaskType` 维度的事件总线单例，任务状态变更时通知订阅方（任务面板/提示弹窗解耦）：

- `GetOrCreate(taskType)`：Dictionary 惰性建 `UnityEvent<TaskStatusChange>`，重复订阅不重建
- `Subscribe/Unsubscribe` 成对 API；`TaskStatusChange` 数据载体（taskType + Status）
- ⚠️ 当前 `Notify()` 被注释掉未激活（骨架先行），待接入任务完成检测后开放

```csharp
public void Subscribe(TaskType taskType, UnityAction<TaskStatusChange> callback)
{
    GetOrCreate(taskType).AddListener(callback);
}
public UnityEvent<TaskStatusChange> GetOrCreate(TaskType taskType)
{
    if (!tasksEvents.TryGetValue(taskType, out var events))
    {
        events = new UnityEvent<TaskStatusChange>();
        tasksEvents[taskType] = events;
    }
    return events;
}
```

> 知识点：UnityEvent 按 key 分桶 = 轻量事件总线，比全局大事件更精准（只收自己关心的任务类型）。订阅必须与 `Unsubscribe`/`OnDisable` 成对，否则面板反复 SetActive 会叠加回调。📎 [[MonoBehaviour生命周期与SetActive的坑]]

### FireSim_URP_VR — VerticalBackPack.Confirm 装备链路打通（TipsPopup + EquipmentManager）

目标：`Assets/Scripts/Author/Wt/UI/WristUI/VerticalBackPack/VerticalBackPack.cs`

手腕背包确认装备的完整链路今日打通：`Confirm()` 选中 → `EquipmentManager.Equip` 生成右手装备 → `TipsPopup.Show` 弹出"装备了 XXX"提示：

- 空列表防护 + `index = Mathf.Clamp(index, 0, itemList.Count - 1)` 越界钳制（数据变更重建后 index 可能越界）
- 选中状态图标：先全部刷回 `sprite_NotChoose`，再把目标 item 刷成 `sprite_Choose`（`TryGetValue` 防 key 不存在崩溃）
- `EquipmentManager.Instance.Equip(chooseEquip)` 与 `TipsPopup.instance.Show(...)` 均判空再调（场景里可能没挂）

```csharp
if (itemList == null || itemList.Count == 0) return;          // 空列表防护
index = Mathf.Clamp(index, 0, itemList.Count - 1);            // 越界钳制
var chooseEquip = itemList[index]?.equip;
if (chooseEquip == null) return;
onChooseData?.Invoke(chooseEquip);
if (EquipmentManager.Instance != null)
    EquipmentManager.Instance.Equip(chooseEquip);
if (TipsPopup.instance != null)
    TipsPopup.instance.Show($"装备了 {chooseEquip.displayName}");
```

> 知识点：数据驱动列表重建后，`index` 必须重新 Clamp——这是"清空重建"类 UI 的通用崩溃源。装备/提示系统全走单例判空调用，模块可独立卸载。📎 [[XR Grab Interactable 完整参考手册]]、[[UGUI布局系统与强制刷新]]
