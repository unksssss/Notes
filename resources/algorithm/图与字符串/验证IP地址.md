# 验证IP地址

> **题目**：判断给定字符串是 `IPv4`、`IPv6` 还是 `Neither`。
>
> **IPv4 规则**：4 段，`.` 分隔；每段 1~3 位**纯数字**；**不允许前导零**（`"01"` 非法，但 `"0"` 合法）；值 `≤ 255`。
> **IPv6 规则**：8 段，`:` 分隔；每段 1~4 位**十六进制**（`0-9a-fA-F`，大小写都行，**允许前导零**）；**不允许 `::` 压缩**。

## 一、核心认知：并联验证，不是串联猜测

很多人的第一反应是「先看出现在是哪种 IP，再按那种规则验」。这思路有个洞：**如果两种分隔符都没有呢？**

```
"abc"  →  没有 '.' 也没有 ':'  →  类型判断变量保持初值  →  误走某个分支
```

正确做法是**放弃"猜类型"这一步**：

```cpp
if (isIPv4(IP)) return "IPv4";
if (isIPv6(IP)) return "IPv6";
return "Neither";
```

两个验证函数各自独立、各自完整，并且**每个都自己检查"不该出现的分隔符有没有出现"**（`isIPv4` 里发现 `:` 直接 false，反之亦然）。这样「类型判断」这件事自动消失了。

## 二、初版实现错的 12 处（实测 23 个用例只对 11 个）

### 分类 1：控制流 / 判据层面

| # | 问题 | 后果（实测） |
| --- | --- | --- |
| 1 | `bool isIPv4 = false;` + 只找第一个 `.`/`:` | `"abc"`（无分隔符）→ 走 IPv6 分支 → 返回 **`IPv6`** |
| 2 | **完全没检查段数** | `"1.1.1"`（3 段）、`"1.1.1.1.1"`（5 段）→ 返回 `IPv4` |
| 3 | **循环结束后没校验最后一段** | `"1.1.1.999"`、`"1.1.1."`、`"1.1.1"` 全部放过 |
| 4 | IPv6 分支**完全不校验字符** | `"gggg:gggg:..."` → 返回 `IPv6` |
| 5 | IPv6 最后一段也没校验 | `"1:2:3:4:5:6:7:"` → 返回 `IPv6` |

### 分类 2：IPv4 数值判断

| # | 问题 | 后果（实测） |
| --- | --- | --- |
| 6 | `toNum` 写成 `sum += sum*10 + (s[i]-'0')` | 应为 `sum = sum*10 + ...`。`"123"` 算成 **146**、`"240"` 算成 **286**、`"255"` 算成 **302** |
| 7 | `toNum(s) >= 255` | 应为 `> 255`。**255 是合法值**，被误拒 |
| 8 | `s[0] == '0'` 判前导零 | 应为 `s.size() > 1 && s[0] == '0'`。**单个 `"0"` 被抓走**，`"0.0.0.0"` 被拒 |
| 9 | `s[0]` 在 `s` 为空时崩溃/UB | `"1..1.1"` 连续点时 `s` 为空，`s[0]` 是 UB |

第 6 条错得最隐蔽 —— `sum += sum * 10` 实际是 `sum = sum + sum*10 = sum*11`，加的不只是移位。`toNum` 实测结果：

| 输入 | 正确值 | 原版 toNum |
| --- | --- | --- |
| `"0"` | 0 | 0 |
| `"1"` | 1 | 1 |
| `"12"` | 12 | **13** |
| `"123"` | 123 | **146** |
| `"200"` | 200 | **242** |
| `"240"` | 240 | **286** |
| `"255"` | 255 | **302** |
| `"300"` | 300 | **363** |

只有 0 和 1 是对的 —— 因为单字符时 `sum*mul` 那项还没起作用。

### 正确写法（`= ` 不是 `+=`）

```cpp
int v = 0;
for (char c : seg) v = v * 10 + (c - '0');
```

## 三、正确实现：split + 逐段验证

```cpp
static vector<string> split(const string& s, char sep) {
    vector<string> parts;
    string cur;
    for (char c : s) {
        if (c == sep) { parts.push_back(cur); cur.clear(); }
        else cur += c;
    }
    parts.push_back(cur);            // ★ 别忘最后一段，否则 "1.1.1." 会被当成 3 段
    return parts;
}

static bool isIPv4(const string& s) {
    if (s.find(':') != string::npos) return false;          // 混了冒号
    vector<string> p = split(s, '.');
    if (p.size() != 4) return false;                        // ★ 段数
    for (const string& seg : p) {
        if (seg.empty() || seg.size() > 3) return false;     // ★ 空段 / 超长
        for (char c : seg) if (!isdigit((unsigned char)c)) return false;
        if (seg.size() > 1 && seg[0] == '0') return false;   // ★ 前导零，但 "0" 合法
        int v = 0;
        for (char c : seg) v = v * 10 + (c - '0');           // ★ = 不是 +=
        if (v > 255) return false;                            // ★ 255 合法
    }
    return true;
}

static bool isIPv6(const string& s) {
    if (s.find('.') != string::npos) return false;
    vector<string> p = split(s, ':');
    if (p.size() != 8) return false;
    for (const string& seg : p) {
        if (seg.empty() || seg.size() > 4) return false;
        for (char c : seg) if (!isxdigit((unsigned char)c)) return false;   // ★ 十六进制
    }
    return true;
}

string solve(string IP) {
    if (isIPv4(IP)) return "IPv4";
    if (isIPv6(IP)) return "IPv6";
    return "Neither";
}
```

**`split` 里那句 `parts.push_back(cur)` 是全场最容易漏的** —— 循环只在遇到分隔符时才 push，最后一段永远不会被 push。漏了它，`"1.1.1."` 会被切成 3 段（`1`、`1`、`1`）从而误判合法。

## 四、IPv4 与 IPv6 的规则对照

| 检查项 | IPv4 | IPv6 |
| --- | --- | --- |
| 分隔符 | `.` | `:` |
| 段数 | **必须 4** | **必须 8** |
| 每段长度 | 1~3 | 1~4 |
| 允许字符 | `0-9` | `0-9 a-f A-F` |
| 前导零 | **禁止**（`"01"` 非法） | **允许**（`"0db8"` 合法） |
| 数值上限 | `≤ 255` | 无需换算（4 位十六进制天然 `≤ 0xFFFF`） |
| 压缩写法 `::` | 不涉及 | **不允许**（必须写满 8 段） |

**「前导零」这条最容易被整体套用** —— 很多人的直觉是「IP 都不能有前导零」，但 IPv6 恰恰允许（因为它是定长 16 位分组，`0db8` 和 `db8` 等价但都合法）。

## 五、易错点

1. **先猜类型再验证** —— 无分隔符的串会走错分支，改成「两个都试」
2. **忘查段数** —— `1.1.1`、`1.1.1.1.1`、7 段的 IPv6 全部漏过
3. **忘校验最后一段** —— 循环里只在遇到分隔符时校验，循环结束后必须再校验一次
4. **`split` 忘 push 最后一段** —— 尾部空段被吃掉，`"1.1.1."` 变 3 段
5. **`toNum` 写成 `sum += sum*10`** —— 应为 `sum = sum*10`
6. **`>= 255` 应为 `> 255`** —— 255 合法
7. **前导零判断漏 `size() > 1`** —— 单个 `"0"` 是合法的
8. **IPv6 不校验字符集** —— `gggg` 也能过
9. **把 IPv6 也当禁止前导零** —— 规则不同，`0db8` 合法
10. **`s[0]` 在空段上访问** —— 连续分隔符产生空段，访问前要判空
11. **`isdigit` / `isxdigit` 参数要转 `unsigned char`** —— 高位字节传负数是 UB

## 六、复杂度

| 维度 | 值 |
| --- | --- |
| 时间 | `O(L)`，`L` = 字符串长度，每个字符访问常数次 |
| 空间 | `O(L)`（split 出来的段）；也可以不 split，双指针原地扫，`O(1)` |

## 七、面试延伸

- **「不 split，用双指针原地扫」** —— 一边扫一边统计当前段长度、字符合法性，遇到分隔符就结算并清零，省掉 `vector<string>`
- **「真实的 IPv6 允许 `::` 压缩」** —— 那就要处理「最多一次连续冒号」，而且压缩后段数可变（`::` 代表 1 到 8 个零组）。本题故意简化了，面试时可以说一句「我知道真实规则更复杂」
- **「IPv4 带掩码 `/24`」** —— 先按 `/` 切一刀
- **「字符串转整数不要用 `atoi`」** —— `atoi` 遇到非数字返回 0，无法区分「真的 0」和「非法」，必须自己校验字符集
- **「为什么用 `isdigit` 而不是 `c >= '0' && c <= '9'`」** —— 前者受 locale 影响（某些 locale 下 `isdigit` 会有意外行为），但本题数据是 ASCII，两者等价；后者更直白、无 locale 依赖，竞赛里常用

## 附：`isxdigit` 这类字符分类函数怎么写

标准库版本就够用，**只要记得传 `unsigned char`**：

```cpp
#include <cctype>
isxdigit((unsigned char)c);     // 是十六进制数字返回非 0，否则返回 0
```

`isdigit` / `isalpha` / `isalnum` / `isspace` / `isupper` 全是同一套用法。

### 自己实现的三种写法

**写法一：三段范围判断（最直白）**

```cpp
bool myHex(char c) {
    return (c >= '0' && c <= '9') ||
           (c >= 'a' && c <= 'f') ||
           (c >= 'A' && c <= 'F');
}
```

**写法二：用位运算把大写折成小写，少写一段**

```cpp
bool myHex(char c) {
    if (c >= '0' && c <= '9') return true;
    char l = (char)(c | 0x20);        // 'A'(0x41) | 0x20 = 'a'(0x61)
    return l >= 'a' && l <= 'f';
}
```

`0x20` 就是 ASCII 里大小写唯一的差别位（`'A' = 0x41`、`'a' = 0x61`）。数字 `'0'..'9'` 是 `0x30..0x39`，这一位本来就是 1，`| 0x20` 后不变，所以不受影响 —— 这也是为什么必须先判数字、再折小写。

**写法三：查表**（对 256 个值建一次表，之后一次索引）

```cpp
bool myHex(char c) {
    static bool tbl[256];
    static bool init = false;
    if (!init) {
        for (int i = 0; i < 256; ++i) tbl[i] = myHex1((char)i);
        init = true;
    }
    return tbl[(unsigned char)c];      // ★ 索引也要转 unsigned char
}
```

### 三种写法与标准库的一致性（实测）

对**全部 256 个字节值**逐一与 `isxdigit` 比对：

```
写法一差异 0，写法二差异 0，写法三差异 0
```

判定为十六进制字符的共 **22** 个：`0123456789ABCDEFabcdef`（10 + 6 + 6）。

### ⚠️ 为什么参数必须转 `unsigned char`

标准库实现基本都用**查表**，索引就是传入的 `int`。`char` 在 x86 上是有符号的，遇到 >127 的字节（比如 UTF-8 中文首字节 `228`）会变成负数：

| 调用 | 实际传入 | 结果 |
| --- | --- | --- |
| `isxdigit((unsigned char)c)` | `228` | ✅ 返回 `0`，安全 |
| `isxdigit(c)` | `-28` | ⚠️ 负索引 → **未定义行为** |

实测本机 glibc 上 `isxdigit((char)200)` 返回 `0`（glibc 的表覆盖 `-128..255`，负值碰巧能查），**但标准不保证**，换平台或换实现就可能崩。

**结论**：调用处统一写 `(unsigned char)c`，不要赌实现宽容。

### 什么时候值得自己写

- **不想引 `<cctype>`**（嵌入式、极简环境）
- **要确定性**：自己写的范围判断不受 locale 影响（`isdigit` 等在非 "C" locale 下行为可能不同）
- **想内联**：范围判断是纯计算，编译器容易优化成几条指令

刷题和工程里**直接用标准库**就行，`(unsigned char)` 强制转换是唯一必须记住的事。
