# 哈希表冲突解决与 C# Dictionary 底层

## 两种冲突解决方式

| 方式 | 原理 | 查找最坏复杂度 | 删除注意 |
|------|------|--------------|---------|
| **链地址法（分离链接）** | 冲突元素挂同桶链表 | O(n)（全部冲突时），平均 O(1) | 直接删链表节点即可 |
| **开放地址法（线性探测）** | 冲突后向后找空槽 | O(n)，平均 O(1) | ⚠️ 不能直接置空！会破坏探测链 → 需"墓碑"标记（lazy deletion） |

> 开放地址法删除为什么不能直接置空：线性探测的查找依赖探测链连续性，直接置空会让后续本可命中的元素在探测中途"撞墙"结束，误判为不存在。

## C# Dictionary 底层（面试高频）

### 结构 = 分离链接法

- `buckets`（哈希桶数组）+ `entries`（条目数组）+ 每个 entry 的 `next` 字段
- 冲突元素通过 `next` 串成链 → **分离链接法**

### 扩容机制

- 触发条件：插入时 `count >= entries.Length`
- 新容量：`ExpandPrime(oldSize)` = **大于旧容量 2 倍的最小质数**（3 → 7 → 17 → 37 → 79…）
- 为什么用质数：让 `hash % capacity` 分布更均匀，减少碰撞
- 扩容代价：全量 **rehash**（所有元素重新计算桶位），O(n)
- 最佳实践：预知数据量时 `new Dictionary(capacity)` 预分配，避免频繁扩容

## 记忆要点

- 哈希表平均 O(1)，最坏 O(n)（链地址法）
- 链地址法未必比开放地址法省内存（每节点要存指针）
