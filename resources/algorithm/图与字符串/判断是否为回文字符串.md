# 判断是否为回文字符串

## 一、题目

给定字符串 `str`，判断它是否为回文（正着读和倒着读一样）。

```
"aba"     → true
"abba"    → true
"abcba"   → true
"ab"      → false
"abca"    → false
```

## 二、核心认知

对撞双指针：`i` 从前、`j` 从后，一次比一对，字符不等立刻失败。

**但真正的题眼在收尾**：循环有**两种**退出方式

| 退出原因 | 指针状态 | 结论 |
|---|---|---|
| 字符不等 | `i < j` | 不是回文 |
| 全部比完 | 奇数长度 `i == j`（相遇）<br>偶数长度 `i == j + 1`（交错） | 是回文 |

`i == j` 只认了「相遇」这一种。**偶数长度永远不会有相遇**，它是在 `j = i - 1` 时直接结束的 —— 这就是灯皇初版的致命错。

## 三、❌ 灯皇初版的问题

```cpp
bool judge(string str) {
    if (str.length() == 1) return true;          // ④ 冗余特判
    int i = 0;
    int j = str.length() - 1;                    // ② 无符号下溢（空串时）
    while (str[i] == str[j] && i < j) {          // ③ 边界判断放在右边
        i++;
        j--;
    }
    if (i == j) return true;                     // ① 只认相遇，漏掉交错
    else return false;
}
```

### ① `if (i == j) return true;` → 所有偶数长度回文全错（主因）

`"abba"` 走一遍：

| 步 | i | j | 比较 | 之后 |
|---|---|---|---|---|
| 1 | 0 | 3 | `a` vs `a` 相等 | i=1, j=2 |
| 2 | 1 | 2 | `b` vs `b` 相等 | i=2, j=1 |
| 3 | 2 | 1 | 先算 `str[2] == str[1]`（`b`==`b` 真），但 `i < j` 为假 → 退出 | — |

退出时 `i = 2`、`j = 1` → `i == j` 不成立 → 返回 **false**。可 `abba` 明明是回文。

穷举 `{a,b}` 长度 0~6 共 127 个串实测：

| 长度 | 用例数 | 判错数 |
|---|---|---|
| 奇数 | 42 | **0** |
| 偶数 | 85 | **15** |

那 15 个里 **14 个是全部偶数长度回文**（`aa`/`bb`、`aaaa`/`abba`/`baab`/`bbbb`、8 个六位回文），另 1 个是空串。

> 偶数长度的**非回文**反而全对 —— 因为它们一般在中间之前就 mismatch 退出了，轮不到收尾判断。
> **所以这 bug 的表现是「一部分用例过、一部分挂」，不是「全错」**，最难自查的那类。

### ② 空串：`int j = str.length() - 1` 是下溢 + 越界

`length()` 返回 `size_t`（无符号），空串时 `0 - 1` 下溢成 `18446744073709551615`，赋给 `int` 再变成 `-1`。

`str[-1]` 的 `-1` 又会转回 `size_t` 的巨大值 → **越界读**。实测：

```
普通编译：s[-1] 读到 0，程序不崩（纯属运气）
加 -D_GLIBCXX_ASSERTIONS：Assertion '__pos <= size()' failed. → 直接 abort
```

牛客这题保证 `1 ≤ n`，所以平台上看不到 —— 但这是运气，不是正确性。

### ③ `while (str[i] == str[j] && i < j)` 顺序反了

`&&` 从左往右求值，`str[i] == str[j]` **先执行**，`i < j` 只是事后检查。空串时 `j = -1`，这一步已经在越界读了。

**铁律**：安全判断永远放 `&&` / `||` 的**左边**。如果只能记一条，就记这条：

```cpp
while (i < j && str[i] == str[j])   // ✅ i >= j 时右边根本不会被求值
```

### ④ 冗余与啰嗦

- `if (str.length() == 1) return true;` 可以删 —— 单字符走循环也是 `i == j`，照样返回 true
- `if (i == j) return true; else return false;` → 直接 `return i >= j;`

## 四、正解

```cpp
class Solution {
public:
    bool judge(string str) {
        int i = 0, j = (int)str.size() - 1;      // ★ 先转 int 再减 1
        while (i < j && str[i] == str[j]) {      // ★ 边界在前
            ++i;
            --j;
        }
        return i >= j;                            // ★ 相遇(奇) 或 交错(偶) 都算通过
    }
};
```

三处改动的分工：

| 改动 | 解决 |
|---|---|
| `i < j &&` 放前面 | 空串/单字符时不越界读 |
| `(int)str.size() - 1` | 无符号下溢 |
| `return i >= j;` | 偶数长度收尾 |

`i >= j` 为什么一次覆盖两种：正常走完时，奇数长度 `i == j`、偶数长度 `i == j + 1`，两者都满足 `i >= j`；而字符不等退出时一定是 `i < j`。

## 五、必须记住的点

1. **循环的退出条件要和"结论"一一对应**。写 `while` 之前先问：这个循环会因为几种原因停下来？每种原因对应什么结论？这题两种原因，你的收尾只处理了一种。
2. **奇数"相遇"、偶数"交错"** —— 这个 1 格的差异，是所有双指针「往中间收」类题目（回文、二分、快排 partition）的共同收尾细节。
3. **安全判断必须在 `&&` 左边** —— `while (i < j && ...)`。你之前在 `最长公共前缀`（`j >= size() ||` 放左边）栽过一次，同一个知识点第二次。
4. **`size()` 是 `size_t`，减 1 前先转 `int`** —— 空容器下溢是无声的（变成 1844…615），但一定会越界。

## 六、易错点

1. **`if (i == j)` 只认相遇** —— 偶数回文全挂，而且"非回文反而全对"，迷惑性极强。
2. **空串 `size() - 1` 下溢** → 越界读，普通编译不崩，Debug（`_GLIBCXX_ASSERTIONS`）直接 abort。
3. **条件顺序** `str[i] == str[j] && i < j` —— 先取值后判界。
4. **删了单字符特判就以为漏了** —— 其实不用特判，循环本身能覆盖（但前提是收尾写对）。
5. **`if (...) return true; else return false;`** —— 直接 `return 表达式;`，少一层分支少一个错点。

## 七、复杂度

| 维度 | 值 |
|---|---|
| 时间 | `O(n)`，最多比 `n/2` 对 |
| 空间 | `O(1)`（`reverse` 后比较的写法是 `O(n)`） |

## 八、面试延伸

- **LC 125 验证回文串**：先过滤非字母数字 + 统一大小写，再对撞；`isalnum((unsigned char)c)` 注意负值 UB
- **LC 234 回文链表**：不能倒着走 → 快慢指针找中点 + 反转后半段 + 比较
- **LC 5 最长回文子串**：中心扩展 `O(n²)`；Manacher `O(n)`
- **LC 516 最长回文子序列**：不能对撞，是区间 DP `dp[i][j]`
- **回文数（LC 9）**：取数字后一半反转比较，不用转字符串
- **工程里**：`std::equal(s.begin(), s.begin() + n/2, s.rbegin())` 一行搞定
