# 重建二叉树

对应 **剑指 Offer 7 / LeetCode 105**。

> 题面：给定节点数为 `n` 的二叉树的**前序遍历**和**中序遍历**结果，请重建出该二叉树并返回它的头结点。
> 约定：节点值互不相同。

## 一、核心思路（就三步）

关键在两个遍历的结构定义：

| 遍历 | 结构 |
| --- | --- |
| **前序** | `[根] + [左子树前序] + [右子树前序]` |
| **中序** | `[左子树中序] + [根] + [右子树中序]` |

于是：

1. **前序第一个元素一定是根** —— 这是唯一入口
2. 拿着根去**中序里找位置**，它把中序**切成两半**：左边全是左子树节点，右边全是右子树节点
3. 左半边有几个节点，就说明左子树有 `leftSize` 个节点 → 前序中「根之后的 `leftSize` 个」就是左子树，剩下的是右子树
4. **对左右两段递归**

> **一句话**：前序给出「谁是根」，中序给出「左右怎么分」。两个一起用才能定出唯一结构。

## 二、下标推算（本题唯一难点）

设当前子树的区间：

- 前序 `pre[pl … pr]`
- 中序 `vin[il … ir]`
- 根在中序里的下标 `k = pos[rootVal]`
- **左子树节点数 `leftSize = k - il`**

| 子树 | 前序区间 | 中序区间 |
| --- | --- | --- |
| **左** | `[pl + 1, pl + leftSize]` | `[il, k - 1]` |
| **右** | `[pl + leftSize + 1, pr]` | `[k + 1, ir]` |

### 三个必须想明白的点

**① 左子树的前序「紧跟在根后面」**

前序是「根-左-右」，根占掉 `pl`，紧接着的 `leftSize` 个就是左子树。所以起点是 `pl + 1`。

**② 右子树前序起点是 `pl + leftSize + 1`**

那个 `+ 1` 是**跳过根**，最容易漏写。

**③ `leftSize = k - il`，不是 `k`**

因为递归到子树时，中序区间**不一定从 0 开始**。

> ⚠️ 这是最阴的坑：写 `leftSize = k` 在**根节点这一层**恰好对（因为 `il == 0`），但**一递归到子树就全错**。

**④ 左区间的右端点也必须是 `pl + leftSize`，绝不能写 `pr + leftSize`**

```cpp
root->left = build(pre, pl + 1, pr + leftSize, vin, il, k - 1);   // ❌ 内存超限
root->left = build(pre, pl + 1, pl + leftSize, vin, il, k - 1);   // ✅
```

**这是「区间不收缩」型 bug，后果不是答案错，而是程序被打爆（MLE / 爆栈）。** 推演一遍就明白了：

| 层 | `pl` | `pr` | `leftSize` | 左区间 `[pl+1, pr+leftSize]` | 收缩了吗 |
| --- | --- | --- | --- | --- | --- |
| 1 | 0 | 4 | 1 | `[1, 5]` | ❌ 右端点 5 已**越界**（合法 0..4） |
| 2 | 1 | 5 | 0 | `[2, 5]` | ❌ 区间还是没变小 |
| 3 | 2 | 5 | 0 | `[3, 5]` | ❌ 还在 |
| … | 每层 `pl+1` | **`pr` 不再减小** | | | **永不收敛** |

看出来了吗：正确写法里 `pl` 和 `pr` **两头一起往中间收**（`pl+1` 与 `pl+leftSize`），区间按 `leftSize` 缩短；而 `pr + leftSize` 相当于右端点**跟着 `leftSize` 长**，只有左端点在前移 —— 每层只挪一格，永远走不到 `pl > pr`。

于是：

1. 递归深度无限 → **`new TreeNode` 无限次调用** → 内存耗尽（LeetCode 一般报 `Memory Limit Exceeded` 或者直接崩）
2. 顺带还会**越界读** `preOrder[5]`（`operator[]` 不做检查），读到垃圾值
3. 垃圾值拿去 `pos[rootVal]` 查不到 → **`unordered_map::operator[]` 会静默插入默认值 0** → `k = 0` → `leftSize = k - il` 变成负数或 0 → 区间更加不收缩

> 这是「**静默失效**」的又一变种：没有任何报错、没有空指针，只是递归永远停不下来。**自查口诀：递归函数写完，用最小规模（2 个节点）手推一层，确认两个子区间的长度都严格小于父区间。**

## 三、代码

```cpp
class Solution {
public:
    TreeNode* reConstructBinaryTree(const vector<int>& pre, const vector<int>& vin) {
        pos.clear();
        for (int i = 0; i < (int)vin.size(); ++i)
            pos[vin[i]] = i;                     // 值 → 中序下标，O(1) 定位根

        int n = (int)pre.size();
        if (n == 0) return nullptr;
        return build(pre, 0, n - 1, vin, 0, n - 1);
    }

private:
    unordered_map<int, int> pos;

    TreeNode* build(const vector<int>& pre, int pl, int pr,
                    const vector<int>& vin, int il, int ir) {
        if (pl > pr) return nullptr;             // ① 区间空 → 没有节点

        int rootVal = pre[pl];                   // ② 前序第一个 = 根
        TreeNode* root = new TreeNode(rootVal);

        int k = pos[rootVal];                    // ③ 根在中序里的位置
        int leftSize = k - il;                   // ④ 左子树节点个数

        root->left  = build(pre, pl + 1,            pl + leftSize,     vin, il,    k - 1);
        root->right = build(pre, pl + leftSize + 1, pr,                vin, k + 1, ir);
        return root;
    }
};
```

## 四、手推一遍

`pre = [3, 9, 20, 15, 7]`，`vin = [9, 3, 15, 20, 7]`

| 调用 | rootVal | k | leftSize | 左子调用 | 右子调用 |
| --- | --- | --- | --- | --- | --- |
| `build(pre,0,4, vin,0,4)` | 3 | 1 | **1** | `(1,1, 0,0)` | `(2,4, 2,4)` |
| `build(pre,1,1, vin,0,0)` | 9 | 0 | 0 | 空 | 空 |
| `build(pre,2,4, vin,2,4)` | 20 | 3 | **1** | `(3,3, 2,2)` | `(4,4, 4,4)` |
| `build(pre,3,3, vin,2,2)` | 15 | 2 | 0 | 空 | 空 |
| `build(pre,4,4, vin,4,4)` | 7 | 4 | 0 | 空 | 空 |

结果：

```
      3
     / \
    9   20
       /  \
      15   7
```

**序列对照（这就是验证方法）**：

```
前序：[3 | 9 | 20, 15, 7]
       ↑根  ↑左子   ↑右子树（3 个）

中序：[9 | 3 | 15, 20, 7]
       ↑左子 ↑根   ↑右子树（3 个）
```

## 五、必须记住的点

**① 判定空区间用 `pl > pr`**

写成 `pl >= pr` 会把**叶子节点**也当成空区间，整棵树丢光。

**② `leftSize = k - il`**

不用 `k`。递归到子树时中序起点不是 0。

**③ 右子树前序起点 `pl + leftSize + 1`**

`+1` 不能漏，它跳过根。

**④ 用哈希表存「值 → 中序下标」**

暴力线性查找会让复杂度从 `O(n)` 退化到 `O(n²)`（链状树最坏）。

## 六、复杂度

| 做法 | 时间 | 空间 |
| --- | --- | --- |
| 中序里**线性查找**根 | **O(n²)**（链状树最坏） | O(h) 递归栈 |
| **哈希表**预处理 | **O(n)** | O(n) 哈希表 + O(h) 递归栈 |

面试策略：先写哈希表版，再补一句「不用哈希表这里是 `O(n²)`」。

## 七、易错点

0. **左区间右端点写成 `pr + leftSize`** → 区间不收缩 → **无限递归 → MLE / 爆栈**（本笔记 §二④ 有完整推演）。不是答案错，是程序被打死，最难查
1. **`leftSize = k` 而非 `k - il`** → 根层对、子树层全错（最阴）
2. **右子树起点漏 `+ 1`** → 整段错位
3. **`if (pl > pr)` 写成 `>=`** → 叶子节点丢失
4. 中序里找根用线性搜索 → `O(n²)`
5. 空数组未处理 → `n - 1` 变成 −1，索引越界
6. 前序/中序长度不同 → 非法输入，工程代码应校验
7. 节点值有重复 → 哈希表被覆盖（题目保证不重复，但要知道这是前提）

## 八、变体：后序 + 中序（LC106）

把「前序第一个」换成「**后序最后一个**」，方向全部反过来：

```cpp
int rootVal = post[pr];                    // 后序最后 = 根
int k = pos[rootVal];
int rightSize = ir - k;                    // 这里用的是右子树大小

root->left  = build(post, pl,               pr - rightSize - 1, vin, il,    k - 1);
root->right = build(post, pr - rightSize,   pr - 1,             vin, k + 1, ir);
```

**注意：后序版算的是 `rightSize`，不是 `leftSize`** —— 因为后序是「左-右-根」，根的左边紧邻的是**右子树**。

## 九、哪些遍历组合能唯一确定一棵树

| 组合 | 能否唯一还原 | 说明 |
| --- | --- | --- |
| 中序 + 前序 | ✅ | 前序给根，中序给左右切分 |
| 中序 + 后序 | ✅ | 后序给根（最后一个），中序给切分 |
| 中序 + 层序 | ✅ | 层序第一个是根，同样靠中序切分 |
| **前序 + 后序** | ❌ | **无法区分单孩子节点的左右** |

前序+后序不行，举个最小反例：`pre = [1,2]`、`post = [2,1]` —— `2` 可能是 `1` 的左孩子，也可能是右孩子，两个都满足序列。

## 十、不建树：区间即隐式节点

**核心认知**：`(pl, pr, il, ir)` 这四个整数**已经完整等价于一个子树** —— `pre[pl]` 是它的根，`leftSize = k - il` 决定了孩子怎么切。既然结构信息齐了，就**没有任何「必须落到内存」的理由**。

只要问题的产物是「某个遍历序列」而不是「树对象」，就可以直接在两段序列上递归，一个 `new` 都不用。

### 各遍历的代价

| 想要的遍历 | 怎么写 | 需要 `pos` 吗 | 额外空间 |
| --- | --- | --- | --- |
| **前序** | **直接输出 `pre[pl..pr]` 整段** | ❌ | `O(1)` |
| **中序** | **直接输出 `vin[il..ir]` 整段** | ❌ | `O(1)` |
| 后序 | 递归「左 → 右 → 根」 | ✅ | `O(h)` 栈 |
| 层序 | DFS + 按深度分桶 | ✅ | `O(n)` 桶 |
| 右视图 | DFS「根-右-左」+ 深度首现 | ✅ | `O(h)` |

**前两行值得单独看一眼**：给的就是前序 + 中序，问「前序遍历结果」—— **答案就是 `pre` 本身**，连递归都不用写；中序同理。真正需要计算的只有后序 / 层序 / 视图这类「换一种访问顺序」的产物。

### 后序为什么能算出来

因为链条自洽，一路都是算术：

```
pre[pl] = 根  →  pos 查 k  →  leftSize = k - il
                            →  左子树区间两头都定了
                            →  右子树区间两头也定了
```

`leftSize` 一旦确定，两个孩子的区间就是纯算术，不需要任何指针。

### 层序的隐式做法（容易忽略的一点）

DFS 用「根-左-右」时，**同一深度的访问顺序天然是从左到右**（左子树整体先于右子树被访问，而左子树的横坐标整体更小）。所以层序 = 按深度分桶，桶内顺序直接可用：

```cpp
vector<vector<int>> buckets;

void dfs(const vector<int>& pre, int pl, int pr,
         const vector<int>& vin, int il, int ir, int depth) {
    if (pl > pr) return;
    if (depth == (int)buckets.size()) buckets.push_back({});
    buckets[depth].push_back(pre[pl]);          // 桶内天然左→右

    int k = pos[pre[pl]];
    int leftSize = k - il;
    dfs(pre, pl + 1,            pl + leftSize, vin, il,  k - 1, depth + 1);
    dfs(pre, pl + 1 + leftSize, pr,            vin, k + 1, ir,    depth + 1);
}
```

根-左-右 → 每层从左到右；换成根-右-左 → 每层从右到左（右视图直接取 `buckets[d][0]`）。

### 三条边界（「任何方式」要打点折扣）

1. **必须能唯一确定结构** —— 前序+中序 ✅ / 中序+后序 ✅ / 中序+层序 ✅，但**前序+后序 ❌**（单孩子分不清左右），且节点值要**互不相同**
2. **只适用于「只读」** —— 要**改**结构的（旋转、删除、原地改指针、AVL/RBT 的 fixup）必须建树；要**节点身份**的（`root == p` 这类指针比较，如 LC236）也必须建树
3. **省的是常数，不是复杂度** —— 省掉 n 次 `new`（约 `24n` 字节）和一次全树 `delete`，但 `pos` 表仍是 `O(n)`；**渐进复杂度一点没变**

### 推广：隐式数据结构

「结构可以不落到指针里」是个通用套路，你在别处已经见过它：

| 结构 | 隐式表示 | 「孩子在哪」怎么答 |
| --- | --- | --- |
| 堆 / `priority_queue` | 数组下标 | **固定公式**：左 `2i`、右 `2i+1`、父 `i/2` |
| 线段树 | 数组 | 固定公式（也有动态开点版） |
| 字典树 Trie | `int[26]` 二维数组 / 双数组 | 固定值域 |
| **本文：任意二叉树** | **前序区间 + 中序区间** | **靠 `pos` 查表（没有固定公式）** |

差别全在最后一行：堆能靠公式直接算孩子位置，任意二叉树不行，必须查一次表 —— 这就是为什么本文省不掉 `pos` 的 `O(n)` 空间，而堆能真正做到 `O(1)` 额外空间。

> **一句话**：树是结构的一种表示，不是唯一表示。给定前序+中序，结构已经完整存在了；建树只是把它翻译成指针形式 —— 不需要指针形式的时候，就不必翻译。

## 十一、面试延伸

- **「为什么前序第一个一定是根」** → 前序定义就是「根-左-右」，根最先被访问
- **「为什么必须带上中序」** → 中序是唯一能提供「左右归属」信息的遍历；前序/后序只给「谁是根」
- **「如果节点值有重复怎么办」** → 哈希表不行（会覆盖）；改用「中序区间内扫描」定位，且要处理多个候选（题目一般保证互不相同）
- **「能否不用递归」** → 可以，用显式栈模拟；代码量翻倍，面试不必
- **「和序列化/反序列化的关系」** → 本质相同：[[二叉树的序列化与反序列化]] 是自己设计格式，本题是给定现成格式（前序+中序）反推
