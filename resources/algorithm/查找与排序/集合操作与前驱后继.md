# 集合操作与前驱后继

## 一、题目

维护一个集合（不重复），`q` 次操作：

| op | 格式 | 含义 |
|---|---|---|
| 1 | `1 x` | 插入 `x` |
| 2 | `2 x` | 删除 `x`（不存在则无操作） |
| 3 | `3 x` | 查询 `x` 是否在集合中 → `YES` / `NO` |
| 4 | `4` | 输出集合大小 |
| 5 | `5 x` | 输出前驱：**小于 `x` 的最大元素**，不存在输出 `-1` |
| 6 | `6 x` | 输出后继：**大于 `x` 的最小元素**，不存在输出 `-1` |

## 二、核心认知

前驱 / 后继就是**有序序列上的二分**：

- **前驱** = 「最后一个 `< x` 的元素」
- **后继** = 「第一个 `> x` 的元素」

`std::set` 底层是**红黑树**（有序），天然支持二分：`lower_bound` / `upper_bound` 都是 `O(log n)`。

所以这题的正解是 **`set` + 两个 bound 函数**，一个循环都不该有。

## 三、❌ 灯皇的写法：逻辑对，复杂度错

```cpp
int getPre(int x){
    int pre = INT_MIN;
    for (int i : s) {                  // ❌ 遍历整个集合
        if (i > pre && i < x) pre = i;
    }
    return pre == INT_MIN ? -1 : pre;
}
```

逻辑完全正确（`i < x` 且取最大），但**一次查询要扫 `n` 个元素**。

`q` 次查询 × 集合大小 `n` → **`O(nq)`**。当 `n = q = 10⁵` 时是 `10¹⁰`，必然超时。

> **80% 通过率就是这么来的**：小数据用例全过，大数据用例 TLE。这类"部分通过 + 逻辑找不出错"的现象，先怀疑复杂度。

实测（本机 `-O2`，2 万次插入 + 2 万次前驱查询，`q = 4×10⁴`）：

| 版本 | 耗时 |
|---|---|
| 线性扫描（你的） | **2.10 s** |
| `lower_bound` | **0.33 s** |

`q = 4×10⁴` 就 2 秒，`q = 10⁵` 就是十几秒 —— 必挂。

## 四、正解：用两个 bound 做二分

```cpp
#include <iostream>
#include <set>
using namespace std;

set<int> s;

int getPre(int x) {                 // 前驱：< x 的最大元素
    auto it = s.lower_bound(x);     // 第一个 >= x
    if (it == s.begin()) return -1; // 它就是开头 → 没有比 x 更小的
    --it;                           // 退一步 = 最后一个 < x
    return *it;
}

int getBack(int x) {                // 后继：> x 的最小元素
    auto it = s.upper_bound(x);     // 第一个 > x
    if (it == s.end()) return -1;   // 没有比 x 更大的
    return *it;
}

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    int q;  cin >> q;
    while (q--) {
        int op, x;
        cin >> op;
        switch (op) {
            case 1: cin >> x; s.insert(x); break;
            case 2: cin >> x; s.erase(x);  break;
            case 3: cin >> x; cout << (s.count(x) ? "YES" : "NO") << '\n'; break;
            case 4: cout << s.size() << '\n'; break;
            case 5: cin >> x; cout << getPre(x)  << '\n'; break;
            case 6: cin >> x; cout << getBack(x) << '\n'; break;
        }
    }
    return 0;
}
```

### 三个易错点

1. **`lower_bound(x)` 是「第一个 `>= x`」，不是「第一个 `> x`」**
   - 前驱要 `< x` → 用 `lower_bound` 再 `--`
   - 后继要 `> x` → 用 `upper_bound`
   - 两个对调就错：用 `lower_bound` 找后继，当 `x` 在集合里时会返回 `x` 自己。
2. **`--it` 之前必须检查 `it == s.begin()`** —— `begin()` 再往前一步是 UB（红黑树的 header 节点），不是"安全的 end"。
3. **`set` 的迭代器是双向的，只能 `++` / `--`，不能 `+1`** —— `it + 1` 编译不过（那是 `vector` 的随机访问迭代器才有的）。

## 五、为什么这题要用 `set` 而不是 `vector`

| 结构 | 插入 | 删除 | 查存在 | 前驱/后继 | 有序 |
|---|---|---|---|---|---|
| `vector`（无序） | `O(1)` | `O(n)` | `O(n)` | `O(n)` | ❌ |
| `vector`（始终有序） | `O(n)` | `O(n)` | `O(log n)` | `O(log n)` | ✅ |
| `set`（红黑树） | `O(log n)` | `O(log n)` | `O(log n)` | `O(log n)` | ✅ |

前驱 / 后继要求"动态维护有序性 + 二分"，只有平衡树能同时做到 `O(log n)`。C++ 里就是 `set` / `multiset`（要重复元素用后者）。

## 六、这题真正在考什么

**"模板题"三个字的意思是：它在考你知不知道标准库有现成的接口。**

自己写平衡树也能过，但面试/比赛里正确的做法是：

> 看到「动态插入删除 + 找前驱后继 / 第 k 小 / 排名」→ 立刻想到 `set` / `map` / `__gnu_pbds::tree`。

这就是「知道有这么个东西」和「自己造轮子」的差距 —— 后者是学习价值，前者是工程效率。

## 七、复杂度

| 操作 | 复杂度 |
|---|---|
| 插入 / 删除 / 查询 / 大小 | `O(log n)` / `O(1)` |
| **前驱 / 后继** | **`O(log n)`**（你的版本 `O(n)`） |
| 总 | `O(q log n)` |

## 八、面试延伸

- **「前驱/后继允许等于自己吗」**：本题是严格小于/大于。有些题（如平衡树模板）定义前驱为 `≤ x`，那就前驱用 `upper_bound` 再 `--`。**看题面，别背**
- **「要重复元素」**：`multiset`，`erase(x)` 会删掉**所有**等于 `x` 的，只删一个要 `erase(s.find(x))`
- **「要第 k 小 / 排名」**：`set` 做不到，用 `__gnu_pbds::tree` 或手写树状数组 / 平衡树
- **「区间内元素个数」**：`distance(lower_bound(l), upper_bound(r))` 是 `O(n)`，要 `O(log n)` 得上 pbds
- **Unity/C# 对应**：`SortedSet<T>` / `SortedDictionary<K,V>`（红黑树），`GetViewBetween` 可做范围查询
