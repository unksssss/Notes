### FireSim_URP_PC — TaskStateManager 计数隐患第 7 日观察 + 调用侧本地计数兜底

- **目标文件**: `Assets/Scripts/Author/Wt/UI/WristUI/TaskTips/TaskStateManager.cs`（17:21）+ `WristUI/TaskPanelPlus/TaskPanelPlus.cs`（17:21）
- **隐患仍在**: `SetStatus` 里 `if (status == Finished) completedTaskCount++` 无条件累加，`Init()` 只 `dataDict.Clear()` **不重置 completedTaskCount** → 任务列表二次 Init/重复置 Finished 仍会翻倍（08-31 起连续标注第 7 日）
- **今日变化**: TaskPanelPlus 全量刷新路径 `Refresh(IReadOnlyDictionary)` 改为**本地遍历计数**，不再依赖全局属性:

```cs
private void Refresh(IReadOnlyDictionary<TaskType, TaskStatus> _dataDict)
{
    int completedTaskCount = 0;          // 本地计数，绕开全局累加隐患
    foreach (var kv in _dataDict)
    {
        itemDict[kv.Key].img_Status.color = statusSpriteDict[kv.Value];
        if (kv.Value == TaskStatus.Finished) completedTaskCount++;
    }
    tmp_titleProgress.text = $"任务列表  ({completedTaskCount}/{itemList.Count})";
}
```

- **观察**: 但单任务增量路径 `Refresh(TaskType, TaskStatus)` 仍读 `TaskStateManager.Instance.CompletedTaskCount`——两路径计数来源不一致，修复只做了一半；TaskStateManager 为静态单例（`Instance { get; } = new()`）📎[[单例模式与静态类选型]]，状态变更走事件、UI 订阅刷新正是 📎[[UI-逻辑-数据分层与事件驱动]] 范式
