# 二叉搜索树转双向链表

对应 **剑指 Offer 36 / LeetCode 426**。

> 题面：输入一棵二叉搜索树，将它转换成一个排序的双向链表。
> 1. 不能创建任何新节点，只能调整树中节点指针的指向；转换完成后**左指针指向前驱、右指针指向后继**；
> 2. 返回链表中第一个节点的指针。

## 一、核心认知：这是「遍历题」，不是「结构变形题」

BST 的**中序遍历结果就是升序序列** —— 题目要的「排序链表」，答案已经藏在遍历顺序里了。

所以本题的动作只有一句话：

> **在中序遍历的「根」这一步，把当前节点接到「上一个被访问的节点」后面。**

记 `prev` = 中序序列里的前驱节点，每个节点做三件事：

```
node->left = prev;             // 当前节点的前驱
if (prev) prev->right = node;  // 前驱的后继
prev = node;                   // 自己成为下一个节点的前驱
```

💡 为什么 `left` / `right` 两个字段能直接复用？因为「前驱 / 后继」和「左孩子 / 右孩子」正好落在同两个指针槽里 —— 这正是题面说「TreeNode 可以看成一个双向链表的数据结构」的原因。

## 二、❌ 为什么「旋转拉直树」这条思路走不通

一个很容易冒出来的思路：左旋左子树、右旋右子树，把左子树变成纯左树、右子树变成纯右树，再补齐前后驱。

**方向可以理解，但工具用错了。**

| 问题 | 说明 |
| --- | --- |
| **目的错位** | 旋转是**平衡树**（AVL / 红黑树）用来**调高度**的工具，不是用来产出有序序列的 |
| **成本爆炸** | 一次旋转只挪动一条边，把高 h 的树拉成链需要 **O(n) 次**旋转 |
| **无法收敛** | 每旋一次结构就变，递归时还得重新判型（LL / LR / RL / RR），没有稳定的递归出口 |
| **极易写错** | 旋转只动两条边，且**必须把新根挂回父节点**，漏了就丢子树 |

一个写错的「左旋」反例 —— 两处硬伤：把 `y->right` 当非空用、没把新根挂回父节点：

```cpp
// ❌ 这不是旋转，是把 y 摘下来挂到 root->left，还顺手清掉了 y 的原右子树
TreeNode* RotateLeft(TreeNode* root) {
    if (!root) return nullptr;
    TreeNode* y = root->left;
    TreeNode* x = y->right;
    root->left = x;
    x->right = y;       // ← y->right 为 nullptr 时空指针解引用
    y->right = nullptr; // ← 把 y 原有的子树清掉了
    return root;
}
```

真正的左旋是「**右孩子上位当新根，原根变成它的左孩子**」，还要 `return` 新根并由调用方接住。

## 三、解法一：递归中序 + `prev` 引用（首选）

```cpp
class Solution {
public:
    TreeNode* Convert(TreeNode* pRootOfTree) {
        if (!pRootOfTree) return nullptr;              // 空树 → 空链表
        TreeNode* prev = nullptr;                      // 中序前驱
        InOrder(pRootOfTree, prev);
        // prev 现在指向链尾（最大值节点），一路向左走到底就是链头
        TreeNode* head = prev;
        while (head && head->left) head = head->left;
        return head;
    }

private:
    void InOrder(TreeNode* node, TreeNode*& prev) {    // ★ 必须传引用
        if (!node) return;

        InOrder(node->left, prev);      // 1. 左子树整条串好，prev = 左子树最右节点
        //   ↑ 递归返回后，prev 恰好落在 node 的【前驱】上

        node->left = prev;              // 2. node 的前驱
        if (prev) prev->right = node;   // 3. 前驱的后继（首节点时 prev 为空，跳过）
        prev = node;                    // 4. 自己成为新的「上一个」

        InOrder(node->right, prev);     // 5. 再串右子树
    }
};
```

### 三个必须记住的点

**① `prev` 必须是引用 `TreeNode*&`**

指针也是变量，**默认传参是拷贝**。值传递时每层递归各持一份副本，最内层改完、返回时副本随栈帧销毁 → 最外层 `prev` 仍是 `nullptr` → 找不到链头，函数返回空指针。这类 bug **编译通过、运行不崩、结果全错**，最难查。详见第六节。

**② `node->left = prev` 必须在「递归完左子树之后」执行**

这是**后序位置**，不是前序位置。顺序反了（先改 `node->left` 再递归），就顺着新指针走进前驱里，原子树直接丢失。

**③ 链头 / 链尾无需手动清空**

- 链头 = 最小节点 = 树最左下，本来没有左孩子 → `left` 已是 `nullptr` ✔
- 链尾 = 最大节点 = 树最右下，本来没有右孩子 → `right` 已是 `nullptr` ✔

因此「不创建新节点」自然满足，**连 dummy 哨兵都不用**（哨兵也算新建节点，本题禁用）。

## 四、解法二：迭代中序（显式栈）

```cpp
TreeNode* Convert(TreeNode* pRootOfTree) {
    if (!pRootOfTree) return nullptr;
    stack<TreeNode*> st;
    TreeNode* cur  = pRootOfTree;
    TreeNode* prev = nullptr;
    TreeNode* head = nullptr;

    while (cur || !st.empty()) {
        while (cur) { st.push(cur); cur = cur->left; }   // 向左压到底
        cur = st.top(); st.pop();                        // 弹出 = 访问

        if (!prev) head = cur;                           // 第一个访问的节点即链头
        else { prev->right = cur; cur->left = prev; }

        prev = cur;
        cur = cur->right;                                // 转右子树
    }
    return head;
}
```

优点：不用引用、不怕递归爆栈。面试官追问「不用递归怎么写」时直接上。

## 五、解法三：分治返回 `pair<head, tail>`

```cpp
pair<TreeNode*, TreeNode*> dfs(TreeNode* root) {        // 返回 {head, tail}
    if (!root) return {nullptr, nullptr};
    auto [lh, lt] = dfs(root->left);
    auto [rh, rt] = dfs(root->right);
    if (lt) { lt->right = root; root->left  = lt; }      // 左尾 → root
    if (rh) { root->right = rh; rh->left   = root; }     // root → 右头
    return { lh ? lh : root, rt ? rt : root };
}
```

思路最「函数式」，不依赖任何可变状态，最好推理；代价是要处理 `lt` / `rh` 为空时头尾的选取。

## 六、附：`TreeNode*&` 到底在干什么（本题最大坑）

### 语法拆解

```cpp
TreeNode*  last;   // 变量 last，类型是「指向 TreeNode 的指针」
TreeNode*& last;   // 变量 last 的【引用】—— 它的别名
```

关键认知：**指针本身也是个变量**（8 字节的格子，存的是地址）。所以它和 `int` 一样，传参默认**拷贝**。

- `void f(TreeNode* last)` → 拿到的是地址的**复印件**；函数里 `last = node` 改的是复印件
- `void f(TreeNode*& last)` → 形参 `last` 是调用方变量的**另一个名字**，操作同一块内存（不存在副本）

`&` 与取地址运算符长得一样，但前面带类型时它是**引用声明**。

### 三种把修改「带出去」的写法

| 写法 | 调用形式 | 函数内赋值 | 生效？ |
| --- | --- | --- | --- |
| `TreeNode* last` | `InOrder(root, last)` | `last = node` | ❌ 改的是副本 |
| `TreeNode*& last` | `InOrder(root, last)` | `last = node` | ✅ 改原变量 |
| `TreeNode** last` | `InOrder(root, &last)` | `*last = node` | ✅ 改原变量 |

二级指针版语义等价，但函数体要写满 `*last`，少一个 `*` 就是另一层语义；引用版语法透明，且**不能为空、不能改绑**，更安全。

### 判断准则

> **谁需要把改动带出去，谁就加 `&`。**

本题里 `node` 只读不传出 → 值传递足够；`last` 每层都要更新且最外层要用 → 必须引用。

### 与「链表相加必须接返回值」的呼应

同一条规则的两面：

```cpp
void f(ListNode* head) {
    head->next = p;   // ✅ 生效：改的是「指针指向的那个节点」的字段
    head = p;         // ❌ 无效：改的是「指针自己」这个局部变量
}
void g(ListNode*& head) {
    head = p;         // ✅ 生效：改的就是调用方的 head
}
```

- 改**指针指向的内容**（`head->xxx`）→ 值传递就行
- 改**指针本身**（`head = ...`）→ 必须用引用，或让函数 `return` 新指针且**调用处接住**

## 七、易错点

1. `prev` 用了值传递 → 编译通过但返回空指针（最阴）
2. 先改 `node->left` 再递归左子树 → 丢左子树
3. 忘记 `if (prev)` 判空 → 首节点时对空指针取 `->right`
4. 用 `while (head->left)` 找链头时没判 `head` 为空
5. 用 dummy 哨兵 → 违反「不能创建新节点」
6. 试图用旋转 → 复杂度爆炸且写不对

## 八、复杂度

| 维度 | 值 |
| --- | --- |
| 时间 | **O(n)**，每个节点恰好访问一次 |
| 空间 | 递归 / 迭代栈 **O(h)**，h 为树高；最坏（退化成链）O(n) |
| 原地性 | ✅ 只改指针，不额外分配节点 |

## 九、面试延伸

- **「为什么中序能直接得到有序？」** BST 性质：左子树 < 根 < 右子树，中序 = 左 → 根 → 右，天然升序
- **「改成单向链表怎么做？」** 只接 `right`（或只接 `left`），少一次赋值
- **「要返回链尾怎么办？」** 递归版返回时 `prev` 已在链尾，直接返回；或从头遍历到尾
- **「循环链表呢？」** 最后把链尾 `right` 接到链头、链头 `left` 接到链尾
- **变体：BST 中序 → 有序数组** 同理，只是「串指针」换成「写数组」
- **对比 Morris 遍历** 能做到 O(1) 空间、不借栈，代价是临时改指针（本题正好也在改指针，但目的不同）
