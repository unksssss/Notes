# 二分查找

## 原理

每次拿数组**正中间**元素与目标比较：

- 相等 → 命中 ✅
- 目标更大 → 扔掉左半边，搜右半边
- 目标更小 → 扔掉右半边，搜左半边

**关键：每比较一次，搜索范围减半。**

## 最少 / 最多比较次数（高频考点）

- **最少 1 次**：目标恰好是第一次取到的中间元素，首中
- **最多 ⌈log₂n⌉ 次**（也写作 ⌊log₂n⌋+1）：
  - 比较 1 次覆盖 2 个元素、2 次覆盖 4 个…比较 k 次最多覆盖 2^k 个元素
  - n 个元素要保证命中，需 2^k ≥ n → k = ⌈log₂n⌉
  - 例：1000 个元素 → 2⁹=512 < 1000 ≤ 2¹⁰=1024 → **最多 10 次**
  - 例：100 万 → 2²⁰=1,048,576 ≥ 100万 → **最多 20 次**

> 生活化理解：1~1000 猜数游戏，每次"大了/小了"，最多 10 次锁定。10 亿数据也只要 30 次。

## 复杂度

- 时间：**O(log n)**（每轮砍半）
- 空间：O(1)（迭代版）

## 前提

**数组必须有序**。无序数组要先排序（排序 O(n log n)），数据量小或频繁插入时线性查找/哈希表可能更合适。

## C# 内置实现

```csharp
int idx = Array.BinarySearch(arr, target);        // 返回索引，找不到返回负数
int idx2 = list.BinarySearch(target);             // List<T> 版本
```

底层就是二分查找，别手写。注意找不到时返回的是「插入点的按位取反」（~idx 可还原插入位置）。
