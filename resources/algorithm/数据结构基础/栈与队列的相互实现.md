# 栈与队列的相互实现

面试经典「栈与队列互转」，核心就一句话：**两者都是线性表，区别只在"哪头进出"**——栈后进先出（LIFO），队列先进先出（FIFO）。用 A 实现 B，本质是在 push/pop 的某一端**牺牲一次 O(n) 转圈来调整顺序**。

## 一、两栈实现队列（Day 15 答对 ✅）

**思路：入队栈 + 出队栈（双栈倒腾）**

```csharp
class QueueUsingTwoStacks<T>
{
    Stack<T> inStack  = new();   // 只管入队
    Stack<T> outStack = new();   // 只管出队

    public void Enqueue(T x) => inStack.Push(x);

    public T Dequeue()
    {
        if (outStack.Count == 0)           // 出队栈空了才倒腾
            while (inStack.Count > 0)
                outStack.Push(inStack.Pop());  // 整体翻个个儿
        return outStack.Pop();
    }
}
```

**为什么这样对**：入队顺序 1,2,3 → inStack 顶是 3；全部翻进 outStack 后顶变成 1 → 出队顺序 1,2,3，FIFO ✅。

| 操作 | 摊还复杂度 | 说明 |
|---|---|---|
| Enqueue | O(1) | 直接压入 |
| Dequeue | **摊还 O(1)** | outStack 有货时直接 O(1)；空了才整体倒腾一次 O(n)，每个元素只被翻一次 → 摊还 O(1) |

> 关键：**只在 outStack 空时才倒**，不要每次 Dequeue 都翻（那会变 O(n) 每次）。

### ❌ 一个真实的错误版本（2026-10-22 灯皇代码）

```cpp
int pop() {
    while (!stack1.empty()) {        // ① 每次 pop 都无脑倒
        stack2.push(stack1.top());
        stack1.pop();
    }
    stack2.pop();                    // ② 先把栈顶弹出去了
    return stack2.top();             // ③ 再取 top → 拿到的是下一个元素
}
```

**两处错，性质完全不同**：

| # | 问题 | 后果 | 实测 |
| --- | --- | --- | --- |
| 1 | **`pop()` 写在 `top()` 之前** | 队首被白白丢掉，返回的是**第二个**元素；第二次调用还会把栈弹空后再取 `top()` → **未定义行为**（`std::stack::top()` 对空栈**不抛异常**，只是 UB，和 Java 的 `EmptyStackException` 不一样） | `push(1) push(2)` 后第一次 `pop()` 返回 **2**（应为 1），第二次返回垃圾值 |
| 2 | **每次 `pop` 都无脑倒** | 新元素压到旧元素**上方** → 出队顺序错乱 | `push 1,2 → pop → push 3 → pop` 得到 `[1,3,2]`（应为 `[1,2,3]`） |

第 2 条最容易误判成「只是性能差」，其实**是正确性问题**：

```
push(1) push(2)   →  in = [1, 2↑]
pop()             →  倒成 out = [2, 1↑]，弹 1 ✅ 剩 out = [2]
push(3)           →  in = [3]
pop()  正确做法   →  out 非空，不搬 → 弹 2 ✅
pop()  错误做法   →  无脑倒 → out = [2, 3↑] → 弹 3 ❌ 顺序变成 1 → 3
```

### 不变量：`out` 从栈顶到栈底 = 队列从队首到队尾

这一句话能推出全部三条规则：

1. 新元素只能进 `in`，**绝不能进 `out`** —— 一进就挤到队首前面去了
2. `out` 空了才把 `in` 整个翻过来 —— 翻一次正好把 LIFO 倒成 FIFO
3. 出队永远只从 `out` 顶部拿

所以「先判 `out` 空」**不是省时间的优化，是正确性前提**。

### C++ 正确版

```cpp
class Solution {
public:
    void push(int node) { stack1.push(node); }

    int pop() {
        if (stack2.empty()) {                 // ★ 判空再倒：既是正确性，也是摊还 O(1) 的来源
            while (!stack1.empty()) {
                stack2.push(stack1.top());
                stack1.pop();
            }
        }
        int v = stack2.top();                 // ★ 先看一眼
        stack2.pop();                         // ★ 再扔掉
        return v;
    }
private:
    stack<int> stack1, stack2;
};
```

**顺序记法**：`top()` 是「看一眼」，`pop()` 是「扔掉」—— **必须先看再扔**；`return` 之后才 `top()` 早就来不及了。

（题目若要求支持空队列：`pop` 开头加 `if (stack1.empty() && stack2.empty()) throw runtime_error("empty");`。牛客/LeetCode 一般保证非空。）

### 实测

| 版本 | 结果 |
| --- | --- |
| 原版（`pop` 在 `top` 前 + 无脑倒） | 第一次 `pop()` 返回 2；第二次弹空栈后取 `top()` → UB |
| 只改顺序、仍无脑倒 | 出队序列 `[1,3,2]` |
| 正确版 | `[1,2,3]`；1000 元素压测严格 FIFO ✅ |


## 二、单队列实现栈（Day 34 失分点 ❌）

**思路：push 时转圈——enqueue 后把前面 size-1 个旧元素依次出队再入队，让新元素拱到队头**

```csharp
class StackUsingOneQueue<T>
{
    Queue<T> q = new();

    // 栈顶 = 队头；出栈 = 直接 Dequeue
    public void Push(T x)
    {
        q.Enqueue(x);
        int n = q.Count;
        for (int i = 0; i < n - 1; i++)   // 前面 size-1 个全部转一圈
            q.Enqueue(q.Dequeue());       // 出队再入队 = 插到队尾
    }

    public T Pop() => q.Dequeue();        // O(1)
}
```

**推演**：push 1 → [1]；push 2 → enqueue [1,2]，转 1 次：1 出队再入队 → [2,1]（队头=2=栈顶 ✅）；push 3 → [2,1,3]，转 2 次：2→尾 [1,3,2]，1→尾 [3,2,1]（队头=3=栈顶 ✅）。出栈顺序 3,2,1，LIFO ✅。

| 操作 | 复杂度 | 说明 |
|---|---|---|
| Push | O(n) | 每次都要转 size-1 圈 |
| Pop | O(1) | 队头即栈顶 |

> ⚠️ **Day 34 灯皇的坑**：选了「push 前先把整个队列反转」——**方向反了**！反转后队头变成**最老的元素**，而栈顶要的是**最新**的元素，南辕北辙。且"先反转"意味着上上次 push 的元素顺序全乱。
>
> 对比记忆：**push 后转圈 = 把新元素顶到最前（栈要新的）**；出队栈倒腾 = 把最老的翻到顶（队要老的）。一个是"最新的当栈顶"，一个是"最老的当队头"——想清楚你要哪个在队头，方向就不会反。

## 三、对称总结表

| 题目 | 手法 | 谁牺牲 | 代价 |
|---|---|---|---|
| 两栈实现队列 | 入队栈 + 出队栈，出队栈空才整体倒 | Dequeue | 摊还 O(1) |
| 单队列实现栈 | push 后转 size-1 圈把新元素拱到队头 | Push | O(n) |
| 双队列实现栈 | 主队列 + 辅助队列，push 时倒腾 | Push | O(n)（写法更繁，单队列版即可） |

**通用结论**：队列 → 栈，转圈在 **push**（让"后进"的到队头）；栈 → 队列，倒腾在 **pop/peek**（让"先进"的到栈顶）。复杂度的本质都是**摊还/均摊一次 O(n)**，总代价 O(n) 摊到 n 次操作 = 单次摊还 O(1)（两栈版严格成立，单队列版 push 每次真 O(n)）。

## 四、应用延伸：括号匹配（Day 35 S4 失分 ❌ → 已补讲）

判断只含 `()[]{}` 的字符串是否合法：`(([]){})` 合法，`([)]` **非法**（括号交叉）。

**⚠️ 错误示范（Day 35 灯皇思路）**：把字符串**平分成两半**，一半入栈再出栈去镜像匹配另一半——❌ 那是"**回文/对称**"校验，不是括号匹配。`()[]` 合法但平分后 `() ` 出栈顺序 `)(` 与 `[]` 对不上；`([)]` 非法却"看起来对称"。平分法校验的是对称性，与嵌套合法性无关。

**正确算法（逐字符扫描 + 栈）**：
```
for 每个字符 c:
  遇左括号 ( [ {  →  入栈              // 挂起，等待未来配对
  遇右括号 ) ] }  →  栈空 → 非法
                     否则看栈顶：配对 → 弹出
                                 不配对 → 非法（交叉立刻暴露）
扫描结束：栈非空 → 有左括号未闭合 → 非法；栈空 → 合法
```

**为什么栈（LIFO）天生合适**：括号的嵌套结构天然是 LIFO——**最近遇到的左括号必须最先被闭合**。栈顶永远保存"当前最内层、最紧急待闭合"的括号：`([)]` 扫到 `)` 时，栈顶是 `[`，配对失败，交叉立刻暴露。复杂度：时间 O(n)（每字符至多进出栈一次）、空间 O(n)（最坏全左括号）。

**识别套路**：看到"**最近优先 / 回溯 / 嵌套**"的结构 → 想栈；看到"**先来先服务 / 按层推进 / 最短路径**" → 想队列。

## 括号匹配：三条件 + 两边界（Day 35 失分 → Day 36 补强）

合法 = 三条件缺一不可：

1. 遇左括号 `( { [` → **入栈**；
2. 遇右括号 `) } ]` → 看**栈顶**：配对 → 弹出；不配 → **立即非法**；
3. **扫描完全串后栈必须为空** → 最终合法。

**两边界（最易漏）**：
- **栈空遇右括号 = 非法**（如 `"]("` 第一个字符就无物可出——独立于"不配对"的非法）；
- **扫完栈非空 = 非法**（如 `"(([]"` 剩两个 `(` 未闭合）。

**为什么栈天然匹配**：括号嵌套是"后打开的先关闭"，栈顶永远指向**最近未闭合**的左括号，LIFO 对齐嵌套结构。`([]}` 在 `}` 处栈顶是 `(`（该配 `)`）→ 不配非法。复杂度 O(n)/O(n)。⚠️ "平分对称"是回文校验思路，与括号匹配无关（Day 35 误区）。
