# 递归与迭代的转换

## 两者的本质区别

| 维度 | 递归 | 迭代 |
|------|------|------|
| 机制 | 函数自调用，靠**调用栈**保存每层局部状态 | `while`/`for` 循环 + 显式变量 |
| 栈溢出 | 层数深了会溢出（Unity 主线程栈默认约 1MB） | 不会 |
| 开销 | 每次调用有压栈/出栈 | 无函数调用开销 |
| 代码 | 优雅、短 | 略啰嗦 |

## 🧾 账本比喻（理解利器）

递归 = 每层"没算完的活"都记在**调用栈**（系统账本）上，算到最底层再一层层回来**结算**（回溯）。

以 `f(n) = n × f(n-1)` 为例：

```
f(4) = 4 × f(3)     ← 账本记：4 × ?  （等 f(3)）
  f(3) = 3 × f(2)   ← 账本记：3 × ?
    f(2) = 2 × f(1) ← 账本记：2 × ?
      f(0) = 1      ← 到底了！
    f(2) = 2 × 1 = 2  ← 逐层回来算账
  f(3) = 3 × 2 = 6
f(4) = 4 × 6 = 24
```

迭代 = **不欠账**：一个 `result` 变量从 1 乘到 n，中间结果永远只存一个变量，不用回头。

**判断口诀**：递归的"状态"是什么，就用什么结构显式保存——
- **不欠账（一路算到底）→ 直接循环 + 中间变量**（阶乘、斐波那契滚动递推）
- **欠账要回溯（先深入再回头处理兄弟）→ 显式栈模拟调用栈**（树的前/中/后序、汉诺塔）
- **广度推进 → 队列**（层序）

## 转换套路（重点）

1. **尾递归 → 直接改循环**：尾递归本质就是循环。`sum(n) = n + sum(n-1)` 不是尾递归（有回溯），但 `sumAcc(n, acc)` 是——递归发生在最后一步，返回值直接透传。
2. **一般递归 → 看状态类型**：
   - 只关心"结果回溯"（阶乘）→ 用**临时变量累加**
   - 先深入再逐层返回处理（树的遍历）→ **自己用栈模拟调用栈**
   - 广度优先 → **队列**
3. **显式栈里存什么**：存"还没处理完的中间状态"（节点 / 参数 / 返回点），不是只存一个值——这是迭代版遍历最容易写错的地方。
4. **迭代 → 递归**（反向）：把循环变量变成递归参数、把循环不变式变成递归出口条件即可；注意不是所有递归都好转迭代（相互递归、迷宫 DFS 回溯复杂，递归反而直观）。

## 尾递归与尾调用优化（TCO）（Day 25 教学）

**定义**：递归调用是函数返回前的**最后一步**，返回值直接透传，返回后不需要做任何计算。

```csharp
// 普通递归：n * Fact(n-1)  ← 乘号在调用前，返回后还要回来乘 → 栈帧不能释放
int Fact(int n) => n <= 1 ? 1 : n * Fact(n - 1);

// 尾递归：递归调用是最后一步，acc 累积结果直接透传 → 返回后无事可做
int FactTail(int n, int acc) => n <= 1 ? acc : FactTail(n - 1, acc * n);
```

**为什么尾递归不爆栈（在有 TCO 的语言里）**：
- 普通递归每层都在等"结果回来再乘"→ 每层栈帧都占着 → 深度 10 万爆栈
- 尾递归"返回前无事可做"→ 编译器可以把递归调用**复用当前栈帧**（尾调用优化 TCO）→ 等价于 `while` 循环
- 比喻：普通递归 = 上楼梯记账，每层都要回来补算；尾递归 = 接力赛，交棒即可退场，赛道上永远只有一个选手

**⚠️ C# 的坑（面试陷阱）**：**C# 编译器默认不做 TCO**！所以 C# 里写尾递归照样爆栈，必须手动改成 `while` 循环。选项说"尾递归一定不会栈溢出"是错的——取决于编译器是否支持 TCO（F#/Haskell/Scheme 会做，C# 不会）。

```csharp
// C# 里尾递归的正确打开方式：手动转循环
int FactLoop(int n)
{
    int acc = 1;
    while (n > 1) { acc *= n; n--; }
    return acc;
}
```

## 经典案例

### 斐波那契
- 递归版：`F(n) = F(n-1) + F(n-2)`，重复计算爆炸，O(2ⁿ)
- 迭代版：两个变量滚动递推，O(n)，不会栈溢出

### 二叉树前序遍历（迭代版，高频）
```csharp
public IList<int> PreorderTraversal(TreeNode root)
{
    var result = new List<int>();
    if (root == null) return result;
    var stack = new Stack<TreeNode>();
    stack.Push(root);
    while (stack.Count > 0)
    {
        var node = stack.Pop();
        result.Add(node.val);          // 访问根
        if (node.right != null) stack.Push(node.right);  // 先压右
        if (node.left  != null) stack.Push(node.left);   // 后压左
    }
    return result;
}
```

> **为什么先压右再压左？** 栈是 LIFO，左孩子后进栈→先出栈，访问顺序就是"根→左→右"；压反了就成"根→右→左"了。队列是 BFS（层序）的武器，DFS 迭代必须用栈——这是面试高频陷阱。
