### 其他技术产出

**最长公共子串归档**（`264a437`，14:59，5 files）

- 目标文件：`resources/algorithm/图与字符串/最长公共子串.md`（201 行，新建），同步 `resources/_index.md`、`resources/algorithm/_index.md`、`_tags.md`、`_graph.md`。
- 题面：牛客 BM66 / LeetCode 718，求两串的**最长公共子串**（必须连续），返回该子串本身。
- 灯皇初版实测 **10 例 5 错**：

  | 输入 | 期望 | 初版输出 | 症状 |
  | --- | --- | --- | --- |
  | `1AB2345CD` / `12345EF` | `2345` | `1234` | 多一个前导字符 |
  | `abcdef` / `zab` | `ab` | `za` | 完全跑偏 |
  | `abcde` / `bc` | `bc` | `c` | 少一个 |
  | `abc` / `def` | `""` | `f` | 无解却输出字符 |
  | `""` / `abc` | `""` | `c` | 无解却输出字符 |

- **根因一：把子串当子序列做。** 转移写成 `max(dp[i-1][j], dp[i][j-1])`。`dp[i][j]` 的定义是「以 `s1[i-1]`、`s2[j-1]` **结尾**的公共子串长度」，两个字符不等时这个「以它们结尾的串」压根不存在，长度只能是 0；继承来的最优值意味着结尾不是当前字符，连续性已断。**子序列的 DP 求最大值，子串的 DP 求最长后缀。**

```diff
  if (str1[i - 1] == str2[j - 1])
      dp[i][j] = dp[i - 1][j - 1] + 1;
  else
-     dp[i][j] = max(dp[i - 1][j], dp[i][j - 1]);   // ✗ 这是 LC1143 子序列
+     dp[i][j] = 0;                                  // ✓ 断链归零
```

- **根因二：答案从 dp 表最后一行反推。** 最后一行只描述「`s2` 每个字符对 `s1` 整体」的匹配情况，不含「这一段是否连续」的信息；再叠加 `max` 转移让最后一行单调递增，任何递增段都会被误认成答案 —— 这正是「多一个前导字符」的来源。正确做法是**边填边记**：

```cpp
int best = 0, endi = 0;                     // endi = 最大值所在行，对应 s1 的结束下标
if (dp[i][j] > best) { best = dp[i][j]; endi = i; }
// ...
return best ? str1.substr(endi - best, best) : "";
```

  `endi - best` 的来历：`dp[i][j]` 表示「以 `s1[i-1]` 结尾、长 `best`」，0-based 下起点 = `i - best`。

- **根因三：判据多写一个条件。** `str1[i] == str2[j] && str1[i-1] == str2[j-1]` —— 多要的条件本身就让匹配窗口错位；更隐蔽的是 `for (int i = 1; i < dp.size(); i++)` 里 `i` 最大到 `str1.size()`，`str1[str1.size()]` 越界读，而 `operator[]` 在 `pos == size()` 返回 `'\0'`（C++11 明确允许），**不崩、不报错，读到假数据**。
- **根因四：`anwser(string, vector<vector<int>> dp)` 按值传**，每次调用拷贝整张 `O(nm)` 表；应 `const vector<vector<int>>&`。
- **空间优化**：滚动数组降到 `O(m)`，但 `swap(prev, cur)` 后**必须 `fill(cur.begin(), cur.end(), 0)`** —— `cur` 是上一轮换下来的 `prev`，残留旧值会被当成「左上角」。

## Ideas

- **「能不能跳过字符」是 DP 题的第一个开关。** 子串 / 子序列 / 前缀三兄弟（LC718 / LC1143 / LC14）骨架几乎一样，差别只在 `else` 分支与起始位置。以后碰到「最长公共 X」先问这一句，比背转移式管用。
- **「不报错的错」该单独建一份清单。** 今天又添两条：`std::string::operator[]` 越界返回 `'\0'`、`substr` 第二参是长度不是下标。加上之前的 `out` 参数循环覆盖、`SetBool` 参数名不存在只打警告、`Resources.Load` 名字错一个字符返回 null —— 这些的共同点是**编译器与运行时都不吭声**，只能靠对拍和断言兜住。
- **对拍是低成本的正确性保险。** 10 组手写用例只能证明「没全错」，2 万组随机对拍才能证明「基本对」。以后 DP 题写完先写暴力解对拍，再谈优化。
- **热更主线静默 23 天，已经不是「忙别的」了。** 要么在 `HybirdCLR` 上定一个具体的小目标（比如把 `AOTGenericReferences` 从空清单跑出真内容），要么明确归档为「已学完、不再推进」，别让每日扫描继续产出一个固定为空的结果。
