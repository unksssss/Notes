#### 1. `Global/ResourcesMgr.cs` — 池 API 与路径常量收敛

```cs
public class ResourcesPath
{
    public const string Bullets = "Bullets";
    public const string Effects = "Effects";
    public const string Effect_Imp_Metal = "Imp_Metal";
    public const string Effect_Explosive_Barrel = "P_EXP_Barrel";
    public const string Roles = "Roles";
    public const string Weapons = "Weapons";
}

public GameObject GetInPool(string _path, string fileName)   // 原签名只有 fileName
{
    if (gameObjectPool.ContainsKey(fileName))
    {
        var bullsts = gameObjectPool[fileName];
        if (bullsts.Count == 0) return LoadAndCreateBullet(_path, fileName);
        GameObject go = bullsts[0];
        go.SetActive(true);
        bullsts.RemoveAt(0);
        return go;
    }
    return LoadAndCreateBullet(_path, fileName);
}
```

- **为什么改**：`"Prefab/Bullets/xxx"` 这种字符串原来散在 `Player` / `Bullet` 里各拼一遍，改名就全局搜替换；收敛成常量类后，池与加载共用一套路径规则。
- **关键设计（也是今天的隐患）**：`_path` 只参与「未命中 → `Resources.Load`」，**池的 key 仍然只有 `fileName`**。两个目录下同名资源会串池。
- `ReturnPool(fileName, go)` 只做 `SetActive(false)` + 入表，**没有去重**——同一个 GO 回池两次就会在表里出现两份引用，后续 `GetInPool` 会把同一个实例发给两个使用者。

#### 3. `Fightings/Bullet.cs` — 子弹三件事：定位、飞行、命中

```cs
public void StartMove(string _bulletName, int _attackValue, float _speed, int _range,
                      AudioClip _audioClip, string _imp_EffectName)
{
    bulletName = _bulletName;  attackValue = _attackValue;
    speed = _speed;            range = _range;
    impact_AudioClip = _audioClip;
    imp_effectFileName = _imp_EffectName;
    beginPosition = transform.position;
    isMove = true;
    MainPlayerShoot();          // ← 这里会把 transform.position 改回 ray.origin
}

private void Move()
{
    transform.Translate(ray.direction * (Time.deltaTime * speed), Space.World);
    float distance = Vector3.Distance(beginPosition, transform.position);
    if (distance > range)
    {
        isMove = false;
        ResourcesMgr.Instance.ReturnPool(bulletName, this.gameObject);
    }
    int layer = ~(1 << LayerMask.NameToLayer("Projectile"));   // 忽略自身层
    if (Physics.Raycast(ray, out var hit, distance, layer)) { /* 命中 → 特效 → 回池 */ }
}
```

- **参数化的用意**：伤害 / 射速 / 射程 / 击中音效 / 击中特效全部由调用方（`Player` 读配表）灌进来，`Bullet` 自己不碰配表 → 子弹是纯执行体，换武器不用改子弹。
- **`beginPosition` 的作用**：射程按「起点到当前位置的直线距离」算，而不是累计路程 → 斜向飞行时不会因为绕路提前超距。

#### 4. `Role/Player.cs` — 武器装配与双枪种开火

```cs
public void EquipWeapon(int ID)
{
    currWeaponItem?.gameObject.SetActive(false);              // ① 先关旧枪

    for (int i = 0; i < playerWeaponLst.Count; i++)           // ② 命中缓存 → 直接复用
    {
        if (playerWeaponLst[i].ID == ID)
        {
            currWeaponItem = playerWeaponLst[i];
            currWeaponItem.gameObject.SetActive(true);
            animatorManager.EquipeGun(ResourcesMgr.Instance.LoadAnimatorController(currWeaponItem.AnimatorType));
            muzzle = currWeaponItem.transform.Find("Muzzle");
            currWeaponItem.transform.Find("RL_01_Projectile").gameObject.SetActive(true);
            return;
        }
    }

    var config = WeaponGunManager.Instance.GetConfig(ID);     // ③ 未命中 → 读表 → 造一把
    var go = ResourcesMgr.Instance.LoadAndCreate(ResourcesPath.Weapons, config.PrefabName);
    go.transform.parent = WeaponPoint;
    go.transform.localPosition = Vector3.zero;
    go.transform.localRotation = Quaternion.identity;
    go.SetActive(true);

    var weaponItem = go.AddComponent<WeaponItem>();
    weaponItem.Init(config);
    currWeaponItem = weaponItem;
    animatorManager.EquipeGun(ResourcesMgr.Instance.LoadAnimatorController(weaponItem.AnimatorType));
    muzzle = weaponItem.transform.Find("Muzzle");
    weaponItem.transform.Find("RL_01_Projectile").gameObject.SetActive(true);
    playerWeaponLst.Add(weaponItem);
}
```

- **三级路径**（关旧 → 查缓存 → 读表新建）是「武器实例复用」的最小实现：同一把枪第二次切回来不再 `Instantiate`，动画控制器也只换 `runtimeAnimatorController` 引用。
- **`RL_01_Projectile` 的开关**是枪种区分：RPG 的预制体里带一个「看得见的弹体」，真子弹发射后要把它关掉，否则会跟着枪口一起飞。
- 开火分两支：`Fire_ARs()` 走「子弹 + 枪口火焰 + 步枪音效」，`Fire_Launchers()` 走「火箭弹 + 桶爆炸特效 + RPG 音效」，并额外把 `RL_01_Projectile` 关掉。
- `public static event Action OnFire;` 是给外部（UI / 后坐力 / 计数）留的钩子，`Fire_*` 一进来就 `OnFire?.Invoke()`。

### 其他技术产出（Part D）

> 本节记**代码里定位到的缺陷**（已定位、未修）。按灯皇的习惯只给「哪里错 + 怎么改」，不动原文件。

#### ① 子弹起点被 `StartMove` 二次覆盖（今日最重）

**目标文件**：`Assets/Scripts/Role/Player.cs` + `Assets/Scripts/Fightings/Bullet.cs`

**现象**：枪口位置明明摆了，子弹却从镜头位置飞出；近距离射击弹孔系统性偏移；有时子弹出手即消失并在角色身上炸出特效。

**根因**：调用方先摆好枪口位姿，随后 `StartMove` 内部又把它覆盖掉：

```cs
// Player.Fire_ARs
bulletGo.transform.position = muzzle.position;
bulletGo.transform.rotation = muzzle.rotation;
bullet.StartMove(...);            // 内部 MainPlayerShoot() 又执行：
                                  // this.transform.position = ray.origin;   ← 相机近裁剪面中心
```

而 `ray` 来自 `Camera.main.ScreenPointToRay(center)`，**origin 是相机**。第三人称下相机在角色背后 → 子弹「从脑后飞出」。同时 `Move()` 里的 `Physics.Raycast(ray, ...)` 起点也在相机，角色正好挡在相机与准星之间 → 掩码只排除 `Projectile` 层时，**先命中角色自己**，于是「出手即命中、立刻回池、在角色身上放特效」。

**修复方向**：起点统一换成枪口，方向用屏幕中心射线的远点反解：

```cs
Vector3 target = Camera.main.ScreenPointToRay(center).GetPoint(100f);
Vector3 dir = (target - muzzle.position).normalized;
transform.position = muzzle.position;
transform.rotation = Quaternion.LookRotation(dir);
// 射线自己建，别复用相机那条
if (Physics.Raycast(muzzle.position, dir, out var hit, range, mask)) { ... }
```

细节已归档 📎 [[Physics Raycast 与 NonAlloc]]（今日补强「弹道射线：起点该用相机还是枪口」）。

#### ② 池的 key 只按文件名 → 跨目录同名资源串池

**目标文件**：`Assets/Scripts/Global/ResourcesMgr.cs`

`GetInPool(_path, fileName)` 里 `_path` 只用于 `Resources.Load`，`gameObjectPool` 的 key 是 `fileName`。`ResourcesPath` 里已经有 `Effects` / `Bullets` 两个目录，一旦出现同名（比如子弹和特效都叫 `Imp_Metal`），取出来的就是另一类对象，`GetOrAddComponent<Bullet>()` 会往一个粒子特效上挂子弹脚本。

**修复方向**：key 用 `_path + "/" + fileName`，或干脆用 prefab 引用（`GameObject`）当 key，从根上消掉字符串。

#### ③ 超距分支缺 `return` → 同一帧二次回池（同型第 3 天）

```cs
if (distance > range)
{
    isMove = false;
    ResourcesMgr.Instance.ReturnPool(bulletName, this.gameObject);   // ← 缺 return
}
int layer = ...;
if (Physics.Raycast(...)) { ... ReturnPool(...); }                    // 可能再回一次
```

**根因**：回池后没有终止本次 `Move()`，下一段射线若命中会**第二次** `ReturnPool` 同一个 GO。`ReturnPool` 又没做去重 → 池表里同一实例出现两份 → 之后两次 `GetInPool` 拿到同一个对象，两发子弹共用一份 `Transform`，表现为「一发子弹凭空消失、另一发打出双倍伤害」。

**修复**：`ReturnPool` 后立刻 `return;`（顺带在 `ReturnPool` 里加 `if (gameObjectPool[key].Contains(go)) return;`）。

#### ④ `Random.Range(-1, 1)` 走 int 重载（同型第 3 天）

**目标文件**：`Assets/Scripts/Fightings/Bullet.cs` — `MainPlayerShoot()`

```cs
float offSetX = Random.Range(-1, 1) * accuracy;   // int 重载，上界独占 → 只有 -1 和 0
```

**根因**：两个实参都是 `int` 字面量 → 编译器选 `Random.Range(int, int)`，返回 `[-1, 1)` 的整数，即 `-1 / 0`，**恒 ≤ 0** → 弹道整体偏左下，而不是「以准星为中心的散布」。

**修复**：`Random.Range(-1f, 1f) * accuracy`。

#### ⑤ `ImpactEffect` 的回收时机与粒子时长脱钩

**目标文件**：`Assets/Scripts/Fightings/ImpactEffect.cs`

```cs
this.particle = this.transform.GetComponent<ParticleSystem>();   // 取了，但从不 Play()
audioSource.clip = _impactClip;
audioSource.Play();
Invoke(nameof(RemoveEffect), 1f);                                // 写死 1 秒
```

三个问题：
1. `particle` 字段赋值后**没有任何使用**（不 `Play()`、不读 `main.duration`）→ 要么是漏了播放，要么是纯废字段。
2. 1 秒硬编码与粒子实际时长无关：粒子 0.3s → 白等 0.7s；粒子 1.5s → 播到一半被 `SetActive(false)` 掐断。
3. 池化对象在 1 秒内被再次取用（连续命中同一位置）时，**上一次的 `Invoke` 仍在计时**，会把正在播放的新特效提前回收；而 `Invoke` 不会因为 `SetActive(false)` 自动清空，重新 `SetActive(true)` 后又接着跑。

**修复方向**：`Invoke` 时长取 `particle.main.duration + particle.main.startLifetime.constantMax`；`OnEnable`/取池时 `CancelInvoke()` 清掉上一次的待执行；`RemoveEffect` 里再判一次 `if (!gameObject.activeInHierarchy) return;`。

#### ⑥ 相机俯仰被 `LateUpdate` 每帧抹掉

**目标文件**：`Assets/Scripts/Role/Player.cs`

```cs
private void OnMouseMove(InputAction.CallbackContext ctx)
{
    float mouseX = ctx.ReadValue<Vector2>().x;
    float mouseY = ctx.ReadValue<Vector2>().y;
    transform.rotation *= Quaternion.Euler(0, mouseX * EulerSpeed, 0);          // 偏航：加在角色上
    cameraTransform.rotation *= Quaternion.Euler(-mouseY * EulerSpeed, 0, 0);   // 俯仰：加在子相机上
}

private void LateUpdate()
{
    playerCamera.position = transform.position;
    playerCamera.rotation = transform.rotation;    // ← 父节点世界旋转每帧被重写
}
```

**根因**：俯仰写在 `Main Camera`（`playerCamera` 的子节点）上，但 `LateUpdate` 每帧把父节点 `playerCamera` 的**世界旋转**改成角色的旋转 → 子节点继承的父旋转被重置，`OnMouseMove` 累加进去的 pitch 每帧清零。表现为「左右能转、上下转不动」或「视角一顿一顿」。

另有两处：`EulerSpeed = 0.1f` 直接乘鼠标 delta，**没有 `Time.deltaTime`**（帧率越高转得越慢）；pitch 也**没有 ±89° 夹取**，理论上能翻过头顶。

**修复方向**：把 pitch 累加到一个 `float pitch` 字段并夹取，在 `LateUpdate` 里**先同步位置、再一次性合成旋转**：`playerCamera.rotation = transform.rotation * Quaternion.Euler(pitch, 0, 0)`，`OnMouseMove` 只改 `pitch` / 角色 yaw。

#### ⑧ 层名拼错时 `~(1 << NameToLayer(x))` 静默退化为「几乎不过滤」

`LayerMask.NameToLayer("Projectile")` 找不到层时返回 `-1` 且**不报错**；`1 << -1` 在 C# 里按移位量取模 31 → `int.MinValue`，取反成 `0x7FFFFFFF` → 除第 31 层外全开。层名差一个字母，掩码就悄悄失效。已归档 📎 [[Physics Raycast 与 NonAlloc]]。
