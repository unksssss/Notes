# 合并两个有序数组

## 一、题目

A 的前 `m` 个位置放 `m` 个有序整数，后面还有 `m` 个空位；B 有 `n` 个有序整数。把 B 合并进 A，使 A 整体升序。

```
A = [1, 3, 5, _ , _ , _ ]   m = 3
B = [2, 4, 6]               n = 3
→   [1, 2, 3, 4, 5, 6]
```

三个约束决定了做法：

1. **A 的空间恰好是 `m + n`**（不多不少）
2. **不返回新数组**，原地改 A
3. A 在 `[0, m-1]` 有序

## 二、核心认知

**A 尾部的空位是资源，不是障碍。**

正着合并（谁小谁先写）需要从头写 A[0]、A[1]…，可这些位置本来放着还没处理的元素 —— 写进去就把人家盖掉了。

倒着合并（谁大谁先写 A 的末尾）就不会：**你要写的那一格，永远是当前还没被写过、也不属于任何未处理元素的位置**。

> 一句话：**空位在尾部，就从尾部开始填。** 这是这题唯一的题眼。

## 三、❌ 从前合并：覆盖是静默的

```cpp
int i = 0, j = 0, k = 0;
while (i < m && j < n) {
    if (A[i] <= B[j]) A[k++] = A[i++];
    else              A[k++] = B[j++];   // ❌ 这里会踩到没处理的 A[i]
}
```

`A = [1,3,5,_,_,_]`、`B = [2,4,6]` 实测输出：

```
1 2 2 2 4 6        ← 应该是 1 2 3 4 5 6
```

走到第 2 步时 `A[1]` 被 `2` 覆盖，原来的 `3` 从此消失；后面再读 `A[1]` 读到的是 `2`，于是 `2` 又被写了两次。

**这类错误不崩、不越界、不报警**，只是数据被吃掉 —— 和「大数加法的进位恒 0」一样属于静默失效。

## 四、解法一：三指针从后往前（正解）

```cpp
class Solution {
public:
    void merge(int A[], int m, int B[], int n) {
        int i = m - 1;        // A 的有效区末位
        int j = n - 1;        // B 的末位
        int k = m + n - 1;    // A 的写入位置（从最末尾开始）
        while (i >= 0 && j >= 0) {          // ★ 用 &&，任一方用完就停
            if (A[i] > B[j]) A[k--] = A[i--];
            else             A[k--] = B[j--];
        }
        while (j >= 0) A[k--] = B[j--];     // ★ 只补 B
    }
};
```

### 走一遍

`A = [1,3,5,_,_,_]`、`B = [2,4,6]`，`i=2, j=2, k=5`：

| 步 | 比较 | 写入 | 之后 |
|---|---|---|---|
| 1 | `A[2]=5` vs `B[2]=6` | `A[5]=6` | j=1, k=4 |
| 2 | `5` vs `B[1]=4` | `A[4]=5` | i=1, k=3 |
| 3 | `A[1]=3` vs `4` | `A[3]=4` | j=0, k=2 |
| 4 | `3` vs `B[0]=2` | `A[2]=3` | i=0, k=1 |
| 5 | `A[0]=1` vs `2` | `A[1]=2` | j=-1, k=0 |
| — | B 用完，退出 | `A[0]=1` 原地不动 | → `1 2 3 4 5 6` |

## 五、解法二：辅助数组（对照用）

```cpp
void merge(int A[], int m, int B[], int n) {
    std::vector<int> tmp(m + n);
    int i = 0, j = 0, k = 0;
    while (i < m && j < n)
        tmp[k++] = (A[i] <= B[j]) ? A[i++] : B[j++];
    while (i < m) tmp[k++] = A[i++];
    while (j < n) tmp[k++] = B[j++];
    std::copy(tmp.begin(), tmp.end(), A);     // 再拷回 A
}
```

写法最不容易错，代价是 `O(m + n)` 额外空间。**面试时先讲这个，再讲从后往前，把 O(1) 空间作为优化点**，比直接背答案好。

## 六、必须记住的点

1. **空位在哪，就从哪开始写** —— 尾部有空位就必须从后往前，否则覆盖。同理：如果题目给的是「B 后面有空位」，那就要从 B 的尾部开始。
2. **收尾是不对称的**：循环退出时若 `j >= 0`，说明 B 还有剩，必须补；若 `i >= 0`（B 先用完），A 剩下的元素**本来就在正确位置**，一格都不用动。补 A 那些代码是**自赋值**（此刻 `k` 恒等于 `i`，可以把 `k = i + j + 1` 这一不变式代进去验证）。
3. **循环条件用 `&&`** —— 只要有一方用完就停，剩下的交给收尾处理。写成 `||` 会在 `i == -1` 时读 `A[-1]`，直接越界。

## 七、易错点

1. **从前合并 → 静默覆盖**（最阴，见第三节实测）。
2. **`while (i >= 0 || j >= 0)`** → `A[-1]` / `B[-1]` 越界读。
3. **忘了 `k` 从 `m + n - 1` 开始**，写成 `m` 或 `n`。
4. **两个收尾 while 都写** —— 补 A 那段是自赋值，多余（不算错，但说明没想清不变式）。
5. **`m == 0`**：循环不进，`while (j >= 0)` 把 B 全搬过来，必须对。
6. **`n == 0`**：直接返回，A 不动，必须对。
7. **相等时取谁**：`A[i] > B[j]` 取 A 则相等时先取 B，取反也行 —— 值相同，不影响结果（若要"稳定"才需要纠结）。

## 八、复杂度

| 维度 | 三指针版 | 辅助数组版 |
|---|---|---|
| 时间 | `O(m + n)` | `O(m + n)` |
| 额外空间 | **`O(1)`** | `O(m + n)` |
| 是否原地 | 是 | 需要回拷 |

## 九、面试延伸

- **LC 21 合并两个有序链表**：没有"空位"问题，直接尾插 + 哑节点，`O(1)` 空间
- **归并排序的 `merge` 就是这题**：目标数组是新数组时两种方向都行；只有原地挪才有"必须从后往前"的约束
- **三路归并**：三个指针从后往前，每次取三者最大
- **k 路归并 / 外部排序**：两个大文件排序用最小堆，`O(N log k)`
- **追问「A 没有多余空间怎么办」**：那就不能 `O(1)` 原地，必须新开数组（或先整体后移 `O(m·n)`，不划算）
