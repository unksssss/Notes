### FireSim_URP_PC — 任务状态链路事件驱动化：SceneTaskBase 广播 + TaskStateManager 消费

- **目标文件**: `Assets/Scripts/Author/Lv/Task/Core/SceneTaskBase.cs`（同事侧，17:06）+ `Assets/Scripts/Author/Wt/UI/WristUI/TaskTips/TaskStateManager.cs`（我方，15:58）
- **问题描述**: 场景端任务完成后 UI 永远停在「进行中」——所有子类 `OnTaskComplete()` 只 `Debug.LogWarning`，基类无任何事件出口，数据层无从感知
- **根因分析**: 场景↔UI 之间缺少单向回传通道。原设计只有 UI→场景（`StartTask()` 调 `TaskStart()`），没有场景→UI；`TaskTipsSystem` 这条 `TaskType + UnityEvent` 总线无人 Notify
- **修复代码**（基类新增广播，带状态去重）:

```cs
/// <summary>任务状态变化事件（参数：任务类型 + 新状态）—— 供外部 UI/数据层订阅</summary>
public event Action<TaskType, TaskState> OnTaskStateChanged;

private TaskState _lastNotifiedState = TaskState.None;

/// <summary>统一的状态广播入口，内部去重，避免同一状态重复通知</summary>
protected void RaiseStateChanged()
{
    if (_lastNotifiedState == TaskStateBase) return;
    _lastNotifiedState = TaskStateBase;
    OnTaskStateChanged?.Invoke(TaskTypeBase, TaskStateBase);
}
```

- 四个状态方法（`TaskStart` / `TaskBegin` / `TaskSelect` / `TaskComplete` / `TaskReset`）末尾各补一次 `RaiseStateChanged()`；数据层订阅后即可驱动 UI 刷新 📎[[UI-逻辑-数据分层与事件驱动]]

### FireSim_URP_PC — TaskStateManager 重写：连续 7 日隐患终修复（计数 / 幂等 / 防倒退）

- **目标文件**: `Assets/Scripts/Author/Wt/UI/WristUI/TaskTips/TaskStateManager.cs`
- **背景**: `CompletedTaskCount` 隐患自 08-31 起连续标注 7 日——`Init()` 只 `dataDict.Clear()` 不重置计数、`SetStatus` 无条件 `completedTaskCount++` → 二次 Init 或重复置 Finished 会翻倍
- **修复代码**:

```cs
// ① Init：先解绑上一批实例（静态单例会一直持有已卸载场景的对象），再重置计数
foreach (var old in sceneTasksDict.Values)
    if (old != null) old.OnTaskStateChanged -= OnSceneTaskStateChanged;

dataDict.Clear();
sceneTasksDict.Clear();
completedTaskCount = 0;

// ② SetStatus：同状态直接返回，完成数只在「首次进入 Finished」时累加
public void SetStatus(TaskType taskType, TaskStatus status)
{
    bool hasPrev = dataDict.TryGetValue(taskType, out var prev);
    if (hasPrev && prev == status) return;

    dataDict[taskType] = status;

    if (status == TaskStatus.Finished && (!hasPrev || prev != TaskStatus.Finished))
        completedTaskCount++;

    OnTaskStatusChanged?.Invoke(taskType, status);
}
```

- **防状态倒退**（本次最关键的时序坑）: 基类 `TaskStart()` 内部会 `TaskReset()` → 广播一次 `NotCompleted`，会把刚设好的「进行中」冲掉。用状态等级拦截:

```cs
private static int StatusRank(TaskStatus status) => status switch
{
    TaskStatus.Finished    => 3,
    TaskStatus.GoingOn     => 2,
    TaskStatus.Interrupted => 2,   // 进行中/中断同级，可互相切换
    TaskStatus.NotFinished => 1,
    _                      => 0,
};

if (StatusRank(status) < StatusRank(GetTaskState(taskType))) return;   // 低等级不得覆盖高等级
```

- 其它加固：`Init` 用索引赋值替代 `Add`（同类型任务不再抛异常）、`StartTask` 改 `TryGetValue` 防 KeyNotFound、`BindEventSystem` 匿名 lambda 改具名方法便于解绑、新增 `SelectTask(type, isSelect)` 供 UI 驱动场景高亮
- **连带变化**: 09-09 在 `TaskPanelPlus.Refresh` 打的「本地遍历计数」临时兜底**已撤除**，回到读全局 `CompletedTaskCount`——因为根因（Init 不重置 + 无条件累加）本次已真正修掉，兜底没必要了 📎[[单例模式与静态类选型]]

/// <summary>
/// 标记任务进入「进行中」——由子类在玩家第一次与任务物体交互时调用。
/// 幂等：已进行中/已完成时直接返回，可以放心在多个交互点调用。
/// </summary>
public void TaskBegin()
{
    if (TaskStateBase == TaskState.InProgress || TaskStateBase == TaskState.Completed) return;
    TaskStateBase = TaskState.InProgress;
    RaiseStateChanged();

### FireSim_URP_PC — TaskPanelItemPlus 选中事件拆分（原实现漏判 isOn）

public event UnityAction<TaskPanelItemPlus> OnSelected;
