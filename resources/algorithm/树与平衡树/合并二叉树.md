# 合并二叉树

对应 **LeetCode 617**。

> 题面：给你两棵二叉树 `root1` 和 `root2`。想象你将其中一棵覆盖到另一棵之上，两棵树上的一些节点将会重叠。
> 合并规则：
> 1. 若两个节点**重叠**（都非空），将两个节点的值**相加**作为合并后节点的新值；
> 2. 否则，**不为 null 的节点将直接作为新二叉树的节点**（连同它的整棵子树）；
> 3. 返回合并后的二叉树的根节点。

## 一、核心认知：配对是「同侧」

合并两个节点对 `(a, b)` 时：

```
a->left  与 b->left   配对
a->right 与 b->right  配对
```

**左右各自对齐**，不做任何翻转。

这一点必须牢牢记住 —— 它和 [[对称的二叉树]] 的**交叉配对**（`a->left` 配 `b->right`）**正好相反**。两道题的递归骨架长得极像，唯一差别就是这一处；写混了就会互相串成对方的错误答案。

## 二、解法一：递归（原地合并，面试首选）

```cpp
class Solution {
public:
    TreeNode* mergeTrees(TreeNode* root1, TreeNode* root2) {
        if (!root1) return root2;        // ① root1 空 → root2 整棵子树直接接管
        if (!root2) return root1;        // ② 反之亦然
        root1->val += root2->val;        // ③ 都非空 → 值相加，复用 root1 的节点
        root1->left  = mergeTrees(root1->left,  root2->left);    // ★ 同侧
        root1->right = mergeTrees(root1->right, root2->right);
        return root1;                    // ④ 别忘返回
    }
};
```

### 必须记住的点

**① 两个 base case 必须 `return root2` / `return root1`，不能 `return nullptr`**

这是本题最容易被低估的地方。题面第 2 条规定：不重叠的节点**连同它的整棵子树**直接接管。所以一侧为空时，另一侧那棵子树整棵挂上去即可，**`O(1)` 完成，根本不用往下遍历**。

写成 `if (!root1 || !root2) return nullptr;` 会丢掉所有不重叠的子树 —— 这是本题第一大坑。

**② 配对是同侧，不是交叉**

写成 `mergeTrees(root1->left, root2->right)` 就变成「按镜像方式合并」了，与题目要求不符。

**③ 递归调用必须接住返回值**

`root1->left = mergeTrees(...)` —— 与链表递归「`head = f(head)` 必须赋值」是同一条铁律：函数返回的是**新的子树根**，不接就白算了。

**④ `root1->val += root2->val` 是原地修改（有副作用）**

LeetCode 617 允许复用 `root1` 的节点，省一次 `new`。但如果调用方之后还要用 `root1` 原树，必须先深拷贝 —— 面试时主动提一句「我原地改了入参」是加分项。

## 三、解法二：不破坏输入的版本

若题目要求**不改动入参**，每个重叠节点都新建：

```cpp
TreeNode* mergeTrees(TreeNode* a, TreeNode* b) {
    if (!a && !b) return nullptr;
    TreeNode* node = new TreeNode((a ? a->val : 0) + (b ? b->val : 0));
    node->left  = mergeTrees(a ? a->left  : nullptr, b ? b->left  : nullptr);
    node->right = mergeTrees(a ? a->right : nullptr, b ? b->right : nullptr);
    return node;
}
```

这个版本把「两个都空」也纳入统一处理，**少一个分支反而更简洁**；代价是每个重叠节点都要 `new`（空间从 `O(h)` 变成 `O(重叠节点数)`）。

## 四、解法三：迭代（队列存「成对节点」）

```cpp
TreeNode* mergeTrees(TreeNode* root1, TreeNode* root2) {
    if (!root1) return root2;
    if (!root2) return root1;
    queue<pair<TreeNode*, TreeNode*>> q;            // 队列元素是「一对」
    q.push({root1, root2});
    while (!q.empty()) {
        auto [a, b] = q.front(); q.pop();
        a->val += b->val;

        if (a->left && b->left) q.push({a->left, b->left});
        else if (!a->left) a->left = b->left;       // a 缺 → 整棵接管

        if (a->right && b->right) q.push({a->right, b->right});
        else if (!a->right) a->right = b->right;
    }
    return root1;
}
```

**两处 `else if` 的方向要看清**：

- `a` **缺**孩子 → 接管 `b` 的（连子树）
- `a` **有**孩子、`b` 没有 → **什么都不做**（`a` 的原孩子保留）

写成 `if (!a->left) a->left = b->left;` 而不加 `else` 其实也对，但显式写成 `else if` 更能表达「互斥」语义。

## 五、与《对称的二叉树》对照

| | 合并二叉树 LC617 | [[对称的二叉树]] LC101 |
| --- | --- | --- |
| 递归签名 | `f(a, b)` → `TreeNode*` | `isMirror(a, b)` → `bool` |
| base case | `!a` → **返回 `b`**（接管子树） | 都空 true / 一空一非空 false |
| **配对方式** | **同侧**：`a->left` ↔ `b->left` | **交叉**：`a->left` ↔ `b->right` |
| 值处理 | 相加 | 比较 |
| 剪枝 | 无（必须走完重叠部分） | 有（不等立即 `false`） |
| 副作用 | 原地修改入参 | 纯读 |

**记法**：合并是「**左右各自对齐**」，对称是「**左右互相对调**」。

## 六、易错点

1. **base case 写成 `return nullptr`** → 丢掉所有不重叠的子树（第一大坑）
2. **配对写成交叉**（`root1->left` 配 `root2->right`）→ 变成镜像合并，结果错
3. 忘记 `return root1` / 递归返回值没接住
4. 原地合并的副作用没意识到 → 后续复用原树时数据已被改
5. 迭代版把「`a` 有孩子、`b` 没有」也去覆盖 → 把 `a` 的原子树改没了

## 七、复杂度

| 维度 | 值 |
| --- | --- |
| 时间 | **O(min(m, n))** —— 只遍历「两棵树都非空」的重合部分；一侧为空的子树 `O(1)` 挂上 |
| 空间 | **O(min(h₁, h₂))** —— 递归深度受较矮的那棵限制（原地版） |
| 新建版空间 | O(重叠节点数) |

## 八、面试延伸

- **「怎么判两棵树是否相同」** → LC100，用 `bool` 返回 + 同侧比较，无合并动作
- **「怎么判两棵树互为镜像」** → [[对称的二叉树]]，同侧换成交叉
- **「合并 N 棵二叉树」** → 依次两两合并，或用队列层序逐层累加
- **「合并 BST」** → 结果一般不再是 BST（值相加破坏有序性），需要中序取出所有值重新建树
- **思想层面**：**「两个递归参 → 同侧还是交叉」是这类题的唯一分水岭**，先确定配对方式再写代码
