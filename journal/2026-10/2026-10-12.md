#### 1. `Assets/Editor/CreateAB.cs`（新建）—— 第一个 Editor 打包脚本

```csharp
using System.Collections;
using System.Collections.Generic;
using System.IO;
using UnityEditor;
using UnityEngine;
public class CreateAB
{
    [MenuItem("Assets/CreateAB")]
    public static void BuildAllAB()
    {
        string dir = "AssetsBundles";
        if (!Directory.Exists(dir))
        {
            Directory.CreateDirectory(dir);
        }
        BuildPipeline.BuildAssetBundles(dir, BuildAssetBundleOptions.None, BuildTarget.StandaloneWindows64);
    }
}
```

**四个关键点**：

- **为什么必须放 `Assets/Editor/`**：`Editor` 是 Unity 的**编译约定目录**，里面的脚本只编进编辑器程序集（`Assembly-CSharp-Editor`），**打 Player 时整体剔除**。脚本里 `using UnityEditor` 也只有在这个目录下才合法 —— 放普通目录会编译通过但**构建 Player 时报错**（找不到 `UnityEditor` 命名空间）。
- **输出目录为什么是 `AssetsBundles` 而不是 `Assets/AssetsBundles`**：这里给的是**相对项目根目录**的路径。AB 产物**绝不能放进 `Assets/` 内**，否则 ① 会被 Unity 当普通资源导入并生成 `.meta`；② 下一轮打包会把上一轮的 `.bundle` 再当资源打一遍，包体**滚雪球**；③ 资源引用关系可能自锁成循环依赖。这是 AB 打包的第一条工程纪律。
- **`BuildAssetBundleOptions.None` = 默认 LZMA 压缩**（全流压缩）：包体最小，但加载需整体解压 → **加载最慢、解压内存峰值最高**。要权衡包体/内存就得换 `ChunkCompression`（LZ4，128KB 块）或 `UncompressedAssetBundle`。
- **`BuildTarget.StandaloneWindows64` 硬编码**：AB **与目标平台强绑定**，换平台必须重打。工程化时应取 `EditorUserBuildSettings.activeBuildTarget` 或做成菜单参数。

#### 2. `AssetsBundles/` —— 裸 AB 产物四件套与 `main.manifest` 解读

产物 4 个文件，**两两配对**：

| 文件 | 是什么 |
| --- | --- |
| `main` | **AB 本体**（真正的资源包），包名来自资源上指定的 AssetBundle 名 |
| `main.manifest` | 该包的**清单**：CRC / 内含资源列表 / 依赖列表 / 类型树 Hash |
| `AssetsBundles` | **总 Manifest bundle**（与输出目录同名），存**所有包之间的依赖关系** |
| `AssetsBundles.manifest` | 总清单的文本形式，即运行时 `AssetBundleManifest` 的序列化来源 |

实际读到的 `main.manifest` 关键字段：

```yaml
ManifestFileVersion: 0
CRC: 3128260053
Hashes:
  AssetFileHash: { Hash: 9938ccf0c6be19970a02ee82fa672e46 }
  TypeTreeHash:  { Hash: bfc629bcbc5d327c442afdb2922bd5c7 }
HashAppended: 0
ClassTypes:
- Class: 1     # GameObject
- Class: 4     # Transform
- Class: 114   # MonoBehaviour ×2
- Class: 115   # Prefab（PrefabInstance）
Assets:
- Assets/Resources/prefab/GameObject.prefab
Dependencies: []
```

- **`CRC: 3128260053`** → 完整性校验码：远端下载后比对，防传输损坏/中间篡改。配合 `Hash` 一起，就是「**清单 MD5 判断要不要下、CRC 判断下下来对不对**」这对组合拳。
- **`Dependencies: []`** → 该包**不依赖任何其他包**，所以 `LoadFromAB` 里可以直接 `LoadAsset`，不需要先加载依赖包。一旦这里有内容，加载顺序就必须**先父后子**（否则材质洋红）。
- **`ClassTypes`** → 包里出现了哪些原生类型（GameObject / Transform / MonoBehaviour / Prefab），是 Unity 反序列化时按 ID 建对象用的表。
- ⚠️ **一个实打实的坑**：资源路径是 `Assets/Resources/prefab/GameObject.prefab` —— 这个 prefab **既躺在 `Resources/` 目录里、又被指定了 AssetBundle 名** → 它会被打**两份**：一份进 `resources.assets`（Resources 构建流程），一份进 `main`（AB 构建流程），**包体直接翻倍**。`Resources` 与 `AssetBundle` 不应同时收同一个资源。

#### 3. `Assets/AOT/LoadFromAB.cs`（新建）—— 裸 AB 加载闭环

```csharp
public class LoadFromAB : MonoBehaviour
{
    void Start()
    {
        AssetBundle ab = AssetBundle.LoadFromFile("AssetsBundles/main");
        var go = ab.LoadAsset<GameObject>("GameObject");
        Instantiate(go);
        Debug.Log(go.name);
    }
}
```

**做了什么**：同步加载 AB 文件 → 从包里取 `GameObject` 资产 → `Instantiate` 进场景。三行就是 AB 加载的全部骨架（**加载包 ≠ 加载资源 ≠ 实例化**，三步分离是面试高频考点）。

**⚠️ 三个问题（当前是「先跑通」阶段，属已知技术债）**：

1. **路径只在 Editor 里成立**：`LoadFromFile` 的相对路径是相对 `Application.dataPath`（即 `<项目>/Assets`）解析的，而 AB 实际在项目根 `AssetsBundles/`。**Editor 下能跑，构建 Player 后必然失败**（Player 里根本没有 `AssetsBundles/` 这个目录）。正确落点只有两个：随包的 `Application.streamingAssetsPath`，或远端下载后落到 `Application.persistentDataPath`。
2. **`LoadAsset<T>(name)` 传的是资产名不是路径**：这里资产名 = **资源文件名去扩展名**（`GameObject.prefab` → `"GameObject"`）。**找不到时 `LoadAsset` 不抛异常、只返回 null** → 接着 `Instantiate(null)` 才炸，报错点离根因很远。必须补 `if (go == null)` 判空（`ab` 本身在文件缺失时也会是 null）。
3. **没有 `ab.Unload(false)`**：AB 包头 + 内存中的资源实例会一直常驻到场景卸载。正确顺序是 **先 `Instantiate` 再 `Unload(false)`**（`false` 卸包头、保实例；`true` 会连实例一起销毁 → 场景里正在用的东西变粉红）。

📎 [[AssetBundle 生命周期与卸载语义]]（`Unload(false/true)` 两档位语义 + 粉红材质排查三方向）

## Ideas

- **AB 输出目录工程化三连**：① `BuildTarget` 改取 `EditorUserBuildSettings.activeBuildTarget`（或做成菜单参数）；② 输出目录挪到项目外或 `StreamingAssets`；③ 加 `BuildAssetBundleOptions.ChunkCompression` 开关 —— 顺手就能把「压缩格式三选」做成可切换的实测脚本。
- **压缩格式实测（正好是 Day 43 Q1 的答案）**：同一个 prefab 分别用 LZMA / LZ4 / Uncompressed 打三次，记录**包体大小、加载耗时、内存峰值**三个数。预期结论方向：LZMA 最小最慢、LZ4 折中（推荐）、Uncompressed 最快最大 —— 用数字代替背书。
- **加载 API 选型实验**：`LoadFromFile` / `LoadFromFileAsync` / `LoadFromMemory` / `LoadFromStream` 四者分别对应什么场景（本地同步 / 本地异步不卡帧 / 网络下载后从内存 / 流式），是资源管理面经的固定考点，而资源库里这一块完全空白。
- **消除双份包体的验证**：把 `Assets/Resources/prefab/GameObject.prefab` 移出 `Resources/`，重新打包对比 `main` 与 `resources.assets` 的大小变化 —— 直观感受「Resources 与 AB 不能同时收」这条纪律的代价。
