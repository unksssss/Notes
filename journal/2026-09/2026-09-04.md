### C++ 数据结构线 — 红黑树理论 + 手搓启动（下午会话）

- 背景：08-31 完成 AVL 后树系进阶，灯皇主动点名红黑树；今日无 Unity 项目改动，下午集中红黑树理论学习 + 手搓第一步。
- **五条性质**：① 节点非红即黑 ② 根黑 ③ NIL 空叶子算黑 ④ 禁"红红"（红节点两孩子必黑）⑤ 任一节点到后代 NIL 的各路径黑高相等。
- **黑高推导**：全黑路径最短 = 黑高 h，红黑交替时最长 ≤ 2h（每层至多夹 1 红）→ 树高 ≤ 2·log₂(n+1)，O(log n) 有保证（比 AVL 略松）。
- **插入三 case（父红才触发，看叔节点）**：
  - Case1 叔红 → P/U 变黑、G 变红，**G 当新节点上推循环**（可能一路到根，最后染根黑）
  - Case2 叔黑 + 之字（新节点与 P 方向相反）→ 绕 P 旋转"掰直"，进入 Case3
  - Case3 叔黑 + 一字（方向相同）→ 绕 G 旋转 + P/G 换色，**插入修复结束**（旋转封顶 2 次）
- **颜色意义 = 2-3-4 树同构**：黑 = 占层的格子、红 = 格子内不占层的挂件；禁红红 = 每格 ≤3 key；Case1 = 满格劈开中键上提。**旋转仍看结构，颜色只是 1 bit 失衡记账**（AVL 用 int height、RBT 用 bool color）——纠正"靠颜色决定旋转"的认知偏差。
- **AVL vs RBT 纠错备忘**：AVL **插入**至多 1 次单/双旋（O(log n) 在沿途 height 刷新，非旋转次数）；AVL 痛点是**删除**最坏 O(log n) 次旋转；RBT 收益 = 无违规时插入零维护 + 旋转封顶 2~3 次 + 变色 O(1)/层。
- **教学表达踩坑**：首版抽象字母图（G/P/U/X 拼贴）看不懂 → 换真实数字实例（插 14，P=13/G=15/U=17；Case1 三帧变色演变、Case2/3 旋转实例）→ 仍不够 → 交付**交互式红黑树插入演示器**（HTML widget：逐帧执行插入/染根黑/判父黑/Case1 上推/Case2 掰直/Case3 旋转换色，整树实时重绘 + 合法性检查；预设序列 A=1~9 递增触发 Case3/Case1/根黑、B=30 40 35 25 20 10 45 50 含之字双旋）。教学画图"具体 > 抽象"：字母符号 < 真实数字动图 < 可交互逐步执行。
- **手搓进度**：`D:\CppTest\hello\Tree\RBT.cpp` 已落地（RBNode 带 parent + 红黑枚举 + RBT 类 + 普通 BST 插入雏形，fixInsert/rotate 空壳待填，尚未编译）。演示器 JS 逻辑与后续 C++ fixInsert 一一对应，可当验证基准。
