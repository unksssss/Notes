### 其他技术产出（Part D）

#### 一、《排序算法》快排章节大扩：四种写法 + 实测数据

**目标文件**：`D:\Notes\resources\algorithm\查找与排序\排序算法-快排归并堆排.md`
**提交**：`973c64e`（16:52），1 file changed，**+144 −13**，正文 115 → 246 行

**问题描述**：原快排节只有 20 行——「分治三步走 + 复杂度 + 不稳定 + 随机选基准/三数取中」四句口诀。能背，但**不能解释为什么**：为什么递归边界是 `j` 不是 `i`、为什么 pivot 取中间就够、Lomuto 到底怎么退化的。这类口诀在面试追问一层就崩。

**改了什么**（四个小节 + 两张表）：

| 小节 | 内容 | 关键点 |
| --- | --- | --- |
| 1.1 Hoare 划分 | ★ 推荐直接背的版本 | `i = l-1` / `j = r+1` + `do-while` = **天然哨兵**；`a[i] < p` 必须严格小于；递归边界用 `j` / `j+1`；pivot 取**中间位置** |
| 1.2 Lomuto 划分 | 最好懂、讲解用它 | pivot 取最右 → 有序 / 全相同都退 `O(n²)`，附退化实测表 |
| 1.3 三路划分 | `[l,lt) < p \| [lt,i) == p \| (gt,r] > p` | 等值段**完全不再参与递归**，1e6 全相同 0ms |
| 1.4 迭代版 | 显式栈 + 短半递归 / 长半循环 | 尾递归消除，栈深恒 `O(log n)` |

**根因分析（四个必须理解的点）**

1. **为什么 `i` 从 `l-1`、`j` 从 `r+1` 起？** 配 `do ++i` 的「先加再用」，首次比较正好是 `a[l]` 与 `a[r]`；而 `p` 取自区间**内部**，所以 `a[i] < p` 一定会在两端停住 —— 天然哨兵，不用额外写 `i <= r` 防越界。
2. **为什么不能写 `a[i] <= p`？** 全相同数组里 `i` 会一路冲到底，越界崩溃。
3. **为什么递归边界是 `j` 和 `j+1`？** 交叉后 `j` 是左半最后一个下标、`i` 是右半第一个下标；用 `j` 才能保证 `[l,j]` 与 `[j+1,r]` 两段都非空。**这是最容易写成死循环的地方。**
4. **为什么 pivot 取 `a[(l+r)>>1]`？** 有序数组里中间位置的值恰好是中位数，划分最均衡 —— **免费的抗退化**，不需要随机化。

**实测数据（本机 `g++ -O2`）**

Lomuto vs Hoare（有序输入）：

| n | Lomuto 有序 | Hoare 有序 | Lomuto 全相同 |
|---|---|---|---|
| 2000 | 2.05 ms | ~0 ms | ~0 ms |
| 4000 | 5.39 ms | ~0 ms | 2.65 ms |
| 8000 | 19.85 ms | ~0 ms | 11.44 ms |
| 16000 | **77.46 ms** | **1.01 ms** | **45.44 ms** |

n 每翻倍耗时 ×4 —— 这就是 `O(n²)` 的指纹。`n = 1e5` 会到十几秒。

四写法横评（1e6 元素）：

| 场景 | Hoare | 随机 pivot + 尾递归 | 三路 | 迭代 |
|---|---|---|---|---|
| 随机 | 66 ms | 75 ms | 77 ms | 66 ms |
| 全相同 | 8 ms | — | **0 ms** | — |
| 已升序 | 8 ms | 33 ms | — | — |
| 已降序 | 8 ms | — | — | 10 ms |

**结论（与旧口诀相反）**：随机化**不是免费的** —— 随机数据下 Hoare（中间 pivot）最快，加了 `rand()` 开销反而慢 15%。所以「优先中间位置 pivot，不要无脑随机化」。三路的收益在**等值段排除**而非更快（随机数据 77ms 反而慢于 66ms）；迭代版的收益在**栈深上限**而非速度（66ms 持平）。

**五个坑速查**

| 坑 | 表现 |
|---|---|
| 递归边界用 `i` 而不是 `j` | 死循环 / 栈溢出 |
| `while (a[i] < p)` 写成 `<=` | 全相同数组越界崩溃 |
| pivot 固定取 `a[l]` 或 `a[r]` | 有序输入退化 `O(n²)` |
| 漏掉 `if (l >= r) return` | 空区间无限递归 |
| 递归先处理长的那半 | 深度 `O(n)`，1e5 以上易爆栈 |

**为什么这么写**：主推版本选 Hoare（能直接背、工程上最快），Lomuto 降级为「讲解版」而不是「推荐版」；所有复杂度结论都挂本机实测数字 —— `77ms vs 1ms` 比「O(n²)」三个字有说服力得多，也顺手把「随机化必做」这条过时口诀推翻了。配套更新 `resources/_index.md` 该条 summary 与 `_tags.md` 算法节条目，`updated` → 2026-10-26。

## Ideas

- **「中间位置 pivot」是位置选择，不是随机化**。旧口诀把「抗退化」和「随机化」绑在一起，实测证明前者单独就够。以后遇到「教科书优化」，先问一句「它防的是哪个前提」。
- **哨兵技巧依赖前提**：`i=l-1 / j=r+1` 之所以不越界，是因为 `p` 取自区间**内部**。若改成 `p = a[l]`，前提立刻崩 —— 技巧和前提必须绑着记，单记技巧就是埋雷。
- **实测表是笔记里最抗遗忘的部分**。今天这张表把「n 翻倍 ×4」变成了可验证事实；复杂度结论以后尽量带本机数据，而不是只写大 O。
- **三路划分的收益常被说错**：它不是「更快」，是「等值段不递归」。随机数据下它比 Hoare 慢 11ms，但全相同数据下 0ms vs 8ms —— 优化项要标清适用场景。
- **算法区 39 篇 vs unity/performance 只有 1 篇**：知识库结构明显偏斜，性能方向（Profiler 实战 / 内存 / GC）几乎是空的，而这是面试与工程双高频。
