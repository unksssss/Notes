# 最小覆盖子串

## 一、题目

在 `S` 中找出**最短的连续子串**，使它包含 `T` 的全部字符（含重复次数）。无解返回空串。

```
S = "XDOYEZODEYXNZ", T = "XYZ"    → "YXNZ"
S = "ADOBECODEBANC", T = "ABC"    → "BANC"
S = "ab",           T = "A"       → ""
```

## 二、核心认知

**变长滑动窗口**，两个指针各管一件事：

- `right` **膨胀**：直到窗口满足条件（包含 T 的全部字符）
- `left` **收缩**：在满足的前提下尽量往右挪，每挪一步都是一个"更短的候选答案"

```
right 一路向右 ──→
     [ left ...... right ]   不满足 → right 右移
     [   left .... right ]   满足   → 记答案，left 右移
```

**答案必须在「满足」的那一侧记录**，也就是收缩循环里。

灯皇的思路（哈希表 + 双指针 + 左右各管一件事）**完全正确**，问题全在边界。

## 三、三处独立错误

穷举 6552 组（S 长度 1~6 over `{a,b,c}` × 6 个 T），阶梯修复实测：

| 修复到哪一步 | 错组数 | 该 bug 贡献 |
|---|---|---|
| 原版 | **6552 / 6552** | — |
| ① `length` 补 `+1` | 2981 | `-1` **3571** |
| ② 无解返回空串 | 1196 | 兜底 **1785** |
| ③ `start` 条件更新 | **0** | 错配 **1196** |

### ① `length = right - left` 少 1

```cpp
length = min(length, right - left);       // ❌
length = min(length, right - left + 1);   // ✅ 闭区间 [left, right]
```

`left` 和 `right` 都是**下标**，闭区间长度是 `right - left + 1`。

你的窗口明明是 `[left, right]`，却按 `right - left` 记账 —— **每个答案都短一个字符**：

```
S="a",  T="a"      → 你的 ""    正确 "a"
S="ab", T="b"      → 你的 ""    正确 "b"
S="ADOBECODEBANC" T="ABC" → 你的 "BAN"  正确 "BANC"
```

这一条让 **6552 组全错**，所以看起来"完全不对"，其实只差一格。

### ② 无解时 `substr(start, INT_MAX)` 返回整串

```cpp
int length = INT_MAX;
...
return S.substr(start, length);   // ❌ length 还是 INT_MAX
```

`substr(pos, n)` 的 `n` 超过剩余长度时会**截到串尾**，不会返回空串。于是「压根没有解」的用例返回了从 `start` 到结尾的一大段：

```
S="ab", T="A"    → 你的 "ab"    正确 ""
S="a",  T="aa"   → 你的 "a"     正确 ""
```

**兜底值必须单独判**：

```cpp
return length == INT_MAX ? string("") : S.substr(start, length);
```

### ③ `start = left` 无条件更新（最隐蔽）

```cpp
start  = left;                          // ❌ 只要窗口有效就覆盖
length = min(length, right - left);     // length 却取 min
```

`start` 是"赋值"，`length` 是"取最小" —— 两者不同步！

先找到一个长度 4 的窗口（`start = 9`），后面又碰到一个长度 10 的窗口（`left = 0`）：

```
start = 0;  length = min(4, 10) = 4;   // 结果 substr(0, 4) —— 既不是旧答案也不是新答案
```

**必须一起更新**：

```cpp
if (right - left + 1 < length) {
    length = right - left + 1;
    start  = left;
}
```

这一条贡献 1196 组错，而且输出是"某种杂交"，`cabwefgewcwaefgcf` / `cae` 输出 `aef`（正确 `cwae`）就是这个味道。

## 四、正解（标准两层循环 + matched 计数）

```cpp
class Solution {
public:
    string minWindow(string S, string T) {
        unordered_map<char, int> need, window;
        for (char c : T) ++need[c];

        int required = (int)need.size();   // 需要满足的「字符种类数」
        int matched  = 0;                  // 已经满足的种类数
        int left = 0, start = 0, best = INT_MAX;

        for (int right = 0; right < (int)S.size(); ++right) {
            char c = S[right];
            if (need.count(c)) {
                if (++window[c] == need[c]) ++matched;   // ★ 只在「刚好达标」时 +1
            }
            while (matched == required) {                 // 满足 → 收缩
                if (right - left + 1 < best) {            // ★ 先记答案
                    best  = right - left + 1;
                    start = left;
                }
                char d = S[left];
                if (need.count(d)) {
                    if (window[d] == need[d]) --matched;  // ★ 先判「要破了」再减
                    --window[d];
                }
                ++left;
            }
        }
        return best == INT_MAX ? string("") : S.substr(start, best);
    }
};
```

### 为什么 `==` 而不是 `>=`

`window[c]` 可能超过 `need[c]`（窗口里某字符多了）。若用 `>=`，每加一次都会 `matched++`，导致**重复计数**，`matched == required` 就再也不会精确成立。

所以只在 **`++window[c]` 之后恰好等于 `need[c]`** 那一刻 `+1`；收缩时对称地，只在 **减之前 `== need[c]`**（说明马上要破了）那一刻 `-1`。

## 五、你的 `IsValid()` 为什么该换掉

```cpp
bool IsValid() {
    for (auto pair : need)              // 每轮 O(|T|)
        if (window[pair.first] >= pair.second) valid++;
    return valid == need.size();
}
```

正确，但**每轮都要重扫一遍 `need`** → 总复杂度 `O(n · |T|)`。

用 `matched` 计数后，每次膨胀/收缩都是 `O(1)`，总复杂度降到 `O(n + |T|)`。这是滑动窗口题的标准写法，也是面试官会追问的点。

另外 `window[pair.first]` 用的是 `operator[]` —— **key 不存在会插入一个 0**，悄悄改大你的 map。只读场景要用 `.at()` 或先 `find`。

## 六、必须记住的点

1. **闭区间长度 = `right - left + 1`** —— 两个指针都是下标不是长度。这一条你已经栽过不止一次（`判断是否为回文字符串` 的收尾也是差 1 格）。
2. **`start` 和 `length` 必须同一个 `if` 里更新** —— 一个赋值一个取 min，早晚错配。
3. **`matched` 只在"刚好等于"时变化** —— `==` 不是 `>=`，否则重复计数。
4. **兜底值（`INT_MAX`）要单独判** —— `substr` 的越界参数是"截断"不是"报错"，会悄悄给出半截答案。

## 七、易错点

1. **`right - left` 少 1** → 全部答案短一个字符，表现为"看起来全错"，最难往"只差一格"上想。
2. **`start` 无条件赋值** → 输出既不是旧答案也不是新答案，是"杂交体"。
3. **无解返回整串** → `substr(start, INT_MAX)` 静默截断。
4. **`IsValid` 用 `operator[]`** → 意外插入 `0` 值 key，把 `window` 污染（也会让"用 `window.find` 判断是否回撤"的判断跟着失准）。
5. **`right++` 之后才访问 `S[right]`** —— 最后一轮会读到 `S[size()]`（`std::string` 保证返回 `'\0'`，不崩但绕）。规范写法是**先取 `S[right]`、再决定要不要 `++`**（正解里用 `for` 循环天然避开）。
6. **`need` / `window` 是成员变量且不复位** —— 同一个 `Solution` 对象调用两次就会累加脏数据。牛客一般每个用例新建对象，但这是实打实的类设计坑；写成局部变量最稳。

## 八、复杂度

| 版本 | 时间 | 空间 |
|---|---|---|
| 你的（`IsValid` 重扫） | `O(n · \|T\|)` | `O(\|T\|)` |
| 正解（`matched` 计数） | `O(n + \|T\|)` | `O(\|T\|)` |
| 字符集固定时用 `int[128]` | `O(n)` | `O(1)` |

`left` 和 `right` 各自只前进不后退，总移动 `≤ 2n`，所以是线性的。

## 九、面试延伸

- **LC 567 字符串的排列**：窗口**定长** `|T|`，只需判断计数是否全等，不需要收缩循环
- **LC 438 找到所有字母异位词**：同上，窗口每滑一步比一次
- **LC 3 无重复字符的最长子串**：条件是"窗口内无重复"，收缩判据是 `window[c] > 1`
- **LC 340 至多包含 K 个不同字符**：把"种类数"当作窗口状态维护
- **LC 992 K 个不同整数的子数组**：`恰好 K 个 = 至多 K 个 − 至多 K−1 个`
- **字符集是 ASCII 时**：`unordered_map` 换 `int need[128]`，去掉哈希开销，常数小一半

## 十、补记：第二版（2026-11-16 11:45）—— 改出两个新问题

灯皇按建议重写了，加了 `matched` 计数，但引入两处：

### ① `if (length < right - left + 1)` 比较方向反了

```cpp
if (length < right - left + 1) {        // ❌ 「当前最优更短」才更新 → 记的变成最长
    length = right - left + 1;
    start  = left;
}
if (right - left + 1 < length) { ... }  // ✅
```

`length` 初值是 `INT_MAX`，而 `INT_MAX < 任何窗口长度` 恒为假 —— **一次都不会更新**，最后 `length` 仍是 `INT_MAX`，直接返回 `""`。

题面用例 `XDOYEZODEYXNZ` / `XYZ` 实测输出：**空串**（正确 `YXNZ`）。

### ② 初始 `macthed++` 无条件，遇到重复字符直接崩

```cpp
if (need.find(S[0]) != need.end()) {
    window[S[0]]++;
    macthed++;      // ❌ 没判断「刚好达标」
}
```

`S[0]` 在 `need` 里 ≠ 它的数量已经够了。若 `T` 里某字符要求 ≥ 2 个，`matched` 会被提早算满：

```
S = "XX", T = "XX"     need[X] = 2
初始 window[X] = 1 → matched = 1 == required → 立刻进收缩分支
收缩时 window[X] = 1 != need[X] = 2 → matched 不减少 → 永远「满足」
→ left 一路涨过串尾 → S[left] 越界 → Segmentation fault
```

**实测他的原始文件在这组输入上直接 `Segmentation fault`（退出码 139）**，不是答错，是崩溃。

```cpp
if (need.count(S[0]) && ++window[S[0]] == need[S[0]]) ++matched;   // ✅
```

### 实测（8736 组：S 长度 1~6 over {a,b,c} × 8 个 T，含 `aa`/`aab`/`cc` 这类重复字符）

| 版本 | 错组数 | 其中「收缩越界」（会崩） |
|---|---|---|
| 第二版原样 | **5958** | **728** |
| ① 改比较方向 | 960 | 728 |
| ② 再修初始 matched | **0** | **0** |

两个 bug 都独立成立：只修 ① 仍有 728 组会越界 —— `matched` 一旦算错，收缩分支就失去终止条件。

### 从这轮学到的两条

1. **初始状态必须和「增量更新」用同一套判据**。循环里写的是「`++window[c] == need[c]` 才 `+1`」，那初始化 `[0,0]` 时也必须用同一个判断。**同一个量有两处来源，判据就必须一致。**
2. **比较方向反了没有编译错误、也没有警告**。`a < b` 和 `b < a` 都合法。写完 `if (x < y)` 用中文念一遍：「x 比 y 短就更新」—— **x 到底是"当前最优"还是"新候选"？** 这里写反，加上 `INT_MAX` 的初值，整个函数永远不更新。
