# 位运算

## 一、六个运算符

| 运算符 | 名字 | 作用 |
|---|---|---|
| `&` | 按位与 | 都是 1 才 1（**取位 / 清位**用） |
| `\|` | 按位或 | 有一个 1 就 1（**置位**用） |
| `^` | 按位异或 | 不同才 1（**翻转位、无进位加法**） |
| `~` | 按位取反 | 0↔1（配合与用来清位） |
| `<<` | 左移 | 整体左挪，低位补 0 = **×2ⁿ** |
| `>>` | 右移 | 整体右挪 = **÷2ⁿ**（向下取整） |

---

## 二、地基：补码

这是理解所有位运算的前提。**整数在内存里存的是补码**，正数补码 = 原码，负数是「取反加一」。

实测（32 位 int，每 4 位空一格）：

```
          5 -> 0000 0000 0000 0000 0000 0000 0000 0101
         -5 -> 1111 1111 1111 1111 1111 1111 1111 1011
         -1 -> 1111 1111 1111 1111 1111 1111 1111 1111
         -2 -> 1111 1111 1111 1111 1111 1111 1111 1110
 2147483647 -> 0111 1111 1111 1111 1111 1111 1111 1111
-2147483648 -> 1000 0000 0000 0000 0000 0000 0000 0000
```

三个推论直接就能用：

1. **`-1` 是全 1**（32 个 1）。因为 `-1 + 1 = 0`，而全 1 加 1 恰好全部进位溢出成 0。
2. **`~x = -x - 1`** —— 因为 `x + ~x = 全 1 = -1`。
3. **最高位（bit31）是符号位**：0 正、1 负。`INT_MAX` 是「0 + 31 个 1」，`INT_MIN` 是「1 + 31 个 0」。

> 这也是为什么 `LONG_MAX` 在 Windows 上只有 32 位 —— 之前踩过的那个坑，根子在这里。

## 三、取位与改位六件套（★ 背这张表）

以 `x = 180`（二进制 `1011 0100`）、`k = 2` 为例：

| 目标 | 写法 | 说明 |
|---|---|---|
| **取第 k 位** | `(x >> k) & 1` | 右移把那一位挪到最低，再与 1 |
| **置 1** | `x = x \| (1 << k)` | 该位变 1，其他位不变 |
| **清 0** | `x = x & ~(1 << k)` | `~(1<<k)` 只有该位是 0，与完就清掉了 |
| **翻转** | `x = x ^ (1 << k)` | 异或 1 取反、异或 0 不变 |
| **最低位的 1**（lowbit） | `x & (-x)` | 见第四节 |
| **消掉最低位的 1** | `x & (x - 1)` | 每消一次少一个 1，可用来数 1 的个数 |

实测（x = 180）：

```
x            = 180  0000 0000 0000 0000 0000 0000 1011 0100
x & 1        = 0    (奇偶：1 奇 0 偶)
(x>>3)&1     = 0    (取第 3 位)
x | (1<<2)   = 180  ← 第 2 位本来就是 1，所以看不出变化
x & ~(1<<2)  = 176  0000 0000 0000 0000 0000 0000 1011 0000  (清 0)
x ^ (1<<2)   = 176  (翻转，1 变 0)
x & -x       = 4    (lowbit)
x & (x-1)    = 176  (消掉最低位的 1)
```

> 注意第三行：**位运算只动指定的那一位，其他位原样保留**。所以「置 1」看不出变化是正常的 —— 拿「清 0」和「翻转」验证更直观。

### 三个组合判断

```cpp
x & 1                     // 判奇偶（比 x % 2 快，且对负数也正确）
x > 0 && !(x & (x - 1))   // 判是不是 2 的幂（只允许一个 1）
(x >> k) & 1              // 判第 k 位是不是 1
```

`x & (x-1)` 能判 2 的幂，是因为**只有单个 1 的数减 1 后，会把它变成 0、低位全变 1**，两者相与必然是 0。

---

### `n - 1` 在位上是怎样变化的（理解 `x & (x-1)` 的地基）

减 1 的十进制直觉是「末位减一」，但**二进制里会触发借位**，实际效果是：

> **从最低位那个 `1` 开始，把它变成 `0`；它下面所有的 `0` 全部变成 `1`；它上面的位完全不动。**

一句话：**翻转「最低位 1」这一整段后缀，高位不动。**

```
20 = 0001 0100
19 = 0001 0011
     └──┬──┘│└┬┘
       高位  │  低位 0 → 全变 1
       不变  最低位的 1 → 0
```

为什么是这三段？因为减 1 时最低位是 0 不够减，要**向高位借**：借到的 1 拆成 2，减掉 1 剩 1 留在这一位；然后这个「借」一路往低位传，每经过一个 0 都留下一个 1。直到碰到最低位的那个 1 —— 它被借走了，变成 0。

**变的是「最低位 1 及其以下」，其余一位没动。**

实测 12 个例子，规律完全一致：

| n | n 的二进制 | n-1 | 变化 |
|---|---|---|---|
| 5 | 0000 0101 | 0000 0100 | 末尾 0 个 0；第 0 位 1→0 |
| 6 | 0000 0110 | 0000 0101 | 末尾 1 个 0 变 1；第 1 位 1→0 |
| 8 | 0000 1000 | 0000 0111 | 末尾 3 个 0 全变 1；第 3 位 1→0 |
| 12 | 0000 1100 | 0000 1011 | 末尾 2 个 0 全变 1；第 2 位 1→0 |
| 20 | 0001 0100 | 0001 0011 | 末尾 2 个 0 全变 1；第 2 位 1→0 |
| 100 | 0110 0100 | 0110 0011 | 末尾 2 个 0 全变 1；第 2 位 1→0 |

**「末尾连续 0 的个数」= 最低位 1 的下标**（也就是 `lowbit = 2^k` 里那个 `k`）。所以：

```cpp
lowbit = n & (-n) = 1 << (末尾 0 的个数)
```

### 为什么 `x & (x - 1)` 正好清掉最低位的那个 1

把上面的结论代进「按位与」，三段分别算：

| 位置 | x | x-1 | 相与 |
|---|---|---|---|
| 高位（最低位 1 之上） | 原样 | **原样**（不变） | **= 原样** ✅ 保留 |
| 最低位的 1 所在那一格 | `1` | `0` | `1 & 0 = 0` ✅ **清掉** |
| 低位（那一位之下） | 全 `0` | 全 `1` | `0 & 1 = 0` ✅ 仍是 0 |

结果就是：**高位原样保留 + 那一格清零 + 低位全 0** —— 即「把最低位的 1 抹掉，其他一位不动」。

```
20        0001 0100
19        0001 0011
20&19     0001 0000   = 16   ← 20 减去 lowbit(4)
```

所以还得到一个实用恒等式：

```cpp
n & (n - 1) == n - (n & -n)      // 两种写法等价，都是"消掉最低位 1"
```

（实现上直接用 `n & (n-1)` 更快，一次操作顶两次。）

### 三个反直觉点

**① `n - 1` 不一定让 1 变少，反而可能变多**

```
8 = 0000 1000  →  7 = 0000 0111      popcount 从 1 变成 3  ← 变多了！
```

因为「末尾 3 个 0 全变 1」这四个字本身就是「凭空冒出三个 1」。所以**想减少 1 的个数，`n-1` 不管用**。

**② 但 `n & (n-1)` 一定让 1 的个数减少恰好 1 个**

因为它是三段运算的净结果：高位不动、那一位清掉、低位全 0。1 的个数严格递减 → **循环必然会终止**。

```cpp
int popcount(int n) {              // 循环次数 = 1 的个数，不是 32
    int c = 0;
    while (n) { n &= n - 1; ++c; }
    return c;
}
```

实测 `n = 100`（`popcount = 3`）：

```
step 0: n = 100  popcount=3  lowbit=4   -> n&(n-1) = 96
step 1: n = 96   popcount=2  lowbit=32  -> n&(n-1) = 64
step 2: n = 64   popcount=1  lowbit=64  -> n&(n-1) = 0
共 3 步，正好等于 popcount
```

**③ `n = 0` 时 `n - 1` 会变成全 1**

`0 - 1` 在补码下是 `-1`（全 1）。所以 `0 & (0-1) = 0`，`popcount(0)` 也正确返回 0 —— **但这也正是「判 2 的幂」必须先判 `n > 0` 的原因**（见 §3 与练习题 A1）。

### 反过来：`n + 1` 是怎么变的

对称地，加 1 会**翻转「最低位的 0」这一整段后缀**：

```
20 = 0001 0100  →  21 = 0001 0101     末尾那个 0 变 1，没进位
23 = 0001 0111  →  24 = 0001 1000     末尾 3 个 1 全变 0，第 3 位 0 变 1
```

| | 减 1 | 加 1 |
|---|---|---|
| 从哪儿开始 | 最低位的 **1** | 最低位的 **0** |
| 那一位 | `1 → 0` | `0 → 1` |
| 下方各位 | `0 → 1` | `1 → 0` |
| 高位 | 不动 | 不动 |

于是 `x & (x+1)` 是「清掉最低位的 0」（用于「末尾最长的连续 1」这类问题），和 `x & (x-1)` 正好成对。

## 四、lowbit：`x & (-x)` 为什么成立

`x = 12 = 0000 1100`，最低位的 1 在 bit2（权值 4）。

```
x     = 0000 1100
-x    = 1111 0100      ← 取反加一
x & -x= 0000 0100  = 4
```

**推理过程**：

1. 设 x 最低位的 1 在第 k 位，那它下面的 k 位全是 0。
2. `~x` 把这些低位 0 全变成 1；`+1` 之后这一串 1 全部进位回 0，并把第 k 位重新变回 1。
3. 所以 **`-x` 在第 k 位及以下与 `x` 完全一致**（低位都是 0，第 k 位都是 1）。
4. 而 **k 位以上，`-x` 与 `x` 恰好互补** → 相与全是 0。

结果就只剩第 k 位那一个 1。

**用途**：

| 场景 | 用法 |
|---|---|
| 树状数组 | `i += i & (-i)` 向上跳；`i -= i & (-i)` 向下跳 |
| 求最大 2 的幂因子 | `x & -x` 直接就是「x 能被 2 的几次方整除」的结果 |
| 拆解二进制 | 循环取 lowbit 再减掉，可逐个拿到所有 1 |

## 五、异或的四条性质（刷题神器）

```
a ^ a = 0          自反：任何数异或自己归零
a ^ b ^ a = b      交换 + 结合：成对出现的都消掉
a ^ 0 = a          0 是单位元
a ^ b              = 「无进位加法」
```

**应用一：找唯一出现一次的数**（其他都出现两次）

```cpp
int singleNumber(vector<int>& a) {
    int r = 0;
    for (int v : a) r ^= v;     // 成对的互相抵消，剩下的就是答案
    return r;
}
```

实测 `{3, 7, 3, 4, 7, 4, 9}` → `9`。

**应用二：不用临时变量交换**

```cpp
a ^= b;  b ^= a;  a ^= b;
```

⚠️ 但**不推荐在工程里用**：可读性差、`a` 和 `b` 是同一个变量时会把自己清零。刷题炫技可以，写业务别用。

**应用三：找两个只出现一次的数**

先全部异或得到 `a^b`（非 0），取它的 lowbit 作为「分界线」，把数组分成两组分别异或 —— 两个答案就被分到不同组里了。

## 六、移位：`<<` 和 `>>` 的完整过程

### 6.1 一句话

> **左移：每一位整体往左挪，右边空出来的位置补 0，从最左边挤出去的直接丢。**
> **右移：每一位整体往右挪，左边空出来的位置补「原来的符号位」**（正数补 0、负数补 1），右边挤出去的丢。

关键在于**补进来的那个位**——它决定了移位到底等价于 ×2 还是不完全等价。

### 6.2 左移的过程

`5 << 1`（8 位视角）：

```
5      = 0000 0101
5 << 1 = 0000 1010  = 10      ← 最右边补进来一个 0
5 << 2 = 0001 0100  = 20
5 << 3 = 0010 1000  = 40
```

**为什么等价 ×2**：二进制里「往左挪一位」意味着后面每个 1 的权值都升一级（1→2、2→4、4→8…），整体就是乘 2。

**负数也一样**（左移永远补 0）：

```
-5      = 1111 1011 = -5
-5 << 1 = 1111 0110 = -10      ← 数值上仍是 ×2
-5 << 2 = 1110 1100 = -20
```

### 6.3 右移的过程：分四种情况

右移补什么，取决于**类型是否有符号** + **最高位是什么**：

| 类型 | 最高位 | 补什么 | 叫什么 |
|---|---|---|---|
| `unsigned` | 任意 | 补 `0` | **逻辑右移** |
| `int` | 0（正数） | 补 `0` | 算术右移（和逻辑一样） |
| `int` | 1（负数） | **补 `1`** | **算术右移** |

实测（8 位视角）：

```
 20      = 0001 0100
 20 >> 1 = 0000 1010 = 10      高位补 0
 20 >> 2 = 0000 0101 = 5
 20 >> 3 = 0000 0010 = 2

-8       = 1111 1000
-8 >> 1  = 1111 1100 = -4      ★ 高位补 1（符号位），不是补 0
-8 >> 2  = 1111 1110 = -2
```

**为什么负数要补 1**：负数的补码最高位是符号位 `1`，如果补 0 就会突然变成一个巨大的正数。补 1 才能保持「除以 2 之后还是负数」。

想强制逻辑右移，先转无符号：

```cpp
int x = -8;
x >> 1                    // -4          算术右移
(unsigned)x >> 1          // 2147483644  逻辑右移，高位补 0
```

⚠️ **注意区分**：位模式完全一样（都是 `1111 1100`），差别只在**怎么解释**。`(unsigned)-8` 的位模式就是 `1111...1000`，右移补 0 后高 24 位全变 0，于是变成一个大正数。

### 6.4 ★ 当 ×2 / ÷2 用的时候，哪里会不一样

这是本节最实用的一条。

**左移当 ×2：正负都对得上**（只要不溢出）

| n | `n<<1` | `n*2` | 相同？ |
|---|---|---|---|
| 5 | 10 | 10 | ✅ |
| -5 | -10 | -10 | ✅ |
| 100 | 200 | 200 | ✅ |
| -100 | -200 | -200 | ✅ |

**右移当 ÷2：负数且除不尽时，结果不一样！**

| n | `n>>1` | `n/2` | 相同？ |
|---|---|---|---|
| 20 | 10 | 10 | ✅ |
| 21 | 10 | 10 | ✅ |
| -20 | -10 | -10 | ✅ |
| **-21** | **-11** | **-10** | ❌ |
| **-7** | **-4** | **-3** | ❌ |
| **-5** | **-3** | **-2** | ❌ |

**根本原因**：

- **右移 = 向下取整**（往 −∞ 方向）：`-7 / 2 = -3.5`，向下取整 → `-4`
- **C++ 除法 = 向零取整**（往 0 方向）：`-7 / 2 = -3.5`，向零取整 → `-3`

> **判据**：`n >> k` 与 `n / 2^k` 只在「`n` 为正数」或「`n` 恰好能被 `2^k` 整除」时相等。
> 刷题里但凡遇到**可能为负**的数据，别用 `>>` 代替除法；二分求中点也一样（所以推荐写 `l + (r-l)/2`，而不是 `(l+r)>>1`——后者虽然多数情况没事，但负数区间下界会偏）。

### 6.5 三个坑

| 坑 | 说明 |
|---|---|
| **有符号右移是算术右移** | `-8 >> 1` 实测得 `-4`（补符号位），不是逻辑右移。C++ 标准里这是**实现定义**，只是所有主流编译器都做算术右移 |
| **`1 << 31` 是 UB** | 对有符号 int 左移溢出是未定义行为。实测 g++ 得到 `-2147483648`，但换编译器可能不同。**正确写法 `1u << 31`** |
| **移位数 ≥ 位宽是 UB** | `x << 32` 在 int 上未定义，不会自动变成 0，可能得到任何值 |

实测：

```
-8      >> 1 = -4              （算术右移）
0xFFFFFFF8 >> 1 = 2147483644   （逻辑右移，因为是无符号）
1 << 31  = -2147483648         （UB，只是 gcc 这么实现）
1u << 31 = 2147483648          （正确写法）
-1 >> 1  = -1                  （实现定义）
```

**关于「移位数 ≥ 位宽」有一个很好的 UB 实证**：同一份代码，编译期折叠和运行期执行结果不同：

```cpp
printf("%d\n", 1 << 32);        // 编译期折叠 -> 0
volatile int s = 32;
printf("%d\n", 1 << s);         // CPU 实际执行 -> 1
```

原因：x86 的 `shl` 指令只取移位量的**低 5 位**（`32 & 31 == 0`），等于「移 0 位」，所以运行期得 `1`；而编译器在编译期按数学意义处理给了 `0`。

**两个结果都不算错，但都不能依赖** —— 这就是 UB 的本质：标准不管，实现随便。

**规矩**：位运算尽量在**无符号类型**上做；需要 `2^31` 这类值时用 `1u`、`1LL`。

## 七、★ 优先级：最容易出错的地方

**位运算符的优先级低于比较运算符**，这是 C 语言历史遗留的设计失误。

```cpp
if (x & 1 == 1)      // ❌ 实际是 x & (1 == 1)，即 x & 1
if (x & 2 == 2)      // ❌ 实际是 x & (2 == 2)，即 x & 1 —— 完全错了！
if ((x & 1) == 1)    // ✅
if ((x & 3) == 3)    // ✅
```

优先级从高到低大致是：

```
~  →  算术 * / %  →  + -  →  移位 << >>  →  比较 < > <= >=  →  相等 == !=
   →  按位与 &  →  按位异或 ^  →  按位或 |  →  逻辑与 &&  →  逻辑或 ||  →  赋值
```

**结论：只要不是单独一句，位运算一律加括号。** 这不是风格问题，`x & 2 == 2` 这种写法会静默给出错误答案。

## 八、实战五个

### 1. 子集枚举（状压 DP 的基础）

```cpp
int n = 3;
for (int mask = 0; mask < (1 << n); ++mask) {
    for (int i = 0; i < n; ++i)
        if (mask >> i & 1) { /* 第 i 个元素被选中 */ }
}
```

`mask` 的每一位代表一个元素选没选，`2^n` 个子集一次枚举完。

### 2. 快速幂

```cpp
long long qpow(long long base, long long exp, long long mod) {
    long long res = 1;
    while (exp) {
        if (exp & 1) res = res * base % mod;   // 这一位要乘
        base = base * base % mod;
        exp >>= 1;
    }
    return res;
}
```

实测 `3^13 = 1594323`。原理：把指数按二进制拆开，`3^13 = 3^(1101b) = 3^8 · 3^4 · 3^1`。

### 3. 不用加减乘除做加法

```cpp
int add(int a, int b) {
    while (b) {
        int carry = (unsigned)(a & b) << 1;   // 进位：都是 1 的位
        a ^= b;                                // 无进位加法
        b = carry;
    }
    return a;
}
```

实测 `15 + 27 = 42`。这就是「异或 = 无进位加法」的直接应用。

### 4. 数 1 的个数（popcount）

```cpp
int popcount(unsigned x) {
    int cnt = 0;
    for (; x; x &= x - 1) ++cnt;   // 每次消掉最低位的 1
    return cnt;
}
```

C++20 有 `std::popcount`，GCC 有 `__builtin_popcount`。

### 5. 无分支取绝对值

```cpp
int myAbs(int x) {
    int mask = x >> 31;            // 负数得 -1（全 1），正数得 0
    return (x ^ mask) - mask;      // 负数：(~x)+1 = -x
}
```

## 九、易错点速查

| 坑 | 表现 |
|---|---|
| `x & 1 == 1` 不加括号 | 优先级问题，静默出错 |
| `1 << 31` | UB，应用 `1u << 31` |
| 有符号数做位运算 | 右移、溢出都不可控，尽量转 `unsigned` |
| `a ^= b ^= a ^= b` | 自交换会清零，且旧标准下是 UB |
| 把 `~` 当成「逻辑取反」 | `~` 是逐位取反，`!` 才是逻辑取反 |
| `x & (x-1)` 判 2 的幂忘了 `x > 0` | `0 & -1 == 0`，会把 0 判成 2 的幂 |
| `1 << k` 里 k 是 long long | 移位结果类型是 int，可能溢出，写 `1LL << k` |

## 十、面试延伸

- **为什么计算机用补码而不是原码**：原码有 ±0 两个零，减法还要单独处理符号；补码让「减法 = 加负数」，同一套加法器通吃。
- **`x & (x-1)` 和 `x & -x` 的区别**：前者消掉最低位的 1（用于数 1），后者取出最低位的 1（用于树状数组）。
- **BitSet 的底层**：`std::bitset<N>` 内部就是 `unsigned long` 数组，一个 64 位字装 64 个布尔值 —— 空间省 64 倍。
- **掩码（mask）在工程里**：Unity 的 `LayerMask`、文件权限位、状态标志位，都是「一个 int 存多个布尔」。

## 十一、练习题（8 道，分三档）

> 只给提示和验收数据，**不给答案** —— 答案在对应题目里自己推。

### A 档：先把六个算子练熟

**A1 · LC 231「2 的幂」**
给整数 `n`，判断是不是 2 的幂（0 和负数都不是）。

- 提示：2 的幂二进制里**只有一个 1**。`x & (x-1)` 会消掉最低位的 1，消完为 0 就是。
- 验收：`1→true`、`16→true`、`0→false`、`6→false`、`-16→false`、**`INT_MIN→false`**
- 别忘了先判 `n > 0`（`0 & -1 == 0` 会把 0 误判成 2 的幂）。
- ⚠️ **`INT_MIN` 是最阴的用例**：补码 `1000...0000` 同样只有一位 1，`x & (x-1)` 也等于 0 → 漏 `n > 0` 时会被判成 2 的幂。而 `-16` 这类负数恰好被挡住，所以「测过负数」不代表安全，**`INT_MIN` 必须单独测**。
- 实测（g++ 8.1.0，11 个边界用例）：漏判版只在 `0` 与 `INT_MIN` 上错；带 `n > 0` 的两种写法全通过。

**A2 · LC 191「位 1 的个数」**
给无符号整数，返回二进制里 1 的个数。

- 提示：两种都要会。① 循环 32 次，`(n >> i) & 1` 累加；② 更快的是 `while (n) { n &= n - 1; ++cnt; }` —— 循环次数等于 1 的个数。
- 验收：`11 (1011) → 3`、`128 → 1`、`0 → 0`

**A3 · LC 136「只出现一次的数字」**
除一个数只出现一次，其他都出现两次。要求 `O(n)` 时间 / `O(1)` 空间。

- 提示：异或的 `a^a=0`、`a^0=a`、交换律。全部异或一遍，成对的自己消掉。
- 验收：`[2,2,1] → 1`、`[4,1,2,1,2] → 4`

### B 档：两个算子组合

**B1 · LC 461「汉明距离」**
两个整数二进制不同位的个数。

- 提示：`x ^ y` 把不同的位全变 1，剩下就是 A2。
- 验收：`1,4 → 2`、`3,1 → 1`

**B2 · LC 260「只出现一次的数字 III」**
**两个**数各出现一次，其余出现两次，找出这两个数。

- 提示：全部异或得 `a^b`（非 0）。取它的 **lowbit** 当分界线，把数组按这一位分两组各自异或。
- 这是 `x & (-x)` 最经典的用法，务必手写一遍。
- 验收：`[1,2,1,3,2,5] → [3,5]`

**B3 · LC 338「比特位计数」**
返回 `0..n` 每个数的 1 的个数。

- 提示：别对每个数扫 32 位。递推 `cnt[i] = cnt[i >> 1] + (i & 1)`，或 `cnt[i] = cnt[i & (i-1)] + 1`。
- 验收：`n=5 → [0,1,1,2,1,2]`

### C 档：想清楚再动手

**C1 · LC 201「数字范围按位与」**
区间 `[left, right]` 内所有整数按位与的结果。

- 提示：某一位上只要出现过 0，结果这一位就是 0。**本质是求 left 与 right 的公共前缀**，后面的位全归零。做法：两者不断右移直到相等，再左移回来。
- 验收：`[5,7] → 4`、`[0,0] → 0`、`[1,2147483647] → 0`

**C2 · 剑指 65「不用加减乘除做加法」**
求两数之和，不能用 `+ - * /`。

- 提示：`a ^ b` 是无进位加法，`(a & b) << 1` 是进位。循环把进位加回去，直到进位为 0。
- ⚠️ 左移前转 `unsigned`，避免 int 溢出（`(unsigned)(a & b) << 1`）。
- 验收：`1,2 → 3`、`-1,2 → 1`、`-5,-7 → -12`（负数用例最重要）
- 进阶：如果规定不能用循环、也不能用乘除，用 `(a ^ b) * ...` 那套位运算递推公式也可以试。
