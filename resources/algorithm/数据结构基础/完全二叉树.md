# 完全二叉树

## 一、定义（两种等价说法）

**形状说法**：除最后一层外，每一层都被完全填满；最后一层的所有节点都集中在**最左边**、连续排列。

**编号说法**：按层序从上到下、从左到右编号 `1..n`，每个节点的编号和位置，与同样高度的**满二叉树**中编号 `1..n` 的节点**一一对应**。

判断时用编号说法更快：**层序编号后 1..n 号位置必须全被占满，中间不能有空洞。**

```
      ✓ 完全               ✗ 最后一层没靠左        ✗ 中间有空洞
        1                    1                     1
       / \                  / \                   / \
      2   3                2   3                 2   3
     / \  /                    \   \             /     \
    4  5 6                      5   6           4       7
```

## 二、三个近义概念别混

| 类型 | 英文 | 特征 | 高度 h 的节点数 |
| --- | --- | --- | --- |
| 满二叉树 | **Perfect** Binary Tree | 每一层都填满 | 恰好 `2^h − 1` |
| **完全二叉树** | **Complete** Binary Tree | 只有最后一层可不填满，且**靠左连续** | `2^(h−1) ≤ n ≤ 2^h − 1` |
| 真二叉树 | **Full** Binary Tree | 每个节点有 **0 或 2** 个孩子 | 与 h 无固定关系 |

- **包含关系**：满 ⊂ 完全。满的一定是完全的，完全的不一定是满的。
- **Full 与 Complete 无包含关系**。中文教材有时把 Full 也译作「满二叉树」，看英文原文要留神。

## 三、最大价值：能用数组连续存储

因为「层序编号恰好占满 1..n」，所以直接按下标放进数组，**没有任何空洞**。

```
下标(1-based)：  1    2    3    4    5    6
值：            10   20   30   40   50   60
                ↑ 根
```

父子关系用纯下标算术直接算，**不需要存任何指针**：

| 关系 | 1-based | 0-based |
| --- | --- | --- |
| 节点 i 的左孩子 | `2i` | `2i + 1` |
| 节点 i 的右孩子 | `2i + 1` | `2i + 2` |
| 节点 i 的父节点 | `i / 2` | `(i − 1) / 2` |

**这就是堆（`priority_queue`）与线段树都用数组实现的根本原因。**

> ⚠️ 反过来说：**BST 不能这样存** —— 它的形状完全可以退化成链，数组里会满是空洞。

## 四、常用性质（n 个节点）

| 性质 | 值 |
| --- | --- |
| 高度（层数） | `⌊log₂n⌋ + 1` |
| 叶子节点数 | `⌈n / 2⌉` |
| 非叶子节点数 | `⌊n / 2⌋` |
| 最后一个非叶子节点的下标（1-based） | `⌊n / 2⌋`，从它往前全是非叶子 |
| 度为 1 的节点数 | 最多 1 个（且只在 n 为偶数时出现） |

## 五、怎么判断一棵树是完全二叉树

**思路**：层序遍历，一旦出现过空节点，后面就不允许再出现非空节点。

```cpp
bool isComplete(TreeNode* root) {
    if (!root) return true;
    queue<TreeNode*> q;
    q.push(root);
    bool seenEmpty = false;                          // 是否已经遇到过空节点
    while (!q.empty()) {
        TreeNode* node = q.front(); q.pop();
        if (!node) { seenEmpty = true; continue; }   // 空节点：打标记，继续
        if (seenEmpty) return false;                 // 之后又冒出非空 → 不是
        q.push(node->left);                          // ★ 故意把 nullptr 也入队
        q.push(node->right);
    }
    return true;
}
```

⚠️ **注意这里故意把 `nullptr` 也推进队列** —— 和常规 BFS「判空再入队」正好相反。正是靠它来标出断层位置。

**另一种写法**：BFS 时给每个节点编下标（左 `2i`、右 `2i+1`），最后判断 **最大下标是否等于节点总数**。

## 六、与二叉搜索树的关系：两个正交维度

这是最容易混的地方。两者**互不包含、互不推导**：

| | 完全二叉树 | 二叉搜索树（BST） |
| --- | --- | --- |
| 约束对象 | **形状**（结构） | **值序**（内容） |
| 核心规则 | 除最后一层外填满，最后一层靠左连续 | 左子树全 < 根 < 右子树全 |
| 关心节点值吗 | ❌ 完全不关心 | ✅ 只关心大小关系 |
| 关心树的形状吗 | ✅ 完全由形状定义 | ❌ 形状随便，链状也行 |
| 数组存储 | ✅ 天然支持 | ❌ 有空洞 |
| 中序遍历 | 无序 | **升序** |
| 典型用途 | 堆、线段树 | 查找、有序遍历 |

### 四象限：任意组合都合法

| | **是 BST** | **不是 BST** |
| --- | --- | --- |
| **完全** | `2 / 1, 3` | `9 / 5, 8` ← **这就是大顶堆** |
| **非完全** | `2 / 1, 4(左3)` | `1 / 3, 2` |

- **完全 + BST**：两层填满且 `1 < 2 < 3`，两全其美
- **完全 + 非 BST**：`9 / 5, 8` —— 堆只保证「父 ≥ 子」，`8` 在 `9` 的右子树却比 `9` 小，BST 规则破功
- **非完全 + BST**：`2 / 1, 4(左 3)` —— 合法 BST，但层序编号是 `1,2,3,6`，位置 4、5 空着
- **都非**：`1 / 3, 2` —— `3 > 1` 却挂左边

### ⚠️ 最大的误解：堆不是 BST

| | 堆 | BST |
| --- | --- | --- |
| 形状 | **必须是完全二叉树** | 无要求 |
| 值序 | **弱序**：父 ≥ 子（大顶堆）或父 ≤ 子（小顶堆） | **全序**：左子树全 < 根 < 右子树全 |
| 查找任意值 | ❌ O(n) | ✅ O(log n) |
| 取最值 | ✅ O(1) | O(log n) |
| 中序遍历 | **无序** | **升序** |
| 数组存储 | ✅ | ❌ |

「堆顶是最大值」**不等于**「堆是 BST」。堆只给局部有序（父子），BST 给的是全局有序。

## 七、一个值得想的点：为什么平衡树不追求「完全」

完全二叉树理论上**高度最优**（`⌊log₂n⌋ + 1` 层），那 BST 为什么不干脆维持「完全」？

因为**维持「完全」的代价极高**：插入一个节点可能要让整层节点平移来「补洞」，删除更糟。所以平衡树选择退一步 —— 只保证**高度有界**（AVL 的 `|bf| ≤ 1`、红黑树的 `≤ 2log₂(n+1)`），而不保证形状完全。见 [[二叉平衡树AVL]]。

## 八、一句话记住

> **完全二叉树 = 「按层序编号后 1..n 号位置恰好全被占满」的树。** 所以它天生适合用数组存。
> **它是「骨架」，BST 是「排序规则」，堆是「骨架 + 弱排序」。三者可以叠加，但互不推导。**
