# 小地图实现 — 图标投影与坐标映射

## 一、两条路线，先选对

| | 方案 A：RenderTexture 相机 | 方案 B：UI 图标投影 |
| --- | --- | --- |
| 原理 | 头顶再放一台正交相机，`targetTexture` 输出到一张 RT，`RawImage` 显示 | 拿每个目标的 XZ 算成 2D 坐标，用 UI `Image` 摆点 |
| 看到什么 | 真实地形/建筑轮廓 | 只有点和图标 |
| 代价 | 多一次完整渲染 pass（几何 + 阴影 + 后处理都要重跑），RT 显存常驻；正交相机还要单独设 `cullingMask` / `depth` / `near-far` | 每帧 N 次坐标运算 + N 个 `RectTransform` 赋值，几乎零 GPU 成本 |
| 适合 | 需要地形信息的战术地图（MOBA、RTS、开放世界） | 只需要「敌人在哪个方向、多远」（射击、ARPG、吃鸡小地图的雷达层） |

**射击游戏里绝大多数是 B**，因为玩家真正要的是方位与距离，不是地形贴图。真要地形就 A 打底 + B 叠图标（两层 RawImage/Image 叠在同一个 `RectMask2D` 里）。

方案 A 的关键设置（漏一个就黑屏/不刷新）：

```csharp
var cam = minimapCamera.GetComponent<Camera>();
cam.orthographic     = true;
cam.orthographicSize = mapRadius;          // 正交半高 = 地图半径
cam.cullingMask      = LayerMask.GetMask("Ground", "Enemy", "Player");
cam.clearFlags       = CameraClearFlags.SolidColor;
cam.targetTexture    = rt;                  // ← 不设就渲染到屏幕
cam.depth            = -10;                 // 必须小于主相机的 depth
// RT 分辨率只跟显示尺寸有关，240×240 的 UI 别给 1024
```

## 二、坐标映射：从世界 XZ 到 UI XY

核心就三步：**取相对偏移 → 除以视野半径归一化 → 乘 UI 半尺寸**。

```csharp
// 敌人相对玩家的水平偏移
float dx = enemy.x - player.x;
float dz = enemy.z - player.z;

// 归一化到 -1 ~ 1（detectRadius 是小地图覆盖的世界半径）
float nx = dx / detectRadius;
float nz = dz / detectRadius;

// 映射到 UI 局部坐标（anchor 居中、pivot 0.5 时 anchoredPosition 即 localPosition.xy）
float half = rectTransform.rect.width * 0.5f - iconHalf;   // ← 减图标半宽
Vector2 anchored = new Vector2(nx, nz) * half;
```

三个必须记住的点：

### 1. 符号方向：`enemy - player`，不是 `player - enemy`

写成 `(player.x - enemy.x)` 会让整张小地图**旋转 180°**——敌人在右显示在左、在前显示在后。这个 bug 特别阴：图标都在动、数量也对，只有方向全错，容易误判成「美术资源反了」。

### 2. 世界 Z 映射 UI **Y**，不是 Z

俯视图里世界是 XZ 平面，UI 是 XY 平面，`z → y`。而且世界 +Z 对应屏幕**上方**（UI +Y），所以是 `nz` 直接当 `y`，不要取反。

### 3. `detectRadius` 要 ≥ 敌人可能出现的最大距离

如果 `detectRadius = 50` 而敌人生成半径是 40~60，那么 60 距离的敌人一出生就贴边，且**所有超范围的敌人都挤在边框上**，距离信息直接丢失。取「视野半径」时要么放大到覆盖全场，要么接受贴边但用颜色/透明度区分远近。

## 三、yaw 旋转：让「上」永远是玩家前方

上面那套是**固定北向上**（世界 +Z 恒朝上），适合固定俯视的地图。第三人称射击一般要**玩家前方朝上**，做法是把世界偏移转到玩家本地坐标系：

```csharp
Vector3 local = Quaternion.Euler(0f, -player.eulerAngles.y, 0f) * new Vector3(dx, 0f, dz);
// 注意是 -yaw：抵消玩家的朝向，等价于「把地图反向转」
Vector2 anchored = new Vector2(local.x, local.z) * half;
```

同时玩家图标本身要跟着转（箭头指向前方）：

```csharp
playerIcon.localEulerAngles = new Vector3(0f, 0f, -player.eulerAngles.y);
```

漏了玩家图标旋转 → 地图转了、箭头没转，视觉上箭头永远朝上但敌人绕着它转，玩家会以为地图坏了。

## 四、clamp：方形内缩 vs 圆形半径

```csharp
// 方形小地图：逐轴 clamp，注意减掉图标半宽，否则边缘图标有一半被 Mask 裁掉
float half = rect.width * 0.5f - iconSize * 0.5f;
Vector2 p = new Vector2(nx, nz) * rect.width * 0.5f;
p.x = Mathf.Clamp(p.x, -half, half);
p.y = Mathf.Clamp(p.y, -half, half);

// 圆形小地图：按模长 clamp，保持方向不变
Vector2 p2 = new Vector2(nx, nz) * rect.width * 0.5f;
float r = rect.width * 0.5f - iconSize * 0.5f;
if (p2.magnitude > r) p2 = p2.normalized * r;
```

**逐轴 clamp 会把对角方向的点拉向角落**（曼哈顿式），圆形雷达要按模长。另外贴边后如果多个敌人同方向，会**完全重叠成一个点**——常见做法是贴边时缩小图标 + 变红，用「有几个」的计数代替位置。

## 五、生命周期：模板隐藏 → 实例化 → 字典 → 移除

```csharp
// 1. 模板常驻但隐藏，克隆它
imgEnemyTemplate.gameObject.SetActive(false);

// 2. 克隆时显式归零，别信模板的 anchoredPosition
var go = Instantiate(imgEnemyTemplate, transform);      // 等价 SetParent(transform, false)
go.GetComponent<RectTransform>().anchoredPosition = Vector2.zero;
go.SetActive(true);

// 3. 用「业务对象 → 图标」的字典双向查
enemyIcons.Add(enemyAI, go.transform);

// 4. 死亡时按 key 移除，同时从数组里同步删除
if (enemyIcons.Remove(enemyAI, out var icon)) Destroy(icon);
```

`Instantiate(prefab, parent)` 这个重载**内部就是 `SetParent(parent, false)`**，比手写 `transform.parent = parent` 安全——后者保持世界坐标，会把模板在层级里的世界位置换算成新 `localPosition`，UI 上表现为「克隆体先闪一下在模板位置」。

字典 key 用 `UnityEngine.Object` 有两个雷：

- **fake null**：对象被 `Destroy` 后 key 变成「假 null」，`Dictionary` 的哈希仍基于原始 instanceID，条目**永远不会被清掉** → 内存与遍历双泄漏。所以必须**显式 `Remove`**，不能靠「对象没了自动消失」。
- **`dict[key]` 直接索引**：key 不在就抛 `KeyNotFoundException`。所有「从数组里拿对象、再去字典里查」的地方，数组和字典必须**同一时刻更新**，否则中间帧必炸。用 `TryGetValue` 兜底。

## 六、2026-11-24 Empty 实战：8 个坑

项目是「UI 图标投影」路线，`Assets/Scripts/UI/MiniMap.cs`（240×240、右上角、`detectRadius = 50`、敌人环形生成半径 40~60）。

### 坑 1（最重）：`Start` 顺序竞争 → `Instantiate(null)`

`FightingManager.Start` 末尾直接调 `UIFightingView.Instance.InitMiniMap()`，而 `MiniMap` 的引用（`imgEnemy` / `rectTransform`）是在它自己的 `Start` 里 `transform.Find` 出来的。两个 `Start` 谁先跑**没有保证**（`MonoManager` 里没配执行顺序），`FightingManager` 先跑时 `imgEnemy` 还是 null：

```csharp
Instantiate<GameObject>(null);   // ArgumentException，之后 enemyImg.transform 直接 NRE
```

**修法**：引用初始化搬到 `Awake`（`Awake` 一定早于任何 `Start`），或给 `MiniMap` 一个显式 `Init()` 由调用方驱动，别依赖 `Start` 的隐式时机。参见 [[MonoBehaviour生命周期与SetActive的坑]]。

### 坑 2：符号反了 180°

```csharp
float x = (playerPos.x - enemyAIs[i].transform.position.x) / detectRadius;  // ← 反
float z = (playerPos.z - enemyAIs[i].transform.position.z) / detectRadius;
```

两个轴同时反 → 整张小地图转 180°，左右前后全错。

### 坑 3：模板 `anchoredPosition` 不是 (0,0)

场景里 `enemy` 模板的 `anchoredPosition = (-34.3, -29.9)`。克隆时没归零，而 `SetEnemyImgPos()` 开头有两处提前 return：

```csharp
if (player == null) return;
if (enemyAIs.Length == 0) return;     // ← 这里返回时，所有图标还叠在 (-34.3,-29.9)
```

于是「玩家没就绪」或「敌人清空」的那几帧，全部图标堆在同一个角落。修法：`Instantiate` 后立刻 `anchoredPosition = Vector2.zero`。

### 坑 4：clamp 没减图标半宽

`rect.width * 0.5f * x` 得到 ±120，而容器只有 240、图标 20×20 → 贴边图标有一半在容器外，被 `RectMask2D` 裁掉。

### 坑 5：`enemyAIs` 判了 `Length` 没判 `null`

`enemyAIs` 由 `SetEnemyAIs()` 赋值，`Update` 里每帧 `SetEnemyImgPos()`。若 `InitMiniMap()` 没被调用（UI 面板未激活、`FightingManager` 提前 return），`enemyAIs` 为 null → `enemyAIs.Length` 直接 NRE。

### 坑 6：`enemyImgs[key]` 直接索引

```csharp
enemyImgs[enemyAIs[i]].localPosition = ...;   // key 不在就 KeyNotFoundException
```

`enemyAIs` 是 `GetEnemies().ToArray()` 的**快照**，`enemyImgs` 是实时字典。两者只在 `SetEnemyAIs()` 被调用时同步，中间任何一帧不同步就会炸。用 `TryGetValue`。

### 坑 7：`transform.parent = transform` 而非 `SetParent(parent, false)`

本例模板与容器同父，实际表现正常（world position 不变），但一旦模板挪成 `Resources` 预制体就必偏移。规范上统一用 `Instantiate(prefab, parent)`。

### 坑 8：`using Unity.VisualScripting;`

`VisualScripting` 里有 `GameObject` 扩展方法，和 `UnityEngine.GameObject` 同名，属于随时可能引发歧义的脏引用；本例没用它的任何 API，删掉。

## 七、性能：小地图本身很便宜，别写成很贵

- 每帧 N 次 `transform.position` 访问 + N 次 `localPosition` 赋值，10~50 个目标完全无压力；上百个才需要分帧（每帧只更新 1/3）。
- **不要每帧 `GetComponent`**：图标引用在创建时缓存。
- `rectTransform.rect` 每帧读是安全的（纯 struct 拷贝，不触发 rebuild），但尺寸不变就缓存到字段。
- 图标数量变化时才 `Instantiate`/`Destroy`，别每帧重建；量级上来了再上对象池（见 [[对象池实现]]）。
- 每帧给 `Text` 赋 `string` 会持续产生 GC，见 [[TMP Text 零分配更新]]。
