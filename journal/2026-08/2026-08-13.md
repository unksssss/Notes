### 配电房项目 — 地面导航指引线 TaskNavGuideLine（经 Unity MCP 落地）

- 目标文件：`Assets/Scripts/Author/Wt/Task/TaskNavGuideLine.cs`（三项目同步：配电房 / FireSim_URP `Wt/TaskNavGuideLine.cs` / FireSim_URP_VR `Wt/Task/TaskNavGuideLine.cs`）
- 需求：玩家从起点沿 NavMesh 路径到目标物体的地面指引线，LineRenderer 贴地渲染 + 纹理流动箭头动画（VR 消防任务引导）
- 落地流程（Unity MCP mcp-for-unity-server v3.4.7）：
  1. `create_script` 建 TaskNavGuideLine.cs → `manage_gameobject create` 建 NavGuideLine 对象挂脚本 + LineRenderer
  2. `execute_code`（CodeDom 老编译器：要求 return + 全限定名、不支持 using）设 `target = SM_楼梯间B`
  3. NavMeshSurface 在 `Unity.AI.Navigation` 命名空间，**CodeDom 访问受限** → 绕道编辑器脚本 NavBakeTool.cs + `execute_menu_item` 触发烘焙
- 核心实现（对后续导航功能可复用）：
  - `NavMesh.CalculatePath(start, end, NavMesh.AllAreas, path)`：**起终点必须先用 `SamplePosition` 吸附**，直接传悬浮点（玩家脚部 y=7.88）返回 PathInvalid
  - **`PathPartial`（终点附近不完全可达）也算有效路径**，不能只认 PathComplete——Partial 画出来的线能引导大部分路径
  - `Subdivide(corners, 4)` 角点间线性插值，陡坡/台阶更平滑
  - `SnapToGround` 用 `NavMesh.SamplePosition` 取可走表面高度，**不用物理向下射线**：封闭楼梯间里向下射线会先撞屋顶（y 恒 18.46），而 NavMesh 只烘焙可走面（地面/楼梯/平台），采样永远是真正落脚面——验证 y 从 9.60→10.02→10.57→11.15 逐级爬升贴合台阶 ✅
  - 运行时生成箭头贴图（Texture2D 64x16，横向渐变亮段），`mainTextureOffset` 滚动实现流动动画，无需额外美术资源
  - 距离 < `hideDistance(1.5)` 自动隐藏；`SetTarget(Transform)` 运行时指定目标

```cs
// 起终点先吸附 NavMesh 表面，避免 PathInvalid
start = SampleOnNavMesh(start);
end = SampleOnNavMesh(end);

// PathPartial 也算有效：能引导大部分路径
if (NavMesh.CalculatePath(start, end, NavMesh.AllAreas, path)
    && path.status != NavMeshPathStatus.PathInvalid
    && path.corners.Length > 1)
{
    pts = Subdivide(path.corners, cornerSubdivisions);
}
else pts = new[] { start, end }; // 不可达直线兜底
```

### FireSim_URP_VR — NavBakeTool 增强版（3 种烘焙模式）

- 目标文件：`FireSim_URP_VR/Assets/Scripts/Author/Wt/Editor/NavBakeTool.cs`（89 行 3 菜单）📎 [[Unity编辑器扩展开发入门]]
- 抽取 `GetOrCreateSurface()`，新增两种按区域烘焙：
  - **按 ModifierVolume 区域**（`CollectObjects.Volume`）：把 `NavMeshModifierVolume` 的世界边界作为采集范围，只有区域内地面参与烘焙
  - **按 NavMeshModifier 标记**（`CollectObjects.MarkedWithModifier`）：只烘焙挂了 `NavMeshModifier` 且未忽略的地面
- **坑**：`NavMeshSurface` 的 `center/size` 是**相对自身 transform 的本地值** → 用 `TransformPoint` 换算 volume 世界中心、`lossyScale` 绝对值换算世界尺寸后，把宿主挪到 volume 中心再烘焙

```cs
// 把 volume 世界边界换算成 NavMeshSurface 本地 center/size
var volCenter = vol.transform.TransformPoint(vol.center);
var volScale = vol.transform.lossyScale;
var volSize = new Vector3(
    vol.size.x * Mathf.Abs(volScale.x),
    vol.size.y * Mathf.Abs(volScale.y),
    vol.size.z * Mathf.Abs(volScale.z));
surface.transform.position = volCenter;
surface.transform.rotation = Quaternion.identity;
surface.center = Vector3.zero;
surface.size = volSize;
```

### FireSim_URP_VR — 指引线方向/渲染 Bug 修复

- 目标文件：`FireSim_URP_VR/Assets/Scripts/Author/Wt/Task/TaskNavGuideLine.cs`
- **Bug 1：线不随玩家移动 + 方向错**
  - 根因：`GetStartPos()` 依赖 `Camera.main`，而场景 Main Camera 的 tag 是 **Untagged**！`Camera.main` 按 MainCamera tag 查找，缺 tag 返回 null → 起点退化为 transform.position（固定点）→ 线不更新、方向错
  - 修复：`Camera.main` 为 null 时 `Object.FindObjectOfType<Camera>()` 兜底；配电房版用 execute_code 编辑模式设 tag + MarkSceneDirty + 保存场景持久化
- **Bug 2：URP 下材质不渲染（能看到 NavMesh 却看不到线）**
  - 根因：`Legacy Shaders/Particles/Additive` 是 **Built-in 管线 shader**，URP 项目里 `new Material()` 创建成功但**不渲染**
  - 修复：改用 `Universal Render Pipeline/Unlit` + `_BaseColor`（内置管线兜底 `Unlit/Color`）；纹理属性检查 `HasProperty("_BaseMap")`
- **Bug 3：流动动画无效**
  - 根因：`mainTextureOffset` 对应 `_MainTex`，**URP Unlit 的纹理属性是 `_BaseMap`**，mainTextureOffset 在 URP 下无效
  - 修复：`Get/SetTextureOffset("_BaseMap")`；同时方向 `-=` 改 `+=`（LineRenderer uv.x 起点 0→终点 1，offset 增大 → 亮段向目标方向流动）

```cs
// 材质/纹理兼容写法：先 HasProperty 再分支
if (mat.HasProperty("_BaseColor")) mat.SetColor("_BaseColor", lineColor);
else mat.color = lineColor;
if (mat.HasProperty("_BaseMap")) mat.SetTexture("_BaseMap", CreateArrowTexture());
else mat.mainTexture = CreateArrowTexture();
```

- **Bug 4：LineRenderer 场景里序列化为失活**（enabled=false，Play 模式看不到线）→ 双保险：脚本 `Awake` 里 `line.enabled = true` + 编辑模式 execute_code 设 enabled + MarkSceneDirty + 保存场景
