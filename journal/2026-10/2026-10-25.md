```csharp
// PlayerBrain.cs:157-173 现状 —— 唯一一条绕过广播的状态切换
private void HandleJump(PlayerInput input)
{
    if (!input.JumpPressed) return;
    if (state == PlayerState.Grounded)
    {
        motor.Jump(config.normalJumpForce);
        state = PlayerState.Airborne;   // ← 缺 StateChanged?.Invoke(state)
        Jumped?.Invoke();
    }
    else if (state == PlayerState.Airborne && !hasDoubleJumped)
    {
        hasDoubleJumped = true;
        motor.Jump(config.longJumpForce);
        boostRemaining = config.longJumpBoostDuration;
        DoubleJumped?.Invoke();         // ← 二段跳连 state 都没碰，本来就不该发
    }
}
```

后果：`PlayerAnimator` 的 `Grounded` 参数卡在 `true` → `jump_over` 转移失效，跳跃动画不播。**根因不是「忘了写」，而是 `state` 是字段而不是属性**——只要允许直接赋值，旁路就会一直长出来。根治方式是私有 `SetState()` 收口，见 📎 [[有限状态机FSM — 手写实现与状态切换边界]]

## Ideas

- **「资产重存」和「参数改动」在无版本管理时无法区分**。今天 `.mat` 的时间戳变了，唯一能拿到的证据是「与 shader 默认值逐项比对」——这只能证明「现在等于默认」，证明不了「他没调过又改回来」。这类取证成本，就是没 `git init` 的利息
- **状态机只要 `state` 是字段，旁路就永远存在**。`PlayerBrain` 里 7 处切换、6 处老实发事件、1 处不发——不是纪律问题，是「允许直接赋值」这个设计给的自由度。私有 `SetState()` 不是洁癖，是把「漏广播」变成编译不过
- **asmdef 才是「禁止 using UnityEditor」的唯一有效手段**。10-23 行为树一次、10-24 `PlayerBrain` 两次，三次都是 VS 自动补全塞进去的——靠人记，必然复发
- 镜面是**每帧一次镜像相机渲染**（额外 RT + 一次全场景 DrawCall）。跑酷这种快节奏场景应该做「距离/朝向开关」或降分辨率，而不是常开；`_ReflectStrength` 调低不省任何开销
- **工具依赖硬编码路径是脆的**。`机试` 改个名，Part A 的扫描就会静默返回 0 条——而「0 条」和「目录不存在」在日志里长得一模一样。全域 `find` 兜底比路径白名单可靠
- Day 53 的盲区清单里有三个方向是**资源库一个字都没有**的：骨骼蒙皮、PVS 遮挡剔除、BRG / GPU Resident Drawer。这三块恰好是「图形岗面试必问、日常工作不碰」的典型
