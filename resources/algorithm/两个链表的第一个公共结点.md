# 两个链表的第一个公共结点

对应 **剑指 Offer 52 / LeetCode 160**。题面：输入两个单链表，找出它们的**第一个公共结点**（无公共结点返回 `null`）。

## 前置认知：为什么必然是「Y 形」而不是「X 形」

单链表的每个结点**只有一个 `next`**。所以一旦两个链表共用某个结点，那个结点之后的路径**完全重合**——不可能出现"合了又分"。

```
A:  a1 → a2 ┐
            ├→ c1 → c2 → c3 → null
B:  b1 → b2 ┘        ↑
                 第一个公共结点
```

这个认知是所有解法的基础，也是面试官第一个想确认的点。

## 解法一：长度差对齐法（最直观）

思路：先各求一次长度，算出差 `d`；**长链先走 `d` 步**，然后两指针同步走，第一个相同结点就是答案。

```csharp
public ListNode GetIntersectionNode(ListNode headA, ListNode headB)
{
    int lenA = GetLen(headA), lenB = GetLen(headB);
    // 让 a 指向较长链
    ListNode a = lenA >= lenB ? headA : headB;
    ListNode b = lenA >= lenB ? headB : headA;
    int d = Math.Abs(lenA - lenB);

    while (d-- > 0) a = a.next;          // 长链先对齐
    while (a != b) { a = a.next; b = b.next; }
    return a;                            // 无交点时 a、b 同时为 null，直接返回 null
}
private int GetLen(ListNode h) { int n = 0; while (h != null) { n++; h = h.next; } return n; }
```

时间 **O(m+n)**、空间 **O(1)**。

## 解法二：双指针「走完自己走对方」（代码最短，面试首选）

思路：`pA` 走到 `null` 就跳到 `headB` 继续，`pB` 同理。两者走过的总路程都是 `m + n`，**必然同时走到交点**；若无交点，则同时走到 `null`。

```csharp
public ListNode GetIntersectionNode(ListNode headA, ListNode headB)
{
    if (headA == null || headB == null) return null;
    ListNode pA = headA, pB = headB;
    while (pA != pB)                       // 无交点时 pA、pB 最终同时为 null，循环自然退出
    {
        pA = pA == null ? headB : pA.next;
        pB = pB == null ? headA : pB.next;
    }
    return pA;
}
```

**为什么成立**：设 A 独立段长 `a`、B 独立段长 `b`、公共段长 `c`。
`pA` 路程 = `a + c + b`，`pB` 路程 = `b + c + a` —— **完全相同**，所以同时抵达交点。

时间 **O(m+n)**、空间 **O(1)**。注意是 `pA != pB`（比较引用），不需要额外求长度。

## 解法三：哈希表（思路最朴素，但费空间）

遍历 A，把所有结点存进 `HashSet<ListNode>`；再遍历 B，第一个已在集合里的结点就是答案。

- 时间 O(m+n)，空间 **O(m)** —— 空间不占优，一般只作为"能想到的兜底解"在面试里提一句。

## 三种解法对比

| 解法 | 时间复杂度 | 空间复杂度 | 评价 |
| --- | --- | --- | --- |
| 长度差对齐法 | O(m+n) | **O(1)** | 最直观，两趟走 |
| 双指针走完自己走对方 | O(m+n) | **O(1)** | **代码最短，面试首选** |
| 哈希表 | O(m+n) | O(m) | 思路简单但不省空间 |

## 易错点（面试扣分项）

1. **比较的是「结点引用」而不是「值」** —— 两链表里出现相同数值的结点**不算**公共结点。
2. **不能"从后往前找最后一个不同的"** —— 单链表不能反向遍历。要反向就得先反转，反而把结构破坏了。
3. **无交点必须返回 `null`** —— 双指针法自动满足（同时为 null）；长度差法里 `a != b` 循环也会自然退出并返回 null。别写死循环。
4. **解法二里判断 `pA == null` 要放在取 `next` 之前**，写法上 `pA = pA == null ? headB : pA.next` 是安全的；写成先 `pA = pA.next` 会空引用。

## 面试延伸（加分）

- **和「链表中环的入口结点」的关系**：两题都靠"路程相等"的巧劲，一个用双指针走完全程、一个用快慢指针 1:2 速度差。见 [[链表中环的入口结点]]。
- **变体**：求"两个链表是否相交 + 交点在哪个位置"是同一题；若问"相交后的公共段长度"，先求交点再走一遍即可。
- **工程落点**：Git 的提交历史合并（merge base）本质就是"两个有向链表的第一个公共结点"。
