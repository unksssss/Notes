# 魂类命中判定 — 动画窗口与多段去重

## 一、核心认知

**魂类的判定不是「射线打中掉血」，是「动画驱动的时间窗口 + 逐帧碰撞 + 一次攻击只结算一次」。**

一次挥砍被切成三段：

```
前摇（长） → 判定窗口（短） → 后摇（长）
              ↑ 只有这一段 hitbox 开启，且去重集合在此清空
```

**这个结构是设计意图，不是技术限制**：

- **前摇长**：给对手读招时间，也让玩家自己不能无脑连点
- **判定窗口短**：让「时机」变成技术
- **后摇长**：攻击是有代价的，打完不能立刻撤

普通 ARPG 追求手感爽快（前摇短、窗口长），魂类反过来——**它要的是每一次攻击都有重量**。

---

## 二、判定窗口怎么开

| 方式 | 做法 | 适用 |
| --- | --- | --- |
| **Animation Event** | 动画第 N 帧插事件，回调里 `collider.enabled = true/false` | 最常用，和美术协作最直接 |
| **`normalizedTime` 判断** | 每帧读 `AnimatorStateInfo(0).normalizedTime`，落在 `[start, end]` 才判定 | 不想改动画资源时 |
| **ScriptableObject 配攻击数据** | 每招配 `windowStart / windowEnd` | **招式多、要策划调参**，最工程化 |

第三种的价值：**招式数据外置，加新招不用动代码**，每招的手感（窗口长短、顿帧时长、削韧值）都能单独调。

---

## 三、判定形状：三种方案

| 方案 | 做法 | 优点 | 代价 |
| --- | --- | --- | --- |
| **武器骨骼挂 Collider** | 胶囊/盒体跟随手部骨骼，`OnTriggerEnter` | 精确、支持擦边，能判「刀刃划过」 | 开销高，**必须去重** |
| **固定帧 Overlap 快照** | 判定帧做一次 `OverlapBox/Sphere` | 便宜、无状态 | **高速武器会穿透**（tunneling） |
| **扫掠检测** | `CapsuleCast` 从上一帧位置扫到本帧 | 折中，不穿透 | 需要上一帧位置，方向计算更麻烦 |

魂类通常用第一种——**「刀刃划过」本身就是要被判定的东西**，擦边命中是手感的一部分。

---

## 四、一次攻击只结算一次（最关键）

一次挥砍跨 10~20 帧，同一把刀会反复进入同一个敌人的碰撞体。不处理就会**一刀打掉十段血**。

```csharp
public class WeaponHitbox : MonoBehaviour
{
    [SerializeField] Collider hitCollider;
    [SerializeField] LayerMask targetMask;
    [SerializeField] AttackData currentAttack;

    readonly HashSet<Collider> hitThisSwing = new HashSet<Collider>();

    // 由 Animation Event 在判定窗口起点调用
    public void OpenHitbox()
    {
        hitThisSwing.Clear();          // ★ 每次挥砍开始清空
        hitCollider.enabled = true;
    }

    public void CloseHitbox() => hitCollider.enabled = false;

    void OnTriggerEnter(Collider other)
    {
        if (!hitCollider.enabled) return;
        if ((targetMask & (1 << other.gameObject.layer)) == 0) return;

        // Add 返回 false = 已存在 → 这一次挥砍已经打过它
        if (!hitThisSwing.Add(other)) return;

        var hurtbox = other.GetComponent<Hurtbox>();
        if (hurtbox == null) return;

        var result = DamageCalc.Calculate(
            currentAttack, hurtbox.Owner, hurtbox.ZoneMultiplier);

        hurtbox.Apply(result);          // 扣血 + 削韧 + 硬直
        HitFeedback.Play(result);       // 顿帧 + 特效 + 音效 + 震屏
    }
}
```

**`HashSet.Add` 返回 false 就说明已存在**——一行完成「检查 + 记录」，比先 `Contains` 再 `Add` 少一次哈希。

### 两个必踩的坑

1. **连段必须按段重置**
   三连斩共用同一个集合的话，第二段砍同一个敌人不掉血。做法：每段进判定窗口都 `Clear()`，或用 `Dictionary<int attackId, HashSet<Collider>>` 按段隔离。

2. **集合要复用，不要每次 new**
   每次挥砍 `new HashSet` 会产生持续 GC 垃圾。`Clear()` 复用就好。

## 五、部位判定与削韧（魂类的重点不是伤害）

```csharp
public class Hurtbox : MonoBehaviour
{
    [SerializeField] float zoneMultiplier = 1f;          // 头 2.0 / 身 1.0 / 尾 0.7
    [SerializeField] float poiseDamageMultiplier = 1f;

    public Character Owner;
    public float ZoneMultiplier => zoneMultiplier;

    public void Apply(HitResult r)
    {
        Owner.TakeDamage(r.damage * zoneMultiplier);
        Owner.ReducePoise(r.poiseDamage * poiseDamageMultiplier);
        // 削韧归零 → 触发硬直动画，期间不可行动
    }
}
```

敌人身上挂多个 `Hurtbox`（头、身、尾），命中时**从 collider 反查部位倍率**——不用在伤害公式里写 if-else。这是数据驱动在战斗系统里的典型形态。

**魂类的战斗节奏由削韧（poise）驱动，而不是血量**：打不断对方动作，就没法安全输出；削韧满了才有一次硬直窗口。这是它区别于普通 ARPG 的核心。

## 六、无敌帧（i-frame）用曲线驱动

```csharp
[SerializeField] AnimationCurve invincibleCurve;   // 0 = 可被击中，1 = 无敌

public bool IsInvincible =>
    invincibleCurve.Evaluate(
        animator.GetCurrentAnimatorStateInfo(0).normalizedTime % 1f) > 0.5f;
```

用曲线而不是 `if (t > 0.1f && t < 0.4f)`：**策划能在 Inspector 里拖曲线调手感**，翻滚多久无敌、什么时候结束全部可视化。

⚠️ **不要用 `Physics.IgnoreLayerCollision` 实现无敌**——它影响整个层的碰撞，会连带废掉触发器和射线。

## 七、顿帧：手感的真正来源

```csharp
IEnumerator HitStop(float duration, float scale = 0.05f)
{
    Time.timeScale = scale;
    yield return new WaitForSecondsRealtime(duration);   // ★ 必须 Realtime
    Time.timeScale = 1f;
}
```

**`WaitForSeconds` 在这里是错的**：它受 `timeScale` 影响，缩到 0.05 之后等 0.05 秒需要 1 秒真实时间，画面像卡死。必须用 `WaitForSecondsRealtime`。

这也解释了魂类「砍中」和「砍空」手感差这么多——**砍空没有顿帧**。

---

## 八、联机的取舍：刻意不做延迟补偿

魂类的 PVP 用**主机权威 + 客户端不做回溯补偿**：判定在主机端算，客户端只做表现预测。

它**刻意不做 lag compensation**——回溯判定会让「高延迟玩家打你更准」，反而不公平。它选择让延迟对称地存在于双方，这也是魂系 PVP 常被吐槽网络差的原因。

> 对比：FPS 必须做回溯补偿（因为射击是像素级精度），格斗游戏用回滚（rollback）。**判定要不要回溯，取决于「玩家能不能接受被延迟杀死」**。

---

## 九、面试话术

> 「魂类的判定不是即时射线命中，是**动画驱动的时间窗口**。攻击动画分成前摇、判定窗口、后摇三段，只在判定窗口内开启武器的 hitbox 做逐帧碰撞——前摇长、窗口短、后摇长是刻意的设计，逼玩家读招、也让攻击有代价。
>
> 因为一次挥砍跨十几帧、会反复碰到同一个敌人，所以要有 `HashSet` 去重，**每次挥砍开始清空，连段每段都要单独重置**，否则第二段打不到同一个目标。
>
> 命中后不止算伤害，还要算**削韧和硬直**，敌人身上挂多个 Hurtbox 做部位倍率。玩家的翻滚有无敌帧，一般用 AnimationCurve 驱动而不是硬编码时间，方便调手感。」

## 十、自测四问

1. 为什么魂类的判定窗口不覆盖整个动画？
2. 一刀打掉十段血是什么原因？怎么修？连段为什么需要额外处理？
3. 削韧（poise）和伤害在代码上是分开算的，为什么？
4. 顿帧为什么必须用 `WaitForSecondsRealtime`？

> 第 2 题的关键词是「**逐帧重复进入碰撞体**」+「`HashSet.Add` 返回 false」。第 4 题的答案：`WaitForSeconds` 受 `timeScale` 影响，缩时后等待会被无限拉长。
