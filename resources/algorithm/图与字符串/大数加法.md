# 大数加法

## 一、题目

两个用字符串表示的非负整数，返回它们的和的字符串。`long long` 装不下（长度可达 10⁵），不能用内置大整数。

```
"1"    + "2"     → "3"
"9"    + "9"     → "18"
"99"   + "1"     → "100"
"12"   + "999"   → "1011"
"0"    + "0"     → "0"
```

## 二、核心认知

这就是**小学竖式加法**，一次循环同时完成三件事：

1. **取位**：短的一方走完了就补 `0`（`i >= 0 ? s[i]-'0' : 0`）
2. **相加**：`sum = a + b + carry`
3. **写出**：本位 `sum % 10`，进位 `sum / 10`

因为是从**低位往高位**算，结果只能**从后往前写**（`push_back` 完再 `reverse`），或者每次往头部插（`insert(begin())`，但那样是 `O(n²)`）。

## 三、灯皇初版的四处错

穷举 7 组用例实测：

| s | t | 原版 | 只修①下标 | +②`>=10` | +③进位对调 | 标准答案 |
|---|---|---|---|---|---|---|
| 1 | 2 | 死循环 | 3 | 3 | 3 | **3** |
| 9 | 9 | 死循环 | 1 | 1 | 8 | **18** |
| 5 | 5 | 死循环 | `:` | 1 | 0 | **10** |
| 99 | 1 | 死循环 | `9:` | 91 | 00 | **100** |
| 12 | 999 | 死循环 | `:11` | 111 | 011 | **1011** |
| 999 | 999 | 死循环 | 221 | 221 | 998 | **1998** |
| 0 | 0 | 死循环 | 0 | 0 | 0 | **0** |

> 注意「只修①」那一列已经出现冒号 `:` —— 那是 `10 + '0'`（ASCII 58）被当作数字写进了结果。

### ① `if (i > 0) i--;` → 下标永远到不了 `-1`

```cpp
if (i > 0) i--;     // ❌ i 卡在 0 不动
if (i >= 0) i--;    // ✅
```

`i == 0` 时条件为假，`i` 永远停在 `0`，于是 `i < 0 && j < 0` **永远不成立**，`while (true)` 永不退出。

**7 组用例 7 组死循环** —— 这题一个用例都没过，不是"答案差一点"。

### ② `if (sum > 10)` → 漏了等号

```cpp
if (sum > 10)   // ❌ sum == 10 时走不进去
if (sum >= 10)  // ✅
```

`5 + 5 = 10`，判断为假 → 不进位 → 直接把 `sum + '0'` 也就是 `10 + '0'` 写进结果，字符是 **`:`**（ASCII 58）。

**这个 bug 的表现很醒目**：输出里出现冒号、分号之类的怪字符，就是"数字超过 9 没拆位"。

### ③ 进位和本位写反了

```cpp
carray = sum % 10;  sum = sum / 10;   // ❌ 把个位当进位
carray = sum / 10;  sum = sum % 10;   // ✅
```

不是"差一个"，是**每一位都错**：`999 + 999` 应该 `1998`，实测输出 `221`。

### ④ 最后一次进位没有补

即使前三条全改对，`9 + 9` 仍然输出 `1`（正确 `18`）。因为：

- 两个输入位都取完了，循环退出
- 但 `carry = 1` 还没有任何一位负责写出来

**最高位的进位是"凭空多出来的一位"**，没有任何输入位对应它 —— 所以它必须自己成为一条循环条件：

```cpp
while (i >= 0 || j >= 0 || carry)   // ★ carry 单独一趟
```

### 附带：`insert(begin())` 是 `O(n²)`

```cpp
result.insert(result.begin(), sum + '0');   // 每次搬动整串
result.push_back(sum + '0');                // O(1) 摊还，最后 reverse 一次
```

长度 10⁵ 时前者约 5×10⁹ 次字符搬动，能过也悬。

## 四、正解

```cpp
class Solution {
public:
    string solve(string s, string t) {
        int i = (int)s.size() - 1, j = (int)t.size() - 1;
        int carry = 0;
        string res;
        while (i >= 0 || j >= 0 || carry) {          // ★ 三条退出条件
            int a = i >= 0 ? s[i--] - '0' : 0;       // 取位 + 自减一步到位
            int b = j >= 0 ? t[j--] - '0' : 0;
            int sum = a + b + carry;
            res.push_back(char(sum % 10 + '0'));     // 本位
            carry = sum / 10;                        // 进位
        }
        reverse(res.begin(), res.end());             // 低位在前 → 翻过来
        return res;
    }
};
```

**关键点：不要 `if (sum >= 10)` 分支。** `% 10` 和 `/ 10` 对 `sum < 10` 天然返回 `sum` 和 `0`，一行搞定两种情形 —— 你那个 `if` 除了多一个可能漏等号的地方，没有任何收益。

## 五、必须记住的点

1. **`sum == 10` 必须进位** —— `10 + '0'` 是 `':'`，不是"10"。凡是"数字转字符"的地方，先想清楚 0~9 之外会发生什么。
2. **进位是 `sum / 10`，本位是 `sum % 10`，写反了全盘皆错** —— 而且错得很"均匀"，不容易一眼看出规律。
3. **`carry` 要进循环条件** —— 「两个数都读完了」不等于「算完了」，还可能剩一个进位。
4. **下标递减的条件统一用 `>= 0`** —— 凡是 `i > 0` 作为"继续"的条件，几乎都该是 `i >= 0`。这已经是第 N 次见到 `> 0` / `>= 0` 的错位了（`字符串变形`、`最长公共子串` 同源）。

## 六、易错点

1. **`if (i > 0) i--` → 死循环** —— 不报错、不崩、不超内存，就是跑不出结果（TLE）。这类"不产出错误答案、只是不前进"的 bug 最难自查，**写完循环先问一句「这个循环靠什么退出」**。
2. **`sum > 10` 漏等号** —— 表现是输出冒号。
3. **进位 / 本位写反** —— `221` 那种。
4. **末次进位丢失** —— `9 + 9 → 1`。
5. **`insert(begin())`** —— 功能对、复杂度错。
6. **`0 + 0` 要输出 `0`** —— 如果结果串做了"去前导零"，别把唯一的 `0` 也删掉变成空串。
7. **`s.size()` 是 `size_t`** —— `int i = s.size() - 1;` 在空串时会下溢成 `SIZE_MAX` 再截断，务必先 `(int)` 再减。

## 七、复杂度

| 维度 | 值 |
|---|---|
| 时间 | `O(max(m, n))`（`insert(begin())` 版退化成 `O(n²)`） |
| 空间 | `O(max(m, n))` | 
| 额外空间 | `O(1)`（除结果本身） |

## 八、面试延伸

- **大数减法**：先比长度/字典序定符号，再从低位借位；`a < b` 时交换并补 `-`
- **大数乘法（LC 43）**：竖式错位累加，`res[i + j + 1] += a[i] * b[j]`，最后统一处理进位 —— `O(n·m)`
- **LC 2 两数相加**：链表版，**逆序存储** → 天然从低位开始，连 `reverse` 都省了
- **LC 67 二进制求和**：完全同构，只把 `% 10` / `/ 10` 换成 `% 2` / `/ 2`
- **大数阶乘 / 2 的 n 次幂**：用「大数 × 小数」的乘法反复乘
- **工程里怎么写**：Java `BigInteger`、Python 任意精度整数；C++ 没有内置，要么手写，要么 `boost::multiprecision::cpp_int`

## 九、补记：第二版改写后仍错（2026-11-14 10:05）

循环条件和 `push_back` 都改对之后，灯皇报了新用例过不了：

```
s = "9"
t = "99…94"（62 位，末位是 4）
```

原因是一行**变量覆盖**：

```cpp
int sum = a + b + carray;
sum = sum % 10;                  // ❌ 原始的和（十位信息）在这里被覆盖掉
result.push_back(char(sum + '0'));
carray = sum / 10;               // ❌ 此时 sum < 10，恒为 0 —— 一次进位都没做
```

`sum % 10 < 10` 恒成立 ⇒ `sum / 10` **恒等于 0**，进位链整条断掉。等价于「只把末位加起来、永不向高位进」。

| | 位数 | 值 |
|---|---|---|
| 你的输出 | 62 | `99…93`（把 t 末位 4 改成 3，长度不变） |
| 正确输出 | 63 | `100…003`（进位一路推到最高位，凭空多一位） |

注意差值不在"数值差多少"，而在**位数**上 —— 这正是"进位丢了"的特征：该长出来的那位没长出来。

正确写法是**先取本位、再算进位，两次都读未改动的 `sum`**：

```cpp
int sum = a + b + carry;
result.push_back(char(sum % 10 + '0'));   // 本位
carry = sum / 10;                          // 进位（sum 原封不动）
```

或者干脆用两个变量 `digit` / `carry`。**不要用同一个变量既存"和"又存"本位"** —— 一旦覆盖，第二次读到的就不是那个和了。

> 这是「静默失效」的又一种形态：不崩、不报警，连 `1 + 2`、`9 + 1` 这种不进位的小用例都对，只有**需要连续进位**的用例才暴露。
