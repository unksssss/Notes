### FireSim_URP_VR — VerticalBackPack 对接消防车（外部追加 + 强制重建）

`VerticalBackPack.cs` 新增 `AddEquip` 订阅 `fireTruckUI.OnConfirmEquips`，实现多次追加装备数据：

```csharp
private void AddEquip(List<EquipDefinition> equipLst)
{
    dataList.AddRange(equipLst);
    // 强制重建 item（新数据必须生成新 item）
    foreach (var kv in itemDict)
        if (kv.Value != null) Destroy(kv.Value.gameObject);
    itemDict.Clear();
    itemList.Clear();
    Init();   // CreatItems + stepScrollView.Init + SetMaxStep
}
```

关键点：**追加数据后必须 Destroy 旧 item 再重建**，而不是原地 `Refresh()`——因为 item 数量变了，走 `Refresh` 分支不会创建新 item，会出现数据与 UI 不同步。这也是 `WristStepPanel<TData,TItem>` 泛型基类（`Init/CreatItems/Refresh` 三分支）在 `FireTruckUI` 场景下的第三次复用。

### FireSim_URP_VR — FireHoseFXToIgnisLink 灭火调参（真实灭火时间测量）

`FireHoseFXToIgnisLink.cs` 升级：默认启用**专用灭火粒子系统**（`useDedicatedExtinguishSystem=true`），灭火与视觉完全解耦——视觉粒子密度不影响灭火速率，反之亦然。核心调参公式（注释原话）：

```
调参公式(5秒灭火): incrementalPower ≈ (approxSize * fullExtinguishToughness * 0.5 - particleExtinquishRadius) / (5 × 50 × 0.3)
典型值 0.001~0.01，0.004 ≈ 5 秒灭火(默认 cube)
```

**真实灭火时间测量**（不再依赖估算）：订阅 `FlameEventInvoker` 的 `Ignited/Extinguished/BurntOut` 事件：

```csharp
// 处理"订阅时已在燃烧"的情况:用 onFireTimer 反推起点
var flammable = go.GetComponent<Ignis.FlammableObject>();
if (flammable != null && flammable.onFireTimer > 0f)
    _ignitedAt[go] = Time.time - flammable.onFireTimer;

// 被扑灭回调
inv.Extinguished.AddListener(() =>
{
    if (_ignitedAt.TryGetValue(go, out float t0))
    {
        float realSec = Time.time - t0;
        Debug.Log("[真实灭火] " + go.name + " 被扑灭耗时 = " + realSec.ToString("F2") + " 秒");
    }
});
```

坑点记录：
- **订阅去重**：用 `gameObject.GetInstanceID().ToString()` 存 HashSet，防止重复监听导致事件多次触发
- **粒子创建时序**：`AddComponent<ParticleSystem>` 后 `playOnAwake` 默认 true、粒子已在播放，必须**先 `Stop()` 再改 main 参数**，否则抛 "system is still playing"
- **防穿墙反弹**：`collision.lifetimeLoss = 1f` + `maxKillSpeed = 9999f`，粒子第一次撞任何碰撞体立即死掉，不会反弹二次命中火焰
- **Muzzle 解析**：`jet.muzzle` → 按名递归找 `Muzzle` → 自身，三级兜底
