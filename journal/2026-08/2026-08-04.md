### 每日知识问答 — Day 15（10/10 🏆 史上首个满分）

两个连续失分点（DFS/BFS 3 连败、Obi Blueprint 2 连败）全部攻破，新知识点首学即吸收。

**Q1（选择题·算法）快排退化条件** — ✅ 📎 [[排序算法-快排归并堆排]]
- 题目：快排平均 O(n log n)，何种情况退化 O(n²)？A.数据量超100万 B.基准取到当前区间最值（有序数组固定取首元素）C.全相同+三路快排 D.随机化基准
- 答案：B。每次划分只分出一个元素 → 递归深度退化 O(n) × 每层 O(n) = O(n²)。三路快排反而解决重复元素；随机化基准是优化手段

**Q2（选择题·项目实战）ContentSizeFitter 动态刷新** — ✅
- 答案：运行时 AddChild 后父尺寸不更新被裁切 → 需手动 `LayoutRebuilder.ForceRebuildLayoutImmediate`（或 `Canvas.ForceUpdateCanvases`）。布局系统走脏标记刷新
- 关联：白天修的 countOfItemInView=1 同款坑——Start 时机读 UI 尺寸要先强制布局（详见下方修复记录 📎 [[UGUI布局系统与强制刷新]]）

**Q3（选择题·经典面试）二叉树层序遍历** — ✅ 📎 [[DFS与BFS遍历算法]]
- 答案：队列。FIFO 保证同一层节点按序出队，BFS 广度优先

**Q4（选择题·算法）两栈实现队列** — ✅
- 答案：stackOut 为空时把 stackIn 全部倒入再 pop；非空直接 pop。摊还 O(1)。直接 pop stackIn 会破坏 FIFO

**Q5（选择题·项目实战）BFS 网格寻路** — ✅ 🎉 📎 [[DFS与BFS遍历算法]]
- 题目：1000×1000 网格找最短路径为何选 BFS 而非 DFS？
- 答案：BFS 按层扩散，第一次到达终点天然最短（无权图）；DFS 找到的不保证最短
- **连续失分点（Day12/13/14）第四次考终于攻破！**

**Q6（简答·经典面试）递归与迭代转换**（先讲后答）— ✅ 📎 [[递归与迭代转换]]
- 讲解：尾递归直接转循环；一般递归按状态类型选结构——DFS 用栈、BFS 用队列；斐波那契递归 O(2ⁿ) vs 迭代 O(n)
- 巩固问：二叉树前序迭代用什么结构？为何先压右再压左？→ "栈，后压左子树先访问左子树" ✅ 补充：LIFO 特性，先压右再压左 → 左先出栈 → 根→左→右

**Q7（简答·算法）动态规划入门**（先讲后答）— ✅ 📎 [[动态规划入门]]
- 讲解：最优子结构 + 重叠子问题；三板斧（定义状态/转移方程/初始值）；爬楼梯 dp[i]=dp[i-1]+dp[i-2]
- 巩固问：一次上 1 或 3 级，转移方程与初始值？→ "dp[1]=1, dp[2]=1, dp[3]=2" ✅ 初始值全对；补转移方程 dp[i]=dp[i-1]+dp[i-3]

**Q8（简答·项目实战）DOTween vs 协程**（先讲后答）— ✅ 📎 [[DOTween与协程选型]]
- 讲解：协程=状态机管流程、DOTween=时间轴补间可暂停/恢复/反向；口诀"动用 DOTween，流程用协程"
- 巩固问：VR 开门中途可反向，选哪个？→ "DOTween，代码简洁性能好缓动曲线多" ✅ 选对；补充最核心理由：**可中断/PlayBackwards 反向控制**（协程要自己记录进度写反向插值）

**Q9（简答·项目实战）Obi Blueprint 坐标系**（先讲后答）— ✅ 🎉 📎 [[Obi Rope粒子约束体系]]
- 讲解：控制点必须写在绳索 Actor 局部坐标，Transform 放端点使 CP0=(0,0,0) 对应端点；Blueprint 管形状、Transform 管摆放
- 巩固问：整体平移绳索要重建 Blueprint 吗？→ "控制端点，不需要重建 blueprint" ✅ 核心答对；修正：正确操作是移动绳索 Transform（拖端点会拉伸不是平移）
- **连续失分点（Day12/14）第三次考终于攻破！**

**Q10（简答·经典面试）Update/FixedUpdate/LateUpdate**（先讲后答）— ✅ 📎 [[Update-FixedUpdate-LateUpdate执行时机]]
- 讲解：FixedUpdate 固定步长跑物理（Rigidbody/碰撞）；Update 帧率相关跑逻辑；LateUpdate 相机跟随防抖动；物理与渲染两套时钟解耦
- 巩固问：相机跟随放哪？CharacterController.Move 放哪？→ "LateUpdate 避免抖动/穿帮，Update" ✅ 全对；补充：CC.Move 是直接驱动位移非物理引擎，Update 标准写法；Rigidbody+AddForce 才必须 FixedUpdate

### FireSim_URP_VR — StepScrollView 高亮策略委托化

- **目标文件**：`FireSim_URP_VR/Assets/Scripts/Author/Wt/UI/StepScrollView.cs`、`.../WristUI/BackPackPlus/StepBackPack.cs`
- **问题**：StepScrollView 内置高亮写死为缩放变化，灯皇要求高亮策略可定制
- **方案**：委托化，组件只负责"高亮发生在第几步"，具体视觉由面板自己定

```cs
// StepScrollView.cs — 新增委托，HighlightItem 改为回调
public System.Action<int> onHighlight;

public void HighlightItem(int index)
{
    onHighlight?.Invoke(index);
}
```

```cs
// StepBackPack.cs — 注册必须在 Init() 之前！
stepScrollView.onHighlight += OnStepHighlight;  // 先注册
stepScrollView.Init();                          // Init 内部立刻触发第一帧高亮

private void OnStepHighlight(int index)
{
    var list = stepScrollView.items;
    if (list == null || list.Count == 0) return;
    for (int i = 0; i < list.Count; i++)
        list[i].DOScale(1f, 0.2f);
    list[Mathf.Clamp(index, 0, list.Count - 1)]
        .DOScale(1.2f, 0.3f).SetEase(Ease.OutBack);
}
```

- **坑**：`Init()` 里 `HighlightItem(stepIndex)` 会立刻触发回调，所以 `onHighlight +=` 必须注册在 `Init()` **之前**，否则第一帧高亮丢失
- StepBackPack 还有 `img_Selected` 移动框（`ApplyStepImg_Select`），缩放只是附加高亮，两者并存

### FireSim_URP_VR — TaskPanelPlus 越界崩溃修复

- **目标文件**：`FireSim_URP_VR/Assets/Scripts/Author/Wt/UI/WristUI/TaskPanelPlus/TaskPanelPlus.cs`
- **问题**：`ArgumentOutOfRangeException` —— 委托化后 Highlight 访问空列表崩溃，TaskTips 的 item 永不填充
- **根因**：`taskTipsItemLst` 字段声明时 `= new List<...>()` 初始化 → `RefreshTaskTipsUI` 里 `if (taskTipsItemLst != null)` 永远走**空循环分支**（只看标题不建 item），else 分支（真正实例化 item 的代码）永不执行

```cs
// 修复前（罪魁）：声明时初始化，if != null 永远为 true → 建 item 的 else 分支被饿死
public List<TaskPanelItemPlus> taskTipsItemLst;   // ← 去掉 = new List<>()

// 修复后：Highlight 增加越界保护
private void Highlight(int _index)
{
    if (taskTipsItemLst == null || taskTipsItemLst.Count == 0) return;
    if (_index < 0 || _index >= taskTipsItemLst.Count) return;
    ...
}
```

- **经验**：字段声明时 `= new List<T>()` 会污染"是否已初始化"的判断——正确做法是保留 null 语义，由初始化流程（RefreshTaskTipsUI 的 else 分支）负责建列表，或显式用 `??=` 惰性初始化

### FireSim_URP_VR — countOfItemInView=1（Start 时机布局未计算）

- **目标文件**：`FireSim_URP_VR/Assets/Scripts/Author/Wt/UI/StepScrollView.cs`
- **问题**：`countOfItemInView` 恒为 1 → 步进边界判断全错
- **根因**：`Init()` 在 Start 时机读 `viewport.rect`，Canvas 布局尚未计算 → anchor 拉伸的 viewport rect 为 (0,0)
- **第一版（失败）**：`LayoutRebuilder.ForceRebuildLayoutImmediate` 只对挂 LayoutGroup 的节点有效，纯 anchor 拉伸的 viewport 不触发；`sizeDelta` 兜底也无效（anchor 拉伸时 sizeDelta 恒为 0）
- **最终版（有效）**：`Canvas.ForceUpdateCanvases()` 强制整棵 Canvas 布局刷新 + `GetWorldCorners` 世界坐标兜底

```cs
Canvas.ForceUpdateCanvases();   // 关键：强制整个 Canvas 布局刷新

float viewportSize = m_Horizontal ? viewport.rect.width : viewport.rect.height;

// 兜底：仍为 0 时用世界坐标 corners 计算实际尺寸
if (viewportSize <= 0)
{
    Vector3[] corners = new Vector3[4];
    viewport.GetWorldCorners(corners);
    viewportSize = m_Horizontal
        ? Vector3.Distance(corners[0], corners[3])
        : Vector3.Distance(corners[0], corners[1]);
}
countOfItemInView = Mathf.Max(1, (int)(viewportSize / m_StepSize));
```

- **经验**：Start 时机读 UI 尺寸 → `Canvas.ForceUpdateCanvases()` 是正解；`GetWorldCorners` 比 `sizeDelta` 可靠（anchor 拉伸时 sizeDelta 恒 0）📎 [[UGUI布局系统与强制刷新]]

### FireSim_URP_VR — 左手腕 UI 两层交互 + XRInputModule API

- **目标文件**：`.../Author/Wt/LeftHandWristUIMgr.cs`、`.../Author/Wt/ClickLimit.cs`、`.../UI/WristUI/IWristUI.cs`
- **设计**：左手柄控制手腕 UI 两层结构——第一层常驻菜单（摇杆↑↓ 切换选中面板，Trigger 进入），第二层具体面板（摇杆←→ 移动选项，Trigger 确认，Grab 关闭返回菜单）。一级菜单常驻不关闭
- **IWristUI 五件套接口**：`Focus/Defocus/MoveNext/MovePrevious/Confirm`，所有手腕面板（StepBackPack/TaskPanelPlus/TaskTipsPanel）统一实现
- **XRInputModule 输入要点**（FireSimVR.XRInput 命名空间）：

```cs
input.WasPressedThisFrame(hand, XRControllerButton.TriggerButton); // 边缘触发，比 IsPressed 适合做单击
input.GetPrimary2DAxis(XRHandSide.Left);                          // Vector2 摇杆值
input.SetCapability(hand, XRInputCapability.UIScroll, false);     // 禁用能力（Move/Turn/Grab/UIScroll/UIInteraction）
input.SetTurnMode(XRHandSide.Left, XRTurnMode.Disabled);          // 禁用转向
```

- **ClickLimit 防连击工具类**：`canClick() + SetLastClickTime()`，基于 `Time.unscaledTime`（不受 timeScale=0 暂停影响），`new ClickLimit(0.3f)` 按 Trigger/Grab 各自实例化

```cs
public class ClickLimit
{
    private float clickLimitTime;
    private float lastClickTime;
    public bool canClick()
    {
        if (Time.unscaledTime - lastClickTime > clickLimitTime)
        {
            SetLastClickTime();
            return true;
        }
        return false;
    }
    private void SetLastClickTime() => lastClickTime = Time.unscaledTime;
    public ClickLimit(float _clickLimitTime) => clickLimitTime = _clickLimitTime;
}
```
