摇杆的职责切分很干净：`JoyStickKnob` 只负责「把拖拽位移变成 [-1,1] 的二维值」，`JoyStick` 只负责「把值转发给外部」，`Player` 只负责「消费值」。转发通道是一个委托字段：

```cs
// JoyStick.cs
internal Action<Vector2> Motion;

void Start()
{
    Motion ??= OnMotion;   // 没人接管时退回默认实现（打日志）
}

// JoyStickKnob.cs —— 拖拽结束必须回零，否则角色会一直滑
public void OnEndDrag(PointerEventData eventData)
{
    transform.position = startPosition;
    joyStick?.Motion(Vector2.zero);
}
```

`Motion` 用 `internal` 字段而非 `public event`，是为了让同程序集的 `Player` 能直接 `joyStick.Motion = OnJoyStick` 赋值——代价是任何一处赋值都会**覆盖**之前的订阅者（详见 [[委托与事件]]）。

### 其他技术产出（Part D）

#### 1. 已修：键盘松手不归零

`Assets/Scripts/Role/Player.cs`

```diff
  input.Player.Move.performed += OnKeyboardMove;
+ input.Player.Move.canceled  += OnKeyboardMove;
```

**根因**：`Player/Move` 是 **Value 类型的 Vector2 action**。Value action 的 `performed` 不是「值每次变化都触发」，而是「值从 `default`（这里是 `(0,0)`）变为非 default」时触发一次。所以在非零区间里 A→D 换向、加按第二个键，**都不会再触发 performed**；松手回零时只触发 `canceled`。只订 `performed`，`moveDirection` 就永远停在最后一次非零值上。

**残留风险**：`OnKeyboardMove` 里仍然是裸的 `ctx.ReadValue<Vector2>()`，靠「canceled 相位下 ReadValue 返回 zero」这个隐式行为归零。显式写法更稳：

```cs
Vector2 value = ctx.canceled ? Vector2.zero : ctx.ReadValue<Vector2>();
```

更彻底的做法是**Value action 一律轮询**（见下方 Ideas），回调只留给 Button。

#### 2. 新建摇杆系统：JoyStick + JoyStickKnob

`Assets/Scripts/UI/JoyStickKnob.cs`（新建）

```cs
public class JoyStickKnob : MonoBehaviour, IBeginDragHandler, IDragHandler, IEndDragHandler
{
    private float maxDragDistance = 128;
    private Vector2 startPosition;
    private Vector2 value;

    void Start()
    {
        startPosition = transform.position;
        joyStick = transform.GetComponentInParent<JoyStick>();
    }

    public void OnDrag(PointerEventData eventData)
    {
        Vector2 motionPosition = eventData.position - startPosition;
        Vector2 normalizedMotion = motionPosition.normalized;
        float distance = Vector3.Distance(eventData.position, startPosition);

        if (distance > maxDragDistance)   // 超出最大行程 → 夹到圆边上
        {
            transform.position = startPosition + normalizedMotion * maxDragDistance;
            x = (normalizedMotion * maxDragDistance).x / maxDragDistance;
            y = (normalizedMotion * maxDragDistance).y / maxDragDistance;
        }
        else
        {
            transform.position = eventData.position;
            x = motionPosition.x / maxDragDistance;
            y = motionPosition.y / maxDragDistance;
        }

        value = new Vector2(x, y);
        joyStick?.Motion(value);
    }
}
```

**跑通的部分**：`IBeginDragHandler / IDragHandler / IEndDragHandler` 三段接口由 `EventSystem` 统一派发（射线命中的是 Knob 自身的 Graphic，见 📎 [[UGUI 事件系统与射线检测链路]]），拖拽 → 归一化 → 委托回调 → `Player.moveDirection` → `CharacterController.Move` 整条链在 Screen Space - Overlay 下可用。

**两个多余的写法**（不报错，但绕）：
- 夹取分支里 `(normalizedMotion * maxDragDistance).x / maxDragDistance` 恒等于 `normalizedMotion.x`，两次乘除纯属自我抵消；
- `Vector3.Distance(eventData.position, startPosition)` 拿 Vector2 与 Vector3 混算（隐式补 z=0），用 `Vector2.Distance` 语义更清楚。

#### 3. 代码评审：摇杆的坐标系混用（尚未修，最该修的一处）

`JoyStickKnob` 里同时用了两套坐标：

| 变量 | 坐标系 |
| --- | --- |
| `eventData.position`（`PointerEventData`） | **屏幕像素** |
| `transform.position`（`Transform`） | **世界坐标** |

```cs
startPosition = transform.position;              // 世界坐标
Vector2 motionPosition = eventData.position - startPosition;  // 屏幕像素 − 世界坐标
transform.position = eventData.position;         // 屏幕像素赋给世界坐标
```

**根因**：在 **Screen Space - Overlay** 下，Canvas 的根节点与屏幕像素是 1:1 映射，所以「世界坐标 = 屏幕像素」这个巧合成立，代码看起来能用。一旦 Canvas 改成 **Screen Space - Camera** 或 **World Space**，或者 `CanvasScaler` 的 `scaleFactor ≠ 1`，两套坐标就彻底错位——摇杆会跳到画面别处、拖动方向和实际方向对不上。

**正确做法**：只认 `RectTransform` 的本地坐标。

```cs
private RectTransform knobRect;
private RectTransform areaRect;

public void OnBeginDrag(PointerEventData eventData)   // 开始拖时才取基准，布局变化也不会失效
{
    RectTransformUtility.ScreenPointToLocalPointInRectangle(
        areaRect, eventData.position, eventData.pressEventCamera, out startLocal);
}

public void OnDrag(PointerEventData eventData)
{
    RectTransformUtility.ScreenPointToLocalPointInRectangle(
        areaRect, eventData.position, eventData.pressEventCamera, out var local);

    Vector2 offset = Vector2.ClampMagnitude(local - startLocal, maxDragDistance);
    knobRect.anchoredPosition = startLocal + offset;
    joyStick?.Motion(offset / maxDragDistance);       // 天然落在 [-1,1]
}
```

顺带解决三件事：① `pressEventCamera` 自动适配三种 Canvas 渲染模式；② `Vector2.ClampMagnitude` 一次完成「限长 + 保方向」，不用自己判距离再乘归一化；③ 基准点移到 `OnBeginDrag` 里取，UI 布局重建/分辨率切换后不会用到过期值。

**同源隐患**：`maxDragDistance = 128` 是硬编码的**像素**值，没乘 `canvas.scaleFactor` → 高 DPI / 不同分辨率下摇杆的物理行程不一致，手感漂移。

#### 5. 顺手记两处小坑

- `Player.OnPlayerMove` 里 `controller.Move(Vector3.down)` **没乘 `Time.deltaTime`**：这是每帧 1 米的瞬移式下压，帧率越高下落越快；而且重力没有累加速度，`isGrounded` 为假时会「匀速贴地」而不是加速下落。CharacterController 该维护一个 `verticalVelocity -= g * dt`，再 `Move(new Vector3(x, verticalVelocity * dt, z))`。📎 [[CharacterController移动 — Move vs SimpleMove]]
- `Player.cs` 顶部 `using Unity.VisualScripting;` 是可视化脚本包的引用，本文件没用到，属于多余依赖（会让该脚本强依赖 Visual Scripting 包，卸载包就编译失败）。

## Ideas

- **Value action 一律轮询，Button 才用回调**。`Update` 里 `input.Player.Move.ReadValue<Vector2>()` 天然每帧归零，不用管 performed/canceled 的相位语义，也不用担心「换向不触发」——今天的 bug 本质是把 Button 的心智模型套在了 Value 上。
- 输入层应该在**归一化之后**再分发给 Animator：键盘给 ±1、摇杆给 ±1，混合树的阈值才只需要维护一套。现在的 ×4/×6 是「用魔法数字补量纲」。
- `internal Action<Vector2> Motion` 用 `=` 赋值会覆盖既有订阅，想支持「键盘 + 摇杆 + 将来的手柄/AI 托管」多源共存，必须改成 `event` 或者显式的 `AddListener/RemoveListener`。
- 摇杆还没做**死区**：手指微抖时 `value` 在 0.01 量级浮动，`moveDirection != Vector2.zero` 就成立，角色会一直有微小位移、动画也在 Idle/Walk 之间抖。
- `maxDragDistance` 是像素值，正确姿势是按摇杆背景的 `rect.width * 0.5` 算，分辨率自适应自动成立。
