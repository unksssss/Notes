# 平面反射 — 镜像相机、斜投影裁剪与反射贴图采样

## 一、先选型：三套反射方案解决的不是同一个问题

| 方案 | 反射内容 | 能否照出角色 | 代价 | 适用 |
| --- | --- | --- | --- | --- |
| **Reflection Probe** | 烘焙/实时捕捉的**环境立方体贴图** | ❌ 照不出场景里的动态物体（除非实时探针 + 高频刷新，仍只是近似） | 一张 cubemap | 室内金属/玻璃的环境色，不要求真实倒影 |
| **SSR**（屏幕空间反射） | 屏幕里**已经渲染出来的像素** | ✅ | 全屏 Pass + 深度/法线重建 + 射线步进，移动端偏贵；**屏幕外的东西反射不出来** | 大面积水面、地面湿滑 |
| **Planar Reflection**（平面反射） | 用**镜像相机重新渲染一遍场景** | ✅ 完全真实，连屏幕外也能照到 | **DrawCall 翻倍**（多渲一遍场景） | 单一平整大平面：地板、水面、镜子 |

> 判据：**只反射环境** → Probe；**要真实倒影且只有一块平地面** → Planar；**到处都要反射、性能敏感** → SSR。跑酷/横版这类「底部一块镜面地板」的需求，Planar 是唯一能照出角色的方案。

## 二、五步链路

```
① 复制主相机 → 沿镜面平面做镜像（位置翻转 + 上下颠倒）
② 用镜像相机把场景渲到一张 RenderTexture（"从水底下往上看"的画面）
③ 地面 Shader 按「屏幕空间 UV」采样这张 RT
④ 把倒影和地面底色混合
⑤ 释放 RT / 销毁镜像相机
```

关键点在于 ③ 的**屏幕空间 UV**：镜像相机和主相机用同一套投影参数，所以屏幕上任意一个像素，在 RT 里对应的就是它自己的倒影。这就是为什么不需要任何世界坐标变换，直接 `screenPos / w` 就能采到。

## 三、镜像矩阵

平面由「一点 + 法线」定义，平面方程 `n · p + d = 0`，其中 `d = -n · planePos`。关于该平面做镜像的矩阵（反射矩阵）：

```cs
private static Matrix4x4 CalculateReflectionMatrix(Vector4 plane)
{
    Matrix4x4 m = Matrix4x4.zero;

    m.m00 = 1f - 2f * plane.x * plane.x;
    m.m01 = -2f * plane.x * plane.y;
    m.m02 = -2f * plane.x * plane.z;
    m.m03 = -2f * plane.w * plane.x;

    m.m10 = -2f * plane.y * plane.x;
    m.m11 = 1f - 2f * plane.y * plane.y;
    m.m12 = -2f * plane.y * plane.z;
    m.m13 = -2f * plane.w * plane.y;

    m.m20 = -2f * plane.z * plane.x;
    m.m21 = -2f * plane.z * plane.y;
    m.m22 = 1f - 2f * plane.z * plane.z;
    m.m23 = -2f * plane.w * plane.z;

    m.m30 = 0f; m.m31 = 0f; m.m32 = 0f; m.m33 = 1f;

    return m;
}
```

结构上就是 `I - 2·n·nᵀ` 再补上平移项 `-2d·n`。用法不是改相机 Transform，而是**乘在 view 矩阵左边**：

```cs
// 让「镜像相机」看到镜像世界
reflectionCamera.worldToCameraMatrix = cam.worldToCameraMatrix * reflectionMat;
```

> ⚠️ 位置和欧拉角也要同步镜像（`MultiplyPoint` + `-euler.x`），否则斜投影与光照方向会出现偏差。

## 四、斜投影裁剪矩阵：只渲染镜面以上的世界

不做裁剪的话，镜像相机看到的是**整个镜像世界**——包括地板背面、地面以下的一切。倒影里会冒出不该有的东西（尤其是地形有厚度时，会看到地板的下表面）。

`Camera.CalculateObliqueMatrix(Vector4 clipPlane)` 的作用：**把近裁剪面扭到任意平面上**，这里扭到镜面平面。于是「镜面以下」全部落在近裁剪面之外，被裁掉。

```cs
// 世界空间的镜面平面 → 镜像相机的相机空间
private Vector4 CameraSpacePlane(Camera cam, Vector3 pos, Vector3 normal, float sideSign)
{
    Vector3 offsetPos = pos + normal * clipPlaneOffset;
    Matrix4x4 m = cam.worldToCameraMatrix;

    Vector3 cPos = m.MultiplyPoint(offsetPos);                      // 平面上的点 → 相机空间
    Vector3 cNormal = m.MultiplyVector(normal).normalized * sideSign; // 法线只受旋转影响，用 MultiplyVector

    return new Vector4(cNormal.x, cNormal.y, cNormal.z, -Vector3.Dot(cPos, cNormal));
}

// 应用
Vector4 clipPlane = CameraSpacePlane(reflectionCamera, planePos, planeNormal, 1f);
reflectionCamera.projectionMatrix = cam.CalculateObliqueMatrix(clipPlane);
```

### `clipPlaneOffset` 为什么必须存在

裁剪面**正好压在镜面上**时，镜面自身会被渲进倒影 → 倒影里出现「镜子里的镜子」→ 无限递归的视觉噪声。往上抬一点点（0.03~0.1m）把镜面本身排除掉，这是最小成本的解法。

更彻底的做法是：镜面单独一个 Layer，从镜像相机的 `cullingMask` 里剔除。

### 只对透视投影成立

`CalculateObliqueMatrix` 是**为透视投影设计**的。正交投影下算出的近裁剪面会退化（w 变成 1.8e6 这种量级），Unity 直接抛：

```
Screen position out of view frustum (screen pos 0,0,1835012) (Camera rect 0 0 1024 1024)
```

**根因不是矩阵算错，是「正交相机不该走这条路」**。处理方式见第七节。

## 五、`GL.invertCulling`：镜像会翻转三角形绕序

镜像变换的行列式是负的，意味着**所有三角形的绕序被翻转**：原本逆时针的变成顺时针。如果不处理，背面剔除（`Cull Back`）会把正面全剔掉、把背面全画出来——整个场景「里外翻过来」，看上去像模型破了。

```cs
GL.invertCulling = true;
reflectionCamera.Render();
GL.invertCulling = false;   // ★ 必须复位
```

`GL.invertCulling` 是**全局静态状态**，不复位会污染后续所有渲染（主相机也跟着翻）。所以必须 `try/finally`：

```cs
try
{
    GL.invertCulling = true;
    reflectionCamera.Render();
}
finally
{
    GL.invertCulling = false;
    insideRendering = false;   // 递归保护标志也要一起复位
}
```

> 中途抛异常（材质被销毁、RT 创建失败）时，如果标志卡在 `true`，之后**所有帧的倒影全部失效且主画面里外翻**——现象离原因极远，很难查。

## 六、Shader 侧：屏幕空间采样

```hlsl
struct v2f
{
    float4 pos       : SV_POSITION;
    float2 uv        : TEXCOORD0;
    float4 screenPos : TEXCOORD1;
};

v2f vert (appdata v)
{
    v2f o;
    o.pos = UnityObjectToClipPos(v.vertex);
    o.uv  = v.uv;
    o.screenPos = ComputeScreenPos(o.pos);   // 齐次坐标，未除 w
    return o;
}

fixed4 frag (v2f i) : SV_Target
{
    fixed4 baseCol = tex2D(_MainTex, i.uv) * _BaseColor;

    float2 reflUV = i.screenPos.xy / i.screenPos.w;        // ★ 必须除 w
    fixed3 reflCol = tex2D(_ReflectionTex, reflUV).rgb * _TintColor.rgb;

    return fixed4(lerp(baseCol.rgb, reflCol, _ReflectStrength), 1);
}
```

| 点 | 说明 |
| --- | --- |
| `ComputeScreenPos` 返回**齐次**坐标 | 不除 `w` 直接用会全屏一个色（透视除法在光栅化后才有） |
| 不用 `_CameraOpaqueTexture` / GrabPass | 那拿到的是「当前画面」，不含倒影；这里要的是**镜像相机的结果** |
| RT 由脚本每帧 `SetTexture` | 也可以用全局 `Shader.SetGlobalTexture`，但多镜面时会互相覆盖 |
| 分辨率 | 512~1024 足够。倒影本来就是模糊的，提分辨率只吃带宽不涨观感 |

## 七、生命周期：RT 与镜像相机

```cs
[ExecuteAlways]                       // 编辑器里也能看到效果
[RequireComponent(typeof(MeshRenderer))]
public class PlanarReflection : MonoBehaviour
{
    private void OnDisable()
    {
        if (reflectionCamera != null)
        {
            if (Application.isPlaying) Destroy(reflectionCamera.gameObject);
            else DestroyImmediate(reflectionCamera.gameObject);   // ★ 编辑态必须用 Immediate
            reflectionCamera = null;
        }

        if (reflectionRT != null)
        {
            reflectionRT.Release();
            if (Application.isPlaying) Destroy(reflectionRT);
            else DestroyImmediate(reflectionRT);
            reflectionRT = null;
        }
    }
}
```

| 坑 | 原因 |
| --- | --- |
| 编辑态用 `Destroy` | 编辑器里 `Destroy` 是延迟到下一帧的，`[ExecuteAlways]` 下会残留一堆隐藏相机 |
| RT 不 `Release` | 显存泄漏，且 RT 是原生资源，GC 不管 |
| 相机 `enabled = true` | 会参与自动渲染 → 额外一次全场景渲染 + 递归 |
| `hideFlags` 不设 | 镜像相机会出现在 Hierarchy 里，被误编辑、被存档序列化 |

**递归保护**：`OnWillRenderObject` 会被**每一个**正在渲染这块地面的相机调用，包括我们自己的镜像相机。

```cs
if (cam.cameraType == CameraType.SceneView ||
    cam.cameraType == CameraType.Preview ||
    cam.cameraType == CameraType.Reflection) return;   // ★ Scene/Preview/镜像相机 一律跳过
if (cam.orthographic) return;                          // 正交主相机也会让斜投影退化
if (insideRendering) return;
insideRendering = true;
```

这三条过滤同时解决了两个问题：递归，以及第七节那个 `out of view frustum` 报错。

## 八、实战报错：`Screen position out of view frustum`

**现象**：Console 每帧刷 `Screen position out of view frustum (screen pos 0,0,1835012) (Camera rect 0 0 1024 1024)`，栈指向 `PlanarReflection.OnWillRenderObject` 里的 `Render()`。

**根因**：`OnWillRenderObject` 被 **Scene 视图相机**触发了。Scene 视图默认是**正交**投影，而 `CalculateObliqueMatrix` 在正交下会算出退化的近裁剪面（w ≈ 1.8e6），Unity 报这个警告。**Game 视图的倒影其实是正常的**，纯粹是 Console 噪音。

**修法**：过滤 `CameraType.SceneView / Preview / Reflection` + 主相机 `orthographic` 直接跳过（见上）。

**若 Game 视图也报**：检查主相机 Near Clip。`0.01` 这种过小的值会让斜投影矩阵条件数变差，调到 `0.3` 左右。

## 九、坑清单

| # | 坑 | 表现 | 修法 |
| --- | --- | --- | --- |
| 1 | 不做斜投影裁剪 | 倒影里出现地板背面 / 地下物体 | `CalculateObliqueMatrix` |
| 2 | `clipPlaneOffset = 0` | 镜面自身被渲进倒影，递归噪点 | 抬 0.03~0.1，或镜面单独 Layer 剔除 |
| 3 | 不翻 `GL.invertCulling` | 场景里外翻、模型像破面 | `try/finally` 置 true |
| 4 | `invertCulling` 不复位 | 主画面也跟着翻 | `finally` 里复位 |
| 5 | 不过滤 SceneView | 每帧 `out of view frustum` 警告 | 按 `cameraType` + `orthographic` 过滤 |
| 6 | RT 不 Release | 显存持续上涨 | `OnDisable` 里 `Release` + `Destroy` |
| 7 | 编辑态用 `Destroy` | Hierarchy 里堆隐藏相机 | `Application.isPlaying` 分支到 `DestroyImmediate` |
| 8 | DrawCall 翻倍 | 大场景帧率腰斩 | 降低 RT 尺寸、`cullingMask` 只留必要层、远处镜面关掉脚本 |
| 9 | 镜面法线不是 +Y | 倒影方向错乱 | `transform.up` 必须是镜面法线，Plane 不能旋转错 |
| 10 | 多块镜面共用一个脚本实例 | 互相覆盖 `_ReflectionTex` | 每块镜面各自持有 RT，或改用全局纹理 + 优先级 |

## 十、移植到 URP 时的对照

| Built-in | URP |
| --- | --- |
| `OnWillRenderObject` 触发 | `ScriptableRenderPass.Execute`（`RenderTargetIdentifier` + `CommandBuffer`） |
| `camera.Render()` 直接渲 | `context.DrawRenderers` 或 `cmd.SetRenderTarget` + `context.ExecuteCommandBuffer` |
| `GL.invertCulling` | `cmd.SetInvertCulling(true)`（走 CommandBuffer，不污染全局） |
| `rend.sharedMaterial.SetTexture` | `cmd.SetGlobalTexture` |
| 手动管 RT | `RenderTexture.GetTemporary / ReleaseTemporary`（池化） |

URP 下还要注意 `ScriptableRenderPass` 的 **RenderPassEvent**：平面反射必须在**不透明物体渲染之前**把 RT 准备好，通常挂在 `BeforeRenderingOpaques`。
