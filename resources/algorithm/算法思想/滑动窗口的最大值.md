# 滑动窗口的最大值

> **题目**：给定数组 `nums` 和窗口大小 `k`，窗口从最左滑到最右，每次向右移一格，输出每个窗口内的最大值。
> 例：`nums = [1,3,-1,-3,5,3,6,7], k = 3` → `[3,3,5,5,6,7]`

## 一、核心认知：为什么必须用「双端」队列

暴力做法是每个窗口扫 `k` 个元素，`O(nk)`。想降到 `O(n)`，就要让「求最大值」这个动作变成 `O(1)`。

关键在于**窗口每滑一步，发生了两件事**：

| 动作 | 位置 | 需要的数据结构能力 |
| --- | --- | --- |
| 新元素从**右边**进来 | 队尾 | `push_back` |
| 最左的元素从**左边**滑出 | 队首 | `pop_front` |
| 求当前最大值 | 队首 | 读 `front` |

**三个动作分别作用在两端** —— 这就是为什么**单调栈做不了**（栈只能动一端）。必须用**双端队列 `deque`**。

于是数据结构定下来了：一个 `deque`，里面存**下标**，对应的值保持**单调递减**。队首永远是当前窗口的最大值。

## 二、三个动作

```cpp
deque<int> dq;                      // 存下标，nums[dq] 单调递减

for (int i = 0; i < n; ++i) {
    // ① 队尾所有 <= nums[i] 的，全弹掉
    while (!dq.empty() && nums[dq.back()] <= nums[i]) dq.pop_back();

    // ② 新元素入队
    dq.push_back(i);

    // ③ 队首若已滑出窗口 [i-k+1, i]，弹掉
    if (dq.front() <= i - k) dq.pop_front();

    // ④ 窗口填满后，队首就是本窗口最大值
    if (i >= k - 1) res.push_back(nums[dq.front()]);
}
```

**① 为什么能弹？** 新元素 `nums[i]` 比队尾大（或相等），并且它**更晚过期**（下标更大）。所以在它过期之前，队尾那些元素**永远不可能成为最大值** —— 它们已经"被彻底淘汰"了，没必要留着。

**③ 为什么是 `<=`？** 窗口是 `[i-k+1, i]`，`dq.front() < i-k+1` 等价于 `dq.front() <= i - k`。写成 `< i - k` 会漏弹一个过期元素。

## 三、完整推演（剑指原题 `k=3`）

| i | `nums[i]` | 弹队尾 | 入队后 `dq`（下标:值） | 队首过期？ | 输出 |
| --- | --- | --- | --- | --- | --- |
| 0 | 1 | — | `[0:1]` | — | — |
| 1 | 3 | 弹 `0` | `[1:3]` | — | — |
| 2 | -1 | — | `[1:3, 2:-1]` | `1 > -1` 否 | **3** |
| 3 | -3 | — | `[1:3, 2:-1, 3:-3]` | `1 > 0` 否 | **3** |
| 4 | 5 | 弹 `3, 2, 1` | `[4:5]` | `4 > 1` | **5** |
| 5 | 3 | — | `[4:5, 5:3]` | `4 > 2` | **5** |
| 6 | 6 | 弹 `5, 4` | `[6:6]` | `6 > 3` | **6** |
| 7 | 7 | 弹 `6` | `[7:7]` | `7 > 4` | **7** |

结果 `[3,3,5,5,6,7]` ✅

**第 4 行最值得看**：`5` 进来一次弹掉 3 个元素 —— 那种"一步弹很多"的直觉会让人以为复杂度退化了，但摊销下来每个下标一生只进出各一次，总体仍是 `O(n)`。

## 四、唯一必须记住的点：存下标，不存值

因为队首出队的判据是「**它的下标是否已经滑出窗口**」。存值的话，你根本不知道队首站在哪个位置。

实测（只存值的错误版）：

| 输入 | 期望 | 只存值的结果 |
| --- | --- | --- |
| `[7,2,4], k=2` | `[7,4]` | **`[7,7]`** |

第二个窗口 `[2,4]` 里，`7` 早就滑出去了，但存值的版本没有任何信息能判断这件事，只能靠 `dq.size() > k` 粗略砍 —— 而 `7` 并没有被弹掉（它最大，不会被队尾淘汰），于是输出继续是 `7`。

> **判据**：只要需要「按位置淘汰」，队列里就必须放**下标**；值是随时能用 `nums[idx]` 查的副产品。

## 五、易错点

1. **存值不存下标** → 无法判断过期（见上，实测 `[7,7]`）
2. **出队条件写 `dq.front() < i - k`** → 应 `<=`，少弹一个过期元素
3. **弹队尾用 `<` 而不是 `<=`** → 结果仍对（最大值相同时不影响），但队里会囤积等值元素；用 `<=` 更干净
4. **记录时机写 `i > k - 1`** → 少输出第一个窗口；应 `i >= k - 1`
5. **在 push 之前判队首过期** → 若队列此时为空，`dq.front()` 是 UB；顺序建议「弹尾 → 入队 → 弹头」
6. **忘了处理 `k <= 0` / `k > n`** → 前者会出现空窗口，后者应返回空数组
7. 空数组直接返回，别进循环

## 六、复杂度

| 维度 | 值 |
| --- | --- |
| 时间 | **`O(n)`** —— 每个下标进队 1 次、出队至多 1 次，总操作 `≤ 2n` |
| 空间 | `O(k)` —— 队列长度不会超过 `k`（多了会被过期弹掉） |

⚠️ 别把 `while` 循环当成 `O(n²)`：**内层 while 的总执行次数受「每个下标只入队一次」约束**，这是摊还分析的典型场景。

## 七、单调栈 vs 单调队列

两个名字很像，解决的问题完全不同：

| | 单调栈 | 单调队列（双端） |
| --- | --- | --- |
| 动哪端 | 只动栈顶（一端） | 队尾弹 + 队首弹（**两端**） |
| 典型问题 | 下一个更大元素、接雨水、直方图最大矩形 | **滑动窗口极值** |
| 为什么 | 只需要「最近的那个更大值」 | 窗口左边界会滑走，必须从头部淘汰 |
| 淘汰依据 | 只比大小 | 比大小 **+** 比下标（是否过期） |

> **看到「窗口 + 极值」→ 单调队列；看到「下一个更大 / 更小」→ 单调栈。** 判据就是「**需不需要按位置淘汰**」。

## 八、面试延伸

- **滑动窗口最小值** → 把 `<=` 全改成 `>=`，队首变最小值，其余一模一样
- **滑动窗口中位数** → 单调队列不适用（中位数不是"淘汰式极值"），要双堆（`multiset` / 对顶堆）
- **滑动窗口平均值** → 前缀和，`O(1)` 每个窗口，不用队列
- **「为什么不用 `multiset` 维护窗口」** → 能过，但每次插入/删除 `O(log k)`，总体 `O(n log k)`，比单调队列的 `O(n)` 慢；而且要处理重复值（得用 `multiset` 不是 `set`）
- **结合 DP**：`LC 1425 带限制的子序列和` 就是「DP + 单调队列优化」，`dp[i] = nums[i] + max(0, max(dp[j]))`，其中 `j` 在一个窗口内 —— 这是单调队列最值钱的应用场景（把 `O(nk)` 的 DP 降到 `O(n)`）
- **双指针 + 单调队列**：`LC 862`（和 ≥ K 的最短子数组）需要仔细处理负数的前缀和单调性

## 实测

`g++ -std=c++17 -Wall -O2` 零警告：

| 用例 | 结果 |
| --- | --- |
| `[1,3,-1,-3,5,3,6,7], k=3` | `[3,3,5,5,6,7]` ✅ |
| `[1], k=1` | `[1]` ✅ |
| `[1,-1], k=1` | `[1,-1]` ✅ |
| `[9,11], k=2`（`k=n`） | `[11]` ✅ |
| `[4,-2], k=2` | `[4]` ✅ |
| `[1,1,1,1], k=2`（重复元素） | `[1,1,1]` ✅ |
| `[7,2,4], k=2`（队首要能滑出） | `[7,4]` ✅ |
| **随机对拍 3000 组 vs 暴力** | 全部一致 ✅ |
