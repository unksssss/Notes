# 栈的操作（命令分发）

## 一、题目

维护一个栈，`q` 次命令：

| 命令 | 含义 | 空栈时 |
|---|---|---|
| `push x` | 入栈 | — |
| `pop` | 出栈 | 输出 `EMPTY` |
| `query` | 输出栈顶 | 输出 `EMPTY` |
| `size` | 输出元素个数 | 输出 `0` |

## 二、核心认知

这题本身没算法，考两件事：**① 命令分发（字符串 → 分支）② 空栈边界**。

`std::stack` 的接口就四个：`push` / `pop` / `top` / `size` / `empty`，和题目一一对应。真正的坑全在**怎么把读到的字符串命令分到分支上**。

## 三、❌ 为什么 `switch` 编译不过

```cpp
string op;
cin >> op;
switch (op) {                  // ← 编译器在这里就报错了
    case "push": { ... }
    case "pop":  { ... }
    ...
}
```

g++ 的真实报错：

```
error: switch quantity not an integer
error: could not convert '"push"' from 'const char [5]' to '<type error>'
error: could not convert '"pop"' from 'const char [4]' to '<type error>'
```

两条硬规则：

1. **`switch` 的条件必须是整型**（`int` / `char` / `bool` / `enum` 及其可整型提升的类型）。`std::string` 是类类型，不在其中 —— C++ **从来没有** 支持过 `switch (string)`。
2. **`case` 标签必须是整型常量表达式**。`"push"` 的类型是 `const char[5]`，既不是整型、也不能隐式转成 `std::string`（`case` 标签处不允许运行期求值）。

> **Java 7+ / C# 可以 `switch` 字符串，C++ 不行。** 如果是从别的语言带过来的直觉，这里就会翻车。

## 四、正解一：`if / else if` 链（推荐）

```cpp
#include <iostream>
#include <stack>
#include <string>
using namespace std;

int main() {
    ios::sync_with_stdio(false);
    cin.tie(nullptr);

    int q;
    if (!(cin >> q)) return 0;

    stack<long long> s;
    while (q--) {
        string op;
        cin >> op;
        if (op == "push") {
            long long x;
            cin >> x;
            s.push(x);
        } else if (op == "pop") {
            if (s.empty()) cout << "EMPTY\n";
            else           s.pop();
        } else if (op == "query") {
            if (s.empty()) cout << "EMPTY\n";
            else           cout << s.top() << '\n';
        } else if (op == "size") {
            cout << s.size() << '\n';
        }
    }
    return 0;
}
```

`string` 之间可以直接 `==` 比较，字符串字面量会自动构造临时 `string`，所以写起来和 `switch` 一样直观。

实测：

```
输入              输出
9
push 1
query             1
push 2
size              2
pop
query             1
pop
query             EMPTY
size              0
```

## 五、正解二：真要 `switch`，就先映射成 enum

```cpp
enum Cmd { PUSH, POP, QUERY, SIZE, UNKNOWN };

Cmd toCmd(const string& s) {
    if (s == "push")  return PUSH;
    if (s == "pop")   return POP;
    if (s == "query") return QUERY;
    if (s == "size")  return SIZE;
    return UNKNOWN;
}

switch (toCmd(op)) {
    case PUSH:  { long long x; cin >> x; s.push(x); break; }
    case POP:   { if (s.empty()) cout << "EMPTY\n"; else s.pop(); break; }
    case QUERY: { cout << (s.empty() ? "EMPTY" : to_string(s.top())) << '\n'; break; }
    case SIZE:  { cout << s.size() << '\n'; break; }
    default:    break;
}
```

多了一层映射，只在分支特别多（十几个命令）时才值得。

## 六、其他可以顺手改的

| 项 | 你的写法 | 建议 |
|---|---|---|
| 元素类型 | `stack<int>` | 题目提示「64 位输出请用 `%lld`」→ 用 `stack<long long>`，`cin` 读 `long long` 即可 |
| 多余头文件 | `#include <functional>`、`<ios>` | 删掉，`<iostream>` + `<stack>` + `<string>` 就够 |
| 空栈判断顺序 | `if (!s.empty()) pop(); else cout<<"EMPTY"` | 正确（先判空再操作），保持 |
| 换行 | `cout << "EMPTY" << "\n"` | 可用，但 `cout << "EMPTY\n"` 更直接 |
| `return 0;` | 省略 | `main` 隐式返回 0，不算错；写上也行 |

**注意 `pop` 的语义**：`std::stack::pop()` 只删除不返回，要取栈顶必须先 `top()`。所以 `query` 里 `top()` 之前必须判空 —— 这条你在 `pop` 里做到了，`query` 里也做到了 ✅。

## 七、复杂度

| 项 | 值 |
|---|---|
| 每个命令 | `O(1)`（`size`/`top`/`push`/`pop` 都是常数） |
| 总时间 | `O(q)` |
| 空间 | `O(q)` |

## 八、面试延伸

- **「用 vector 实现一个栈」**：见 [[用vector实现栈]]，`push_back` / `back` / `pop_back` 三件套
- **「如何让 `pop` 返回被删的元素」**：`T v = s.top(); s.pop(); return v;` —— 标准库刻意分开，是为了异常安全
- **两栈实现队列 / 单队列实现栈**：见 [[栈与队列的相互实现]]

## 九、补记：70% 通过率，只因一个大写（2026-11-20 10:22）

换成 `if` 链后逻辑全对，但提交只过 **70%**。原因**不是逻辑**，是输出字面量大小写：

```cpp
cout << "EMPTY" << "\n";   // ❌ 题目要的是 "Empty"
cout << "Empty" << "\n";   // ✅
```

官方题面：

> pop()：若栈非空，则删除栈顶元素；否则输出 **Empty**
> query()：若栈非空，则输出栈顶元素；否则输出 **Empty**

样例（官方示例 1）：

```
输入              正确输出
7                 2
push 1            2
push 2            Empty
size
query
pop
pop
query
```

用他的代码跑这个样例，输出是 `2 / 2 / EMPTY` —— 只差大小写。

### 为什么恰好是 70%

**只要某个用例里出现过「空栈 pop / 空栈 query」，那个用例的整行比对就失败**；一次都没遇到的用例全对。所以通过率不是 0 也不是 100，而是"含空栈操作的用例数"决定的 —— 这种 70%、80% 的通过率，几乎都是**格式/字面量**问题，不是算法问题。

### 怎么 5 秒定位

```bash
./a.out < in.txt > out.txt
cat -A out.txt          # 看行尾有没有多余空格、\r
diff out.txt expect.txt # 逐字符比对，一眼看出大小写
```

Windows 下 `cout` 重定向会输出 `\r\n`（文本模式转换），本地 `cat -A` 看到 `^M$` 是正常的，**OJ 在 Linux 上没有这个差异**，别被它吓到。

### 记一条铁律

> **OJ 输出是逐字符比对，大小写、空格、换行都算。**
> 题目里写 `Empty` 就绝不能输出 `EMPTY`；样例输出那一行，**照着抄**，别凭印象打。
