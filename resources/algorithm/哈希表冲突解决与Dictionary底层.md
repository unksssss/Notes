# 哈希表冲突解决与 C# Dictionary 底层

## 两种冲突解决方式

| 方式 | 原理 | 查找最坏复杂度 | 删除注意 |
|------|------|--------------|---------|
| **链地址法（分离链接）** | 冲突元素挂同桶链表 | O(n)（全部冲突时），平均 O(1) | 直接删链表节点即可 |
| **开放地址法（线性探测）** | 冲突后向后找空槽 | O(n)，平均 O(1) | ⚠️ 不能直接置空！会破坏探测链 → 需"墓碑"标记（lazy deletion） |

> 开放地址法删除为什么不能直接置空：线性探测的查找依赖探测链连续性，直接置空会让后续本可命中的元素在探测中途"撞墙"结束，误判为不存在。

### 形象比喻：信箱 vs 停车场（面试讲题可用）

**链地址法 = 信箱（邮箱墙）📮**

- 哈希表是一面**邮箱墙**，每个桶 = 一个信箱
- 冲突 = 好几封信都想投进**同一个信箱**
- 链地址法 = 信箱里用**一条链子把多封信串起来**（链表），取信时把这一个信箱里的信全部翻一遍
- 想删哪封抽哪封（直接删链表节点），**删除无副作用**
- 缺点：每封信要额外记"下一封信是谁"（next 指针），内存开销大；极端情况所有信堆进同一个信箱 → 全挂一条链 O(n)

**开放地址法 = 停车场（占车位）🚗**

- 哈希表 = 停车场，每个槽位 = 一个**车位**，一个车位只能停一辆车
- 冲突 = 目标车位被占了 → **往后找下一个空车位**（线性探测），停进去
- 取车时：从哈希位置往后挨个找，直到找到车，或遇到**空位**就停止（说明车不在这条道上）
- **删除的坑（墓碑）**：不能把车开走就清空车位！中间空了一个位，后面本来该找到的车会在空位处"断链"停住，误判"车不在"。正确做法是留一个**墓碑标记**（"此位曾经有车，请继续往后找"）
- 优点：没有指针，内存紧凑、**缓存友好**（数据在连续数组里）；缺点：表快满时几乎放不进新元素、有**聚集现象**（车扎堆，探测链变长）

**一句话记忆**：链地址法=冲突的信放进同一信箱用链子串；开放地址法=冲突的车开去下一个空车位停（删车位要立墓碑）。

## C# Dictionary 底层（面试高频）

### 结构 = 分离链接法

- `buckets`（哈希桶数组）+ `entries`（条目数组）+ 每个 entry 的 `next` 字段
- 冲突元素通过 `next` 串成链 → **分离链接法**

### 扩容机制

- 触发条件：插入时 `count >= entries.Length`
- 新容量：`ExpandPrime(oldSize)` = **大于旧容量 2 倍的最小质数**（3 → 7 → 17 → 37 → 79…）
- 为什么用质数：让 `hash % capacity` 分布更均匀，减少碰撞
- 扩容代价：全量 **rehash**（所有元素重新计算桶位），O(n)
- 最佳实践：预知数据量时 `new Dictionary(capacity)` 预分配，避免频繁扩容

### 为什么质数取模更均匀（数论本质，2026-08-17 补）

取模聚集的根源 = **hash 的规律性 × 表大小的因子**撞车。若 hash 都是 d 的倍数：

- `gcd(d, m) = 1`（互质）→ 映射 `q → (q·d) mod m` 是 0..m-1 上的**置换**，铺满所有桶
- `gcd(d, m) = g > 1` → 结果只落在 **m/g 个桶**，其余空转

例子（hash 全是 4 的倍数：4, 8, 12, 16, 20, 24, 28）：

| 表大小 | gcd(4, m) | 落桶数 | 结果 |
|---|---|---|---|
| m = 8（2 的幂） | 4 | 8/4 = 2（只有 0、4） | 🔴 一半桶空转，链长 3-4 |
| m = 7（质数） | 1 | 7 | 🟢 每桶恰好 1 个 |

**质数不挑食**：质数 p 与任何小于它的正整数互质 → 无论 hash 有什么等差/等倍规律都能均匀铺开，对"差 hash"宽容，实现简单（代价：除法比位运算慢）。

**2 的幂的隐藏坑**：`h % 2ⁿ` 二进制上只保留低 n 位、高位全丢——若 hash 低位有规律（如 8 字节对齐 → 末 3 位恒 0），一半桶直接空转。所以 Java HashMap 用 2 的幂时**必须配高位混合扰动**（`h ^ (h >>> 16)`），先搅匀再 `& (size-1)` 位运算换速度。

**一句话**：质数取模 = 不挑 hash 直接均匀；2 的幂 = 先保证 hash 够好再位运算换速度。最怕"2 的幂 + 不搅 hash"。

## 记忆要点

- 哈希表平均 O(1)，最坏 O(n)（链地址法）
- 链地址法未必比开放地址法省内存（每节点要存指针）
