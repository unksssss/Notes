#### 1. `JsonManager` 改成 CRTP 泛型单例 —— 每张表一份 Instance

**文件**：`E:\unityproject\Empty\Assets\Scripts\File\JsonManager.cs`、`File\WeaponGunManager.cs`

**改了什么**：从「泛型索引基类 + 外部 `new`」变成「抽象泛型单例基类 + 子类一行声明」，并把 `TConfigDict` 从 `static` 改成实例字段。

```csharp
public abstract class JsonManager<T, U>
    where T : class, IJsonData, new()
    where U : JsonManager<T, U>, new()
{
    private static JsonManager<T, U> instance;

    public static JsonManager<T, U> Instance
    {
        get
        {
            if (instance == null)
            {
                instance = new U();      // 懒加载：第一次拿 Instance 才读表
                instance.LoadConfig();
            }
            return instance;
        }
        set => instance = value;
    }

    private Dictionary<int, T> TConfigDict = new Dictionary<int, T>();

    protected abstract string JsonPath { get; }   // 带参构造和 new() 冲突 → 用抽象属性传路径
    ...
}
```

```csharp
public class WeaponGunManager : JsonManager<WeaponConfig, WeaponGunManager>
{
    protected override string JsonPath => @"E:\unityproject\Empty\Assets\StreamingAssets\WeaponGun.json";
}
```

**为什么这么写（关键机制）**：

1. **`static` 字段属于封闭泛型类型，不属于泛型定义**。`JsonManager<WeaponConfig, WeaponGunManager>.instance` 和 `JsonManager<BulletConfig, BulletManager>.instance` 是**两个完全独立的内存槽**，JIT 为每组类型实参生成独立类型 → 一份基类代码天然得到「每张表一个单例」。
2. **CRTP（Curiously Recurring Template Pattern，奇异递归模板）**：基类把派生类自己作为类型参数传回来（`JsonManager<WeaponConfig, WeaponGunManager>`），基类因此能在静态方法里 `new U()` 构造出**具体子类**，而不需要反射或工厂。代价是 `new()` 约束 —— 子类必须有无参公开构造，**外部依然可以 `new WeaponGunManager()` 绕过单例**。
3. **懒加载放 getter 里**：`instance = new U()` 之后立刻 `LoadConfig()`，而不是放构造函数 —— 构造函数里调虚方法（`JsonPath`）在 C# 里能跑但语义危险（子类字段尚未初始化），且 `new()` 要求无参构造，路径没法从构造参数进。
4. **`TConfigDict` 必须去 static**：静态集合会跨实例串味（第一次 `new` 出来的数据永远留着），而且静态引用是 GC Root，场景切了也不回收。

**已知妥协（他自己决定先不做）**：`Instance` 返回 `JsonManager<T,U>` 而不是 `U`，外部拿不到子类特有成员；彻底封死外部 `new` 需要 `Activator.CreateInstance(typeof(U), true)` 走非公开构造，属于过度设计。

#### 2. `Player.EquipWeapon(int ID)` —— 装备链路跑通

**文件**：`E:\unityproject\Empty\Assets\Scripts\Role\Player.cs`

**做了什么**：从「捡到枪 = 显示在 UI 列表」推进到「点 UI 项 → 枪真的挂到手上」。核心是**已装备列表复用 + 新枪实例化挂点**。

```csharp
private List<WeaponItem> playerWeaponLst = new List<WeaponItem>();
private WeaponItem currWeaponItem;

public void EquipWeapon(int ID)
{
    currWeaponItem?.gameObject.SetActive(false);        // 先收起当前枪

    for (int i = 0; i < playerWeaponLst.Count; i++)     // 已装备过 → 直接复用，不重复实例化
    {
        if (playerWeaponLst[i].ID == ID)
        {
            currWeaponItem = playerWeaponLst[i];
            currWeaponItem.gameObject.SetActive(true);
            return;
        }
    }

    var config = WeaponGunManager.Instance.GetConfig(ID);
    var prefab = Resources.Load<GameObject>("Prefab/Weapon/" + config.PrefabName);
    var go = Instantiate(prefab, WeaponPoint);

    go.transform.parent = WeaponPoint;                  // ⚠️ 冗余：Instantiate(prefab, parent) 已经设过父节点
    go.transform.localPosition = Vector3.zero;
    go.transform.localRotation = Quaternion.identity;
    go.SetActive(true);                                 // ⚠️ 冗余：新实例本来就是 active

    var weaponItem = go.AddComponent<WeaponItem>();
    weaponItem.Init(config);
    currWeaponItem = weaponItem;
    playerWeaponLst.Add(weaponItem);
}
```

**要点**：

- **切枪用 `SetActive` 而不是 `Destroy`**：同一把枪反复捡时零分配，也不触发 `Resources.Load` 的重复 IO。
- **`Resources.Load` 的路径拼接**靠配表里的 `PrefabName`，`config` 为 null 时下一行直接 NRE —— 配表 ID 和 JSON 对不上时表现是「点一下没反应 + 空引用」，不是「枪不存在」。
- `Instantiate(prefab, WeaponPoint)` 用的是 `(Object, Transform)` 重载，**默认 `worldPositionStays = false`**，实例的 localPosition/localRotation 保持 prefab 原值 → 所以后面必须手动归零，否则枪会飘在挂点旁边。

#### 3. `UIWeaponView` —— ScrollView 子项复用刷新

**文件**：`E:\unityproject\Empty\Assets\Scripts\UI\UIWeaponView.cs`

**做了什么**：订阅 `OnAreaWeaponChanged`，进范围就刷列表，出范围就隐藏整个 `Scroll View`；列表项**够用就复用、不够才 Instantiate**。

```csharp
private void OnNewChange(List<WeaponItem> AreaWeapons)
{
    Transform Item0 = Content.GetChild(0);
    if (AreaWeapons.Count <= 0) { ScrollView.SetActive(false); return; }
    ScrollView.SetActive(true);

    for (int i = 0; i < AreaWeapons.Count; i++)
    {
        GameObject go = (i < Content.childCount)
            ? Content.GetChild(i).gameObject
            : Instantiate(Item0.gameObject, Content);   // 不够才建，Item0 当模板

        go.transform.Find("TxtName").GetComponent<Text>().text = AreaWeapons[i].WeaponName;
        go.transform.Find("Icon").GetComponent<Image>().sprite =
            Resources.Load<Sprite>("Icon/" + AreaWeapons[i].IconName);

        OnClickItem(go, AreaWeapons[i]);
    }
}
```

**两个必须记住的坑**：

1. **列表变短时多出来的 item 不会被隐藏** —— 循环只跑到 `AreaWeapons.Count`，`Content` 里第 N 项之后的旧 item 还留着上一次的内容。正确做法是刷完再补一轮 `for (i = count; i < Content.childCount; i++) go.SetActive(false)`。
2. **闭包捕获的是 `item` 参数而不是循环变量**（这里传进来的是方法参数，安全），但 `btn.onClick.RemoveAllListeners()` 每次刷新都清空重加是**必须的** —— 复用 item 时不清就会叠加上一次的监听，点一次触发多次装备。

#### 4. 「有的物体运行时拖不动」—— 真凶是动画曲线

**现象**：在 Scene 视图里运行时拖 `Player` 的子物体 `ik_hand_r`，松手立刻弹回原位。

**排查过程（分两层）**：

1. **先排物理**：`FightingManager.OnSceneCreateGun` 给每把枪 `AddComponent<Rigidbody>()` + `useGravity = true`、未设 `isKinematic` → 非 kinematic 刚体每帧用物理结果覆盖 `transform`，这是「拖不动」的经典原因之一。但 `ik_hand_r` 是骨骼，身上没有刚体 → **不是这条**。
2. **再排动画**：grep 素材包动画文件，`External/Infima Games/Low Poly Shooter Pack/Art/Animations/Character/**` 多个 `.anim` 曲线里都写了 `ik_hand_r` 的路径，`Resources/Prefab/Role/SK_TP_CH_Default.prefab` 也带这条绑定 → **真凶确认**。

**根因**：Animator 的求值发生在 **`Update` 之后、`LateUpdate` 之前**，每帧把动画曲线值写回 `transform`。所以：

- 手拖 / 代码在 `Update` 里改 → 当帧就被覆盖，表现为「弹回」；
- 想用代码控制，**必须写 `LateUpdate`**（在 Animator 之后执行），写在 `Update` 里等于没写。

**三档解法**：

| 场景 | 做法 |
| --- | --- |
| 只是编辑期调姿势 | 关掉 Animator，或用 Animation 窗口的 Preview 把姿势录进动画 |
| 运行时要代码控制 | 写 `LateUpdate`，或用 `OnAnimatorIK`（IK Pass 打开时在动画之后回调） |
| 要自由摆姿势（举枪/换弹的手部定位） | **Animation Rigging**：建独立的 Target 物体（不挂动画曲线），用 IK 约束去追它 —— 改 Target 而不是改骨骼 |

**隐蔽坑**：某个 clip 里**根本没有这条曲线**，骨骼依然被重置回默认值 —— 那是 Animator Layer 的 **Write Defaults = true**：没被曲线驱动的属性也会被写回默认值。排查时容易误判成「动画里有曲线」。

## Ideas

- `JsonPath` 换 `Path.Combine(Application.streamingAssetsPath, "WeaponGun.json")` —— 现在这条绝对路径是「编辑器能跑、打包必挂」的定时炸弹。
- 7 个武器挂点用 **Fisher-Yates 洗牌**再取前 N，替代逐点 `Random.Range`，顺手解决「同款枪重复」。
- `WeaponItem` 十个字段和 `WeaponConfig` 完全重复 —— 要么直接持有 `WeaponConfig` 引用（省一份拷贝），要么把 `WeaponItem` 降级成纯组件、数据全从 manager 查。
- `Instance` 返回 `U` 而不是 `JsonManager<T,U>`，外部就不用为了调子类成员强转；配合 `Activator.CreateInstance(typeof(U), true)` 还能顺手封死外部 `new`。
- `OnEnterWeaponArea` 每帧对全部武器算 `Vector3.Distance` —— 武器多了以后要么上 `Physics.OverlapSphere`，要么改成事件驱动（进触发器才上报）。
